# 1 回目の修正仮説が外れたら — 観測したいものと手段の表

> [`../rules/instrument-before-second-fix.md`](../rules/instrument-before-second-fix.md) の手順 4 で引く表。
> 発動点 (1 回目の仮説 fix が外れ、既存の観測が無いとき) と行の目次は rule 側が持ち、常時読み込まれる。
> この文書は起動時には読まれない (常時読み込みの指示ファイル合計を上限 150k 字に収めるため、2026-11-08 に rule から切り出した。dotfiles issue 414 / 1044 の続き)。

| 観測したいもの | 手段 |
|---|---|
| 状態遷移 / イベント順序 | 構造化ログ (`print` でなく `NSLog`/`os_log`。tee pipe で block-buffered になり出ないため) |
| 境界の入出力 | request/response・引数/戻り値・契約違反を境界でログ |
| ネットワーク wire | `CFNETWORK_DIAGNOSTICS=3` / `URLSessionTaskMetrics` / proxy で byte 比較 |
| 成功 vs 失敗の差分 | 動いている隣接経路と同条件で A-B プローブ |
| 前提の再検証 | 「X は動く」を今この環境で実測し直す (過去ログの思い込みを排除)。🚨 **等式・定義を前提に書くときは、それが破れる入力を 1 つ挙げてから書く**。挙げられないなら「未確認の前提」と明示する (API が返す値の意味の思い込みが典型)。**原因を書く前に、出力を読んだ順と処理が起きた順を分ける** (最後まで流したコマンドの出力は、途中で出たものも最後に出たように見える。retro 687)。**issue / retro に「以後この環境では X が効く」と記録した対策 (dotfile・ローカル設定・常駐) も前提に数えない**: 頼る場面で、設定ファイルではなく実際に使われる値を 1 回読む (`ssh -G <host>` 等) |
| 再現条件 | 毎回か / 初回からか / 特定入力か を切り分ける |
| **人の操作を待つ観測** | 時間窓で区切らず**追記型のログ**にする (「N 秒以内に押してください」は外れる)。🚨 `... \| sort -u >> log` のようにパイプ終端へ整列を置くと**ループが終わるまで 1 行も書き出されない** |
| **「無反応」が no-op の正しい状態から来ていないか** | 端・空・上限・既に達成済みの状態では、正しい実装も「何も起きない」。**「無反応」を仮説の反証として読む前に、その状態に居なかったかを 1 手で潰す** |
| **状態を持つ view / object が使い回されていないか** | 最初の観測ログに**インスタンス識別子** (ObjectIdentifier・アドレス等) を入れる。UI フレームワーク (SwiftUI の `NSViewRepresentable` 等) は、別の対象を描くときに view を作り直さず使い回すことがあり、前の対象の状態が残って「何も起きない」を作る。識別子が無いと、この形はログから見えない |
| **再試行・復帰の合図を複数持つ機構で、実際にどれが効いたか** | 成功ログに**どの合図で成功したか** (trigger 名) を出す。効いていない合図を守るテスト・上限・レビュー対応を積む前に、実機でどれが働いているかを確かめる |
| **成功する入力と失敗する入力の差** | 同じ操作を **成功する入力**でも 1 回やり、何が違うかを言語化する (文字種 / 大文字小文字 / 正規化 / 長さ / provider / 空・1 件・多数)。「たまに動く」は乱数ではなく**分類**であることが多い |
