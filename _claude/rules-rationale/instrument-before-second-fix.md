# 1 回目の修正仮説が外れたら、2 発目を打つ前に「観測を増やす」を選ぶ — なぜ・実例

ルール本文: `~/dotfiles/_claude/rules/instrument-before-second-fix.md`（`~/.claude/rules/` に link され、毎セッション起動時に読まれる）。
この文書は起動時には読まれない。ルールの根拠・起源・実例を保存し、ルールを疑う・改訂する・却下するときに読む。

## なぜ (起源: obaket issue 227 Dropbox -1005, 2026-06-09)

`URLError -1005` の bug で、wire レベル (URLSession が実際に何を送り、サーバがなぜ接続を切ったか) が見えないまま app 層ログだけで推測 fix を 2 連続で外し、commit 4 本 (fix 2 + revert 2) と実機検証 2 周を無駄にした。1 回目が外れた時点で `CFNETWORK_DIAGNOSTICS=3` / `URLSessionTaskMetrics` / 成功経路との A-B プローブを仕込んでいれば最短で真因に寄れた。観測を仕込むコスト (数十分) の方が圧倒的に安い。

## ルール本文から移した実例

本文には規範だけを残し、その根拠になった実例をここへ移した（元の文脈のまま）。

実例 (obaket 582, 2026-08-25): アップロード完了トーストの「アプリ内で表示」が、**大文字を含む
ファイル名では 100% 失敗し、全部小文字なら成功する**バグだった (Dropbox は path を `path_lower`
由来で組むのに、呼び出し側がローカルのファイル名から要求 path を組み直していた = 表現不一致)。
症状が「たまに動く」ためタイミング仮説の修正が繰り返し入り、そのたびに再発していた。
決定打は実機ログ 1 行の**大文字**で、コードを読むより速かった。

実例 (obaket, 2026-08-23): CI の失敗を「パス解決が環境依存で壊れている」と読んで修正したが、
真因は「その実行環境に検査対象のソースが存在しない」で外した。**このとき失敗経路に環境変数の
dump を入れていたので、次の 1 往復で確定できた**。逆に言えば、確度の低い 1 回目の時点で
dump を入れていれば往復は 1 回で済んでいた。
