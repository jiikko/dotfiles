# 端末 UI で全角と半角を同じ列に縦に並べない（桁が揃っても目には揃わない） — なぜ・実例

ルール本文: `~/dotfiles/_claude/rules/no-mixed-width-columns-in-terminal-ui.md`（`~/.claude/rules/` に link され、毎セッション起動時に読まれる）。
この文書は起動時には読まれない。ルールの根拠・起源・実例を保存し、ルールを疑う・改訂する・却下するときに読む。

## なぜ (起源: dotfiles statusline のカレンダー格子, 2026-08-23)

weekly ペース行を「色分割バー + カレンダー格子」に作り替えたとき、バーのセルを
**半角数字 + 空白** (`1 2 3 …`) にし、その下に**全角の曜日**を置いた。
カラム数は上下で一致しており、幅の計算上は完全に揃っていた。

それでも**半角数字が 2 カラム幅セルの左に寄る**ため、目にははっきりズレて見えた。
ユーザーから **2 回**指摘されている (1 回目は「日付なら 2 桁で埋まるから大丈夫」と
逃げ、2 回目でようやく全角数字へ変えて解決した)。

つまりこれは「幅の計算ミス」ではなく **「幅は正しいのに揃って見えない」** 種類の問題で、
幅を数えるテストでは検出できない。人が見るまで分からないので、**組む時点で混ぜない**
以外に防ぐ手立てがない。

## 2026-09-04 dotfiles issue 242 / 246 — 同じ語を別の表示位置へ流用し、直下の理由文と矛盾した

同じ日に 2 セッションが**独立に**踏んだ。どちらも「**語の出典を 1 箇所へ寄せる**」という
正しい原則を適用した結果、**表示位置の違いを潰した**もの。

**242 の P3-1（doctor の確認画面）**: 結果画面の語 (`doctorOutcomeWord`) を確認画面（下見）へ
流用した。`Skipped` は結果画面では「🚫 触れず」(= 実行したが触らなかった) だが、下見の `Skipped` は
`StatusBlocked` 由来で、直下に出る理由文は「いまは対象外です: …」。**1 行の中で語と理由が
食い違った**。一覧 (`disk.Mark`) と同じ「🚫 対象外」へ戻し、`Failed` だけ結果画面の語を借りる形にした。

**246（doctor の下見の中断）**: 中断の語を DryRun と実削除で 1 つの定数に寄せた。下見の結果は
**その直後に確認画面になる**ので、そこに「このエントリには触っていません」と出すと
「この行は消えない」と読める。DryRun は元から何も触らないので、その文は情報量ゼロで誤読だけを生む。
語を分けて「消してよいかを確認できていません」にした。

🚨 **どちらも変異検証は全部 red で通っており、語彙テーブルのテストも緑だった。**
見つけたのは両方とも**敵対的レビュー**で、「その位置で語の直下に出る理由文と語が矛盾しないか」を
実装と突き合わせて初めて見えた。

幅の問題（このルールの本体）と同じ構造: **機械が測れる量（幅の合計 / 語彙テーブルの一致）は
全部通っているのに、人が読むと破綻している**。だから確かめ方も同じで、
**その画面に実際に出して読む**しかない。
