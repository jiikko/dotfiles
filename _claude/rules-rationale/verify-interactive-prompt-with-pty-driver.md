## なぜ (起源: dotfiles av1ify のクリップボード入力, 2026-08-22)

実 TTY での動作確認に `printf 'y\n' | script -q /dev/null zsh -c ...` を使ったところ、
確認プロンプトが **「中止しました」で終わり exit 130** になった。出力だけを見ると
**「y を入れたのに中止される = 実装のバグ」**にしか見えない形だった。

実際の原因はハーネス側で、パイプが閉じた時点で `script` が pty へ EOF を送り、
`read` が空回答を受けていた。`python3` の `pty.fork()` で**プロンプト文字列を待ってから**
`y` を書く driver に替えたら一発で通った (一覧 → 確認 → dry-run 実行、exit 0)。

構造的な理由: **パイプは「入力が尽きた」ことを即座に伝える**。人間の端末は入力が尽きず、
プロンプトが出てから打つ。この差は「回答の中身」ではなく**タイミングと EOF の有無**に出るので、
回答文字列をいくら正しくしても直らない。
