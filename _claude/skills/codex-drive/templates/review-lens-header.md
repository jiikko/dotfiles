# review lens 共通ヘッダ (この下に lens の攻め口と、タスク固有の的の brief を連結して使う)

- 指摘は file:line・理由・最小修正案をセットで出す。要約・称賛・一般論は不要
- 反証・確認できなかった項目は「反証できなかった」「未確認」と明記する (「問題なし」と書かない)
- 確信の持てない指摘は確信度を添える (黙って落とすより、確信度つきで報告する方がよい)
- 発火条件 (どの入力・順序・環境で起きるか) を示せるものは必ず示す。示せなければ「発火条件を示せない」と書く
- **読む範囲は対象差分のファイルとその直接の依存に限定する**。無関係な package の内部実装・`Package.swift`・網羅的なテスト読みに入らない
  (探索が発散すると時間上限 (`CODEX_FANOUT_TIMEOUT`) で出力ゼロのまま kill される — 2026-08-27 に 3 本が死んだ)。
  時間上限内に必ずまとめ、指摘が無い観点は「反証できなかった」と書いて短く終える (obaket issues/619)
