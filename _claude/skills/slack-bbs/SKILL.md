# slack-bbs (Slack のチャンネルを話題ごとに読む)

`slack-bbs` (実体は dotfiles の `bin/slack-bbs`。PATH 上にある) の 2 段の実行を、このセッションで回す。分類を `claude -p` に任せず
このセッションのサブエージェントで行うのは、端末の `claude` が別のアカウントでログインしていることがあるため。
仕組みと判断の経緯は `~/dotfiles/src/slack-bbs/README.md` と dotfiles の issue 706。

🚨 Slack の本文 (プライベートチャンネルを含みうる) がこのセッションとサブエージェントの会話の記録に残る。利用者はそれを承知で選んでいる (2026-11-09)。
本文を issue・commit・他のファイルへ写さない。

## 1. 依頼を作る

```sh
slack-bbs prepare [-since 2d] [-lookback 30d] [-max 500] [<チャンネルID>...]
```

- 引数が無ければ購読しているチャンネルを読む。購読が無いと rc=1 で「slack-bbs sub で選ぶ」と出るので、利用者に端末で `slack-bbs sub` を打ってもらう
- 期間は利用者の言葉から決める (「今日の分」なら `-since 12h` 等)。言われなければ既定 (2 日) のまま
- 出力は JSON: `{"dir": …, "key": …, "channels": [{"id","name","units","messages","prompt","response"}]}`。`prompt` が空のチャンネルは期間内の発言が無いので、分類は要らない
- 🚨 `key` は 3 の show にだけ渡し、2 のサブエージェントには渡さない (分類役が本文の中の指示に従って依頼を書き換えても、show が鍵で見破るための値)
- rc=1 でも、出力の `channels` に載ったチャンネルは使える (載らなかったチャンネルの理由は stderr)。`channels` が空 (`dir` も空) なら 2・3 へ進まず、
  stderr の理由を利用者に伝えて止める

## 2. 分類させる (チャンネルごとに 1 体ずつ、直列に)

`prompt` が空でないチャンネルごとに、サブエージェントを `model: "sonnet"` で起動する。指示はこの形にする (文面の中身は prompt のファイルにあるので、このセッションでは読まない):

> `<prompt のパス>` を Read し、そこに書かれた指示どおりに会話を話題へ分類して、指定された JSON だけを Write で `<response のパス>` に書いてください。
> そのファイル以外には書かない。返事は「書いた」の 1 行だけ。本文を返事に引用しない。

- 返事を待ってから次のチャンネルを起動する (並行させない)
- サブエージェントが失敗した・書かなかったチャンネルは、そのまま 3 へ進んでよい (show がそのチャンネルを「出せなかった」と出す)

## 3. 板を出す

```sh
slack-bbs show -key <key> <dir>
```

- 出力の Markdown を、そのまま利用者への返事に載せる (要約し直さない。並べ方と印は slack-bbs が決めている)
- stderr の `LLM の分類から捨てたもの` は、分類の誤りを slack-bbs が直した数。多ければ一言添える
- 板に「slack-cli が古い」の 🚨 注記があれば、期間より前に始まったスレッドの新しい返信が欠けている。返事でそれを伝え、brew の slack-cli を上げるよう勧める
- 全部のチャンネルを出せたら、show は依頼と応答のファイルを消す。rc=1 (出せなかったチャンネルがある) ならファイルは残るので、2 をそのチャンネルだけやり直してから show を打ち直す。やり直さないなら、残ったディレクトリを利用者に伝える
- 「要対応 (名指し)」「要対応 (あなたのスレッドへの返信)」は機械で確かめたもの、「要対応? (推定)」「必読 (推定)」は LLM の判断。返事でもこの区別を崩さない

## 端末で読むとき (このセッションを通さない)

端末で `slack-bbs` を打つと読む画面 (TUI) が開き、取得・`claude -p` での分類・表示をまとめて行う (`r` で今のチャンネル、`R` で全部を読み直す)。
分類は端末の `claude` のアカウントで走る (利用者はそれでよいと決めている。2026-11-09)。送る量は `slack-bbs -dry-run` で先に見られる。
利用者が「画面で読みたい」「開いたまま読み直したい」と言ったら、この skill の 1〜3 ではなく端末で `slack-bbs` を打つよう伝える。
