# CLAUDE.md Compact

Claude Code は起動時に、常時読み込む指示ファイルの合計が上限を超えると `⚠ N instruction files add up to …k chars, over the …k-char total limit` を出す。
公式の目安は CLAUDE.md 1 本 200 行未満 (https://code.claude.com/docs/en/memory)。この skill は**規範の文を残したまま**、規範でないもの (重複・まとめ・実例・起源・導出できる説明) を常時読み込みの外へ出す。
実体とのずれ (古いパス・消えたコマンド) を直すのは `claude-md-refresh`。ここでは中身の正しさは変えない。

## 引数

```
/claude-md-compact                          # 常時読み込みの全部 (global と cwd の repo)
/claude-md-compact _claude/rules            # ディレクトリ
/claude-md-compact CLAUDE.md docs/CLAUDE.md # ファイル
```

## Step 1: 測る

常時読み込みの集合は次のとおり。サブディレクトリの CLAUDE.md と frontmatter に `paths:` がある rule は、起動時には読まれない。

- cwd から上の階層の `CLAUDE.md` / `CLAUDE.local.md`、`~/.claude/CLAUDE.md`
- `.claude/rules/` と `~/.claude/rules/` の下の `*.md` (サブディレクトリも) のうち、frontmatter に `paths:` が無いもの
- それらの `@path` import の先。**import は費用を減らさない** (展開して一緒に読み込まれる)

数え方は `LC_ALL=en_US.UTF-8 wc -m` (警告の値とほぼ一致する)。dotfiles では `scripts/check_instruction_budget.sh` が global 層と dotfiles のセッションを数え、上限を CI で守る。
節ごとの大きさは次で出す (ファイル名は置き換える)。

```sh
LC_ALL=en_US.UTF-8 awk '/^## /{if(h)printf "%6d %s\n",n,h; h=$0; n=0} {n+=length($0)+1} END{printf "%6d %s\n",n,h}' <file> | sort -rn
```

前の値は `skill-tmpdir claude-md-compact` の dir にファイルで残す (報告の本文にだけ書かない)。どの層を縮めると効くか (global か repo か、どのセッションが上限に近いか) を、値を並べてユーザーに一文で示してから始める。
global 層 (`~/.claude/` の CLAUDE.md・rules) の実体は link 先の repo (dotfiles) にある。縮めるならその repo の規約 (worktree・push の手順) で作業する。

## Step 2: 動かせないものを先に集める

縮める前に、次を grep で集めて控える。これらは残すか、参照側も同じ変更で直す。

- **名前で参照されている見出し・語**: `grep -rn '「<見出し>」' <repo>` を hook・テスト・skill・他の rule に向けて打つ。見出しは rename しない
- **文書を読む検査**: `grep -rln '<ファイル名>' tests/ scripts/`。表の形 (スキル表の `~/.claude/skills/<name>/SKILL.md` など) を検査が数えていることがある
- **過去の決定**: issue・rationale を「常時読み込み」「上限」「paths:」「要約しない」で grep する。決まった方針 (例: 規範の文は要約しない / 行動で発動する rule は `paths:` にしない) に従う
- **ユーザー決定の印**: 「ユーザー指示 YYYY-MM-DD」「ユーザー決定」の語は残す (後で決定を探す手がかり)

## Step 3: 段落を分類して、行き先へ動かす

| 種類 | 行き先 |
|---|---|
| 規範 (する・しない・条件・数値・発動点・例外) | **残す。言い換えて縮めない** |
| ルール節の言い換えの節 (`やること / やらないこと`・まとめの箇条書き) | ルール節に無い項をルール節へ移してから、節を消す。**その節が checklist へ切り出した規範の唯一の常時読み込みなら残す** |
| なぜ・起源・実例 (retro / issue の番号・日付・実測の括弧書き) | 同名の rationale (`rules-rationale/<同名>.md`。CLAUDE.md なら専用の 1 本) の「本文から移した実例」節へ。実例の前に規範の文があれば、規範の部分は本文に残す。**括弧の中の規範 (どう確かめるか・何を見るか) も本文に残す**。起源の文は rationale に同じ形で在ることを `grep -F` で確かめてから消す |
| 発動したときだけ要る手順の詳細・チェックリスト・参照表 | 起動時に読まれないファイル (`rules-checklists/`) へ移し、本文に「発動したら Read する」の 1 行と目次を残す |
| `## 関連` のリンクの網 | 発動点の違う姉妹ルールと一次情報への指し先だけ残す |
| 別のファイルと同じ規範 | 詳しい方を正本にし、他は 1 行の参照にする。**正本は常時読み込みの側に限る** (checklist や `paths:` の rule を正本にすると、常時の規範が参照 1 行に縮む)。層をまたいで移す (repo の規範を global へ上げる) ならユーザーに確かめる |
| コードから導出できること (構成表・一覧・実装の説明) | 消す |
| 特定のファイルを触るときだけ要る規範 | `paths:` で条件ロードにする。**発動が行動 (commit・テスト・push・コマンド) の規範は移さない** (ファイルを読まずにその行動へ進む経路がある)。Read / Write / Edit のどれで読み込まれるかは版で変わるので、移す前に headless のセッションで A-B を測る |
| 人だけが読む保守の注記 | ブロックの HTML コメント `<!-- -->` は注入の前に除去される (公式)。ただし字数の検査 (`wc -m`) は数えるので、検査の値は下がらない |

- rationale・checklist の置き場が無い repo では、作る前に置き場をユーザーに確かめる (repo の構成が変わる)。作らないなら、移す代わりにブロックの HTML コメントにする
- **新しい規範を足さない**。移す先の文書にも、元に無い規則を書き足さない
- **1 回の作業で 1 種類ずつ**動かすと、関門の結果と差分が読みやすい
- 道具で書き換えるなら、置換ごとに当たった回数を assert し、0 件なら止める。括弧を消した跡の空行・行頭に残った句点・余分な空白を、diff で確かめる
- 一時的なスクリプトに、一時領域のパスの語を含む heredoc を書くと、削除を止める hook が誤って止めることがある。そのときは Write でファイルにしてから実行する

## Step 4: 関門で照合する

```sh
python3 -I ~/.claude/skills/claude-md-compact/fidelity.py --base <縮める前の rev> \
  --dest <移し先のファイルかディレクトリ>... -- <縮めたファイル>...
```

部品は範囲 (縮めたファイル + 移し先) の全体で個数を比べるので、元から在った記述や書き直した行では消失を隠さない。文は、縮めたファイルの今の版と、範囲の他のファイルで新しく現れた文に照合する。
rc: 0 = 消えた部品も読む候補も無い / 1 = 消えた部品がある / 3 = 読む候補だけがある / 2 = 使い方の誤り・どの対象も前と後が同じ (`--base` に縮めた後の rev を渡した)。一部の対象だけ同じなら ⚠ の行に出して照合から外すので、縮めたファイルが ⚠ に出ていないかを見る。
1 回にまとめて動かすと件数が数百になり読み切れない (2026-10-30 の rules 32 本の圧縮で、消えた部品 107 件・読む候補 354 件)。Step 3 の種類ごとに区切って回す。

- **消えた部品** (コードスパン・単位つきの数値・日付・番号・URL の個数が、前の版より少ない): 1 件ずつ、移したか・消してよい理由 (消した関連のリンク・導出できる例) があるかを決める。理由が無ければ戻す
- **読む候補** (前の版の文で、照合先に同じ形が無いもの。照合先で最も近い行が並ぶ): 全部読む。**元の文の対象と動作 (何を・どうしない) が、最も近い行に全部そろっているか**を比べる。一部の対象が落ちた言い換え (「作成・削除」が「作成」だけになった) は戻す
- 判定の処理表 (候補ごとに「残った / 移した / 戻した / 消してよい理由」) を `skill-tmpdir claude-md-compact` の dir に残す
- **消えた部品・規範の文を戻さずに進めるなら、何を消すかをユーザーに示して確かめる** (規範を消すのはユーザーの判断)

## Step 5: 反証レビュー

読み取りのみのサブエージェント 1 体 (上位モデル) に、「ルール節のどこにも残っていない規範 (禁止・条件・数値) が消えたものを挙げよ。言い換えで一部の対象 (作成と削除など) が落ちたものも挙げよ。対象がそろって残っている言い換えは指摘しない。消した節・見出しを名前で参照している文書があれば挙げよ」と頼む。
差分の範囲 (`<縮める前の rev>..HEAD`) を渡し、各指摘に「消えた行」と「残っていないことの確認」を添えさせる。指摘は実物で裏を取ってから採る。

## Step 6: 測り直して記録する

- Step 1 と同じ方法で測り直し、前と後を並べる (層ごと・上限までの残り)
- commit message に、前と後の字数・何をどこへ移したか・関門の件数を書く。上限の経緯を持つ issue があれば、そこにも追記する
- `_claude/` を変えたなら、push して実体の checkout へ pull するまでセッションには効かない。dotfiles では `scripts/check_instruction_budget.sh` の値も見る

`skill-tmpdir`・`scripts/check_instruction_budget.sh` は dotfiles の道具。無い環境では、Step 1 の式で測り、作業の dir を `./tmp/claude-md-compact-<日付>/` にする
