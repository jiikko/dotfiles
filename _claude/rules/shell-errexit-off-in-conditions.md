# `set -e` の下で、途中の失敗で止めたい関数を条件 (`if` / `||` / `&&` / `!`) の中で呼ばない

> **トリガー型ルール。** `set -e` の bash のスクリプトで、手順を順に行う関数やサブシェルを `f || die` / `if f; then` / `f && g` / `! f` / `out=$(f)` の形で呼ぼうとした瞬間に発動する
> (条件を 1 つ見るだけの関数は対象外)。

## ルール

bash の話 (3.2 と 5 で同じ)。`set -e` を付けていないスクリプトは対象外 (もともと途中で止まらない)。

「条件の中」は `if` / `elif` / `while` / `until` の条件、`||` と `&&` の左辺、`!` の後ろ。`out=$(f)` のコマンド置換の中も同じ扱いにする
(bash は、置換の中へ `set -e` を引き継がない)。

- **条件の中で呼んだ関数・サブシェルの中では、`set -e` が無効になる**。途中のコマンドが失敗しても先へ進み、条件が見るのは最後のコマンドの rc だけになる
  (`f || die "失敗"` は、f の途中が失敗しても、最後の行が成功すれば die しない)。ERR の trap も呼ばれない
- **途中の失敗を通すと困る関数 (台本・準備・後片付けのように、手順を順に行うもの) は、条件の中で呼ばず、単独の文として呼ぶ** (`f`)
- **サブシェルの中に `set -e` を書き直しても、条件の中では無効のまま**: `( set -e; f ) || rc=$?` の f も途中の失敗を通す
- 単独の文として呼んだうえで
  - どこで止まったかを知らせたいなら、`set -E` と ERR の trap で出す
  - 成功しても失敗しても後片付けをするなら `trap cleanup EXIT`
  - rc を受けて続けたい・失敗したときだけ何かをしたいなら、`set +e; ( set -e; f ); rc=$?; set -e` で受けてから rc を見る (括弧の中で変えた変数は外へ戻らない)
- 条件の中で呼んでよいもの: 外部コマンド 1 つ (`tool x || rc=$?`)、条件を 1 つ見て rc を返すだけの関数 (`if is_ready; then`)
- zsh も、条件の中で呼んだ関数の途中の失敗を通す。細部は bash と違う (`! f` の後で止まることがある・関数の中の失敗では EXIT の trap が呼ばれない) ので、
  zsh でこの rule の書き方に頼るなら、その形を 1 回打って確かめる
- 書いた後に `shellcheck -o check-set-e-suppressed <ファイル>` を打つと、関数を条件の中で呼んだ所に SC2310 が出る (指定しないと出ない)。
  条件を 1 つ見るだけの関数や `f || true` にも出るので、出た所を読んで、途中の失敗を通すと困る関数だけを直す
