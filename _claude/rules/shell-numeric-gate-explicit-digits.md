# shell の数値検証ゲートは、範囲式でなく明示列挙 + 桁数上限で書く

> **トリガー型ルール。** shell で「数値でなければ die / reject する」検証ゲートを
> 書こうとした瞬間に発動する。非数値を安全な既定値へフォールバックさせるだけの分岐
> (`''|*[!0-9]*) v=既定値`) は対象外 — 悪い値が来ても既定値に落ちるだけで機構は死なない。

## ルール

- **文字種の判定は範囲式 `[0-9]` でなく明示列挙 `[0123456789]` で書く**
  (case なら `*[!0123456789]*` で弾く)。範囲式はロケールの照合順に従い、
  `ja_JP.UTF-8` (この開発機の既定) では**全角数字を通す**
- **文字種だけで終えず、桁数 (または値) の上限も同時に検証する**。純数字でも 19 桁以上は
  bash の `[ -ge ]` / `[ -lt ]` が integer expected で常に偽を返し、比較に依存する機構
  (watchdog・閾値ゲート) が**無音で無効化**される
- 「ガードを通った値は整数比較できる」を暗黙の前提にしない。前提はガード自身が保証する
- 実装の形は `bin/codex-fanout` の `validate_timeout` が正本 (明示列挙 + `${#v} -le 9`)

## なぜ

起源: dotfiles `bin/codex-fanout`, 2026-09-01 (issue 150 の敵対レビュー)。根拠・起源・実例は `~/dotfiles/_claude/rules-rationale/shell-numeric-gate-explicit-digits.md` に置く（起動時には読まれない。ルールを疑う・改訂するときに読む）。

## やること / やらないこと

- ✓ die/reject ゲートの数字判定は `[0123456789]` の明示列挙で書く
- ✓ 桁数上限 (例: `[ "${#v}" -le 9 ]`) を併せて検証する
- ✓ ゲートの回帰テストには「最弱部」(全角数字を `LANG=ja_JP.UTF-8` で / 19 桁) を入れる
- ✗ `[0-9]` 範囲式を検証ゲートに使う (ロケールで意味が変わる)
- ✗ 文字種検査だけで「整数比較できる」と前提する
- ✗ フォールバック用途の既存 `*[!0-9]*` (repo 内に多数) を一括で書き換える
  (ゲートではないので対象外。その箇所を触るときに直せばよい)
