# ブランチの切り替え・作成を無断で行わない

## ルール

- **`git switch` / `git checkout` / `git switch -c`（ブランチ作成含む）を、ユーザーの明示的な指示なしに実行しない**
- 「この作業は別ブランチでやるべき」と判断した場合でも、勝手に切り替えず**提案して確認を取る**（例: 「PR を分ける設計なので新ブランチを切りますか？ それとも現在のブランチで作業しますか？」）
- ユーザーが「〜のファイルを作って」「実装して」と言ったとき、それは**現在のブランチ上での作業指示**であり、ブランチ操作の許可を含まない
- 無断で切り替えてしまった場合は、即座に元のブランチへ戻し、作成したブランチが空なら削除して報告する

## なぜ（起源: 2026-07-20）

複数PRに分割する設計に沿って「マイグレーションファイルを作成して」と指示された際、PR用ブランチが必要と判断して無断で `git switch -c` を実行した。ブランチはユーザーの作業状態そのものであり、勝手に変えると:

- working tree の内容が切り替わり、ユーザーが見ている画面・エディタの状態と食い違う
- 並行セッション・エディタの未保存変更・untracked ファイルが意図しないブランチに紐づく
- ユーザーのブランチ命名規則・PR運用の意図を先回りで壊す

「設計上ブランチを分けるべき」という正しさは、無断実行の理由にならない。コミット・push と同様、ブランチ操作もユーザーの領分。

## やること / やらないこと

- ✓ ブランチが必要だと思ったら、切り替え前に提案して指示を待つ
- ✓ ファイル作成・編集は現在のブランチのまま行う（untracked ファイルはブランチ切り替えに追従するので、後からユーザーが正しいブランチで拾える）
- ✗ 指示されていない `git switch` / `git checkout` / ブランチ作成・削除
- ✗ 「PRを分ける設計だから」を理由にした先回りのブランチ操作
