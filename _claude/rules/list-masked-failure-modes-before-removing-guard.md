# 冗長な防御を外すときは、それが「マスク」していた failure mode を先に列挙する

> **トリガー型ルール。** 「このチェックは別のところでやっているから冗長だ」「二重にやっている
> から片方外せる」と判断した瞬間に発動する。外す判断が**正しくても**発動する。
> **「置換」で既存の hook (`onTermination` / `deinit` / cancel handler / cleanup callback) が消えるときも
> 同じ**。外すつもりが無くても、旧実装の hook が担っていた cleanup は外れている
> (実例 obaket 695: eager proxy を lazy wrapper に置き換え、`onTermination { consumer.cancel() }` を
> 引き継がず push 型 source の producer Task が生き残った。変異 4 本 all red の後に敵対レビューが出した)。

## ルール

- **「冗長だから外す」と判断したら、外す前に次の 3 つを書き出す**:
  1. その防御が**単独で**防いでいた failure mode (= 本来の目的)
  2. その防御が**副次的に**防いでいた failure mode (= **マスク**していたもの)
  3. 2 が外れた後、その failure mode を**誰が**防ぐのか
- **3 の答えが「1 箇所のコード」なら、それが壊れたことを機械が検出できるかを確認する**。
  できないなら、外す前に検出手段 (テスト / 静的ゲート) を用意する
- **「本来の目的に対して冗長」と「他に何も守っていない」は別**。前者だけ確かめて外さない
- **関数・ブロックごと消すときは、そのコメントが記録していた failure mode の行き先も決める**
  (残る実装へ固定する / 別の場所のコメントへ移す / 消してよいと判断した理由を書く)。コードと一緒に
  教訓が消えると、同じ罠を別の場所で踏み直す (実測 2026-09-04 av1ify: 旧関数と一緒に消えた
  KSH_ARRAYS の注意書きと同じ罠を、新実装で敵対レビューに P1 として指摘された)

起源: obaket issue 544、2026-08-26 の実測。根拠・起源・実例は `~/dotfiles/_claude/rules-rationale/list-masked-failure-modes-before-removing-guard.md` に置く（起動時には読まれない。ルールを疑う・改訂するときに読む）。

## 特に危険な形

**「省略してもコンパイルが通る引数」「既定値付きの引数」が最後の砦になる形**。

- 既定値が安全側 (`overwrite: Bool = false`) なら、忘れても止まる
- 既定値が危険側 (`= true`) だと、**忘れた瞬間に静かに壊れる**
- hop が 2 つ以上あると (呼び出し側 → ライブラリ)、**どちらか一方を忘れるだけ**で成立する

この形を見つけたら、外す前に静的な形の固定 (lint / gate) を入れる。

## 手順

1. 外そうとしている防御の**呼ばれ方**を全部挙げる (grep)
2. 各経路で「この防御が無かったら何が起きるか」を書く。**本来の目的以外**を必ず 1 つ以上探す
3. 残る防御が単一障害点なら、**それを壊す変異を作って**、既存のテスト・CI が red になるか試す
   ([`mutation-verify-new-tests.md`](mutation-verify-new-tests.md))
4. red にならないなら、検出手段を先に入れてから外す

## やること / やらないこと

- ✓ 外す前に「マスクしていたもの」を列挙する
- ✓ 残る防御が単一障害点かを確認し、壊す変異が検出されるか実験する
- ✓ 検出できないなら、外す前に検出手段 (テスト / 静的ゲート) を用意する
- ✗ 「本来の目的に対して冗長」だけを根拠に外す
- ✗ 危険側の既定値を持つ引数を、無防備なまま最後の砦にする
