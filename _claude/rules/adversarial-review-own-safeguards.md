# 自分で作った「安全機構」は自己レビューで閉じない — 敵対的レビューを最終ゲートにする

> **トリガー型ルール。** 破壊的操作 (削除 / 上書き / 移動)、後始末、検査・ゲート・
> lint・CI チェック・**突合や allowlist のような「正当性の検証」**など
> **「壊れないことを保証する側」のコードを自分で新設した瞬間**に発動する。
> 「セルフレビューしたので大丈夫」と書きそうになったら必ず思い出す。
> **書き始める前に §0 の 2 つの問い**、書いた後に §1 以降を通す。

## ルール

- **自分が新設した安全機構は、自己レビューを通しただけで完了報告しない**。
  CLAUDE.md「レビュー方針」の敵対的レビュー (red team) を最終ゲートとして通す。
  codex が使えなくても、**観点を分けた別視点**を最低 2〜3 用意する
- **red team には「壊す手順を見つけろ。壊せなければ壊せなかったと明記しろ」**と指示する (「レビューして」では追認が返る)
- 指摘は**実コードで裏を取ってから**採否を決める (敵対レビューの出力も無検閲で採用しない)

## なぜ

起源: 2026-08-03 obaket の実測。根拠・起源・実例は `~/dotfiles/_claude/rules-rationale/adversarial-review-own-safeguards.md` に置く（起動時には読まれない。ルールを疑う・改訂するときに読む）。

## やること

### 0. 機構を作る前に「作らずに済む構造」を 1 度問う

安全機構は**それ自体が新しい失敗の入口**なので、作らずに済むならその方が安い。

#### 0-A. 掃除機構: 「そもそも発生させない構造」はないか

- 問い: 「この残骸は**どこで生まれるか**。生まれる側を差し替えれば掃除は要らないのでは?」
  (掃除機構は破壊的操作の新設であり、パターンを 1 つ間違えれば本物のデータを消す)
- 🚨 **機構を 1 つ足すたびに §7 の周回が 1 つ増えると見積もる**。「あると親切」な案内・後始末・分類も
  それ自体が固有の failure mode を持つ安全機構
- **同じ形の問題に前回下した結論を、無検証で持ち越さない** (依存の型が違えばコストは変わる)

#### 0-B. 検証・突合・allowlist: 「その答えを既に出している経路」はないか

- 問い: 「この判定の答えは、どこかで既に計算されていないか。それを呼べないか?」
  あるなら**近似を書かずにその経路をもう一度通す**
- 判定: 書こうとしている近似について **「本物の経路のどの部分を再現していないか」を列挙できるか**。
  できないなら、それは近似ではなく**別の判定**の新設 (2 実装は必ず食い違う)
- **遅さは理由にならない**。本物を通すのが数秒かかっても、破壊的操作の正しさを近似や呼び出し元の申告値に預けるより安い
- **実行時に本物を呼ばない近似 (字句の規則で「OS / ライブラリはこれを X と解釈しない」と判定する等) は、テストで本物を正解役にして
  網羅的に突き合わせてから閉じる**。入力の組み合わせを機械で生成し、近似が通すのに本物が X と解釈する反例が 0 件であることを見る
- 🚨 [`mutation-verify-new-tests.md`](mutation-verify-new-tests.md) の「同じ判定を 2 箇所で別実装していないか」と
  同じ形だが、あちらの発動点はテストを書くとき。**守り・pin・検査を足すとき**はこちらで問う

#### 0-C. 正しさの判定を、落ちうる補助の経路に載せていないか

- 速くするための経路 (キャッシュ・通知・常駐プロセス) は無いことがある。正しさはそれが無くても成り立つ経路で決める。
  載せるなら「その経路が無いとき」の答え (安全側に倒れるか) を先に決める

#### 0-D. 経路を分けたら、各経路に production から届く呼び出し元を列挙してから実装する

- 到達しない経路は、コード・テスト・docstring を持ったまま誰も通らない (obaket 898: 上書きの有無で 2 経路に分けたが、
  upload は全部片方だった。設計・実装・敵対レビュー 3 周を通っても誰も確かめていなかった)。列挙できない経路は仕様の穴か不要

機構が要ると確定したら、以降の節を通す。

### 1. 環境を変えた実験を必ず 1 セット回す

安全機構は「異常時に正しく振る舞うこと」が本体なので、正常系だけ試しても意味がない。

| 作る条件 | 確かめること |
|---|---|
| **対象が 0 件 / 空のディレクトリ / 新品環境** | 落ちないか (grep 無マッチ・空配列・nil) |
| **依存コマンドが失敗する** (偽の実行ファイルを PATH 先頭に置く) | 「検査できなかった」を緑にしていないか |
| **権限が無い / ファイルが消えた** | 握り潰していないか |
| **並行して別プロセスが動いている** | 誤検出・誤削除しないか |
| **違反 0 件 / ヒット 0 件の正常系** | 検査自身が落ちないか (`grep \| while read` の無マッチが `set -e` 下で無言で死ぬ) |

偽の `HOME` や一時ディレクトリでハーネスを組めば、実データを触らずに全部試せる。

🚨 **一時ファイルを作る道具は、正常系の成功パスの後にも残骸ゼロを確認する** (後始末の失敗は正常系でも起きる)。
変異検証の後も同じ。A-B の母集合は複数同時に数える (dir を数えるなら file も)。

- 緑を返した直後に一時領域を `ls` で見る (「self-test OK」は後始末を何も保証しない)
- **EXIT trap は 1 本しか持てない**。後始末が 2 つ以上なら 1 つの handler に束ねる
- **`$(...)` の中で初回生成された一時ファイルは親から見えない**。生成は親側で済ませる
- 🚨 **並列で走る道具の一時名を `$$` だけで作らない** (pid 再利用で別の対象のファイルを掴み、もっともらしい
  判定結果として表に混ざる)。対象を識別する値 + `$$` + `$RANDOM` を混ぜる

### 1.5. 検査・gate・予算を新設したら、それが名指しする退行を当てて red を確認する

**段数によらず発動する。** 検査 1 本でも、名指ししている退行を当てて赤くなるかを見るまでは退行検出力ゼロかもしれない
(観測対象が production から到達不能 / 予算が測っていない量を名指し / assert の失敗が exit code に届かない)。

- 多段なら**段ごとに「その段だけを外す」変異**を当てる (全段を同時に外すと、どれか 1 つの red で残りが見えない)
- 書いた段数と、変異で red になった段の数が合わないなら、**合っていない段は無い**
- 段数をヘッダやドキュメントに書くのは、全段の red を確認した後にする

### 2. 「沈黙 = 成功」になっていないか確認する

検査・ゲートは**検査できなかったときに緑を返さない**。`2>/dev/null` と `|| true` が「失敗を無視する」と同義になっていないか、1 つずつ見る。

- **テストハーネス自身の失敗も緑に畳まない**。「判定できなかった」は第 3 の結果として出す。
  production の検査は「判定不能 → 拒否 (fail-closed)」、**テストの判定は「判定不能 → 専用の値 (harness-error 等)」**で、allow / deny に丸めない
- **skip したことは「テスト自身の出力」に出す** (失敗時のみ表示されるログへの print は沈黙と区別できない)
- 🚨 **「判定不能 → 消さない / 撃たない」は破壊的操作の側にも要る**。応答が無い・読めない・素性が取れないは「対象が無い」ではない
- 🚨 **人へ出す案内に破壊的操作を書くときは、その案内が出る状態を全部列挙する**。1 つでも「やってはいけない状態」が
  混ざるなら読み取り専用の確認へ誘導し、**案内した先を実際に走らせて確かめる**
- 🚨 **沈黙を潰して失敗を見えるようにしたら、同じ commit で (a) 正常系でも鳴り続けないか (b) 鳴ったときの案内が安全か
  (c) その状態から利用者が抜ける操作があるか** を確かめる。「成功にしない」「消さない」「止める」に倒したなら、解消する手段
  (再試行で直る条件・破棄・案内) が UI か手順に在るかを問い、無ければ同じ変更で足すか起票して取り残しを明示する
- **逆向きの沈黙 —「失敗はするが原因が消える」**: `set -euo pipefail` 下の `var=$(... | grep ...)` は無マッチで代入ごと
  スクリプトが死に、直後の「抽出できなかったら FAIL」に到達しない。抽出に `|| true` を付け、空を受けてから明示的に FAIL を出す
- 🚨 **同じ `pipefail` の下で、`<生産側> | grep -q PAT` は在るのに「無い」と出る** (生産側は `printf` / `echo` / `cat` / `strings` /
  任意のコマンド)。`grep -q` が一致で先に終わると、書き込み途中の生産側が SIGPIPE で落ち、パイプライン全体が失敗になる
  (出力がパイプのバッファより大きいと起きる。obaket 2026-09-26: 38 KB で 200 回中 168 回、8.8 MB の `strings` で 50 回中 50 回が誤判定。
  MAS archive への debug API の混入検査が、これで効いていなかった)。変数は `grep -q PAT <<<"$x"`、コマンドは `grep -q PAT < <(cmd)` にする。
  横展開の grep は `| *grep +-[a-zA-Z]*q` のように**パイプの右側で**探す (左側の形で探すと変種を取りこぼす。同じ日に 2 回目を踏んだ)

### 3. 同型バグの横展開を grep する

- **テスト側で見つけた不具合は production 側の同じ API 使用箇所を grep する** (逆も同じ)
- 🚨 **直した直後に自分が書く新しいコードにも当てる** (同じセッションで直した罠を数時間後の新設ファイルで再生産する)
- 🚨 **ガードを 1 箇所に入れた瞬間、同じファイル / 同じ API の別の呼び出しに同じ変換が無検査で残っていないかを見る**

### 4. その機構が CI で実際に走るか、同じ commit で確認する

- 確かめ方: **その機構が守っている修正を revert して、CI が赤くなるか**を見る (手元ではなく CI で)
- 典型的な埋没先: 依存コマンドの有無で skip する gate / `if [ -t 1 ]` の内側 / CI では設定されない環境変数のゲート / 対象 0 件で早期 return
- 🚨 「CI で走っているか」は**ログに検査名が出ているかで確かめる** (skip は緑に見える)
- 🚨 **合格側も見る**。修正前 = 不合格 / 修正後 = 合格 の**両方**を実物で見る。偽陽性のまま母集合を sweep すると誤った一覧が issue に残る

### 5. 観点を分けて別視点に投げる

最低限の分け方: ①**壊す** (データ消失・回避経路) ②**素通りする** (false green・検査の無効化) ③**並行・中断** (途中終了・並列実行・非同期)。

- 🚨 ③ では **lock / actor の境界をまたぐ check-then-act** を必ず問う: 「lock を外して (または `await` を挟んで) から
  取り直し、状態を見て分岐する箇所で、**そのすき間に他のタスクがこの状態を変えられるか**。変えられるなら、すき間で
  起きうる出来事 (キャンセル・完了・時計の advance・別の書き込み) の**それぞれ**に結果を固定したテストがあるか」。
  全アクセスが lock の中なのでデータ競合ではなく、**TSan も lint も検出しない**。1 つの出来事だけをテストして
  残りを見落とす形になりやすい。自作のテスト基盤 (fake / harness) も対象
- 🚨 **in-memory の排他・lock の持ち主は、守る資源 (DB・ファイル・ID の名前空間) より短命な単位に置かない**。
  持ち主が作り直されうる単位 (profile ごとの runtime・画面ごとの object) だと、新旧 2 つの lock ができて排他が外れる (obaket 941)

### 6. 自作の計測に予算を付けるなら「その計測が構造的に見落とすもの」を先に書く

**何を測っていないかを先に言語化し、見落としが致命的なら形に依存しない指標 (比・伸び率) を併置する**
(例: fork 数の予算は直接の子しか数えないので、行数 10 倍で 1 tick が何倍になるかを併置する)。
節 2 は「検査が動かない」、こちらは「検査は動くが構造的に見えない」。

### 7. 敵対レビューの指摘を直したら、直した差分にもう 1 周回してから閉じる

**指摘への修正は新しい安全機構**なので、本ルールの発動条件をそのまま満たす。

- 2 周目は全文再走査でなくてよい。**「1 周目の指摘に対して何を新設したか」を列挙して攻め口として渡す**
- **指摘を「安全側に倒す」で直すときは、その処理が成功パスのどこで走るかを先に確かめる**。確定済みの副作用の後で失敗を増やすと
  「やったのに失敗と報告される」逆向きの実害になる。1 つの分岐で 2 つの判断 (呼び出し側へ何を返すか / 内部状態をどうするか) を
  決めていないかを見る (obaket 898)
- **多段の書き込み・削除の途中失敗を指摘されたら、段の順序を入れ替える前に、残りうる中途状態を consumer 側で拒否できないかを問う**。
  入れ替えは、残る中途状態を別の形に移すだけのことがある (obaket 941: 順序の入れ替えで 2 周往復した)
- 打ち切り条件: 採用する指摘が出なくなるまで。修正を入れた周は必ずもう 1 周ある
  - 例外: 直前の周の修正が **(a) 判定ロジックを新設せず (b) 各修正を直接の実測で確認できた** なら、その旨を明記して打ち切ってよい。
    🚨 ただし**別の環境条件を新たに持ち込む**修正 (大文字小文字 / ロケール / パスの表記) は判定ロジックの変更と数える
- 🚨 **観測 API / 非同期・detached な完了が絡むなら、周回を増やす前に実機を 1 回挟む** (机上では原理的に出ない欠陥がある。周回の数ではなく検証の種類を足す)
  - 挟む時点: **指摘に「本物の挙動が未実測」が 1 つでも出たら、次の周の前**。周を重ねるほど、未実測の前提の上に修正が積もる
    (dotfiles 427: 1 周目から出ていたのに、実機を挟んだのは 5 周目の後だった)
- **同じ判定の別々の書き方の食い違いから指摘が続けて出たら、次の修正を当てる前にその判定を 1 つの関数へ寄せる**。
  寄せないと、同じ形の指摘が書き方の数だけ出る (dotfiles 427: 「PG の session が生きているか」を 3 か所に書き、7〜10 周目の指摘の多くがその食い違いだった)
- 🚨 **破壊的操作の前提を「推論」で組んでいないか**。観測に置き換えられるなら、置き換えるまで周回は終わらない
- **「未確認リスク」を bounded / 無害と判定するときは、その値が届く先の consumer の分岐まで読む**
- **指摘への修正に添える「これで何が防げるか」も主張**。既存の経路で先に防げていないかを導出し直してから書く
  - 🚨 **指摘に無い機構を対応のついでに足したときも同じ**。足す前にその機構が無い状態を 1 回実測し、無いと何が起きるかを観測してから
    理由を書く。観測で差が出ないなら足さない (obaket 939)
- **レビューが名指しした未確認リスクが実機でしか潰せないなら、その human 確認が返るまで done にしない** (app 全体の状態を変える修正で特に効く)
- **既存の未検査領域を理由に指摘を先送りするなら、自分の変更がその領域を通るかを先に見る**。通るなら、既存の穴かどうかに関係なく、その経路を確認する手段を用意する

### 8. 字句 / 構文 gate は「脅威モデル」と「何を検出しないか」を先に書いてから閉じる (stopping rule)

lint / grep / 正規表現の gate は typecheck が通る迂回が原理的に無限にあり、「全部塞ぐ」を目標にすると §7 の
「修正した周はもう 1 周」が収束しない。

- gate を書く**前に** ①脅威モデル (誰の・どの失敗を止めるか) ②「検出しない」と決めた形 ③その形を review で見る責務の所在、
  をヘッダと CLAUDE.md に書く。迂回指摘が②に該当するなら**採用せず記録**する (§7 の「もう 1 周」は①②の範囲内の指摘にだけ当てる)
- 🚨 **①の「守る対象」の表は、コード内の 🚨 / 「絶対に」と宣言された不変条件と照合してから閉じる**。
  リテラルで pin すると決めたら、その判断が依存している定数も数え上げる
- 判定: 迂回を直すたびに新しい迂回が出るなら、**規則の軸が構文にある**印。構文でなく効果 (何が起きるか) へ軸を移す
- 🚨 **「検出しない形」は実装後にもう一度、実装と突き合わせる** (着手前の版は意図であって射程ではない)

## やらないこと

- ✗ 掃除機構を、残骸を発生させない構造を検討せずに新設する
- ✗ 既に答えを出している経路があるのに、守りのために近似の判定を新設する
- ✗ 自分が作った安全機構を「セルフレビュー済み」で完了報告する / 正常系だけ試して「動いた」と書く
- ✗ `2>/dev/null` / `|| true` で失敗を握り潰したまま緑を返す
- ✗ red team の指摘を裏取りせずにそのまま修正する (推測に基づく防御コードを足さない)
- ✗ 新設した検査が CI で走っているかを確かめずに「これで退行を止められる」と書く
- ✗ 「N 段構え」を、段ごとの変異を当てずに宣言する
- ✗ 敵対レビューの指摘を直した差分を、もう 1 周攻めさせずに閉じる
