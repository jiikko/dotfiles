# 端末 UI で全角と半角を同じ列に縦に並べない（桁が揃っても目には揃わない）

> **トリガー型ルール。** 端末に**格子・表・バー・ラベル行**を組み、上下の行を
> 縦に揃えようとした瞬間に発動する。「カラム数は合っているのにズレて見える」と
> 言われてから気づくのでは遅い。**同じ状態語 (結末語・ステータス語) を別の画面へ
> 流用しようとした瞬間**にも発動する。

## ルール

- **同じ列に全角文字と半角文字を混ぜない。** 列ごとにどちらかへ統一する
  (全角の列は全角だけ、半角の列は半角だけ)
- **揃っているかの判定を「表示幅の一致」で終わらせない。** `dispWidth` / `wcwidth` の
  合計が一致していても、**1 セルの中で文字がどちらへ寄るか**は幅の計算に現れない
- 半角を全角セルに合わせたいときは、**空白で埋めるのではなく全角文字そのものに置き換える**
  (`1` + 空白 ではなく `１`)。空白埋めは幅を合わせるだけで、文字は左に寄ったまま
- **表示幅が端末で揺れる記号を使わない**。警告は ⚠️ (U+26A0 + VS16。1 桁 / 2 桁で揺れ、右端が
  フレームごとに動く) でなく 🚨 (U+1F6A8。常に 2 桁) にする。他の「記号 + 異体字セレクタ」も同じ罠
- 迷ったら**実際に端末へ出して目で見る**。等幅フォントでも全角 2 カラムの中央と
  半角 1 文字の位置は一致しない
- **状態語 (結末語・ステータス語) を別の画面へ流用するときは、その画面で語の直下に出る
  理由文と矛盾しないか確かめる**。同じ値 (Outcome / Status) でも**いつ・どこに出るかで語の
  意味が変わる**。幅と同じ構造で、**語彙テーブルのテストも変異検証も全部通ったまま、
  人が読むと 1 行の中で語と理由が食い違う**

## やること / やらないこと

- ✓ 列ごとに全角／半角を統一する
- ✓ 半角を全角セルへ合わせるときは全角文字に置き換える (`１２３…`)
- ✓ 組んだら一度端末に出して目で見る (幅の計算だけで判定しない)
- ✗ 「`dispWidth` が一致しているから揃っている」と結論する
- ✗ 半角 + 空白で全角セルの幅に合わせて済ませる
- ✗ ズレの指摘に対して「桁は合っている」と説明し返す (見え方の問題なので説明は解決にならない)
