# サブエージェントは sonnet が使える箇所では sonnet を使い、アウトプットは必ず main agent が検閲する

## ルール

- **サブエージェント (Agent ツール) を起動するとき、sonnet で足りるタスクには `model: "sonnet"` を指定する**。main モデル (Opus/Fable) を全タスクに使わない
- **sonnet / haiku のアウトプットは無検閲で採用しない。main agent が必ず検閲してから採用・コミットする**
- 検閲なしのコミット・報告への転記を禁止する。「エージェントが完了したので commit」は不可。diff / 成果物を main agent が読んでから

## そもそも委譲するかの判断 (モデル選択より前)

委譲が効くのは「本当に独立していて並列化できる大きな作業」だけで、小さなタスクに適用するとコストと所要時間が倍になる（現行モデルは指示なしでも積極的に委譲するので、抑える側の指示が要る）。

- **数回のツール呼び出しで自分が終わらせられる作業は委譲しない**。委譲の起動・指示文・成果物の検閲を合わせたコストが、自分でやるコストを上回る
- **最低件数のある計測・集計を回す (委譲する) 前に、母集合の件数を安い方法 (grep 等) で数え、満たせるかを確かめる**。
  満たせないなら何を測るかを決め直してから始める (自分で回すときも同じ)
- **その場の思いつきで「確認用サブエージェント」を足さない**（現行モデルは指示なしでも自己修正する。CLAUDE.md「応答・成果物の長さとスコープ」の最終項が一次情報）
  - **既定のルールや skill が定めるレビュー工程は対象外で、要求どおり起動する**: CLAUDE.md「レビュー方針」の codex / 敵対的レビュー、[`verify-design-intent-before-refactor.md`](verify-design-intent-before-refactor.md) の refactor 提案の外部レビュー、[`escalate-to-forge-after-failed-tries.md`](escalate-to-forge-after-failed-tries.md) の forge エスカレーション、forge / cross-review の必須クロスレビュー Phase。抑制するのは「規定になく、自分が今思いついた念のための二重チェック」だけ
- **5h 枠の残量が少ないときは並列数を絞る**。残量を見ずに複数体を起動すると
  **全体が途中で 429 で死ぬ**。枠が開いた直後に起動する方が、同じ体数でも生存率が高い
  - 残量は `ratelimit` (`bin/ratelimit`。Claude と codex の 5h / weekly。`-source` / `-check` / `-json`) で読む
    (モデルを呼ばずに返る)。**本物の session を起こす計測や上位モデルのレビューを重ねる前に見る**
  - 🚨 **weekly 枠はユーザーが自分で把握しているので、判断材料にしない** (提案も控えもしない)。
    `-check` と hook が見るのは 5h 枠だけで、表示 (`ratelimit` 素の実行) には weekly も出るが、それを理由に作業を止めない
  - **UserPromptSubmit (mod `ratelimit-warn`、または その fallback の hook `ratelimit-warn.sh`) が「Claude の 5h 枠が閾値を超えている」と注入したら、大きな作業に
    入る前にユーザーへ提案して判断を仰ぐ**: 控える / 縮小する (体数・周回・モデルを下げる) / リセット後に回す。
    大きな作業 = 複数のサブエージェント・workflow・forge / cross-review・本物の session を起こす計測・長い実装。
    小さな作業と、ユーザーが既に続行を指示した作業は止めない
  - **codex の枠は codex を使う skill の起動時にだけ見る** (`ratelimit -source codex -check`。rc=1 なら超過した枠を
    示して、codex の工程を縮小するか Claude で代替するかを先に聞く)。**超過以外の理由で判定不能を返したら**、長い codex の run の前に、
    同じ経路で上限を短くした疎通確認を 1 本打つ。通らなければ長い工程は起動せず代替 (観点を分けたサブエージェント) に切り替える
    (obaket 1006: 判定不能のまま起動した run が 30 分空走し、空の成果物を返した)
  - **体数だけでなく 1 本の重さも見る**: 長い書き込みの run を重いモデルで起こす前に、その 1 本が枠の何割を食うかを見積もる。
    大半を食うなら、重いモデルは短い高価値な run (レビュー・設計の裁定) に回し、長い実装は軽いモデルで起こす。
    枠切れで途中で死んだ run は、編集の突き合わせと引き継ぎが増えて、run を分けるより高くつく (obaket 1003: 2 回とも実装の途中で死んだ)
- **1 体で足りるなら 1 体にする**。起動数は少なく保つ。同じ観点のエージェントを増やして多数決にするのは、規定の工程 (forge の多視点レビュー等) かユーザーの明示要求があるときだけ
- 委譲が妥当な典型: 複数ディレクトリ横断の広い調査、互いに無関係な複数ファイルの同型書き換え、独立した複数観点のレビュー

## モデル選択の目安

| タスク | モデル |
|---|---|
| 機械的な置換・定型修正・grep 系調査・ファイル列挙 | haiku / sonnet |
| 定型レビュー・ドキュメント推敲・テスト実行と結果報告 | sonnet |
| 設計判断・複雑なデバッグ・アーキテクチャ評価・微妙な判断を伴う編集 | main モデル |
| 迷ったら | sonnet で出して main が検閲 |
| **自作の検査・ゲート・安全機構の敵対的レビュー** | **main モデル級 (opus)**。下記 |

## 自作の検査・ゲートの敵対的レビューは上位モデルに投げる

[`adversarial-review-own-safeguards.md`](adversarial-review-own-safeguards.md) が要求する
最終ゲートは、**sonnet では届かないことがある** (同じ変更に sonnet 2 本は 2 件、opus 2 本は 13 件 + 8 件。
「この検査は退行を観測できるか」の反実仮想は opus にしか出なかった)。

sonnet が弱いのは「実装は正しいが、**検査対象の集合が想定と違う**」形 (定義の書き方を
取りこぼす正規表現 / fixture が退行から不可視 / 不変条件が反転したまま緑)。
**検査・ゲート・安全機構を自分で新設したときの red team は上位モデルに投げる**。
定型レビュー (ドキュメント推敲・実装の読み合わせ) は sonnet のままでよい。

## 指示を書くとき

- **作業者への禁止制約 (「X は触らない」) を書くなら、それが作業の正道と衝突する経路を 1 つ想像し、衝突したときの扱い
  (確認を取る / 規約を優先する / 代替手段) を同じ行に添える**。添えないと、作業者は制約を守って規約を破り、報告には
  「制約を守った」としか書かれないので検閲でも見つけにくい
- **プロセスを起こしうる作業 (レビュー・検証) を頼むときは、pkill / killall / 広いパターンの kill を打たないと書き、自分が起こした
  子や孫を止めたい場面の扱いとして「起こしたときに pid を控え、その pid だけを kill する」を同じ行に添える**。共有のマシンでは、
  広いパターンが他のセッションの同じ道具を止める (レビュー担当が `pkill -f` を打ち、同じ時間帯に本物の描画が killed で落ちた。retro 647)

## 検閲の観点 (sonnet/haiku のアウトプットを採用する前に)

- **根拠のない断定の混入**: もっともらしいが検証されていない claim (「実測確認済み」「〜は存在しない」等) は裏取りする
  - 🚨 **grep ベースの「未使用ゼロ」「参照ゼロ」は overload を数えられない** (同名で signature 違いの
    定義があると、片方の参照をもう片方の参照と数える)。**ツール (analyzer / compiler) の結果で裏取りする**
- **参照の実在性**: エージェントが言及したファイルパス・コマンド・シンボルが実在するか
- **指示逸脱**: 担当外ファイルへの変更・指示にない創作 (新機能・新セクションの発明) が混ざっていないか
- **半端な編集**: 途中終了・部分適用で文書やコードが矛盾状態になっていないか
- 編集系タスクなら `git diff` を main agent が直接読む。報告文だけで判断しない
- 🚨 **検閲の対象は成果物だけではない。「そのエージェントがマシンに残したもの」も見る**
  (残骸プロセス・一時ファイル・worktree)。作法の正本は
  [`parallel-write-agents-need-worktree-isolation.md`](parallel-write-agents-need-worktree-isolation.md)
  の後始末の項

## 例外

- ユーザーが明示的にモデルを指定した場合はそれに従う
- 検閲自体が再実行より高くつく極小タスク (1行の機械的修正など) は main agent が自分でやる方が速い
