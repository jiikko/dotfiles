# 表示・レイアウトの意思決定は、本体へ入れる前にサンプルレンダラで回し切る

> **トリガー型ルール。** 「見た目をどうするか」がまだ決まっていない状態で、
> 本体のコードとテストを書き始めようとした瞬間に発動する。

## ルール

- **見た目 (レイアウト・文言・色・記号・行数) がまだ動く段階では、本体とテストに入れない。**
  使い捨てのサンプルレンダラ (`./tmp/*.sh` 等) で候補を出し、**合意が取れてから**本体へ移す
- サンプルは**捨てる前提**で作る。`./tmp` に置き、commit しない
  (2 回目に使いたくなったら [`new-tool-requires-entrypoint-docs.md`](new-tool-requires-entrypoint-docs.md) の対象になる)
- 合意の境目は「ユーザーが**これでいい**と言ったとき」。それまでは本体を触らない
- 🚨 **「やってみて」は実装の許可であって、見た目の承認ではない**。合意の条件は
  **ユーザーが実物 (かサンプル) を見たこと**で、**モデルが見て選ぶのは合意ではない**
  (色の良し悪しをモデルは判定できない。実例 2026-09-02: 5 案 + 推しを出して
  「じゃあやってみて」を推しへの合意と読み、本体 + テスト + commit まで進めて却下された)
- ただし**確認を挟むかは「却下されたときの損」で決める**。revert が安く実装も軽いなら、
  聞かずに作って実物を見せる方が往復が少ない。テスト・周辺改修が付いて却下が高くつくなら、
  先に見せる (過剰な確認は `~/.claude/CLAUDE.md`「応答・成果物の長さとスコープ」に反する)
- **1 案だけ出して聞かない**。候補を並べて見せると往復が減る (色・レイアウトは
  言葉で説明されるより見た方が速く決まる)
- **繰り返す単位が複数あるレイアウトは、サンプルでも複数単位を描く** (格子・段組み・
  リスト項目・CLI ごとの段)。**1 単位のサンプルは単位間の整列を原理的に検査できない**ので、
  「1 段では綺麗だが 2 段並べると縦がずれる」を見逃す (実例 2026-09-01: ratelimit
  ダッシュボードで 1 段ぶんだけ描いて合意し、実装後に段をまたぐ横位置のずれが出て revert)

## なぜ

起源: dotfiles statusline のカレンダー格子, 2026-08-23。根拠・起源・実例は `~/dotfiles/_claude/rules-rationale/decide-layout-in-sample-renderer-first.md` に置く（起動時には読まれない。ルールを疑う・改訂するときに読む）。

## どこまでがサンプルの仕事か

| まだサンプル | もう本体 |
|---|---|
| 何行にするか / 何を載せるか / 語をどう詰めるか | 決まったレイアウトを組む処理 |
| 色・記号・区切り文字の選択 | 決まった配色を定数にする |
| 全角/半角・桁揃え・端末幅での見え方 ([`no-mixed-width-columns-in-terminal-ui.md`](no-mixed-width-columns-in-terminal-ui.md)) | 幅計算・折り返しのロジックとその境界テスト |
| 「この情報は要るのか」の判断 | データの取得・整形 |

**ロジック (計算・分岐・データ整形) はサンプルを待たずに本体へ書いてよい**。
凍結するのは「見た目の意思決定」だけで、それ以外まで止めると単に遅くなる。

## やること / やらないこと

- ✓ 見た目が動いている間はサンプルで回し、合意後に本体へ移す
- ✓ サンプルは `./tmp` に置き、捨てる
- ✓ 候補を並べて見せる (1 案ずつ聞かない)
- ✗ 見た目が未確定のまま本体 + テストを書き、表示が変わるたびにテストを張り替える
- ✗ サンプルを飛ばして「実装しながら詰める」(見た目の往復回数だけテスト修正が増える)
