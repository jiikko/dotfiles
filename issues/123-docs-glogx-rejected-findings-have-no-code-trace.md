# 123 docs: 却下済みの指摘がコードに痕跡を持たず、別観点の監査で再浮上した

起票日: 2026-08-27 / 出典: ux 監査 (副産物) / priority: low

## 何が起きたか

今日の ux 監査が、**2026-08-20 の設計監査 (`issues/done/071`) で反証済み・
「再提案しないこと」と明記された指摘**を、別の切り口から再び出してきた。

`_claude/rules/pending-issue-rationale-in-code.md` はまさにこれを予防するルールで、
「issue 側の『該当なし』だけでは不十分。**コードは現場に残り続ける**」と定めている。
今回はコード側に痕跡が無かったため再生成された。

## 再浮上した 2 件

### (a) y/N の実行キー述語が 3 通り

3 経路の判定が食い違っている (実在を確認済み):

| 場所 | 判定 | `Y` (shift+y) |
|---|---|---|
| `action_modal.go` (push/pull/rerun) | `ToLower(key) == "y"` | 受理 |
| `status_view.go:discardKey` (**変更を捨てる**) | `ToLower(key) != "y"` | **受理** |
| `issues_view.go:markNextKey` (next へ移動) | `key != "y"` | 拒否 |

**071 の却下理由**: 「厳格側の `Y` は『安全側で閉じる』、寛容側は『意図どおり実行』で
失敗シナリオが作れない。厳格側は doc + テストで pin 済みの契約で、揃える方が不変条件を壊す」

**ux 監査が足した新しい角度**: 寛容側が**最も不可逆な操作** (`X` = 変更を捨てる。
`docs/status-viewer-spec.md` §4 が「復元手段が無い」と明記) で、厳格側が可逆な操作
(ファイル移動) — つまり**非対称が危険な向きに倒れている**。加えて `Y` は job 詳細コピー・
issue 参照コピーに割り当たった常用キー。

**判断**: 却下は維持する。`Y` を y/N プロンプトで押す行為は「はい」の表明であり、
新しい角度も**実際の失敗シナリオにはなっていない**。ただし 3 度目の再生成を防ぐため、
**この結論をコード側に残す**。

### (b) `C` / `X` (CLI update) が押下から最大 5 秒無反応

判定 (`claude --version`) の間、spinner もトーストも出ない。

**却下理由**: `issues/done/074-feat-glogx-parallel-cli-updates.md` の不変条件 4 に
「早期リターン (既に latest) では spinner モーダルを光らせない (**ユーザー指摘 2026-08-12 の回帰**)」
とある。**沈黙はユーザーが選んだ仕様の副作用**。

**判断**: spinner を足す案は却下。不変条件 4 に触れずに埋めるなら「判定が 800ms を超えたときだけ
右下トーストで『バージョンを確認中...』」という案はあるが、効果が薄いなら不要。

## 対応 (これがこの issue の本体)

**却下理由をコードの直近にコメントで残す**:

1. `status_view.go:discardKey` / `action_modal.go:handleKey` / `issues_view.go:markNextKey` の
   3 箇所に、「述語が 3 通りなのは意図的。071 で反証済み (揃える方が不変条件を壊す)。
   厳格側は doc + テストで pin されている」を、**どうなれば再評価するか**つきで書く
2. `action_modal.go:startUpdate` に「押下直後に spinner を出さないのは 074 の不変条件 4
   (ユーザー指摘 2026-08-12 の回帰) による意図。判定中の沈黙はその副作用」を書く

`pending-issue-rationale-in-code.md` が求める 3 要素 (制約の発生源 / どうなれば変更可能か /
grep で追える依存先) を満たすこと。
