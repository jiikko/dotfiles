# 662 (feat): glogx の `F` で開く内蔵ファイラー (木のドリルダウン + 重なっていくウィンドウタイル)

起票日: 2026-10-07

## 概要

glogx で `F` を押すと、repo をディレクトリの木として見せるファイラーを開く。カーソルを当てて
ドリルダウンで降りていき、ファイルで `Enter` を押すとドラクエの設定画面のような**ウィンドウタイル**が開く。
タイルの中からさらに別のファイルへジャンプすると、**新しいタイルを上に重ねて**開く。

この issue は**現時点の要件の記録**。見た目と未決事項 (下) が決まるまで本体には入れない
(`~/.claude/rules/decide-layout-in-sample-renderer-first.md`)。

## 要望 (ユーザーの言葉のまま)

> glogx で F を押したら起動するファイラーが欲しい。ディレクトリを木構造に見立ててカーソルをあてるドリルダウンできる感じで、
> ファイルを enter を押すとドラクエの設定画面のようにウィンドウタイルが開く感じで、ウィンドウタイルの中でさらにファイルに
> ジャンプする場合、タイルを上に開くみたいな ui にしたい。

## 要件 (現時点で確定しているもの)

1. **起動**: glogx で `F` を押すと開く (閉じ方は未決 7)
2. **木**: 起点 (未決 4) 配下のディレクトリを木構造に見立てて表示し、カーソルを当てて移動する
3. **ドリルダウン**: ディレクトリにカーソルを当てて降りていける (形は未決 8)
4. **タイルを開く**: ファイルにカーソルを当てて `Enter` を押すと、ウィンドウタイルが開く。
   見た目の参照はドラクエの設定画面 (木の上に重ねるか、木と入れ替えるかは未決 2)
5. **タイルの重ね**: タイルの中からさらに別のファイルへジャンプすると、今のタイルを閉じずに**新しいタイルを上に開く**。
   閉じると 1 枚ずつ下のタイルへ戻る (スタック)

## 未決事項 (実装前にユーザーと決める)

1. **タイルの中身は何か**。どちらにも読める:
   - (a) ファイルの中身のプレビュー (シンタックスハイライト付きの pager)
   - (b) そのファイルへの操作メニュー (ドラクエの「どうぐ → つかう / わたす / すてる」のようなコマンド窓。開く / エディタ / パスをコピー …)
   - (a) と (b) を両方持つ (メニューの窓の横・上に中身の窓) もありうる
2. **「上に開く」の向き**。どちらにも読める:
   - (a) 手前に重ねる (z 方向。少しずらして前のタイルの上に被せる。ドラクエのコマンド窓の重なり方)
   - (b) 画面の上方向へ積む (前のタイルの上側に新しいタイルが並ぶ)
   - 最初のタイルが木の上に重なるのか、木と入れ替わるのかも同じ問い
3. **タイルの中で「ファイルへジャンプする」とは何か**。候補:
   - 本文中に出てくるパスを選んで開く (issues viewer の本文の `Tab` ジャンプモードと同じ形)
   - タイル内の操作メニューから別のファイルを選ぶ
   - 何段まで積めるか (上限を置くか、置くなら超えたときどうするか。前例の issues viewer の本文は `maxDocDepth = 8` で止める。
     `src/glogx/issues_linkjump.go`)
4. **起点と表示対象**: 起点を repo root に固定するか。`.git/` と gitignore されたもの (`node_modules/` 等) を木に出すか
5. **どの画面から `F` が効くか**: git log 一覧だけか、`i` `s` `R` `D` `U` のような**どの画面からも飛べる横断キー**にするか
6. **既存の `E` (外部ファイラー) との関係**: 併存させるか、`F` を入れたら `E` を外すか (下の「既存の資産」)
7. **閉じ方**: 要望に記述は無い。ui-guide §3 に倣えば `F` 自身・`q`・`Esc`・`h` で閉じるが、タイルを重ねる (要件 5) と
   「`Esc` はタイルを 1 枚閉じるのか木ごと閉じるのか」「`q` は全部閉じるのか」が割れる。issues / status viewer では
   `q`/`Esc` が glogx ごと終了する例外 (§1) もある
8. **ドリルダウンの形**: どちらにも読める:
   - (a) 1 本の木の中で展開 / 畳み込みする (ツリービュー。「木構造に見立てて」寄り)
   - (b) ディレクトリに入ると一覧がその中身に切り替わる (yazi / Miller 列型。「ドリルダウン」寄り)
   - ディレクトリで `Enter` を押したときの挙動 (展開か降下か) と、`l` / `h` (ui-guide §2 で「開く / 閉じる」) の扱いも同じ問い

## 既存の資産と制約 (2026-10-07 に調べた事実)

- **`F` は glogx で未使用** (`src/glogx/*.go` と `src/tuikit/` に `"F"` のキー分岐が無い)。小文字 `f` は全画面で半ページ送り (less の語彙)
- 🚨 **キー語彙の規律と衝突する**: `docs/glogx-ui-guide.md` §2 は「大文字は小文字の強い版またはまとめ版」と定める。
  `F` は `f` (半ページ) の強い版ではない。ただし同じ表の「板の toggle (横断キー)」の `R` `D` `U` も小文字の強い版ではないので、
  **板の toggle の層として割り当てるなら前例がある**。割り当てたら §2 の表に足す (§10 のチェック)
- **外部のファイラーを開く `E` は既に在る** (`src/glogx/open_workspace.go` の `openFilerAtRoot`。yazi → ranger → lf → nnn → vifm の先勝ちで
  TUI を明け渡して起動する)。`e` は repo root で `nvim .`。**どちらも git log 一覧でだけ効く** (`src/glogx/tui.go` の一覧の
  キー分岐。全画面の viewer からは効かない)。`F` はこれらと違い glogx の中に描く内蔵ファイラー
- **「本文中のファイルへジャンプして上に積む」の前例**: issues viewer の本文の `Tab` ジャンプモード (`src/glogx/issues_linkjump.go`)。
  実在するファイルに解決できたパスだけを選べて、`.md` は本文 pager に**積んで**開き `h`/`Esc` で元へ戻る。それ以外は `nvim -R`。
  パスの解決は `src/glogx/issues/filelink.go`、画面上の位置は `tuikit/markdown` の `RenderLinks`。タイルの重ね (要件 5) の流用候補
- **使える tuikit の部品** (`docs/glogx-ui-guide.md` §9): 落ち影つきの板 = `layout.Panel` / 重ねる = `layout.OverlayCentered`・`OverlayRight` /
  開閉の演出 = `anim.Transition` / 一覧の移動 = `listnav.MotionOf` / コードの色付け = `highlight` / 幅 = `termwidth`
- **ファイル名は外部由来の文字列**なので、表示前に termsafe を入口で 1 回通す (`src/glogx/CLAUDE.md`「構造の判断」)
- 全画面の画面どうしの排他は `src/glogx/fullscreen.go` が持つ。新しい板はここに載せる

## 対応方針

1. 未決事項 1〜8 をユーザーと決める
2. タイルの見た目 (枠・重ね方・ずらし幅・木との位置関係) を `src/glogx/tools/` のサンプルレンダラで複数案出し、合意を取る
   (実物の分布で描く: 深い木・長いファイル名・全角のファイル名・3 段以上の重ね)
3. 木とドリルダウン → タイル 1 枚 → タイルの重ね、の順で本体へ入れる
4. 入れるときに同じ変更で直すもの (`docs/glogx-ui-guide.md` §10): `src/glogx/README.md` のキー表・`--help`・ui-guide §2 の表
