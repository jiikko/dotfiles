## 詳細

### P2

1. **この Mac のネットワークが読めないと、黙って空の状態になり、`s` が見当違いの IP へ繋ぐ** (`lanmgr/model.go` の `applyNetLoad`)
   - ReadNet が失敗すると (5 秒の上限切れ・networksetup の失敗。初回でも `r` / L の開き直しでも)、前に読めていた `m.self` を読めた分だけの Snapshot で上書きし (`-listnetworkserviceorder` の失敗と ctx 切れなら空、`ifconfig -l` の失敗なら
     サービスだけの部分 snap と `ErrIPsIncomplete`。`netinfo.Read` の末尾)、
     `netReady = true` にする。`selfErr` を見るのは Report だけで、知らせも見出しも出ない
   - 結果: 未管理の相手の IP が全部「その他」に落ち、`connectIP` が `others[0]` を返す。再現では `s` の宛先が utun の VPN (100.64.0.20) になった
     (正しくは Wi-Fi の 192.168.50.7)
   - 確信度: 再現 + コードで確認 (`m.self, m.selfErr = r.self, r.err` が err でも上書きする)
   - テストの形: ReadNet の偽物が 1 回目は成功・2 回目は err を返す。`r` の後に未管理の相手の `s` の宛先が VPN の IP にならないこと / 知らせが出ること
2. **I/F で決める設定 (`LanByBand=false`) のとき、帯の編集で入力欄が描かれない** (`lanmgr/settings.go` の帯の行の描画)
   - `dim != ""` の行は「名前 + 薄い説明」に置き換わるので、編集中でも入力欄も今の値も出ず、キャレットが説明の文の上に立つ
   - 確信度: 再現
3. **ネットワークを読み終える前に Enter で初期設定を開くと、宛先が台帳の有線の IP のまま固まる** (`lanmgr/model.go` の Enter → `lanmgr/setup.go` の `destFor`)
   - 読み終える前は相手の Addrs を分類しないので `mainIP` が空。管理対象の相手で Enter を押すと `su.dest` が台帳の LAN になり、読み終えても
     `r` (observe) は `su.dest` を作り直さない。閉じて開き直すまで有線の宛先で観測し続ける (再現: 読んだ後に開くと 192.168.50.7、読む前に開くと 192.168.100.13 のまま)
   - 未管理の相手では「この Mac には入れない: IPv4 でない」という分かりにくい理由で断る
   - 確信度: 再現

### P3

4. **「有線で見えた相手だけ」の設定で、画面に出ていなかった Mac へキーが効く** (`lanmgr/model.go` の `followCursor` / `cursorLost`)
   - 空のタブを見ている間に裏の読み込みが終わり、次の tick より先にキーが来ると、`held == ""` なので `cursorLost` が立たず、その場の `takeNetLoad` で
     現れた先頭の Mac (一度も描かれていない) へ `s` が ssh した
   - 確信度: 再現
5. **幅 36〜39 で、別名・ユーザー名の入力欄が板の中で折り返す** (`lanmgr/view.go` の入力の板)
   - 板の幅は `min(内容 + 6, w - 1)` で、「ユーザー  」+ 25 桁の欄が収まらず、ラベルの行と入力の行に割れる。キャレットは欄の外に立つ (`fieldRow = 4` の仮定が崩れる)
   - 確信度: 再現 (24 字を打ったとき w = 36..39 で崩れた)。計算上は `modal` の幅 `min(内容 + 6, w - 1)` から、ユーザー欄 (10 + 25 + 6 = 41) は w ≤ 41、
     別名欄 (6 + 25 + 6 = 37) は w ≤ 37 で折り返しうる (計算のみ・未確認)
6. **相手の行の「その他の IP」が「その他の IP に含める種類」の設定を無視する** (`lanmgr/model.go` の行の組み立て)
   - `pf.Kinds` で絞っているのはこの Mac の行だけ。全部の種類を切っても、相手の +N の札と詳細カードに VPN が出る
   - 確信度: 再現 + コードで確認 (相手の側の `r.others = append(...)` に Kinds の条件が無い)
7. **一覧の space で登録すると、別のプロセスが書いた同じ Mac の行を古い一覧の値で丸ごと上書きする** (`lanmgr/model.go` の space の確認の板 → `Ledger.Upsert`)
   - 板を出している間に glogx の L か単体の mac-lan-manager が同じ Mac を別名・LAN・user 付きで登録すると、`y` で `{Host, User: 推測の名前}` に置き換わり、
     別名と LAN が消える。初期設定の台帳の手順は Update を先に試すが、こちらはそうしていない
   - 確信度: 再現
8. **設定の「帯」の行で、space と ← → の断りが互いを指して堂々巡りになる** (`lanmgr/settings.go`)
   - space は「この項目は ← → で変える」、← → は「この項目は space で入 / 切」と案内する。帯の行は enter で編集する
   - 確信度: コードで確認 (2 つの `default:` の文言)

### 参考 (コードを読んで確か・実害は小さい)

- `reloadLedger` (`lanmgr/model.go`) は Load の失敗を黙って捨てる。登録・外す・別名に成功した後に読み直しが落ちると、一覧が古いまま (「未管理」のまま) で知らせも出ない

### 見つからなかった観点 (レビュアーの記録)

- 非同期の読み込みを古い世代で上書きする形は無い (網・観測・名前の引き直しは、どれもチャネルを差し替えて古い結果を捨てる)
- 確認待ち・未確認の印・試した番号の遷移に、747 で受容・記録したもの以外の穴は無い

## 対応方針

- 1 は「読めなかった」を空の Snapshot に畳まない: 前の `m.self` を残して `selfErr` を知らせに出すか、読めない間は分類を保留する。
  部分 snap (`ErrIPsIncomplete`) をどこまで使うかも同時に決める
  (`_claude/rules/verify-execution-not-just-exit-code.md` の「測れない」と「0」を別の値で持つ)
- 3 は Enter を `needsNet` に入れる (読み終えるまで断る) か、読み終えたときに `su.dest` を作り直す
- 7 は space の登録も「既にあれば Update」にそろえる
- 2・5・6・8 は個別に直す。4 は `held == ""` でもキーの時点で行の集合が変わったら断る
