# 647 (retro): zundamon-kaisetsu の図解 (645)・読みの辞書・エンジンの自動起動の残り (646) の振り返り

起票日: 2026-10-07

## 踏んだところ

### A. 指摘を直すために重い処理を前に出し、安い検査の前に危険な処理を置いた

「ヘッダだけ正しく本体が壊れた画像が通る」という指摘を、大きさの読み方を DecodeConfig から Decode (本体まで展開) に替えて直した。
その結果、縦横の検査より前にピクセル全体を確保するようになり、389KB の PNG で 384MB を確保する解凍爆弾の入口になった
(2 周目のレビューの P1)。`adversarial-review-own-safeguards.md` §7 の「指摘への修正は新しい安全機構」で 2 周目を回したので
拾えたが、直す時点で「安い判定 → 重い処理」の順を崩していないかを自分では見ていなかった。

### B. レビューを頼んだサブエージェントが、共有のマシンで広いパターンの pkill を打った

mermaid の「壊す・並行」のレビュー担当が、調べる途中で `pkill -f` を `^npx|node.*npx` と `zundamon-kaisetsu.*build script.json` で
2 回打ったと自己申告した。同じマシンで他のセッションが zundamon の build や npx を動かしていた可能性があり、巻き込んだかは
確かめられていない。ただ、同じ時間帯に本物の mermaid の描画が 1 回だけ「npx, signal: killed」で落ちていて (issue 645 の記録)、
巻き込んだ疑いがある。依頼文に「起こしたプロセスの残りを確かめろ」とは書いたが、「止めてよいのは自分が起こして pid を控えたもの
だけ」とは書いていなかった (次の依頼から書いた)。

### C. 続けて push すると前の commit の CI が取り消され、push ごとの確認が空振りした

図解の commit を続けて push したところ、前の commit の Lint / Tests が後の push で取り消され (cancelled)、待ちが「取り消し」を
結果として返した。取り消された commit の検査は、それを含む後の commit の run で確かめる必要があり、その都度 run を読み直した。
最初に張った待ちの 1 本は `gh run list --commit` に短い sha を渡していて、結果を拾えないまま回り続けた (途中で止めて張り直した)。

## 提案

| 項目 | 一般形 | 切り出し先 |
|---|---|---|
| A | 検査を強める修正では、安い判定 (ヘッダ・大きさ・件数) より前に重い処理 (展開・確保・外部の呼び出し) を置いていないかを見る。置くなら安い判定で上限を決めてから | `_claude/rules/adversarial-review-own-safeguards.md` §7 に、指摘を直すときの項として追記 (既存の「安全側に倒す」の項は成功パスのどこで走るかの話で、軸が別) |
| B | プロセスを起こしうる作業 (レビュー・検証) をサブエージェントに頼むときは、pkill / killall / 広いパターンの kill を打たないと書き、衝突する場面 (自分が起こした子や孫を止めたい) の扱いとして「起こしたときに pid を控え、その pid だけを kill する」を同じ行に書く | `_claude/rules/subagent-model-tiering.md` の「指示を書くとき」の、禁止制約の項に追記 |
| C | concurrency で取り消された CI の run は失敗でも成功でもなく、その commit を検証していない。その commit を含む後の commit の run で確かめ、待ちもそちらに張り直す (commit は完全な sha か前方一致で指定する) | `_claude/rules/verify-execution-not-just-exit-code.md` の「path filter 付きの CI」節の見出しを「起動しなかった / 取り消された run は、その commit を検証していない」に広げて追記 |
