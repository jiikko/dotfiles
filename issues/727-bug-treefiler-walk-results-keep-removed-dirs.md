# 727 (bug): treefiler の Model.recs と walker.results に消えたフォルダのキーが残り続ける

> 🚨 **担当中: dotfiles-5f**（2026-10-12〜）

起票日: 2026-10-12

## 概要

裏の走査の結果 (`Model.recs` と `walker.results`、`walk.go`) は、フォルダが消えてもキーを持ち続ける。`walker.forget` は stale の印を付けるだけで消さない。
名前の違うフォルダを作って消すのを 60 回繰り返すと、`recs` と `results` がどちらも 61 件になる (監査の実験)。712 より前から。issue 697 の却下の一覧には無い。
発見はユーザー依頼「リソースリークの観点でコードスキャン」の監査 (dotfiles-4e。起票は 4e の依頼で dotfiles-5f)。

## 対応方針

- 消えたフォルダ (ライブ更新・読み直しで木から外れたもの) のキーを `recs` と `results` から落とす。落とすのは木から到達できないパスだけにし、走査中のものと競合しないようにする
- 1 件あたりは小さいので重さは低い (P3)。長く開いたままの glogx で、作っては消すフォルダ (ビルドの出力等) があると伸び続ける

## 受け入れ条件

- [ ] 作って消すのを繰り返しても `recs` / `results` が木の中のフォルダの数を超えて伸びない (テスト + 変異)
