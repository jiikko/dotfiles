# 1062 (feat): slack-bbs で複数のチャンネルを 1 つのグループとして購読し、話題に組み直して読む

> 🚨 **担当中: kojiM3MBP (glogx)**（2026-11-11〜）

起票日: 2026-11-11

## 概要

指定した複数のチャンネル (個人の分報のチャンネルをまとめたもの等) を、論理的な 1 つのチャンネルとして購読する。
グループの中の発言はまとめて話題に組み直して読む (ユーザー要望 2026-11-11)。

## 背景

- 706 の MVP は「チャンネルをまたいだ話題の統合」を作らないものに入れ、「複数チャンネルの横断」を未決の論点に残した
  (706 の「MVP (slack-bbs)」と「未決の論点」)。この issue はその論点を、ユーザーが選んだチャンネルの組に限って開く
- 今は購読の単位がチャンネル 1 つで、読む画面のタブ・取得・分類・キャッシュ・既読の印がどれもチャンネルの ID を鍵にしている

## 今の作りでチャンネル 1 つを前提にしている所 (2026-11-11 に読んだ)

- `subs.Channel` (ID と名前) の並びがタブになる (`src/slack-bbs/subs/store.go`)
- `render.Page` は `Channel` を 1 つだけ持ち、Slack のリンク (`Page.URL`) をその ID で組む。グループの話題では、単位ごとに元のチャンネルが要る
- 単位の ID はスレッドの ts で、ts はチャンネルの中でしか一意でない。グループの中では、単位の ID・既読の印 (`Reads`)・
  キャッシュの鍵 (`cache.Store` の `ch`) にチャンネルを含める必要がある
- 分類 (`claude -p`) は 1 チャンネル分の発言を 1 回で渡す。グループでは渡す量が足し算で増える (706 の「量が多いとき」)。
  件数の上限 (`main.go` の `checkMax`) と `-dry-run` の送信量の表示もチャンネル単位
- ts を鍵にしているのは単位の ID と既読・キャッシュだけではない。`board.ValidateUnits` は単位の ID の重複と、同じ ts の発言が 2 回出ることを拒む
  (別のチャンネルの同じ ts が正当に並ぶと落ちる)。LLM に渡す `members` / 返る `refs` と、その検査 (作られた ID を捨てる・ちょうど 1 つ) も ts で照合する。
  鍵にチャンネルを含める変更は、プロンプトの形・応答の検査・2 段の実行の response.json まで及ぶ
- 言及の収集 (`mentions.go` の `findMentions`) は `archives/<チャンネル ID>` で検索し、リンクの ID が今のチャンネルと違うものを捨てる。
  グループの中の別のチャンネルへのリンクを、言及とみるかグループの中の参照とみるかを決める。前例として `render.Mention` は発言ごとにチャンネル名を持つ
- 2 段の実行 (`job` と `slack-bbs prepare` / `show`。skill `slack-bbs` の手順) はチャンネルの ID でファイル名と manifest を作り、
  `job` とキャッシュの置き場 (`cache.Store.path`) は `source.IsChannelID` で ID を検査する。グループの ID は Slack の ID ではないので、別の鍵の形が要る
- 読み直し: `r` (今のタブ) と `R` (全部) の単位をグループにするか。グループの中の 1 チャンネルの取得の失敗 (`eachChannel`) でグループ全体を落とすか

## 対応方針 (案)

- 購読の一覧にグループを足す: 名前と、属するチャンネルの ID の並び。タブにはグループが 1 つとして並ぶ
- 取得はチャンネルごとに行い、発言にチャンネルを付けてから 1 つの板に合わせて分類する。本文の発言の頭にチャンネル名を出す
- 購読の画面 (`s`) でグループを作る・チャンネルを出し入れする

## ユーザーの決定 (2026-11-11)

- グループの決め方: 自分でチャンネルを選んで組む。チャンネルは名前で検索して印を付ける (名前の頭で自動にまとめる案は採らない)
- 話題の組み直し: グループの中でチャンネルをまたいで 1 つの話題にまとめてよい
- グループのチャンネルを出し入れしても、グループの既読の印とキャッシュは引き継ぐ
- 同じチャンネルを複数のグループに入れてよい (グループどうしの重複を許す)
- キャッシュ全体: 2 週間ほど書き換わっていない取得の結果 (raw) などのキャッシュは捨ててよい
- 購読の画面: 検索の語を打つそばから一覧を絞り込み、絞り込んだまま選べるようにする (今は `/` の入力中は移動も付け外しもできず、Enter で検索を閉じてから選ぶ)
