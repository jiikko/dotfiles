## 前提

conf を reload する (`prefix+R` → 確認 → 実行)。reload しないと稼働中サーバには乗らない。

## なぜ人が要るか

自動テストで固定できたのは **bind の登録 / 判定式 / true 側のコマンド**の 3 つまで。

- 🚨 **キー押下そのものは再現できない**。`tmux send-keys` は key table を通さずペインへ直接キーを
  送るので、root テーブルの bind が発火しない (実測 2026-09-04)
- 🚨 **元の症状 (端末エミュレータ → tmux で文字が落ちる) が未再現**。tmux から下流は
  24000 バイトを 1 バイトも落とさないことを実測したので、落ちるとすれば端末側の経路だが、
  そこは人が貼らないと作れない

## 確認してほしいこと

1. **長文が落ちずに入るか**: 数千文字のテキストをコピーし、zsh のプロンプトで `C-v`。
   途中で切れたり文字化けしたりせず全部入ること。**これが本題**
   (比較のため、同じテキストを従来どおり ⌘V でも貼って違いを見てほしい)
2. **複数行が即実行されないか**: 改行を含むテキストを `C-v` で貼り、**実行されずに**
   コマンドラインに載ること (bracketed paste が効いている証拠)
3. **nvim の矩形選択が壊れていないか**: nvim を開いて `C-v` → ビジュアルブロックに入ること
   (ここで pbpaste の中身が流れ込んだら判定が壊れている)
4. **zsh の `quoted-insert` が要るとき**: プロンプトで `C-v` の後に制御文字を入れる用途が
   あるなら、それが使えなくなっていないか (使えなくなっている場合、それが許容できるか)
5. **ペインが複数あるとき誤爆しないか**: 2 ペインに分割し、片方の zsh で `C-v`。
   **押したペインにだけ**入ること (`-t #{pane_id}` がこれを守っている)
