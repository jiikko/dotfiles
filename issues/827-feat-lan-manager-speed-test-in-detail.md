# 827 (feat): lan-manager の詳細カードに相手との通信速度を出す (確認の板の後でスピードテスト)

起票日: 2026-10-18

## 概要

管理対象・未管理のどちらのタブで行を選んでも、右の詳細カード (`src/mac-lan-manager/lanmgr/view.go` の `detail`) に
**相手との通信速度**を出す。測定は帯域を食うので、**確認の板 (y/N) を出し、y を押したときだけ測る**。

## 要望 (ユーザーの依頼、2026-10-18)

- 管理対象・未管理のそれぞれで行を選ぶと、右の詳細カードに通信速度が出る
- 測定は帯域を消費するので、確認ダイアログを出してから測る

## 詳細

### 期待する動作

1. 一覧で相手の行を選び、測定のキーを押す (キーは未定。下の「決めること」)
2. 確認の板が出る。本文には「何を・どれだけ流すか (量か秒数)・どの経路 (宛先の IP / 有線の名前) か」を書く
3. y で測る。測っている間は進捗を出し、終わったら詳細カードに `通信速度  ↑ N Mbps / ↓ N Mbps  (測った時刻)` の行が出る
4. n / Esc なら何も流さない。**y を押さない限り、一覧を動かしただけで測りに行かない** (選ぶたびに自動で測る形にしない)
5. 測った結果は相手ごとに覚え、同じ行に戻ったときは前の結果を時刻付きで出す (測り直しは同じキーで、また確認の板を通す)

### 今の作り (2026-10-18 時点で読んだもの)

- 確認の板は `lanmgr/model.go` の `ask` (y/N。知らないキーはすべて取り消し) と `overlayBox` の `ovConfirm`。台帳への登録・削除 (`askLedger`) がこれを使っている。測定もこの板を通す
- 相手への ssh は `setup/remote.go` の `SSHArgv` (`HostKeyAlias`・`ConnectTimeout=5`) と `live` の `SSHRun` / `Observe`
- 宛先は `m.target(r)` (有線の名前が引ければ名前、なければ IP)

### 実測した前提 (この Mac、2026-10-18)

- **リンク速度 (ネゴシエーションの値) は帯域を食わずには読めない場合がある**: `ifconfig` の `bridge0` (Thunderbolt bridge) は
  `media: <unknown type>`、`en1`〜`en3` は `media: autoselect <full-duplex>` で、速度の値が出ない。
  「リンク速度を出せば測らずに済む」は Thunderbolt の内部の網では成り立たない
- `iperf3` は入っていない (`command -v iperf3` が空)。`/usr/bin/networkQuality` はあるが、既定ではインターネット側の
  Apple のサーバを測るもので、LAN の相手との速度ではない

## 決めること (着手前にユーザーへ確認する)

1. **未管理の相手をどう測るか** — 未管理は鍵で ssh に入れない (初期設定前) ので、相手側で受け手 (`cat > /dev/null` や iperf3 の server) を
   起こせない。案:
   - (a) 未管理は ping の往復時間 (RTT) だけを出し、速度は「初期設定の後に測れる」と出す
   - (b) 相手が smb を広告していれば smb への読み書きで測る (認証が要る。パスワードの扱いが増える)
   - (c) 測定の間だけパスワードで ssh する (端末を明け渡す。初期設定の鍵の手順と同じ形)
   - 推奨は (a)。依頼の「未管理でも速度を出す」を満たさないので、満たす必要があるなら (c)
2. **管理対象の測り方** — 案:
   - (a) ssh 越しに一定量を流して時間を測る (`dd if=/dev/zero bs=1m count=N | ssh … 'cat > /dev/null'`、逆向きは相手から流す)。
     追加の install が要らない。ただし ssh の暗号化が律速になりうる (10GbE / Thunderbolt では実際の回線より低く出る可能性。未実測)
   - (b) iperf3 を両方に入れて測る (回線の速度に近い。両方の Mac に install が要る)
   - 推奨は (a) で始め、表示に「ssh 越し」と書く。律速が ssh だと実測で分かったら (b) を検討する
3. **流す量** — 秒数で切る (例: 5 秒) か量で切る (例: 256 MiB) か。Thunderbolt (数 Gbps) と Wi-Fi 経由 (数十 Mbps) で
   同じ量だと所要時間が桁で違うので、**秒数で切る**方を推奨
4. **キー** — 空いているキーを確認してから決める (`?` の一覧と `Binds` を見る)

## 対応方針 (決めることが決まった後)

- 測定は `setup` と同じく「命令を組む部分」と「起こす部分 (`live`)」に分け、組む部分を偽物でテストする
  (README の「テストは偽物だけが見える PATH で走らせる」に従う)
- 測定中も一覧の操作は止めない。測定中に別の相手で測定を始めない (同時に 2 本流すと互いの帯域を食って値が意味を失う)
- 結果の時刻を出し、古い結果を今の速度と読ませない
- 操作のログ (`~/Library/Logs/mac-lan-manager.log`) に、測った相手・経路・量・秒数・結果・失敗の理由を残す
- `dump` (画面を出さないデバッグ) では測らない (帯域を食う操作を確認なしに起こさないため)
