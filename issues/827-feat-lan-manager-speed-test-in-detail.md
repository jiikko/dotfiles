# 827 (feat): lan-manager の詳細カードに相手との通信速度を出す (確認の板の後でスピードテスト)

> 🚨 **担当中: kojiM3MBP (glogx)**（2026-10-18〜）

起票日: 2026-10-18

## 概要

**管理対象のタブ**で行を選ぶと、右の詳細カード (`src/mac-lan-manager/lanmgr/view.go` の `detail`) に
**相手との通信速度**を出す (未管理には出さない。決めること 1 の決定)。測定は帯域を食うので、**確認の板 (y/N) を出し、y を押したときだけ測る**。

## 要望 (ユーザーの依頼、2026-10-18)

- 管理対象・未管理のそれぞれで行を選ぶと、右の詳細カードに通信速度が出る
- 測定は帯域を消費するので、確認ダイアログを出してから測る
- 2026-10-18 決定: 未管理の相手は鍵で入れず測れないことが多いので、**出すのは管理対象だけ**にする

### 目的 (ユーザー、2026-10-18)

- 繋ぎ方は基本有線だが、無線で繋がっていると遅くなるはずで、**その差を数字で知りたい**
- 途中の機器 (スイッチ・ケーブル・アダプタ) が 100 Mbps で**ボトルネックになっていないかを知りたい**
- 上の 2 つを**簡単に見える形**にしたい (精密なベンチマークではなく、一目で「遅い経路だ」と分かること)

## 詳細

### 期待する動作

1. 一覧で相手の行を選び、測定のキーを押す (キーは未定。下の「決めること」)
2. 確認の板が出る。本文には「何を・どれだけ流すか (量か秒数)・どの経路 (宛先の IP / 有線の名前) か」を書く
3. y で測る。測っている間は進捗を出し、終わったら詳細カードに `通信速度  ↑ N Mbps / ↓ N Mbps  (測った時刻)` の行が出る
4. n / Esc なら何も流さない。**y を押さない限り、一覧を動かしただけで測りに行かない** (選ぶたびに自動で測る形にしない)
5. 測った結果は相手ごとに覚え、同じ行に戻ったときは前の結果を時刻付きで出す (測り直しは同じキーで、また確認の板を通す)

### 今の作り (2026-10-18 時点で読んだもの)

- 確認の板は `lanmgr/model.go` の struct `ask` で、キーの扱いは `HandleInput` の `case ovConfirm`、描画は `view.go` の `overlayBox`。
  台帳への登録・削除 (`askLedger`) がこれを使っている。測定もこの板を通す
  - 🚨 実行の判定は `tuikit/confirm` の `IsYes` で、**y だけでなく Y と Enter でも実行する**。例外は `ask.auto` の板 (Enter を無視) と、
    `ask.exec` のある板の `c` (コマンドをコピーし、板は閉じない)
- **管理対象かどうかは台帳に載っているかだけで決まり、鍵で入れるかは判定に入らない** (`row.managed` / README「公開鍵は見ない」)。
  鍵で入れるかは `setup.ObservePeer` (`live.Observe`・`dump --peer`) が ok / denied / unknown として読む。
  したがって未管理でも鍵で入れる相手はいるし、管理対象でも入れない相手はいる
- 相手への ssh の引数は `setup/remote.go` の `SSHArgv` (`HostKeyAlias`・`ConnectTimeout=5`)。
  `live.SSHRun` は **stdin が /dev/null 固定**で stdout を `Output()` で全部メモリに溜めるので、測定 (送る向きは stdin へ流す・受ける向きは大量の stdout) には流用できない。測定用の runner が別に要る
- 宛先は `m.target(r)` (有線の名前が引ければ名前、なければ IP)。「有線だけ」の設定 (`prefs.WiredOnly`) や、`target` が Wi-Fi の IP を返す場合がある
- 裏の処理は `m.bg` / `takeBG` に載り、`Busy()` が真の間だけ tick が張られて `Advance` で結果を取り込む。既存の進捗の板 (`progress.go` の `progressShown`) は初期設定の画面 (`scSetup`) 専用
- glogx の `L` の板から開いたときは `Model.Close` で板と裏の処理を畳む
- 一覧ではすでに `y` / `Y` がコピーのキー (`Binds`)

### 実測した前提 (この Mac、2026-10-18)

- **リンク速度 (ネゴシエーションの値) は帯域を食わずには読めない場合がある**: `ifconfig` の `bridge0` (Thunderbolt bridge) は
  `media: <unknown type>`、`en1`〜`en3` は `media: autoselect <full-duplex>` で、速度の値が出ない。
  「リンク速度を出せば測らずに済む」は Thunderbolt の内部の網では成り立たない
- `iperf3` は入っていない (`command -v iperf3` が空)。`/usr/bin/networkQuality` はあるが、既定ではインターネット側の
  Apple のサーバを測るもので、LAN の相手との速度ではない

## 決めること (着手前にユーザーへ確認する)

1. ~~鍵で入れない相手をどう測るか~~ — **決定 (ユーザー、2026-10-18): 速度は管理対象のタブだけに出す。未管理の行には測定のキーも行も出さない**。
   管理対象でも鍵で入れない行 (初期設定が途中の `!` の行など。`ObservePeer` が ok でない) は測らず、
   「鍵で入れないので測れない (初期設定で鍵を置く)」と出す。RTT・smb・パスワードの ssh の案は採らない
2. **鍵で入れる相手の測り方** — 案:
   - (a) ssh 越しに一定量を流して時間を測る (`dd if=/dev/zero bs=1m count=N | ssh … 'cat > /dev/null'`、逆向きは相手から流す)。
     追加の install が要らない。ただし ssh の暗号化が律速になりうる (10GbE / Thunderbolt では実際の回線より低く出る可能性。未実測)
   - (b) iperf3 を両方に入れて測る (回線の速度に近い。両方の Mac に install が要る)
   - 推奨は (a) で始め、表示に「ssh 越し」と書く。律速が ssh だと実測で分かったら (b) を検討する
   - 目的との関係: 100 Mbps の頭打ちと無線の遅さは (a) でも見分けられるはず (ssh の暗号化はふつう 100 Mbps より十分速い。未実測)。
     1 Gbps と 10 Gbps / Thunderbolt の区別は (a) では ssh で頭打ちになりうる。区別が要るなら (b)
3. **流す量** — 秒数で切る (例: 5 秒) か量で切る (例: 256 MiB) か。Thunderbolt (数 Gbps) と Wi-Fi 経由 (数十 Mbps) で
   同じ量だと所要時間が桁で違うので、**秒数で切る**方を推奨
4. **キー** — 空いているキーを確認してから決める (`?` の一覧と `Binds` を見る)。足したキーは `Binds` にも足す (足さないと glogx の `L` の板で glogx が先にキーを取る)
6. **見せ方** — 数値だけでなく、目安の段 (〜100 Mbps / 〜1 Gbps / それ以上) との比較を出すか。推奨は、
   数値の横に経路 (有線 / 無線) と「100 Mbps 付近で頭打ち (途中に 100M の機器?)」のような一言を出す形 (例:
   `通信速度  ↑ 94 Mbps ↓ 93 Mbps  有線  🚨 100M の機器で頭打ちの可能性`)。見た目は本体に入れる前に見本で決める
5. **確認の板でどのキーを実行にするか** — 既定の `IsYes` だと Enter と Y でも流れる。帯域を食う操作なので、
   `ask.auto` と同じく Enter を外す (y だけで実行) か、`IsYesStrict` (y / Enter) にするか。推奨は Enter を外す形 (選んで Enter を連打しても流れない)

## 対応方針 (決めることが決まった後)

- 測定は `setup` と同じく「命令を組む部分」と「起こす部分 (`live`)」に分け、組む部分を偽物でテストする
  (README の「テストは偽物だけが見える PATH で走らせる」に従う)
- 起こす側は `SSHRun` を流用せず、stdin へ流す・stdout を捨てて量だけ数える runner を `live` に足す (上の「今の作り」)
- 裏の処理は `m.bg` / `takeBG` の型に載せ、測定中は `Busy()` を真にする (偽のままだと tick が張られず結果を取り込めない)。
  進捗は既存の `progressShown` (初期設定専用) ではなく、詳細カードの測定の行に出す
- glogx の `L` の板を閉じたとき (`Model.Close`) は測定を取り消し、相手側の受け手も残さない
- 測定中も一覧の操作は止めない。測定中に別の相手で測定を始めない (同時に 2 本流すと互いの帯域を食って値が意味を失う)
- 結果の行の「経路 (有線 / 無線)」は issue 828 の判定関数 (Hardware Port から決める) を使う。827 で別に作らない
  (828 で実装済み: `netinfo.Snapshot.Link` / `LinkOf`、繋ぐ先の線は `lanmgr.Model.connectLink`。2026-10-18)
- 確認の板と結果には、実際に流した宛先 (有線の名前 / 内部 IP / Wi-Fi の IP のどれか) を出す。Wi-Fi 経由で測った値を有線の速度と読ませない
- 結果の時刻を出し、古い結果を今の速度と読ませない
- 操作のログ (`~/Library/Logs/mac-lan-manager.log`) に、測った相手・経路・量・秒数・結果・失敗の理由を残す
- `dump` (画面を出さないデバッグ) では測らない (帯域を食う操作を確認なしに起こさないため)
