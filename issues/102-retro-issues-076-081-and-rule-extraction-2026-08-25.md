## 1. `make test` の exit code を確認せずに commit した

081 で `make test >log 2>&1; echo $?` と `git commit` を**同じコマンド連鎖に入れた**ため、
exit 2 (shellcheck SC2034) を見ないまま commit が走った。未 push だったので amend で直したが、
**「テストを回した」と「テストが通った」を同じ 1 手で済ませようとしたのが原因**。

**切り出し先の提案**: `_claude/rules/` への追記ではなく **`~/.claude/skills/c/SKILL.md`
(commit 手順の正本) に 1 行**。「`make test` と `git commit` を同じ Bash 呼び出しに入れない。
exit code を独立に確認してから commit する」。既存の `verify-execution-not-just-exit-code.md` は
「exit 0 は実行された証拠にならない」を扱っており、こちらは「exit code を見ないまま次へ進む」
なので別物。

## 2. 変異検証を「壊れた baseline」の上で回した

078 で指紋を統合した直後に変異 5 本を当て、「1/5 しか red にならない」と読んだ。
だが**そのときすでに `test_resurrect_save_lock.sh` が別の理由で落ちていた**
(テストが削除した関数名を呼んでいた)。baseline が red の状態で変異を当てても、
**red の増減が変異のせいか元から壊れているせいか区別できない**。

気づけたのは「FAIL の中身を読んだ」からで、`0/3 red` という数字だけ見ていたら
「テストが主張を守っていない」と誤診して、要らないテストを足していた。

**切り出し先の提案**: `_claude/rules/mutation-verify-new-tests.md` に 2〜3 行。
「変異を当てる前に **baseline が green であることを測る**。baseline が red のまま当てた変異の
結果は読めない (red の増減が変異由来か区別できない)」。
→ これは **issue 061**「変異の当て方自体が偽物になりうる」と同じ節に入る話なので、
061 を閉じるときに一緒に書くのが良い。

## 3. 手元 1 platform の緑が、本番のバグを隠した

078 の移行ガード (旧書式の lock で生存 owner を奪わない) は、**macOS では緑・Linux では破れる**
実装だった。`ps -o lstart=` の末尾パディングが platform 依存 (macOS は空白で埋める / Linux は
埋めない) で、正規化がその末尾空白に依存していたため。

- テストの問題ではなく**本番のバグ**。Linux では移行ガードが機能せず生存 owner の lock を奪う
- 手元では `make test` も単体テストも緑。**CI (Linux) だけが捕まえた**
- 直したあと「両 platform の形状」をテスト内で作る観点を 3 つ足した

**切り出し先の提案**: `_claude/rules/mutation-verify-new-tests.md` の「よくある『守っていない
テスト』の形」に 1 項目。「**環境が変われば別の値になるコマンド出力** (`ps` / `date` / `stat` の
書式・パディング) を比較に使うテストは、**両方の形状をテスト内で作る**。手元 1 platform の緑は
『その platform では壊せなかった』でしかない」。今日追記した「本番と同じ制約の下で観測して
いるか」の platform 版で、同じ節に並べられる。

## 4. セッション序盤に読み込んだドキュメントを「現在の内容」と思い込んだ

`tests/codex_fanout.bats` の失敗を切り分けたとき、「実装とテストの両方が skill に追随して
いない」と報告した。実際は**実装と skill は一致していて、テストだけが未追随**だった。
原因は、セッション序盤に `Skill` で読み込んだ `codex-drive/SKILL.md` (effort は medium) を
現在の内容と思い込んだこと。その後 `8736d37` で max に変わっていた。

観測 (テストが `low` 期待・HEAD でも赤) は正確で、**帰属だけが誤っていた**。並行セッションに
訂正された。

**切り出し先の提案**: **却下**(ルール化しない)。「長いセッションでは読み込み済みのファイルが
古くなりうる」は一般則すぎて、トリガーが特定できない。代わりに**具体的な行動**として
「他人の領域のファイルを根拠に因果を述べるときは、その場で読み直す」を実践で守る。
