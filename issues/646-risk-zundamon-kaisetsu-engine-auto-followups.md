## 概要

エンジンの自動起動と見張り (`src/zundamon-kaisetsu/engine_auto.go`。commit「エンジンを使うときに自動で起動し、使われなくなったら
見張りが止める」と「自動起動のテストを、手元にランタイムがあるかに依存させない」) に、2026-10-07 に観点を分けた敵対的レビューを 3 本当てた。
P1 の 2 件 (見張りが別のポートに up したコンテナを名前で止める / 本番の配線をどのテストも見ていない) と P2 のロック
(返らない `container run` が起動用ロックを無期限に持つ) は同じ日に直した (コンテナ名をポートごとにし、run に上限を付けて
イメージの取得は上限の外へ分け、ロックの持ち主を表示する。修正への敵対的レビューの指摘も同じ commit で直した)。
ここには直さずに残した項目を置く。

## 残した項目

各項目の「確認」は、レビューで偽物のテストやコードの読みで確かめたものか、推測かを書く。本物のランタイムでの再現はしていない。

### 1. スリープからの復帰で、使用中のエンジンを止めうる (P2・偽物で再現)

- 見張り (`reaper.once`) は「最後に使った時刻」(`engine.last` の mtime) と壁時計の差で止める。時刻はエンジンへの要求の直前
  (`engineRequest` の `engineUseHook`) にしか更新されない
- 長い `synth` の途中で 10 分以上スリープすると、復帰直後に見張りの確認と `synth` の次の要求が競争になり、見張りが先なら止める。
  `synth` の次の要求は「通信できない」で落ちる (本体の途中では起動し直さない)
- 実害は小さい: `synth` は行ごとに合成済みを残すので、打ち直せば続きから進む
- 直し方の案: 使用中のコマンドが共有ロック (または生存を示すロック) を持ち、見張りは誰も持っていないときだけ止める。
  時刻の比較だけに頼らない

### 2. 作成日の描画がテストされていない (P2・変異で確認)

- `TestCreatedDate` が見ているのは `PlayerData.Date` まで。`_claude/skills/zundamon-kaisetsu/templates/player.html` の `stage-date` の要素や、作成日を入れる行を
  消しても全テストが緑のまま
- mp4 のまとめ撮り (`#sheet=`) に作成日が写るかも検査されていない (コードを読む限りでは、作成日は sheet の分岐より先に入るので写る)
- 直し方の案: テンプレートを読み込んで要素と代入の存在を検査するか、ヘッドレス Chrome で 1 枚撮って文字を確かめる

### 3. 見張りが呼び出し側の作業ディレクトリと環境変数を引き継ぐ (P3・コードで確認)

- `spawnReaper` は `cmd.Dir` も `cmd.Env` も指定しない。外付けディスクから実行すると、見張りが動いている間そのディスクを
  取り出せない。見張りは最後に使ってから 10 分で終わるので、期間は「エンジンを使い続けている間 + 10 分」(起動途中なら最大 30 分、
  止めるのに失敗し続けるとさらに最大 20 回 × 30 秒)
- 直し方の案: `cmd.Dir = "/"`。環境変数は `PATH`・`HOME`・`VOICEVOX_URL` など要るものだけにするかを検討する

### 4. 起動途中にコマンドが kill -9 され、取得が 30 分を超えると、後から立ったエンジンが残りうる (P3・推測)

- 起動したコマンドが kill -9 で死に、子の `container run` だけが取得を続ける形。見張りは接続拒否のまま `startGrace` (30 分) を
  過ぎると印を消して終わり、その後に立ったエンジンは印も見張りも無いまま残る
- `container run` 自体は `startRunTimeout` (15 分) で打ち切るが、それは起動したコマンドが生きているときだけ効く
- 確かめていない前提: 子の `container run` が親の死後も取得を続けるか、Apple の container が起動途中に接続を拒否するか

### 5. ランタイムが無い状態を PATH で作るテストは、Linux では本物の docker に届きうる (P3・コードで確認)

- `TestCmdUpClearsMarkerEvenOnFailure` などは PATH を `/usr/bin:/bin` にして「ランタイムが無い」状態を作る。docker が `/usr/bin` に
  ある Linux では、`up` / `down` が本物の docker に届く。macOS (手元と CI の runner) では `/usr/bin` に docker は無い
- `signal_test.go` の `isolatedEnv` は HOME だけを差し替える。Linux では `os.UserCacheDir` が `XDG_CACHE_HOME` を優先する
- 直し方の案: PATH は空のディレクトリと go だけにする / `XDG_CACHE_HOME` も差し替える

### 6. 本物のランタイムでの文言・挙動を測っていない (未確認リスク)

- `stopContainers` が「無い」とみなす `notFoundRe` が、Apple の `container stop` の文言に合うか
- 見張りが起動したバイナリ (go の自動ビルドで差し替わる) と、新しく起動するコマンドの版が違うときに、印の書式やロックの意味が
  食い違わないか (今は差が無い)
- `reaper.log` はローテーションしない (1 回の起動で数行。止める失敗も上限 20 行)
- 見張りは「そのコンテナは無い」(`notFoundRe`) を停止の成功と読む。旧版が固定名 (`zundamon-kaisetsu-voicevox`) で起こしたコンテナと
  印が残った状態で、新版の見張りが止めにいくと、ポート付きの名前のコンテナは無いので「止めた」と記録し、エンジンは応答したまま残る
  (偽物で再現)。止めた後も応答していたら失敗に数える案は採らなかった: 同じポートでデスクトップアプリが応答している正当な場合にも
  当たり、止められないものを止めにいき続ける。今は警告をログ (`reaper.log`) に残すだけ。旧版の固定名のコンテナは `down` が止める
- 版をまたぐ見張り (推測): 固定名を止める旧版の見張りが動いたまま新版に差し替わると、`ensureReaper` は見張りがいるとみなして
  新しい見張りを起こさない。旧版の見張りは固定名を止めにいって「無い」を成功と読み、印を消して終わるので、新版がポート付きの名前で
  起こしたコンテナが残る。旧版の自動起動は 1 日しか出ておらず、直した日の手元には旧版の見張りがいないことを確かめたので、直さない。
  起きたら `zundamon-kaisetsu down` で止める
- 起動用ロックの持ち主の表示 (`withStartLock`) は、持ち主が書く前 (Truncate と WriteAt の間) に読むと「不明」と出て、
  ロックファイルに書かない旧版が持っているときは前の持ち主の pid が出る。表示だけで、ロックの判定 (flock) は壊れない

### 7. SKILL.md のコンテナ名の記述が古い (docs)

- コンテナ名はポートごと (`zundamon-kaisetsu-voicevox-<ポート>`) になったが、`_claude/skills/zundamon-kaisetsu/SKILL.md` の
  片付けの節は固定名のまま。直した日は別のセッションが SKILL.md を編集中で (図解 `show` の節の追加)、版が分かれていたので保留した。
  その変更を取り込んだ版の上で直す
