# 243 feat: doctor の削除確認だけ `Enter` がキャンセル — 共通語彙 (`y/Enter: 実行`) へ揃えるか決める

起票日: 2026-09-04
出典: issue 241 の「別途」節（対応時に切り出し）
重要度: **P3**（倒れる向きは安全側。ただし手癖で押すと無言で閉じる）
対象: `src/glogx/doctor_delete.go` の `handleDeleteKey`（`case d.confirm`）/ `confirmLines` の tail /
      `src/glogx/doctor_view.go` の `hint`

## 何が非対称か

glogx の破壊操作の確認は `status_view.go:discardBox` が **`y/Enter: 実行   n/Esc: キャンセル`** で、
`discardKey` の doc は「push/pull 確認と同じ語彙」と明記し、issue 071 / 123 で 2 度再確認されている。
**doctor の削除確認だけ `Enter` がキャンセル**（案内も `y: 削除する   n/Esc: やめる`）。

issue 241 で送るキー（j/k/ctrl+d/…）は中止から外したが、`Enter` は触っていない。

## 決めること

1. `Enter` を**実行側**へ揃える（共通語彙に合わせる。ただし *削除* の既定を実行側へ倒すので、
   誤爆の代償が push/pull より大きい）
2. `Enter` を**飲むだけ**にする（実行もキャンセルもしない。手癖の誤爆を無害化するが、
   「何も起きない」も分かりにくい）
3. 現状維持（キャンセル）にして、**非対称であることを案内に書く**

## 判断材料

- doctor の確認は「ディスクから実体を消す」操作で、`status_view` の discard（作業ツリーの変更破棄）とは
  取り返しのつかなさが違う
- 一方、同じ画面群で `Enter` の意味が違うのは学習コストになる（241 で「見ようとした打鍵で消える」形は
  塞いだので、残るのは `Enter` だけ）

## 未確認

実際に `Enter` を押して驚いた事例は観測していない（241 は静的な読み取りから起票された）。
人が使って困ったかどうかが分かると判断が早い。

## 追記 (2026-09-04): 非対称は `Enter` だけではなくなった

issue 241 の実装で、送るキー 12 個 (j/k/ctrl+d/… どれも doctor 一覧の移動キー) は
確認を閉じなくなった。`status_view.go:discardKey` は今も**先頭で無条件に閉じてから** y/Enter だけ
実行に回すので、**doctor の削除確認だけが「任意キーでは閉じない唯一の破壊確認」**になっている。

失ったもの: 「モーダルに居ると気づいていないユーザーが、最初の 1 打鍵で必ず一覧へ落ちる」
フェイルセーフ。今は `j` (一覧のカーソル移動) の次に `y` (一覧では「パスをコピー」) を押すと
削除が走る。

したがって本 issue で決めるのは `Enter` の扱いだけでなく、**「破壊確認から抜ける既定」を
doctor と status で揃えるか**になる。選択肢:

1. status に揃える (任意キーで閉じる) — 241 のスクロールと両立しないので、送る手段を
   別の修飾キー (Ctrl-N/P 等) へ移すことになる
2. doctor の今の形を正とし、status 側も「送れる確認」へ寄せる
3. 非対称のまま、doctor の hint に「他のキーでやめる」を明示する (現状の案内は
   `y: 削除する   n/Esc: やめる` で、送るキーが例外であることは書いていない)
