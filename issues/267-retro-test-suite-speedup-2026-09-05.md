## 1. 変異が「red でも green でもない第 3 の結果」だったのを 2 回踏んだ

`mutation-verify-new-tests.md` 手順 1.6 が「変異の diff を目視し、意図した箇所だけが
変わっていることを確認する」と要求しているのに、2 回とも飛ばした。

- **midedit**: `perl -0pi -e` の置換文字列の中で `$src_dir` / `$built_fp` が **perl 自身の
  変数**として空に展開され、コードが破壊された。**`zsh -n` は通る** (構文は valid) ので
  ビルドチェックでは弾けず、テストが早期に死んで rc≠0 = 一見 red に見えた
- **toast**: `python` で「`tmux-toast` を含む最初の行」を潰したら**コメント行**に当たり、
  rc=0 になった。「変異を検知できないテスト」と読みかけた

どちらも「置換ツールを信用して diff を読まなかった」。手順 1.5 (ビルドできたか) は
やっていたが、**構文が通る壊れ方**は 1.5 では捕まらない。

🚨 **「第 3 の結果」という概念自体は既にルールにある** (`mutation-verify-new-tests.md:49`。
反証レビューの指摘で訂正)。足りないのは概念ではなく、**この壊れ方が 1.5 のビルドチェックを
すり抜ける**という具体例。

→ 切り出し: **既存へ追記候補** `mutation-verify-new-tests.md` 手順 1.6 に、具体的な壊れ方を
1 行 (「置換に perl/sed を使うなら、シェルと perl の**両方**で `$` が展開されうる。
コメント行・別の同名箇所に当たっていないかを diff で見る」)。判断待ち

## 2. 固定 sleep を置き換えるとき「窓以外に担保していたもの」を落とした

`test_go_autobuild.sh` の `order` (「あとから始まったビルドが勝つ」) は、`FAKE_GO_SLEEP=1` (A) と
`=4` (B) が **窓を作ると同時に「A が B より先に完走する」順序も担保**していた。ゲート化で
窓だけ置き換えた結果、A と B が同時に走り出して **12 回に 1 回**落ちる flake になった。

`wait "$A_PID"` が順序の担保に見えたのが罠で、`--async` のラッパーは builder を detach して
即 exit するため **$A_PID はとっくに死んでいる**。release 直後に「A の成果物が入ったこと」を
待つ形へ直して 14 回連続 green。

`avoid-wall-clock-assertions.md` は「競合の窓を作るための sleep は入力であり、テストの主張を
決めている」と書いているが、**それが順序も決めていることには触れていない**。

→ 切り出し: **既存へ追記候補** `avoid-wall-clock-assertions.md` の例外節に
「窓を作る sleep を置き換えるときは、その sleep が**他に何を担保していたか** (完走順・到達順・
プロセスの生存期間) を列挙してから外す」。判断待ち

## 3. rebase 競合を `push OK` と誤報しかけた

`git rebase origin/master` が競合した直後に `git push -q origin HEAD:master` を打ち、
**`-q` が "Everything up-to-date" を隠した**ので成功に見えた。実際は HEAD が
origin/master のまま (rebase 途中) で、自分の commit は 1 つも載っていなかった。

`commit-with-pathspec.md` は「push の `Everything up-to-date` は rc=0 なので出力だけ見ると
成功に見える」を既に書いている。**`-q` を付けるとその唯一の手がかりも消える**ことは書いていない。

→ 切り出し: **既存へ追記候補** `commit-with-pathspec.md` に「**push / merge に `-q` を付けない**。
`-q` は空振りの唯一の手がかり (`Everything up-to-date`) を消す。静かにしたいなら出力を
ファイルへ落として後で読む」。判断待ち

## 4. レビュワーの説明を、自分の環境を測らずに否定した

fable の設計レビューが `test_ctrl_v_paste.sh` の赤を「非 UTF-8 locale で日本語が潰れるため」と
説明したのに対し、私は「私の環境では日本語が通るので別原因の可能性がある」と報告した。
`locale` を打ったら **`LANG=""` / `LC_CTYPE=C`** で、レビュワーが正しかった。

🚨 **「ルールに書いていない」は言い過ぎだった** (反証レビューの指摘で訂正)。
`~/.claude/CLAUDE.md:120` は「事実の主張なら裏を取る。取っていないなら『未確認だが』と明示する」を
既に要求している。ただしその節の射程は**ぼやき**と**不在の主張**で、今回のように
**他者の指摘を否定するための、自分の環境についての肯定的な主張**は文面上の対象外に読める。

誤った否定はレビュワーの信頼を下げ、真因の特定を遅らせる
(実際、そのあと原因が分からないまま 1 往復した)。

→ 切り出し: **既存へ追記候補** (射程は狭い) CLAUDE.md「レビュー方針」の「主張は証拠ではない」に
「**これは否定側にも同じく効く**。指摘を『違う』と言う前に、自分の環境・前提を実測する」。
既存の裏取り規定と重複気味なので、**足さない判断も十分あり得る**。判断待ち
