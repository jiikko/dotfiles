## 反省

### 1. 資源の上限を新設したのに、「枠が解放される経路」を通るテストが 1 本も無かった

観点② のレビューが 12 本の変異を当て、**10 本が私の変異 2 本を素通り**した。最大のものは
`defer inFlight.Add(-1)` (枠を戻す側) の削除で、落とすと上限が「累計の更新回数」になり
**詰まりが 1 度も無い健全なマウントでも上限 tick 目に更新が止まる** (既定値で約 80 分)。
自分でも追試して全緑を確認した。

原因は構造的で、私が書いた 3 本のテストはどれも**詰まらせた状態**しか作っておらず、
「上限」と「成功する更新」の相互作用を観測する列が無かった。上限を置くときは
「枯渇する側」だけでなく**「返ってくる側」**を通す列が要る、という一般形。

**切り出し先の提案**: [`mutation-verify-new-tests.md`](../_claude/rules/mutation-verify-new-tests.md) の
「よくある『守っていないテスト』の形」に 1 項目追記 —
**資源の上限 (枠・プール・カウンタ) を新設したら、枯渇の列だけでなく「枠が返る列」を通すテストを置く。
返す側を消す変異が red になるまでが 1 セット**。

### 2. `cmd > log 2>&1; echo "rc=$?"` で rc を潰し、失敗した `make test` を 2 回「rc=0」と報告した

background で `make test` を回すとき、末尾に `echo "rc=$?"` を置いたため、
**ハーネスが報告する終了コードは `echo` のもの**になった。2 回目の `make test` は実際には
失敗していた (私が書いた `done/381-...` リンクが未解決) のに「rc=0」と報告し、
ログを読み直して初めて気づいた。同じセッションで `python3 - <<PY ... PY` と
`bash scripts/issue_done.sh` を `&&` 無しで並べ、**python が失敗しても後段が走った**
(381 の本文更新が未反映のまま done へ移った) のも同族。

[`verify-execution-not-just-exit-code.md`](../_claude/rules/verify-execution-not-just-exit-code.md) は
「パイプ終端の status を見ない」を持つが、**「複合コマンドの最後に置いた echo / 通知が返す rc」**と
**「`;` で繋いだ検証手順は前段の失敗を飲む」**は書かれていない。

**切り出し先の提案**: 同ルールへ 2 行追記 —
**background / 複合コマンドで検証を回すときは、末尾に別コマンドを置かない (rc がそれに化ける)。
判定はログの失敗行で行う**。**検証手順を繋ぐのは `&&` で、`;` で繋がない**。

### 3. レビュー指摘を直すときに書いた説明自体が誇張だった

1 周目の指摘に対応した際、コメントに「返らない更新と成功する更新が交互に来る列では、
上限到達が初めて報告する」と書いた。直後に導出し直したところ、**上限に到達する経路は必ず
事前に期限切れ報告を通る**ので誤りだった (自分で撤回してコメントを直した)。

[`adversarial-review-own-safeguards.md`](../_claude/rules/adversarial-review-own-safeguards.md) §7 は
「指摘を直した差分にもう 1 周回す」を要求しているが、**差分に添えた説明文 (効能の主張) も
同じ検証対象**という点は明示されていない。

**切り出し先の提案**: 同ルール §7 に 1 行 — **指摘への修正に添える「これで何が防げるか」も
主張なので、既存の経路で既に防げていないかを導出し直してから書く**。

### 4. issue の残タスクが誤っていた (起票時の推論の取りこぼし)

381 の残タスク ①「pile-up テストに lease の assert を足す (今の状態で red になるはず)」は
**成立しなかった**。あのテストは FIFO を最後まで退けないので、どの実装でも `Renew` は成功しえず
lease は必ず死ぬ = 常に red = 何も測らない assert になる。本文へ書き戻した。

**切り出し先の提案**: **却下**。CLAUDE.md の「issue の記述を鵜呑みにしない」「不在の主張は
数え直す」で既にカバーされており、今回もその規律どおり着手前に検証して弾けている。
