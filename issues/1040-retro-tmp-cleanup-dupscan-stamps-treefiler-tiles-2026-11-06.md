# 1040 (retro): 一時領域の掃除・dupscan の印・treefiler のタイル (1036 / 1037) の振り返り

起票日: 2026-11-06

## 概要

cleanup-tmp-dir の実行と skill の手直し、dupscan の注入の印が `$TMPDIR` に溜まる件 (1036)、treefiler のタイルがライブ更新と表示の作り直しに追いつかない件 (1037) のセッションの振り返り。

## どこで踏んだか

1. **1037 のテストが、本番のループの順 (大きさの変更 → 描画 → 打鍵) を再現していなかった**。描画の `drawTile` が遅延していた選択の合わせ直しを先に済ませるため、
   打鍵の側だけで見失いを捉える直しは本番では効かなかった。3 周目の敵対的レビューが指摘し、テストに `View()` を挟んでも緑のままだった。
   原因は、テストのタイルが開くアニメの途中で、描画が本文とリンクを描いていなかったこと (`settle` で開き切らせると赤になった)。
   1035 の「状態 × 出来事」の表は先に作っていたが、出来事の行に「描画 (遅延した合わせ直しを実行する)」が無かった。1037 の表の `view` の行は 3 周目の指摘を受けて足した
2. **バックグラウンドの `make test` が走っている同じ worktree で、レビューの指摘を直した**。4 周目のレビューの結果と `make test` が同時に走っていて、
   指摘が先に返ったので編集した。その `make test` は混ざった木を測ったことになり、止めて回し直した (規範は `verify-execution-not-just-exit-code.md` に既にある)
3. 1036 で、敵対的レビューの「直す前の版でも同じ形」という主張を、issue へ写した後で誤りと気づいた (旧版の印はファイル名なので途中で切れない)。写す前に旧版のコードで確かめていれば往復が無かった
4. `container image ls` が `vminit` を出さないまま `prune --all` の承認を取り、見せていない image を消した (`container image prune --all` の出力に `untagged ghcr.io/apple/containerization/vminit:0.47.0`。
   本体 checkout の `tmp/cleanup-tmp-dir/a967cb92-9fd2-44ef-8f7f-52b39d34412b/container-prune.txt`)。skill に、数が合わないときは `vminit` を名指しする手順を足した (16a157b00)
5. `tmpclean plan` が生きている claude の cwd に当たる project を scratchpad に見つけられず rc=2 で止めたとき、skill が「先へ進まない」としか言わなかった。
   止まるのは `session` だけなので、`-kinds` から `session` を外して作り直す道を自分で探した。skill に足した (16a157b00)
6. **この retro の本文を書いた worktree を、未コミットのまま消した**。`git rebase` が未コミットの変更で止まり、`&&` で繋いだ commit は走らなかった。
   続く push は `;` で繋いでいたので走り、`Everything up-to-date` の rc=0 を返した。それを成功と読み、worktree remove まで進んだ。
   本文は会話に残っていたので書き直した。規範は `worktree-per-session.md` (push できたかは自分の commit が origin にあるかで見る) と `commit-with-pathspec.md` (`Everything up-to-date` は空振りの手がかり) に既にある

## 次に効きそうな改善 (提案。実行はユーザーの判断を待つ)

- **A1. 状態 × 出来事の表を作るとき、描画が遅延した処理 (選択の合わせ直し・読み足し・キャッシュの作り直し) を実行する UI では、描画を出来事の 1 つとして数える**。
  描画は打鍵より先に遅延の解決を済ませ、打鍵の側だけで捉える直しを素通りさせる。既存の項 (状態 × 読み手・UI の状態機械に裏の動作を足すとき・表示と実行を揃える) は
  「どの経路が値を読むか」を挙げさせるが、「描画が副作用で状態を進める」ことは挙げていない。
  別の場面でも同じ形になる: 描画の中で遅延の取り込み・読み足し・作り直しをする TUI (bubbletea の View・glogx) や、描くときに計算を済ませる UI 全般。
  切り出し先: 既存の `_claude/rules/survey-receiver-guards-before-passing-new-values.md` の「UI の状態機械に自動の裏の動作を足すとき」の項に追記 (発動点が同じ)
- **C. 検査 (`make test`) の結果に、走っている間に作業ツリーが変わったかを出す**。始まりと終わりで作業ツリーの状態 (`git status --porcelain` と変更したファイルの内容の hash) を比べ、
  変わっていたら「この結果は途中で変わった木を測った」と最後に出す。同じ日に 2 つのセッションで、背景の検査が走っている同じ worktree を編集した (1038 の項目 2・本 retro の項目 2)。
  rule (`verify-execution-not-just-exit-code.md`) はあるが、レビューの結果と検査が並んで返る場面で読み直されず、規範だけでは止まっていない。気づけるのは結果を読むときなので、結果の側に出す。
  切り出し先: 新規 issue (`make test` の集約の出口か `serial-run` に足す。道具の変更なので rule ではない)
- **D. 未コミットの変更がある worktree を消す操作を、道具の側で止める**。`git worktree remove --force` は未コミットの変更ごと消し、object にも残らない。
  `deny-piped-push-then-destroy.sh` は push をパイプに通す形しか見ず、`;` で繋いだ空振りの push の後の remove は止めない (項目 6)。
  消す前に `git -C <worktree> status --porcelain` が空かを確かめ、空でなければ拒否する PreToolUse の判定を足す (`--force` は lock を外すためにも使うので、引数で区別しない)。
  切り出し先: 新規 issue (hook の変更)

## 却下

- A2 (打鍵と描画の順を見るテストは、アニメを終点まで進めてから描画を挟む): `rules-checklists/mutation-verify-new-tests.md` の「fixture と前提」の「fixture を『検査対象が壊れない形』に選んでいないか」が当たる (開く途中の描画は検査したい描画の経路を通らない)。1038 の却下 (3) と同じ類型
- B (レビューと長い検査を並べて起こすなら検査はレビューの後に起こす): `verify-execution-not-just-exit-code.md` の「検証・計測がバックグラウンドで走っている間は…編集しない。編集したくなったら止めてから編集するか別の worktree で編集する」が同じ中身で、1038 の却下も同じ行を引いている。踏んだのは rule を読み直さなかったため (項目 2)
- 3: `claude-md-maintenance.md` の「レビュー・調査の出力にある数値・入口・経路を issue や文書へ写すときも、写す前にコードの定義を 1 回引く」が直接当たる。今回は commit の前に自分で気づいて直した。新しい規範は要らない
- 4: 一般形 (承認で見せた対象と消す対象を一致させる) は `~/.claude/CLAUDE.md` の「確認を求めるとき…消す・止める対象は種類を分けて列挙する」が持つ。踏んだのは、見せる一覧を取る道具 (`image ls`) が対象の一部を出さないことを知らなかったためで、その道具の性質は skill に書いた
- 5: skill の手順の欠け (局所)。skill を直した
- python でコメントを書いて、PostToolUse のコメントの経緯の検査を素通りした件: dotfiles の CLAUDE.md に既に注意があり、`make test` の `test-comment-provenance` が拾った。規範は効いている
- mutate-verify の変異がコンパイルの通らない形 (未使用の変数) になった件: 道具が第 3 の結果として止めたので、道具の設計どおり
