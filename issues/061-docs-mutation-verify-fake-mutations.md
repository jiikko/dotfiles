# mutation-verify-new-tests.md に「変異の当て方自体が偽物になりうる」を足す

起票日: 2026-08-14
種別: docs
優先度: **P2** (ルールが要求する検証が空回りする経路を塞ぐ)

## 何が抜けているか

`_claude/rules/mutation-verify-new-tests.md` は「不変条件を壊す変更を 1 つ当てて red を
見る」まで要求している。だが **当てた変異が偽物でも red は出る** ことに触れていない。

実例 (2026-08-14、issue 050)。「一覧に進捗を出さない」を守るテストの変異検証で、
私はこう当てた:

```go
text := num + " " + badge + " " + catPainted + " " + title + " 1/1"  // ← 文字列を埋めただけ
```

red になったので「テストは効いている」と判断した。**しかし偽物だった**。
本物の機構 (`ReadBody()` → `Progress()` を呼んで一覧に出す) を戻す変異を当て直すと、
そのテストは **green のまま**だった — フィクスチャから checkbox を削っていたので
進捗を出す実装に戻しても `1/1` が生成されなかったため。
つまり**私の変異は「テストが文字列 `1/1` を検出できるか」を確かめただけ**で、
テストが守るはずの「全文読みが復活していないか」は一度も検査していなかった。

## 足す一節 (案)

> ## 変異は「production の機構を戻す」形にする
>
> 変異が red を出しても、それが**その変異を検出できただけ**で、テストが守るはずの
> 不変条件を検査したことにはならない。
>
> - ✗ 期待している文字列・値を直接埋め込む (「テストがその文字列を見つけられるか」しか分からない)
> - ✗ `return` を足して早期に抜ける・定数を返す (壊れ方が実際の退行と違う)
> - ✓ **削除・最適化した機構をそのまま戻す** (呼び出しを復活させる / 旧実装を貼り直す)
>
> 判定: 「この変異は、実際に起こりうる退行の形か？」実装者が将来やりそうな編集
> (最適化を戻す・条件を緩める・呼び出しを足す) を再現していなければ偽物。

## なぜ P2 か

このルールは「green は正しさの証明ではない」を塞ぐために存在するのに、
**塞ぎ方そのものが同じ穴を持っている**。実際 1 セッションで 3 回踏んだ:

| 場面 | 当初の assert が見ていた量 | 壊れても動かない理由 |
|---|---|---|
| issue 047 | 行頭が空白か | 下端の影行は元から空白 2 桁 |
| issue 050 | `1/1` の不在 | checkbox の無いフィクスチャでは元から出ない |
| issue 048 | 確保の**回数** | 削ったのは 1 本の大きなスライスで回数は動かない |

同日に別セッションが確定させたデグレ 4 件 (issues 056-059) も**すべて同じ構造**だった
(行数 / mock に `start_time` が無い / 配達経路の外側で assert / 変異先が sort 順 1 本目)。

## 併せて足すと効きそうな一行

> **その assert が見ている量は、壊れたときに動くのか**を先に問う。
> 動かない量 (総数・行数・存在の否定) を見ていると、変異を当てても素通りする。

`refuse-low-value-coverage.md` の「回帰を捕まえないテストを書かない」と対になる観点。
