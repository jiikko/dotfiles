# 1111 (retro): ja-writing の Go をベンチマークで 10 周改善したセッションの振り返り

起票日: 2026-11-26

## 概要

issue 1079 (epic 1072) の「ベンチマークで Go を改善するループ」を、上限の 10 周まで回したセッション (2026-11-25〜26) の振り返り。
採ったのは 3 周 (6・7・9 周目) で、最後の Go は測った全部のケースで本家の Python より速くなった。数字と各周の記録は 1079 の本文にある。

## どこで踏んだか

- A. **同じコードから作った別のバイナリどうしで、所要に 4% ほどの「速い」「遅い」が出た**。`bench/compare.py` の揺れの帯は、同じバイナリを 2 回測った組
  (same と orig) の比から取るので、バイナリの配置の差を含まない。6 周目の 1 回目の run では、直しが触らない lint のケースにも「遅い」が付き、
  計画の採用条件 (ほかに「遅い」が無い) を満たさなかった。2 回目の run では、対照のバイナリを足した。対象の経路のコードが前の周と同じ別のバイナリ (5 周目に戻した直しのバイナリ) で、
  前の周のバイナリとのこの組でも 1.013〜1.043 倍の「遅い」が出たので、揺れと読めた
- B. **5 周目に「効果なし」として戻した diff の直しが、9 周目に周の数を増やして測り直すと 0.945 倍で採れた**。5 周目の判断は 5 周の run 1 回だけで、
  2 回目の run (6 周目の対照として入れた) では 0.944 倍と食い違っていた。食い違いを見た時点で測り直さず、記録だけ残して先へ進んだ
- C. **比べるバイナリを作業ツリーから作り、当てたままのパッチが前の周のバイナリに混ざった** (jw-it7 を、9 周目のパッチを当てた木から作り直した)。
  パッチを外して作り直し、`cmp` で別物になったことを見てから計測に入った
- D. **check を in-process で測るベンチマークを、3 回作り直してから諦めた**。`check run` は起こし方ごとに別の枝に入る。
  分かれ目は、作業フォルダの照合・作業フォルダの外のファイルの断り・lint と diff を子のプロセスとして起こすときの印の 3 つ。1 回落ちるたびに次の 1 つを見つけた。結局 diff の in-process のベンチマークに切り替えた
- E. **6 周目のレビューの勧めを当てると遅くなった**。勧めは、探索を添字を返す関数に分けて共有する形。分けると `inRanges` がインライン展開されなくなった。
  lint-len-1024k の in-process で 1 回 473 ms → 490〜515 ms。戻して、理由をコードのコメントに書いた

## 次に役立ちそうな改善 (提案。実行はユーザーの判断を待つ)

1. **別々にビルドしたバイナリどうしの所要を比べるときは、対象の経路のコードが同じ別のビルドを対照として同じ run に入れ、その組の比も並べて読む**。
   同じバイナリを繰り返し測った揺れは、配置 (リンクの順・アラインメント) の差を含まない。A の一般形。Go に限らず、コンパイルする言語の性能の比べ全般に当てはまる。
   切り出し先: `_claude/rules/perf-claims-need-measurement.md` の「before / after の所要は、別の時間帯の run どうしで比べない」の項に追記
2. **同じ変更の測り直しで結論が割れたら、記録だけ残して先へ進まず、周の数を増やした run で決着させてから次へ進む**。割れたまま「効果なし」で戻した直しは、
   後から拾い直されない限り失われる (B は 4 周後に拾い直せたが、拾い直す仕組みは無かった)。切り出し先: 1 と同じ項に追記 (1 と同じ文にまとめてよい)
3. **比べるバイナリは、commit から切った worktree で作る**。作業ツリーで作ると、当てたままのパッチ・わざと壊した箇所・未コミットの直しが混ざる。
   C の一般形。切り出し先: 1 と同じ rule の同じ項の近くに 1 行

却下:

- D: 既にある `survey-receiver-guards-before-passing-new-values.md` の項がそのまま当てはまる。新しい起こし方で起こすときは、起動時に挙動を分けている条件を grep で挙げる、という項。
  発動点を踏み損ねただけなので、規範は足さない
- E: 局所的なこと (Go のインライン展開の予算)。理由と測った値は `src/ja-writing/internal/pyunicode/pyunicode.go` の `inRanges` のコメントに書いた
