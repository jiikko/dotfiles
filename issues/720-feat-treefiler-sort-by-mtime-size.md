# 720 (feat): treefiler の並び替えを選べるようにする (名前・更新の新しさ・大きさ・逆順)

起票日: 2026-10-12

## 概要

今の並びは名前順だけ (Folders first・Natural sort の切り替えはある)。更新の新しい順・大きい順・逆順を選べるようにする
(ユーザーの選択 2026-10-12)。spec では「ソートは後回し」にしていたもの (`docs/treefiler-spec.md` §0.1 の表・§0.5・§5.6)。

## 仕様 (案)

- 設定の板 (`,`) の ORDER に `Sort by` (name / modified / size) と `Reverse` を足す。保存する (`~/.config/...` の設定ファイル。他の項目と同じ)
- キーで切り替えるなら `S` で Sort by を巡回 (🚨 推奨で、ユーザー未確認。`s` はシェル)
- modified / size はフォルダにも効く。フォルダの「新しさ」「大きさ」は裏の走査 (`walk.go`) の結果 (配下でいちばん新しい更新・合計の大きさ) を使うか、
  フォルダ自身の mtime / 0 を使うかを決める (走査の結果は遅れて届くので、届くたびに並びが動く。動かすなら動きとして見せる)
- Folders first は Sort by と組み合わせる (フォルダを上に置いた上で、それぞれを Sort by で並べる)

## 対応方針

- 並びは `tree.go` の `sortKids` が持つ (今は `foldersFirst` と `natural` の 2 引数)。比べ方を 1 つの関数にまとめてから Sort by を足す
- 🚨 issue 712 の仮想化と関係する: 並び替えは見せる子の覚えを作り直し (`kids.go`)、巨大なフォルダでは 0.6 秒全部を動かす期間に入る
  (`virt.go` の `noteGeo`)。裏の走査の結果が届くたびに並びが変わる形にすると、巨大なフォルダで毎回この期間に入るので、届いたときの並べ直しを
  間引くか、modified / size のフォルダには走査の結果を使わないかを決める (等価性のテスト `filer/virt_test.go` に並び替えを足し、
  `TREEFILER_VIRT_SEEDS=300` でも回す)
- 設定の項目を足したら、設定の板のテスト (`settings_test.go`) と保存の往復を足す

## 受け入れ条件

- [ ] 4 つの並び (name / modified / size / reverse) が設定の板とキーで切り替わり、保存される
- [ ] 巨大なフォルダで並び替えた後も、仮想化の等価性のテストが通る
- [ ] spec の「ソートは後回し」の記述を直す
