# 800 (research): 複数の Mac に同時に高性能モードで繋げるか

起票日: 2026-10-16

> epic 793 の子。要望の 5 つ目。自作する意味が一番大きく変わる問い。

## 要望 (ユーザーの言)

「ハイパフォーマンスに接続できる mac が 1 台だけで制限が多い」

## 調べたこと (2026-10-16)

- Apple:「Only one High Performance screen sharing session can be active on each Mac at a time.」
  ([Apple](https://support.apple.com/guide/remote-desktop/apdf8e09f5a9/mac))。「各 Mac」なので見る側にもかかり、標準アプリでは 2 台に同時に
  高性能で繋げない
- この制限が、見る側のアプリ (Screen Sharing.app) の中の制限か、相手の Mac が断る形かは、文書から分からない
- iShareScreen と rootshell-vnc の README には、複数のセッションについての記述が無い

## 確かめること

- [ ] 手元の Mac から、rootshell-vnc のビューア (か iShareScreen) を 2 本起こし、別々の 2 台へ同時に高性能モードで繋ぐ。2 本とも映像が流れるか
- [ ] 繋がらない場合、どちらが断ったか (相手の Mac のログ・制御の TCP の応答)
- [ ] 2 本目が繋がったとき、1 本目が切られないか (見る側の Mac で標準アプリが同時に動いていないことも確かめる)
- [ ] 2 本同時のときの帯域と手元の復号の負荷 (VideoToolbox の HEVC の復号を 2 本並べられるか)

## 結果で決まること

- 繋げる → 自作の意味がある。798 の常時接続を複数台で組む
- 繋げない (相手側が断るのではなく、手元の何かが止める) → 何が止めているかを調べる
- 繋げない (仕組みとして 1 本) → 高性能は 1 台だけにし、残りは標準の画面共有 (VNC) で繋いでおく形を考える。または 795 の系統 2
  (相手に自作のサーバを置く) を検討する
