# 805 (design): Claude Code がこの GUI アプリを自分で動かして確かめ、直せる経路 (PDCA の C を閉じる)

起票日: 2026-10-16

> epic 793 の子。作り始める前 (段 2 の前) に決める。作る順番は 802。

## 要望 (ユーザーの言 2026-10-16)

「画面共有は GUI で、Claude Code からどうすれば、デバッグがしやすいのかみたいなことを考える issue md を作成して。できれば Claude が PDCA する C ができる環境・経路を作りたい」

## 不変条件

- **Claude が、人の目を借りずに「直した結果を確かめる」(C) を回せる**。確かめた証拠は文字 (JSON・ログ) か画像のファイルで残り、Claude が読める
- 人の手が要る確かめ (見た目の好み・実物のキーボードでの手触り) は、それと分かる形で人に回す (human issue)。Claude の C に混ぜない
- 確かめ方はその場で考えない。repo の verify の入口 (Makefile の target) だけを叩く (`_claude/rules/no-osascript-for-ui-verification.md` の「確認方法を考えさせない」)

## 経路の案 (安い順。どれも作る前の案)

| # | 経路 | Claude が確かめられること | 前例・根拠 |
|---|---|---|---|
| 1 | **画面を出さない CLI** (アプリと同じ芯を使う別の実行ファイル): `<app> probe --host <Mac> --frames 300 --json` で繋ぎ、受けたコマ数・fps・復号の時間・遅延・モード・帯域を JSON で出して終わる | 接続・認証・高性能か標準か・復号が回るか・性能の数値 | mac-lan-manager の `dump` / `dump --peer` (画面を出さずに、画面と同じ判定を文字で出す) |
| 2 | **構造化したログ** (`os_log` の subsystem を決め、状態の遷移・モードの切り替え・再接続・落としたコマを出す)。`log stream --predicate 'subsystem == "…"'` で読む | 何が起きた順番 (状態の遷移) | `_claude/rules/instrument-before-second-fix.md` の観測の表 (print でなく os_log) |
| 3 | **デバッグ用の口** (debug ビルドだけ。ローカルの Unix ソケットか localhost の HTTP): 状態を読む (セッション・モード・ウインドウの大きさ・見えているか・fps) / 操作を起こす (繋ぐ・切り替える・別ウインドウにする・隠す) | GUI の状態を、画面を見ずに読む。操作の後の状態の変化 | ユーザーの他のアプリの API モード (`bin/tt-client`。perf-analysis の skill の前提) と同じ形 |
| 4 | **自分のウインドウの画像を書き出す** (デバッグの口から): アプリが自分の view を PNG にする (`NSView` の `cacheDisplay` など)。画面収録の許可は要らない見込み (未確認) | 見た目 (Claude が画像を Read する)。レイアウトの崩れ・状態の表示 | XCUITest の attachment と並べる |
| 5 | **XCUITest** (`xcodebuild test`。macOS のアプリなので Claude が回してよい): `accessibilityIdentifier` を振り、一覧・登録・詳細・別ウインドウの操作と状態の変化を assert する | UI の流れ (ボタン・切り替え・ウインドウの出し入れ) | `no-osascript-for-ui-verification.md` の標準手順 |
| 6 | **遅延を自動で測る**: ssh の副経路 (801) で相手の Mac に目印 (時刻を埋めた色の四角など) を出させ、手元のアプリが受けたコマで目印を見つけた時刻との差を出す | 相手が描いてから手元に届くまでの遅延 (画面の外のカメラを使わずに)。803 の負荷対策の前後の比較 | 800 の「体感の遅延は測っていない」を機械で埋める |
| 7 | **偽の相手** (標準モードだけ): 手元で動く VNC のサーバ (libvncserver などで作る) を相手にして、本物の Mac なしで標準モードの流れを回す。高性能モードは Apple の相手でしか試せない (偽物は作れない見込み) | 標準モードの接続・再接続・負荷対策のテスト | CI でも回せる |

- 段 2 (1 台に繋ぐ芯) を作るときに 1・2 を同時に入れる。3〜6 は段 3 から、使い勝手を作りながら足す

## Claude が触ってよい相手の Mac を決める

- 本物の相手で確かめる経路 (1・3・6) は、相手の Mac の画面を暗くする・高性能の枠を取る。ユーザーが使っている Mac を Claude が勝手に使うと邪魔になる
- **試験に使う Mac を 1 台決め** (例: 普段は使っていない Mac)、Claude が繋いでよいのはその Mac だけにする。台帳 (747) か設定に印を付け、CLI は印の無い Mac を断る
- 高性能の枠を取り合わない: 試験の間、ユーザーの標準アプリが高性能で繋いでいる相手には繋がない

## 権限で止まらないようにする

- 画面収録・アクセシビリティ・ローカルネットワークの許可は、初回に人が 1 回だけ許可する。**ビルドのたびに許可が外れない署名にする**
  (手元の ad-hoc 署名はビルドごとにアプリの同一性が変わり、許可を付け直す手間が出うる。未確認。Apple Development の証明書で毎回同じ署名にする)
- 許可が無いときに黙って空の結果を返さない。CLI とデバッグの口は「許可が無い」を判定できない結果として返す
  (`_claude/rules/verify-execution-not-just-exit-code.md`: 走らなかったことを成功に数えない)

## 人に回すもの (Claude の C に入れない)

- 実物のキーボードでの手触り: 手元の macOS が ctrl+→ を取るか (799)。合成したキーのイベントは、実物のキーと同じ経路を通るとは限らない
- 見た目の好み・色・並べ方 (モックで決める。`decide-layout-in-sample-renderer-first.md`)
- 体感の遅延の最終判断 (6 の数値は判断の材料)
