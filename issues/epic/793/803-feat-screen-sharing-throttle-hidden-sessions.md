# 803 (feat): 見えていない画面の負荷を下げる (隠れている間は frame rate を落とす)

起票日: 2026-10-16

> epic 793 の子。常時接続 (798) と、触っている Mac だけ高性能にする案 (800) と組み合わせる。

## 要望 (ユーザーの言 2026-10-16)

「複数の mac を接続しているが、接続しているときは常に 100% の高性能ではなくて、画面が隠れているときは framerate を下げるみたいな負荷対策をやってね」

## 不変条件

- **見えていない画面のために、手元の CPU・GPU・網と、相手の Mac の符号化を使い続けない**
- 見えるようになったら、待たずに今の画面が出る (798 の受け入れ条件「選んでから 0.5 秒以内」を壊さない)

## 状態ごとの落とし方 (案。どれも未実測)

| 手元のウインドウの状態 | 描画 | 復号 | 受信・相手の符号化 |
|---|---|---|---|
| 前面で見えている | 全速 | 全速 | 全速 (高性能なら最大) |
| 見えているが前面でない (別ウインドウ・横に並べた) | 落とす (例: 10 fps) | 必要な分だけ | 落とせるなら落とす |
| 隠れている (他のウインドウの下・最小化・別の操作スペース) | 止める | 止めるか、要所のコマだけ | 落とす / 止める |
| 手元の画面が眠っている・ロック中 | 止める | 止める | 止める (繋がりだけ保つ) |

- 見えているかの判定: `NSWindow.occlusionState` (`.visible`) と、アプリが前面か (`NSApplication.isActive`)、画面の眠り
  (`NSWorkspace.screensDidSleepNotification`)。どれも公開 API で、sandbox でも使える見込み (未確認)
- 一覧 B の縮小画面 (モック) は「見えているが小さい」状態。縮小に要るだけの低い frame rate で足りる

## モードごとに、落とせる手段が違う

- **標準モード (VNC)**: 手元が「次のコマをくれ」と頼む形 (RFB の FramebufferUpdateRequest。RFC 6143 §7.5.3)。頼む間隔を空ければ、
  受信も相手の符号化も減る。止めたければ頼まない。手元だけで決められる
- **高性能モード**: 相手が送り続ける形 (UDP)。手元から frame rate や画質を下げるよう頼めるかは未確認 (rootshell-vnc の `.adaptive` や RTCP の
  帯域の知らせで下がるかを調べる)。頼めないなら、手元で描画と復号を止めるだけになり、網と相手の符号化は減らない。
  その場合は、隠れたら標準に落とす (800 の「触っている Mac だけ高性能」と同じ仕組み) のが網と相手の負荷を減らす手になる
- HEVC は前のコマとの差分で送るので、復号だけ途中を飛ばすことはできない。復号を止めたら、見えるようになったときに全体のコマ (IDR) を
  頼み直す必要がある (iShareScreen には IDR を頼み直すキーがある。README の「f to force an IDR refresh」)。その待ち時間が 0.5 秒に収まるかを測る

## 確かめること

- [ ] 高性能モードで、手元から frame rate・帯域を下げるよう頼めるか
- [ ] 隠れた間に復号を止め、見えたときに IDR を頼み直して画面が出るまでの時間
- [ ] 状態ごとの手元の CPU・GPU・網の実測 (3 台を繋いだまま、1 台だけ前面のとき。落とす前と後)
- [ ] 隠れたと判定してから落とすまでの待ち (すぐ落とすと、一瞬隠れただけで落ちて戻すのを繰り返す)

## 受け入れ条件

- 3 台を繋ぎ、1 台だけ前面にしたとき、隠れている 2 台の分の手元の CPU と受信量が、前面の 1 台より十分小さい (数値は 1 台目が動いてから実測して決める)
- 隠れていた画面を前へ出すと 0.5 秒以内に今の画面が出る (798)
