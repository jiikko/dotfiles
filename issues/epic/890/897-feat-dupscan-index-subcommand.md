# 897 (feat): dupscan の探索のための索引 (似たメソッドの量産を書く前に止める)

起票日: 2026-10-24

## 概要

[891 (要件の正本)](891-design-dupscan-requirements.md) の「索引」節: repo の単位を 1 行 1 件で (名前と署名・場所・test / prod・ターゲット・可視性・doc comment の 1 行目・呼び出し元の数)。
既定は全部の単位 (テスト関数は除く)。共通の置き場所にあるものを先に並べ、private なものは寄せる候補として区別する。
重複のチェックと同じ単位の一覧から作る。commit して置く使い方なら、生成し直した結果との差分を検査で落とせる形にする。

この索引は、Claude Code の編集の最中に効かせる hook ([902](902-feat-dupscan-claude-code-hook.md)) の比べる相手にもなる。hook は編集のたびに引くので、
索引をキャッシュして読み込みを速くし、編集されたファイルの分だけ差し替えられる形にする。索引は**名前・署名の型 (戻り値・引数の型)・doc 文で引ける**ようにする。LSP は使わない (ユーザー決定 2026-10-24: dupscan だけで依存も使い方もシンプルになるなら LSP は使わない)ので、名前の検索もこの索引でまかなう
(1 行 1 件のテキストなので grep でも引ける)。書く前には本体が無いので、本体の形では引けない。依存を増やさないため、ctags などの別の道具も足さず dupscan だけで出す。

## 受け入れ条件

- [ ] 索引: `bin/dupscan` の別の subcommand (例 `index`) で、上の 1 行 1 件の一覧が出る。obaket の `SharedTestSupport` に当てて、
      `bucketLocation(path:)` を含む全部の top-level の関数が載ることをテストで確かめる
- [ ] 生成し直した結果との差分で落とす使い方 (`--check` など) の動き

- 2026-10-24 LSP を使わないことにしたので、名前の検索も索引でまかなう形にした。初版を既存の道具で作る案は、依存を増やすので採らない
