# 897 (feat): dupscan の探索のための索引 (似たメソッドの量産を書く前に止める)

起票日: 2026-10-24

## 概要

[891 (要件の正本)](../891-design-dupscan-requirements.md) の「索引」節: repo の単位を 1 行 1 件で (名前と署名・場所・test / prod・ターゲット・可視性・doc comment の 1 行目・呼び出し元の数)。
既定は全部の単位 (テスト関数は除く)。共通の置き場所にあるものを先に並べ、private なものは寄せる候補として区別する。
重複のチェックと同じ単位の一覧から作る。commit して置く使い方なら、生成し直した結果との差分を検査で落とせる形にする。

この索引は、実装中にメソッドを定義するたびに Claude が気軽に引く (ユーザー 2026-10-24: 適宜参照するくらいカジュアルに使ってほしい。[903](903-docs-dupscan-search-before-write-procedure.md))。そのため、1 回の引きが安いことを要件にする:
変わったファイルだけ作り直し (中身のハッシュで判定)、引く結果は上位の数件に絞って短く出す (並べ方: 引いた型・語との一致の強さ → 共通の置き場所にあるもの → 呼び出し元の数の多いもの)。`gate` ([905](../905-feat-dupscan-ci-check-gate.md)) と同じ単位の一覧を使う。
単位の一覧 (本体の形のハッシュも持つ) をキャッシュして読み込みを速くし、編集されたファイルの分だけ差し替えられる形にする。1 行 1 件の索引はそこから出す。索引は**名前・署名の型 (戻り値・引数の型)・doc 文で引ける**ようにする。LSP は使わない (ユーザー決定 2026-10-24: dupscan だけで依存も使い方もシンプルになるなら LSP は使わない)ので、名前の検索もこの索引でまかなう
(1 行 1 件のテキストなので grep でも引ける)。書く前には本体が無いので、本体の形では引けない。依存を増やさないため、ctags などの別の道具も足さず dupscan だけで出す。

## 受け入れ条件

- [x] 索引: `bin/dupscan` の別の subcommand (例 `index`) で、上の 1 行 1 件の一覧が出る。obaket の `SharedTestSupport` (共通の置き場所として設定で指す) に当てて、
      `bucketLocation(path:)` を含む全部の top-level の関数が載ることをテストで確かめる
- [x] ~~生成し直した結果との差分で落とす使い方 (`--check` など) の動き~~ 作らない (2026-10-25 の進捗。索引を commit して置かないので不要)
- [x] 名前の一部・署名の型 (例: 戻り値が `StorageLocation`)・doc 文の語のそれぞれで、PR 24 の共通のヘルパーが引けることをテストで確かめる (名前の検索を LSP に頼らないので、ここで守る)
- [x] 1 回の引きの所要 (変わったファイルの作り直しを含む) を obaket と DualNoteApp の規模で測る。所要の目安を決め (例: 1 秒以内。実測を見てユーザーと決める)、超えるなら作り直しの単位か保存の形を見直す
- [x] 鮮度: 書く前に引く時点で索引が古いときの扱いを決める (引くたびに変わったファイルだけ作り直すか、古いと分かる印を出すか) と、作り直しの所要を測る
- [x] 呼び出し元の数・所属ターゲットなど近似の値に、近似の印を付ける ([896](896-feat-dupscan-report-output.md) と同じ表し方)
