# 919 (feat): dupscan の除外のプリセット (形で外す: L2 の 1 文の委譲・並べたクロージャ)

起票日: 2026-10-25

## 概要

obaket に gate を組み込む前の流し直し (obaket の issue 1301 の段階 1) で、新しい既定 (下限 20 節・L1/L2。898) でも 100 commit 中 6 commit が赤になった。止めた単位を読むと、3 つの形に分かれた:

| 形 | 例 (obaket) | 段 | 扱い |
|---|---|---|---|
| 同じ呼び出しに違う定数を渡すだけの 1 文の委譲 | `makeTemporaryFile(contents:)` = `try TestScratchDirectory.makeFile(prefix: "<ファイルごとの名前>", contents: contents)` (6 つ)・UserDefaults の fake の `init() { super.init(suiteName: "<名前>.\(UUID())")! }` (3 つ) | L2 | **プリセットで外す**。寄せるには定数を引数にするしかなく、それは呼んでいる関数そのもの |
| 同じ呼び出しの引数に並べたクロージャ (コールバックの表) | `ConnectionStateReleaseCallbacks(moveIntent: { … record("release.move…") … }, transferIntent: { … }, …)` の 3 つ | L2 | **プリセットで外す**。表の行どうしで、違いは文字列のリテラルだけ |
| テストの fake が protocol を満たすメソッド | `save(_ connection:)`・`events() -> AsyncStream<Void>`・`allIntents()`・`discard(intentID:)` | L1 | **外さない**。fake の実装の写しで、共通の fake (`InMemoryConnectionRepository` など) に寄せられる。寄せる側の信号として残す |

ユーザー 2026-10-25: obaket の実装から、除外プリセットを足す必要があったら作っていい。

## 設計 (反証レビューの後に絞った版)

- `.dupscan.json` の `exclude` に 4 つ目の形 `{"preset": "<名前>", "kind": "...", "reason": "..."}` を足す。`kind`・`reason` は他の除外と同じく必須。
  何も消さなければ「効いていない除外」に出る・gate では base の設定に無いプリセットは「新しく足された除外」(要素 `preset:<名前>`) に出て `-fail-new-exclusions` で rc=1・`-no-exclude` で外せる
- プリセットは **組の除外** として効かせる (`exclude.Set.GroupExcluded`)。report・gate・near は既にこの関数を通るので、3 つに同じ判定が効く
- プリセットは 1 つだけ: **`l2-single-call`**。段が L2 の組で、次の両方を満たすときだけ消す
  - メンバー全員が「1 つの呼び出しの委譲」: 本体が 1 文で、その文が呼び出し 1 つ (`return`・`try`・`await`・後置の `!` で包んでよい)。後置のクロージャが無く、引数が全部「原子」
    (リテラル・名前・メンバーの参照 (`a.b`・`.bucket`)・原子だけを埋め込んだ文字列・引数の無い呼び出し (`UUID()`)・それらの `!` / `try` / `await`)。
    判定は adapter が単位に入れる (`tree.Unit.Delegation`。コアは言語の節の種類を知らない)
  - メンバーの L1 のハッシュが全部違う (定数まで同じ写しを 1 つでも含む組には効かせない)
- gate では、プリセットが消した組のうち、除外が無ければ違反だった組の「新しい」単位を **プリセットで通した変わった単位** として 1 行目と JSON に件数と一覧で出す (パスの除外の `PathPassed` と同じ扱い)。
  `-fail-new-exclusions` でも止めない (止めると CI でプリセットの意味が無い)。プリセットそのものを足した変更は「新しく足された除外」で止まる
- **不変条件の例外**: `exclude` の冒頭の「除外は書いたときにあった単位にだけ効く」に、プリセットは当てはまらない (形で将来の単位も覆う)。覆えるのは「違う定数を渡す 1 行の呼び出し」だけに絞り、通した数を毎回出す

### 反証レビュー (設計。codex・読み取りのみ) で落とした案

- **「1 文」で判定する案**: 1 つの巨大な式 (`return x * 3 + … - 23`) や `guard … else { 処理を 5 つ }` の 1 文の写しが、定数を変えるだけで素通りする (P1)。→ 呼び出し 1 つで、引数が原子のものに絞った
- **「L1 で止まる」の前提**: gate は「違反になった最初の段」で打ち切るので、L1 の組では違反にならず (全員が同じ出どころ)、L2 で初めて違反になる写しをプリセットが消す (P1。`gate_test.go` の既存の経路)。→ L1 のハッシュが全部違う組だけに効かせる
- **`l2-sibling-closures` (同じ単位の中のクロージャ)**: Owner が同じでも、同じ呼び出しに並べたクロージャとは限らない (同じ関数の中の別の登録に写した複数文のクロージャも消える。P1)。
  同じ呼び出しに絞っても、表の行として任意の処理を写せる。obaket の 100 commit で効いたのは 1 回だけなので**作らない**。**再開の条件**: 並べたクロージャの組が gate を繰り返し止める事例が出たとき
- **通した単位が見えない**: 組の除外の経路は違反を消すだけで、パスの除外のように通した単位を記録しない (P2)。→ 通した単位を出す
