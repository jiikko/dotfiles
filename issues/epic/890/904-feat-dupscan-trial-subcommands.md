# 904 (feat): dupscan を人が試す入口 (near・explain・hook の空打ち)

起票日: 2026-10-24

## 概要

dupscan は、主に Claude Code の編集の最中に hook から呼ばれる ([902](902-feat-dupscan-claude-code-hook.md))。人が日常的に使う道具ではないが、
**動作確認として「何ができるか・なぜ同じと判定したか」を人が手で試せる入口**が要る (ユーザー 2026-10-24)。
重複の報告 ([896](896-feat-dupscan-report-output.md)) と索引 ([897](897-feat-dupscan-index-subcommand.md)) は repo 全体を相手にするので、
1 つの関数を指して試す入口を 3 つ足す。どれもコア (893・894) と同じ単位の一覧の上に載せ、判定の実装を別に持たない。

| subcommand (名前は仮) | 入力 | 出力 | 何を確かめるか |
|---|---|---|---|
| `dupscan near <file>:<関数名>` (`<file>:<行>` も可) | 1 つの単位 | その単位に近い既存の単位を、一致した段 (Type-2 の L1 / L2 / L3) ごとに並べる。リテラルの違いの表も付ける | 「この関数に似たものは既にあるか」 |
| `dupscan explain <file>:<関数名>` | 1 つの単位 | 段ごとに潰した形 (L1 の番号付けの後・L2 のリテラルの記号化の後・L3 の畳み込みの後) と各段のハッシュ。読めない構文や下限で外れたなら、その理由 | 「なぜ同じ / 違うと判定したか」。閾値や正規化を直すときの手がかりにもなる |
| `dupscan hook --dry-run <file>` | 編集した後のファイル (Claude Code の hook の入力を真似る) | hook が additionalContext で返す文をそのまま表示する。編集はしない | 「Claude が編集したら、何を知らされるか」 |

- 出力は人が読む形を既定にし、`--json` も出す (テストと、Claude が読むとき用)
- `near` と `hook --dry-run` は、hook と同じ照合の関数を呼ぶ (人が試した結果と、Claude が受け取る結果が食い違わないように)
- 単位を名前で指したとき、同じファイルに同名の単位が複数あれば (overload など) 候補を列挙して止める (黙って片方を選ばない)
