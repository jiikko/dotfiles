# 896 (feat): dupscan の出力 (人が読む形・JSON・共通化の判断の材料)

> 🚨 **担当中: kojiM3MBP (glogx)**（2026-10-24〜）

起票日: 2026-10-24

## 概要

[891 (要件の正本)](891-design-dupscan-requirements.md) の「出力」節: 組ごとのメンバー (ファイル:行・関数名・test / prod・所属ターゲット (複数の値)・可視性・呼び出し元の数)・ノード数・段・類似度、
メンバー間のリテラルの違いの表 (プロパティの初期値を 1 段解決)、既にある共通のヘルパーと同じ組の区別。

呼び出し元の数・プロパティの値・所属ターゲットは LSP を使わずに構文木から出す (ユーザー決定 2026-10-24: dupscan だけで依存も使い方もシンプルになるなら LSP は使わない)。正確に決まらないものは近似と分かる形で出す
(呼び出し元の数は、名前と引数ラベルが一致する呼び出しの数。別の型の同名のメソッドも数えうる)。

## 受け入れ条件

- [x] `bin/dupscan <repo>` で、test / prod を分けた組の一覧が出る (人が読む形と `--json`)
- [x] `--format xcode` で、Xcode / SwiftLint と同じ `ファイル:行:列: warning: …` の形式でも出せる。組は、寄せる側の単位 (報告では組の先頭のメンバー) を `warning:` の 1 行にし、残りのメンバーを `note:` の行で続ける。
      パスは絶対パス、列は単位の宣言の先頭、メッセージの末尾に段を `(dupscan.L1)` の形で付ける (swiftlint と並べて回し、Xcode の警告として見せるため。891 の「SwiftLint のルールにしない」)
- [x] 出力のユニットテスト (adapter に依存しない)
- [x] ~~PR 24 の 6 つで、プロパティから値を読む 2 つの初期値が解決されてリテラルの違いの表に出る~~ 保留にして [918](pending/918-feat-dupscan-target-and-literal-table.md) へ移した
- [x] 近似の値 (呼び出し元の数・1 段だけ解決したプロパティの値・所属ターゲット) に、人が読む形と JSON の両方で近似の印が付く (JSON は欄で区別する)
