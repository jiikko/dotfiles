# 895 (feat): dupscan の Type-3 (少し違う写し) の類似度と候補の絞り込み

起票日: 2026-10-24

> **保留** (2026-10-25)。obaket の開発やコードの走査で、L1〜L3 の一致では取れない「少し違う写し」が欲しくなったときに作る (ユーザー 2026-10-25: 必要性を評価できないので、一旦 pending にして、使う中で欲しい機能があったらその時に実装する)。

## 概要

[891 (要件の正本)](../891-design-dupscan-requirements.md) の「組にする」「候補の絞り込み」節。部分木のハッシュの多重集合 (大きさで重み付け) の重なりで類似度を測り、対 (か全員が互いに閾値を超える集まり) で出す。
祖先と子孫の対 (関数とその中のクロージャ) は出さない。obaket の規模 (関数と初期化子だけで約 2.2 万) で総当たりにならないよう、
大きさ k 以上の部分木ハッシュの転置索引か MinHash の LSH で候補を絞ってから比べる。

**後回し** (2026-10-24): 主な用途 (書く前に索引を引く 903 と、`make test` で落とす [905](../905-feat-dupscan-ci-check-gate.md)) では、Type-2 と L3 の一致で足りるかを先に見る (898 の「Claude に書かせた写し」の実測で確かめる)。
mizchi/similarity は木の編集距離 (TSED) で Type-3 を出しているので、着手するときは比べる ([901](../done/901-research-dupscan-existing-tools.md))。

## 受け入れ条件

- [ ] 類似度・推移的に束ねないこと・祖先と子孫を除くこと・候補の絞り込みのユニットテスト (adapter に依存しない)
- [ ] 候補の絞り込みで取りこぼさないこと (総当たりとの一致) を、小さな入力で確かめる
- [ ] obaket の全体での所要を測って書く
