# 906 (feat): 誤検知を除外する設定 (dupscan の除外の設定ファイル)

> 🚨 **担当中: kojiM3MBP (glogx)**（2026-10-25〜）

起票日: 2026-10-24

## 概要

類似メソッドの検出には誤検知 (false positive) が出る (ユーザー 2026-10-24)。典型は、L3 で本体全体が 1 記号に畳まれた自明な一致・
テストの表の形が似ているだけの関数・生成コード・意図して分けている写し。これを除外できる設定を持つ。
除外は、重複の報告 ([896](896-feat-dupscan-report-output.md))・`gate` ([905](905-feat-dupscan-ci-check-gate.md))・`near` ([904](904-feat-dupscan-trial-subcommands.md)) の全部に同じ規則で効かせ、判定の実装は 1 つにする。

## 除外の種類

| 種類 | 何を外すか | 書く場所 |
|---|---|---|
| 組の除外 | 誤検知と判断した特定の組 (この組は同じでない / 分けておく) | 設定ファイル。組のメンバーの鍵 (ファイル + 囲む型 + 名前・署名。名前の無いクロージャは囲む単位の鍵 + その中での出現の順番。それでも重なれば「名指しできない単位」として報告に出す) の集合と段で指す。行番号は使わない (行がずれても効くように)。**効くのは書いたメンバーの間の一致だけ**: 組に新しいメンバーが増えても、その新しいメンバーは除外されず、`gate` の違反と報告に出る (除外した組への新しい写しを黙って通さない)。その段より粗い段でも、同じメンバーの間は一致として扱わない |
| 単位の除外 | 特定の単位を、寄せる側の違反として出さない。**数には入れたまま** (905 の許可と同じ意味。古い単位に付けても、新しい写しの違反は消えない) | 単位の直前のコメント `dupscan:allow <種別> <理由>` (905 と同じ) か、設定ファイル |
| パスの除外 | 生成コード・vendor・fixture などのファイルを丸ごと | 設定ファイルの glob |
| 段の除外 | 特定のパスで、特定の段 (例: L3) を使わない | 設定ファイル (パスの glob + 段) |
| 下限・閾値 | 小さすぎる単位・自明な一致 | 設定ファイル。既定値は [898](898-test-dupscan-obaket-calibration.md) の実測で決める |

## 要件

- **理由と種別を必須にする**: どの除外にも理由と種別 (`false-positive` = 誤検知 / `intentional` = 意図して分けている写し) を書く。無い除外はエラーにする。種別は効果の測り方 (891) で誤検知の割合を数えるのに使う
- **古くなった除外を黙らせない**: 指している組・単位・パスがもう存在しない (改名・削除・寄せ終わった) 除外は、毎回の出力に「効いていない除外」として出す
- **新しく足された除外を見せる**: `gate` は、base から増えた除外を、違反とは別の一覧として出す (905 の許可と同じ扱い)。除外を足せば違反は消えるので、
  Claude が寄せる代わりに除外を書く抜け道になる。止める手段は人がその一覧を見ることだけ (コメントにも設定ファイルにも書き手は残らない)
- **除外を足す手間を小さくする**: 報告の各組に、組の除外に貼れる 1 行 (メンバーの鍵の集合と段) を添える。手で鍵を組み立てさせない
- **設定ファイル**: repo の root に 1 つ (名前と形式は決めること。Go の標準だけで読める JSON か、書きやすい YAML / TOML か。依存を増やさない方を優先する)。
  対象・test / prod の規則・共通のヘルパーの置き場所など、他の設定と同じファイルに置く
- **除外した結果も確かめられる**: `--no-exclude` で除外を外した結果を出せる (除外が正しいかを見直すため)

- 🚨 **クロージャの鍵は、囲む単位の中での出現の順番** (`…#closure3`)。前にクロージャを足すと後ろの鍵がずれ、組の除外が「効いていない除外」になる (敵対的レビュー 2026-10-24。未確認の指摘)。クロージャを指す除外は、鍵ではなく囲む単位 + 本体のハッシュで指すかを決める

## 設計 (2026-10-25。反証レビューを受けて改訂)

原則: **除外は、書いたときにあった単位にだけ効く**。止める手段は「新しく足された除外」を人が見ることだけなので、まだ無い単位を先回りで覆える形
(同じ鍵の写しを後から置く・同じ本体のクロージャを足す・glob の下に新しいファイルを作る) を作らない。

- **設定ファイル**: repo の root の `.dupscan.json`。Go 標準の `encoding/json` だけで読む (依存を増やさない。理由は `reason` に書く)。知らない欄はエラー

  ```json
  {
    "version": 1,
    "exclude": [
      {"paths": ["Generated/**"], "kind": "false-positive", "reason": "生成コード"},
      {"paths": ["**/*Tests.swift"], "levels": ["L3"], "kind": "false-positive", "reason": "テストの表の形が似ているだけ"},
      {"group": ["<釘>", "<釘>"], "level": "L2", "kind": "intentional", "reason": "iOS と macOS で分けておく"},
      {"unit": "<釘>", "kind": "intentional", "reason": "…"}
    ]
  }
  ```

  1 つの除外は `paths` / `group` / `unit` のどれか 1 つ。`levels` は `paths` とだけ組み、粗い側に閉じた集合 (`["L3"]` / `["L2","L3"]` / 全部) だけを受け付ける
  (`["L1"]` だけでは L2 の組として出るので効かない)。今の版で持つのは `exclude` だけ (下限・test の判定の上書きは後の版で足す。足すときは、
  `exclude` 以外の欄が base から変わったことも gate の注記に出す)
- **釘 (除外が単位を指す形)**: `<名前の付いた単位の鍵>@<L1 のハッシュの先頭 12 文字>`。名前の付いた単位の鍵は、関数・初期化子・property ならその鍵から
  多重定義の `#n` を除いたもの。クロージャは、囲む単位を名前の付いた単位までさかのぼった鍵 (途中のクロージャの出現の順番を入れない)
  - 釘には本体が入るので、行のずれ・クロージャの番号のずれ・多重定義の順番のずれでは外れず、本体を直すと外れる (直した写しは見直す対象)
  - **1 つの釘が 2 つ以上の単位に当たる除外は効かせない** (同じ囲む単位に同じ本体のクロージャを足すと、どちらを指すか決まらない)。「名指しできない除外」として出す
- **効き方** (判定は新しい `internal/exclude` の 1 か所にし、report と gate が同じ関数を呼ぶ):
  - パス: その単位を base と head の両方で読まなかったことにする (出どころにも使わない)。`levels` があれば、base と head の両方でその段の比べる対象から外す
  - 組 (段 lv): 組 G (段 lv'、lv ≤ lv') のメンバーが全部 1 つの組の除外の釘に当たれば G を出さない。1 つでも外れたメンバーがいれば G を出す
    (gate では判定もそのままで、外れたメンバーが寄せる側に出る)。組を出さないのは `dropNested` の後
  - 単位: report では組を出したまま、そのメンバーに「許可」の印を付ける。gate では寄せる側の付け替え (寄せる側が空なら触った単位を寄せる側にする)
    の後で、許可の単位を寄せる側から「同じ形」へ移し、寄せる側が空になった違反は出さない。出どころの数には入れたまま
  - **gate では、組・単位の除外は base に同じ釘の単位があったときだけ効く** (消えた写しの釘の場所に後から同じ写しを置いても覆わない)。
    base に無かった単位を覆うのは、その釘が「新しく足された除外」に出ているときだけ
  - 単位の直前のコメント `// dupscan:allow <種別> <理由>` は adapter (894) の変更が要るので、この issue の 2 段目にする
- **効いていない除外**: 除外を外して回したときに、その除外が実際に何も消していない (組を消していない・違反を消していない・パスが単位に当たらない) もの。
  起点の外を指す除外 (釘のファイル・glob が起点の外) は数えない。text は 1 行目の注記に件数、`-v` と json に一覧
- **gate の一覧** (rc は既定では変えない。`-fail-new-exclusions` で、新しく足された除外があれば rc=1 にできる。CI の人の目に届く経路):
  - 新しく足された除外: base の `.dupscan.json` に無く head にある**釘・glob・段の 1 つずつ** (除外の単位ではなく、増えた要素を出す。並べ替え・reason の直しは出さない)
  - パスの除外で比べなかった変わった単位の件数 (glob の下に新しいファイルを作って写しを置く形を、人が見られるように)
  - base の `.dupscan.json` が読めない・形が違うときは空とみなして注記する (壊れた設定を直す commit を通すため。空とみなすと除外は全部新しく見え、安全側)
- **判定不能**: head の `.dupscan.json` が読めない・形が違う・`kind` か `reason` が無いときは rc=2。`-no-exclude` は除外を全部外す (形の誤りは rc=2 のまま)
- **貼れる 1 行**: report の json の各組と text の `-v`、gate の違反の json と text の `-v` に、その組の釘を並べた組の除外の 1 行
  (`kind` と `reason` は空。空のまま貼ると読み込みでエラーになり、書き手に埋めさせる)。包みへ寄せた形の違反は、包み (同じ形の側) に単位の除外を付けても消えず、組の除外で外す
- `near` (904) は未実装。作るときに同じ `internal/exclude` を通す

## 受け入れ条件

- [ ] 組の除外を書いた組が報告・`gate`・`near` のどれにも出ず、除外を外す (`--no-exclude`) と出る
- [ ] 組のメンバーのファイルの中で行がずれても、組の除外が効き続ける
- [ ] 除外した組に新しいメンバーが増えると、その新しいメンバーだけが違反と報告に出る
- [ ] メンバーを改名した後、組の除外が「効いていない除外」として出る
- [ ] パスの除外・段の除外が効く。理由の無い除外はエラーになる
- [ ] `gate` が、base から増えた除外を別の一覧に出す
- [ ] 報告の各組に、組の除外に貼れる 1 行が付く
