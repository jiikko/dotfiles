# 905 (feat): CI で、新しく入った重複を落とす (dupscan check)

起票日: 2026-10-24

## 概要

ユーザー決定 (2026-10-24): **検出できる種類の重複 (Type-2 と L3 の一致) は、hook と CI で止めたい。ただし実行コスト次第**。
hook ([902](902-feat-dupscan-claude-code-hook.md)) は Claude Code の Edit / Write しか見ず、Bash での書き換えや人の手の変更は素通りする。
その抜け道を、commit を相手にする CI で止める。

- `dupscan check --base <ref>` (名前は仮): HEAD の全体を走査して組を作り、**base から HEAD までに新しく入った・変わった単位を 1 つ以上含む組**だけを違反にする。
  既にある重複 (base の時点で在った組) では落とさない (導入した日に全部を直さないと CI が赤のまま、にしない)
- 新しく入った・変わったの判定は 902 と同じ鍵 (ファイル + 名前・署名) で、base の単位の一覧と突き合わせる。file:line は鍵にしない
- **意図した写しを許す書き方**を hook と共通に持つ (例: 単位の直前のコメント `dupscan:allow <理由>`。理由の無い許可は違反にする)。置き方は [891](891-design-dupscan-requirements.md) の「決めること」
- 出力は 896 の組の形 (人が読む形と `--json`)。違反があれば非 0 で終わる。読めない構文で確かめられなかった単位は件数と場所を出し、黙って緑にしない
- CI の workflow は使う側の repo に置く (obaket は obaket issue 1298)。dupscan は command と、組み込みの例を README に持つ

## コスト (止めるかを決める材料。ユーザーが測った値を見て決める)

- CI の 1 回の所要: obaket の規模で、HEAD の全体の走査 + base の単位の一覧の作成。parse だけなら Swift 1626 ファイルで 5.0 秒 (891 の実測) だが、正規化・組分けを含む通しは未実測
- 誤検知の割合: 898 の obaket の実測。違反のたびに人か Claude が直すか許可を書くので、割合がそのまま手間になる
- 測った値で「止める」に見合わないとユーザーが判断したら、違反を落とさず報告だけにする (`--warn-only` 相当) に落とす

## 受け入れ条件

- [ ] obaket の PR 24 の前の木を base にし、6 つのうち 1 つを新しく足した commit で `check` が非 0 になる。足さない commit (無関係な変更) では 0
- [ ] base の時点で既に在った組だけでは落ちない
- [ ] 理由つきの許可を付けた写しでは落ちず、理由の無い許可では落ちる
- [ ] 読めない構文の単位を、件数と場所つきで報告する
- [ ] obaket の規模で 1 回の所要を測って書き、誤検知の割合 (898) と並べてユーザーに見せ、止めるか報告だけにするかの決定を書く
