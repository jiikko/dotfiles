# 905 (feat): make test と CI で、新しく入った重複を落とす (dupscan gate)

起票日: 2026-10-24

## 概要

ユーザー決定 (2026-10-24):
- **検出できる種類の重複 (Type-2 と L3 の一致) は止めたい。ただし実行コスト次第**
- **止める頻度は、編集のたびの hook ではなく、`make test` の中に dupscan を含める程度にする**

そこで、使う側の repo の `make test` に `dupscan gate` を組み込む。CI も `make test` を回すので、同じ検査が CI でも走る。
Claude は `make test` の失敗として受け取り、既存のメソッドへ寄せる。編集のたびの hook ([902](pending/902-feat-dupscan-claude-code-hook.md)) は保留にした。

## `dupscan gate` (名前は仮。897 の索引の `--check` と紛らわしくしないため `check` にしない)

- **比べる 2 つ**: base (下記) と、今の作業ツリー。作業ツリーは未コミットの変更と、ignore されていない untracked のファイルを含む
  (`git ls-files --cached --others --exclude-standard`。Claude が新しく作ったファイルや、Bash で書き換えたファイルもここで拾う)
- **違反の判定**: 段 (L1 / L2 / L3) ごとに、本体の形のハッシュが同じ単位の**数**を base と作業ツリーで数え、**作業ツリーで増えた組**を違反にする。
  - 移動・改名・署名の変更・コメントや整形の変更では数が変わらないので落ちない
  - 既存の写しを共通の置き場所へ寄せる作業では数が減るので落ちない
  - 既にある重複 (base の時点で在った組) では落ちない (導入した日に全部を直さないと赤のまま、にしない)
- **base**: 既定のブランチとの merge-base (`git merge-base HEAD origin/<既定のブランチ>`)。先端を base にすると、分岐した後に既定のブランチで変わった分がその変更のせいに見えるため。
  base の commit が手元に無い (CI の浅い clone など) ときは、黙って全部を「新しい」と数えずに、判定不能として非 0 で終わる。CI では取れる深さで fetch する
- **段ごとに止めるか知らせるかを選べる** (例: Type-2 の L1 / L2 は止め、誤検知の出やすい L3 は報告だけ)。既定は下の「コスト」の測定で決める
- **意図した写しの許可**: 新しく足した単位の直前のコメント `dupscan:allow <理由>` (書き方は決めること)。許可はその単位 1 つだけを外し、組全体は外さない。
  理由の無い許可は違反にする。**新しく足された許可は、違反とは別の一覧として毎回出す** (人がレビューで見られるように)
  - 🚨 失敗の出力が許可の書き方を案内すると、Claude は寄せるより安い方として許可を書いて通しうる。Claude が許可を書いてよいかは [891](891-design-dupscan-requirements.md) の「決めること」
- **対象**: test と prod の両方。テスト関数そのもの (Swift の `@Test` / `func test…`) は除く (891 の adapter)。test と prod にまたがる組も違反にするかは決めること
- **出力**: 896 の組の形 (人が読む形と `--json`)。違反があれば非 0。読めない構文で確かめられなかった単位は件数と場所を出し、黙って緑にしない
- **組み込みの例**: 使う側の repo の Makefile の `test` に足す例と、CI の fetch の深さの注意を README に書く (obaket の組み込みは obaket issue 1298)

## コスト (止めるかを決める材料。測った値をユーザーに見せて決める)

- **所要**: `make test` に足される秒数。base と作業ツリーの 2 回の走査が要る (parse だけなら obaket の Swift 1626 ファイルで 5.0 秒。891 の実測。正規化と組分けを含む通しは未実測)。
  base の単位の一覧は base の commit ごとにキャッシュできる (鍵は commit。中身が変わらない)
- **誤って止める割合**: obaket の過去の commit を N 本 (例: 直近 100 本) 流し直し、1 本ずつ親を base にして `gate` を回し、落ちた本数と、そのうち誤検知の本数を段ごとに数える。
  repo 全体の組の誤検知 (898) とは別の量で、こちらが「make test が誤って赤になる頻度」に当たる
- この 2 つを見て、ユーザーが段ごとに「止める / 報告だけ / 回さない」を決める

## 受け入れ条件

- [ ] obaket の PR 24 の前の木を base にし、6 つのうち 1 つを新しく足した作業ツリーで `gate` が非 0 になる。未コミットのまま・untracked の新しいファイルに足した場合も
- [ ] 否定: 既存の写しのファイルの移動・関数の改名・整形の変更では落ちない。既存の写しを 1 つ共通の置き場所へ寄せた変更で落ちない。base の時点で在った組だけでは落ちない
- [ ] 理由つきの許可を付けた単位では落ちず、理由の無い許可では落ちる。新しく足された許可が別の一覧に出る
- [ ] base の commit が無いとき、判定不能として非 0 で終わる
- [ ] 読めない構文の単位を、件数と場所つきで報告する
- [ ] 所要と、過去の commit の流し直しで数えた誤って止める割合を段ごとに書き、ユーザーの決定 (段ごとに止める / 報告だけ / 回さない) を書く
