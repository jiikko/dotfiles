## 新しい要望

### N1. 組のメンバーの本体を並べて見る

- 場面: 41 組それぞれで「本当に同じか・何が違うか」を読む必要があった。`-v` / JSON は名前と位置しか出さない。自作の python (`show.py`、約 10 行: JSON の file:line から本体を 20〜30 行切り出す) を約 10 回使った。
- 案: `dupscan show <組の番号>` (または `-v -body N`) で、各メンバーの本体の先頭 N 行を並べる。L2 の組は差のある行に印を付ける。
- **未確認**: Swift の `dupscan def <名前>` (本体つき) で足りたか。組のメンバーごとに名前を打つ手間があるので使わなかった。足りるなら、組の番号から `def` を引く入口だけでよい。

### N2. 除外の理由を書くときに、メンバー間の差を機械的に見せる

- 場面: 1308 と 1309 で、除外の理由文に**事実と違う記述**を計 6 件書いた (反証レビューが指摘): 「辞書の持ち方が suite ごとに違う」 (実際は同型)・「suite ごとの固定の接続 ID」 (実際は同じ `c1`)・
  「Core と Presentation の別 target」 (実際は macOS の ObaketTests も入っていた)・「bind と connect が違う」 (実際は `SO_NOSIGPIPE` の setsockopt) など。どれも、メンバーを読んで「違う」と書いたが、読み違えていた。
- 困りごと: 理由を書く瞬間に、メンバー間の違いを確かめる材料が dupscan の出力に無い。
- 案: 除外の 1 行を出すとき、メンバーの (a) 所属 target 一覧、(b) 本体の差の有無 (L1 は「リテラルまで同一」と明記、L2 は違うリテラルの一覧) を添える。「違う」と書く前に、違いが無いことが分かる。

### N3. 除外を書く・消す CLI

- 場面: 1308 で除外 11 + 削除 8、1309 で除外 8 + 削除 3。毎回 python で `.dupscan.json` を読み書きし、reason 文を埋めた。1309 では reason を入れた bash の heredoc が**バッククォートをコマンド置換して語が抜け**、3 件の理由が壊れた (気づいて直した)。
- 案: `dupscan exclude add <組の番号> --kind intentional --reason-file <file>` と `dupscan exclude prune` (効いていない除外を一覧して、確認のうえ消す)。理由をファイルで渡せばシェルの展開に巻き込まれない。整形は dupscan が揃える。
- 補足: これは dupscan の欠陥ではなく私の書き方の事故だが、「手で JSON を編集する」工程があるから起きた。
