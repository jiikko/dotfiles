# 981 (bug): Go の生成ファイルの見出しを付けた新しい写しが gate を無音で通る

> 🚨 **担当中: kojiM3MBP (glogx)**（2026-10-30〜）

起票日: 2026-10-30
優先度: 低 (発火には生成ファイルの見出しが要る。ただし通ったことが出力のどこにも出ない)

## 概要

Go の adapter は `// Code generated … DO NOT EDIT.` の見出しを持つファイルから単位も呼び出しも出さない (`internal/lang/golang/golang.go` の `Parser.Parse` の `ast.IsGenerated`)。
README の「分かっている限界」に書かれた仕様だが、**読まなかったファイルの数がどの出力にも出ない**ため、gate はそのファイルに入った新しい写しを「変わった単位 0」「新しい重複なし」rc=0 で通す。
「読めない構文のファイル」は 1 行目に数が出る (929・959) のに、生成ファイルとして読まなかったファイルは数も出ない。

## 再現 (2026-10-30、`bin/dupscan -no-build`、使い捨て repo)

1. `p/a.go` に 12 行の関数 `Sum` を書いて commit (base)
2. 同じ本体の `Sum2` を、先頭に `// Code generated by hand. DO NOT EDIT.` を付けた `p/gen.go` に足して commit
   - `dupscan gate -base <base> .` → `dupscan gate: 新しい重複なし (base …・変わった単位 0)` **rc=0**
3. 同じ本体の `Sum3` を見出し無しの `p/plain.go` に足して commit
   - 同じ gate → `新しい重複 1 (止める 1 …)` `新しい: p/plain.go:3-14 Sum3` **rc=1**

見出しは 1 行のコメントで、生成器を通さなくても書ける。

## 発火条件

- head で、Go のファイルに `ast.IsGenerated` が真になる見出し (`^// Code generated .* DO NOT EDIT\.$` の行がパッケージ句より前) があり、そのファイルに既存の単位と同じ形の関数がある
- 既に生成ファイルだったファイルを手で書き換えた場合も同じ (生成ファイルの手編集は読まれない)
- Swift の adapter には生成ファイルの判定が無い (言語で扱いが違う。Swift は全部比べる)

## 対応方針 (候補)

1. 生成ファイルとして読まなかったファイルを adapter が返し (`lang.FileResult` に印を 1 つ足す)、report / gate の 1 行目に数を出す (読めない構文のファイルと同じ扱い)。gate は「base で生成ファイルでなかった / base に無かった」ファイルの数を分けて出すと、見出しを付けて通した形が見える
2. 止める (rc=1) かは決めない: 本物の生成コード (stringer・protobuf) の追加で毎回赤くなるのは誤り。数を出すだけで「沈黙 = 成功」を外す
3. Swift との扱いの違いは README の限界に 1 行書く (既に Go 側は書いてある)
