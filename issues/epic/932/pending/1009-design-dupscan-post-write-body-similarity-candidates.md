## 欠けている前提 (これが揃うまで実装に進まない)

1. **雑音を止める手段**: `near -similar` は `dupscan:allow` も除外も見ない (`src/dupscan/similar_cmd.go` の Limitations: `clone exclusions are not applied`)。
   意図して残した組は毎回出て、読まれなくなる。別 module のテストの非公開 helper も 1.0 で出る (実例: `src/doctor/cmd/diskdoctor/exit_test.go:Write` → `svcdoctor/exit_test.go:70`、
   1.0000。A1 の hook は `reachable()` で別 module のテスト helper を除くが、near 側に相当が無い)。
   要るのは、allow・除外を近似の候補にも効かせることと、寄せられない組 (別 module のテスト・到達できない単位) を落とす規則
2. **循環しない測り方**: 946 の 21 件は「書かれた時点」の母集合ではなく、後から掘って寄せた過去の写し。測るなら、写しが**書かれた commit** を git の履歴から特定し
   (946 で寄せた組の各メンバーが入った commit)、その commit の木で、その commit で変わった単位を起点にして既存の側が出るかを数える。
   これで 988 の「dotfiles では写しが 0 件で測れない」も、obaket の checkout を待たずに外せる見込み (946 の 4 module は dotfiles の `src` にある)
3. **採否の基準を測る前に決める**: 例えば「書かれた commit の再生で、既知の写しの X 件以上が上位 3 件に出る」かつ
   「988 の直近 30 commit (変わった単位 358) で、候補が出た単位のうち無関係が Y 割以下」。X と Y を決めてから測る (後から数に合わせて基準を動かさない)

## 実装に進むなら決めること (前提が揃った後)

- 起点の指し方: `near` の `pick()` は同名が 2 つ以上あると失敗する (Go のメソッド・Swift のオーバーロード)。行番号で指す。書きかけで構文が壊れたファイルは `Unreadable` で失敗する。どちらも黙って無出力にしない
- N 個の起点を 1 回の走査で比べる入口 (今の `near` は 1 つずつで、1 回ごとに scope 全体を読む)
- 出す件数と下限 (near の既定 0.4、sweep の節 3 は 0.6)、テスト関数と testdata を比べるか (965 F1)、3 節未満の小さい単位は比べられない (`no useful comparison`。`padLeft` は候補 0)
- 記録: 候補を出したら、起点と候補の組を残す (A1 のログは `名前 候補数 引き方` だけで、後から精度を仕分けられない)
- 安い対照: gate の出力に、変わった単位ごとの `near -similar` の argv を添えるだけの形 (pull 型)。948 は pull 型は使われないと見ているが、比べる対照として先に置く

## 反証レビュー (2026-10-30、sonnet 2 体、読み取りのみ、観点は事実と設計)

最初の版は「書いた直後の hook で、書いた単位を近似照合して差し込む」を新しい案として出し、6 つの未解決をまとめて受けると書いていた。次の指摘で書き直した:

- 事実 P1 (採用): 「`near -similar` の全単位なら 18 件 (86%)」は誤り。946 の表では 86% は 3 手段の累計で、near 単独の新規は 5 件
- 事実 P1 (採用): 928 は「軽い通知 hook から自動 build を起こさない」「tool 呼び出しのたびに全 repo を走査しない」の方針で、A1 は撤去・変更しないと明記している。最初の版の「928 の決定を変えるか」の構図は不正確だった。
  あわせて、書いた直後の hook は **902 として既に起票され、ユーザー指示で保留**だった (依頼側の照合漏れ) → 実行の時点を `make test` / gate に戻した
- 事実 P2 (採用): 963 N2 は除外の行で既に argv を出している / 注入のログは .go / .swift だけで、このマシンでは標本 0 (948)
- 設計 P1 (採用): 雑音を止める手段が無い (allow・除外を見ない、別 module のテスト helper) / 946 の 21 件での再現率は循環する / 採否の基準が無い → 「欠けている前提」の 1〜3
- 設計 P2 (採用): 時間は 1 例で代表的でない (Swift 0.90 秒、N 個で N 倍) / 「名前にも型にも依らない」は言い過ぎ / 同名・構文エラーで黙って失敗する / ログに組が残らない
- 設計 P3 (採用): 安い対照 (gate の出力に argv を添える pull 型)
- 崩せなかった: 片方向でも Dice の値は対称 / 新しい単位が既存の写しなら既存の側を返す / 単独の照合は 0.3〜0.9 秒 / sweep は 8000 単位を超えると近似の節を飛ばすので差分版の代わりにならない / 「受けないもの」の分類
