# 451 (feat): カードを削除する (依頼の列はすぐ消す / 処理中は削除の依頼として PG を止めてから消す)

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-25): 「カードの削除処理も実装して。依頼レーンにあるなら即時削除でよくて、処理中の場合は、delete の依頼扱いみたいな感じ」。
今はカードを消す口が無い (完了のカードを画面から外す片付け `x` は 438 で、記録には残す。削除とは別)。

## 詳細 (期待する動作)

- **依頼の列のカード** (PG がまだ付いていない): すぐ消す。書き手は dispatcher だけ (426 の決定 1) なので、受付の箱に削除の依頼を置き、
  dispatcher が次の適用 (package wake ですぐ起きる) で消す。ユーザーから見て待たされない
- **処理中のカード** (分解済み・作業中・質問待ち・レビュー。PG の session が付いている / 付きうる): 削除の依頼としてカードに印を付けて受け、
  dispatcher がその PG の session を止め、止まったのを確かめてから消す (止め方と「止まった」の判定は 447 の閉じたカードの PG を止める部品と同じ。判定を 2 つ作らない)
- 削除の依頼が付いたカードには、新しく PG を起動・再開しない (テストの係の結果が届いても再開しない)
- 止められないとき: 447 と同じく上限の時間で諦めて、カードは消さずに残し、理由を履歴に書く (PG が動いたままカードだけ消えて見張れなくなる形を作らない)
- 🚨 PG の worktree とブランチは消さない (取り込み前の作業が入っている。消すかは別の判断)
- 消したことは出来事の記録 (444 の events.jsonl) に残す (記録からカードが消えても、いつ誰が消したかを後から追える)
- 口: CLI `pro-con card delete <カード>` と、画面のキー (キーは glogx の UI の決まり `docs/glogx-ui-guide.md` に合わせて選ぶ)。
  処理中のカードを画面から消すときは確認を挟む (PG を止めるので)。本物のモード (live) と模擬のモードの両方で同じ振る舞い

## 対応方針 (候補)

- 受付の箱に `delete` を足す。store の遷移: 依頼の列ならカードを外す / それ以外は削除の印 (447 の StopAfterClose と同じ形の印) を付ける
- dispatcher の Tick: 印の付いたカードの PG を止め、止まったのを確かめたら記録から外す (447 の stopClosed に寄せられるかを先に見る)

## 関連

- 447 (閉じたら PG を止める) / 438 (片付け `x`) / 444 (出来事の記録) / 427 の終了の保証
