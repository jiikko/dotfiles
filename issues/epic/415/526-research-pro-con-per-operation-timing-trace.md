# 526 (research): 操作ごとにどこで何秒かかったかを測る基盤 (画面・dispatcher・Claude Code 待ちの内訳) — アイディア

起票日: 2026-09-26

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼: 「ボトルネックを測定したいので、操作ごとにどのくらい時間がかかるか測定できる基盤を作りたい。カードが移動した・選択カードを移動した、カード操作全般。
もちろん Claude Code 待ちの処理もあるので、そこら辺の内訳がわかるように見たい。ログがいいのかな。とりまアイディアレベルで」。

**この issue はアイディアの段**。作り方を決めるのは、下の「決めること」を詰めてから。

## 今ある計測 (2026-09-26 に確かめた。重ねずに足す)

| 仕組み | 何を測るか | 足りない所 |
|---|---|---|
| `framelog.tsv` (`ui/framelog.go`。`framelog.on` を置くと書く。494) | 画面の 1 つのメッセージの処理 (`Update` / `View`) の時間 | 画面の中だけ。どの操作から始まったかと、その後の dispatcher・PG の時間につながらない |
| `events.jsonl` (`pro-con log`) | dispatcher が何を判断したか (時刻つき) | 時刻はあるが、ある操作の始まりと終わりを結ぶ印が無い |
| 516 のカードごとの記録 | カード 1 枚の列ごとの時間・人の番の時間・回数・枠 | カード単位で、1 回の操作 (選択の移動・並べ替え・回答) の内訳は見えない |

## アイディア: 操作ごとの「区間」を 1 本の記録に残す

- 人の操作 1 回 (キーを押した) と、dispatcher の出来事 1 つを「操作」として ID を振り、その操作が通る区間ごとに始まりと終わりの時刻を記録する (tracing の span の考え方)
- 区間の例 (操作 → 区間の並び):
  - **選択のカードを動かす (j / k)**: キー → `Update` → 描画 (`View`) → 端末に書き終わる。画面の中だけで閉じる
  - **カードの並べ替え (K / J)・回答・追加オーダー・新しい依頼**: キー → 受付の箱に置く → dispatcher が拾う (待ち) → 適用 → 画面が次の様子を読む → 描き直す
  - **カードの列の移動 (PM の plan・PG の review など)**: 受付の箱に置かれた → dispatcher の適用 → 画面に出た
  - **PG / PM / 取り込みの係の起動・再開**: dispatcher が決めた → `claude --bg` を起こす → session が立ち上がる → 最初の応答 → turn の終わり (**Claude Code 待ち**の内訳。枠の待ち・テストの係の順番待ちも区間にする)
  - **テストの係**: 頼まれた → 順番待ち → 走った → 要約 (haiku) → PG の再開
- 見る口: `pro-con trace [--since 10m] [--op <種類>]` で、操作の種類ごとに区間の中央値・最大・件数を並べる / 1 つの操作の区間を時間の帯で並べる (どこで待っていたかが一目で分かる形)
- 記録の置き場: 状態の置き場の `trace.jsonl` (1 行 1 区間: 操作の ID・種類・区間の名前・始まり・終わり・カード)。
  画面と dispatcher は別のプロセスなので、受付の箱の依頼に操作の ID を載せて渡す

## 決めること (アイディアを作りにする前に)

- **いつ記録するか**: いつも (軽い) か、`framelog.on` のように印を置いたときだけか。区間の数は操作 1 回に数個〜十数個。いつも書くなら量と保持の期限 (516 と同じ 90 日か、もっと短いか)
- **時計**: 画面と dispatcher は別のプロセス。同じマシンの壁時計で足りるか (足りる見込み。ずれは ms 以下)
- **Claude Code 待ちをどこまで割るか**: 外から見えるのは「起こした」「transcript に応答が出た」「turn が終わった」まで。モデルの中の時間 (考えている・道具を待っている) は transcript の時刻から出せるか
- **既にある計測との関係**: `framelog.tsv` を区間の記録に置き換えるか、並べて残すか。`events.jsonl` の出来事に操作の ID を足すだけで足りる部分は無いか (新しい記録を増やさずに済むならその方が安い)
- **見る口の見た目**: 表か、時間の帯の図か (見本を出して人に選んでもらう)
