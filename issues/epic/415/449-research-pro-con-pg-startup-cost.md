# 449 (research): PG を起動するコスト — カードごとに claude --bg を起こし直す形の実測

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

今の pro-con は、カード 1 枚ごとに新しい PG の session (`claude --bg`) を起動する。同じカードの再開 (回答・テストの結果・差し戻し) でも、
会話は続けるがプロセスは起こし直して session の ID が変わる。ユーザーが「新しいカードを消化するたびに PG を立ち上げ直すってこと?」と聞き、
その起動コストを測った (「起動コストを測って issue に書いて」)。PG を常駐させて使い回す形 (プール) に替える価値があるかの判断材料にする。

## 測り方

- 対象: 2026-09-25 の dogfooding の PG の transcript 10 本 (カード C-002〜C-006。新しい起動 5 / 再開 5)。
  置き場は `~/.claude/projects/-Users-koji-dotfiles--claude-worktrees-pc-c-00N/<session>.jsonl`
- 起動・再開の時刻: 状態の置き場の `cards.json` の履歴「PG を起動した / 再開した (session X)」の `At`
- トークン: 各応答の `message.usage` (`input_tokens` / `cache_creation_input_tokens` = キャッシュへの書き込み / `cache_read_input_tokens` = キャッシュからの読み / `output_tokens`)。
  同じ `message.id` の重複を除き、止めたときの `<synthetic>` の記録を除いた。再開の transcript は前の会話を写して持つので、再開の時刻より後の応答だけ数えた
- claude 2.1.282 / model claude-opus-5-5。PG の指示 (カードの依頼文) は 1 枚ごとに違う

## 分かったこと

1. **起動 1 回に固有のコストは小さい**。最初の応答まで 3〜8 秒 (うちプロセスが立って transcript に最初の記録が出るまで 1〜5 秒)。
   キャッシュへの書き込みは約 23.5k トークンで、残りはキャッシュから読んでいる。読んだ量は 24,645 (C-003 / C-004) と 26,601 (C-002 / C-005 / C-006) の
   2 種類で、PG どうしで先頭の一部を共有していると思われる (中身と 2 種類に分かれる理由は未確認)。起動の書き込み約 23.5k は、そのカードの書き込みの計の 18〜35%、
   読みを含めた入力の計の 0.3〜2.9% (カードが小さいほど比率が上がる: 応答 11 回の C-005 で 2.9%、59 回の C-002 で 0.3%)
2. **大きいのは起動ではなく、要求のたびに読み直す文脈**。各要求はそれまでの会話全体をキャッシュから読み直す
   (読み = 前の要求の読み + 前の要求の書き込み。C-004 で 20 回中 20 回成り立つ。C-002 の読みは 26,601 から 153,661 まで伸びる)。
   その先頭に毎回、最初の要求の約 48〜50k (CLAUDE.md・常時読まれる rules を含む) が同じ形で入っている。この先頭の分は、C-004 では
   21 回 × 約 48k ≈ 1.0M で読みの計 1.56M の約 65%、C-002 では 59 回 × 約 50k ≈ 2.95M で 7.04M の約 42%。残りはその session の会話の伸びの分。
   **PG を常駐させて使い回しても、先頭の分は減らない** (要求ごとに乗るため)。しかも同じ session で次のカードを続けると、
   前のカードの会話まで毎回読み直すので、読みはむしろ増える。減らすなら先頭そのもの (常時読まれる rules の量) を減らす
3. **再開はプロセスを起こし直しても、前の会話をほぼキャッシュから読む** (書き込み 163〜3,161)。
   1 回 (C-002) だけ 119k を書き直した (キャッシュに当たらなかった)。間隔は 5.7 分で、当たった回 (4.2〜5.5 分) と大差がない。**原因は未確認**
4. **利用枠への換算は未実測**。キャッシュの書き込み・読み・出力が 5 時間 / 週の枠をどの重みで減らすかを知らないので、トークン数の比較に留めた

## 判断材料 (ユーザーの判断待ち)

- プールで減らせるのは、カード 1 枚あたり 3〜8 秒と書き込み約 23.5k トークンだけ。代わりに、文脈が混ざる・worktree を切り替える・
  止める対象 (カードと session の 1 対 1) を別の仕組みで守る、が要る。**今の「カード 1 枚 = 新しい session」を続けるのを推す**
- 効くのはむしろ 2 の固定の文脈の方。PG に常時読ませる rules を減らす (PG 向けに `--setting-sources` などで絞る) 案は、
  PG が rules に従うこと (変異の確認・pathspec commit) と引き換えになるので別に検討する (未起票)
- 再評価の trigger: 応答が数回で終わる小さなカードが多数になったとき (起動の比率が上がる) / 再開でキャッシュに当たらない回が増えたとき

- 2 つの表の数字は C-002〜C-005 で一致 (C-006 は作業中で伸びている)
- 採った: 読みの仕組みの説明 (固定の文脈が乗るのではなく会話全体の読み直しで、その先頭に固定の文脈が入る) / 先頭の共有は 2 種類に分かれる
