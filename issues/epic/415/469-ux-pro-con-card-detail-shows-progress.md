## 概要

ユーザーの依頼 (2026-09-25): 「カードを開いたら、作業進捗を確認したい」。
今の詳細 (enter で開く引き出し。`src/pro-con/ui/drawer.go` の `drawerBody`) に出るのは、状態・担当・issue・依頼の原文・指示・質問・追加オーダー・履歴・出力の末尾 3 行だけで、
「どこまで進んだか・あと何が残っているか」が分からない。2026-09-25 の dogfooding では、PM (人間の代わりの Claude) が PG のブランチの log・`runs/` のテストの出力・
issue の本文の進捗を手で読んで確かめていた (440)。

## 期待する動作 (候補。載せるものと並びは見本で決める)

- **PG の作業**: ブランチの commit (master より先の本数と subject)・未 commit の変更の数・最後に commit / 出力した時刻
- **テスト**: どのディレクトリで走らせたか (2026-09-25 の C-011 は `src/pro-con` の `make test` = pro-con だけの `go test -race` を頼み、17 秒で rc=0。repo 全体の make test と見分けが付かなかった) と、テストの係に頼んだコマンドの状態 (順番待ち何番目 / 実行中の経過 / 終わった rc と所要時間)。出力の末尾の数行
- **issue の進捗**: カードの issue の本文の「進捗」節のチェックボックス (済み / 残り) と、残りの行
- **取り込みの見込み**: master と、ほかの作業中のカードとの取り込みの衝突 (`git merge-tree` で commit 済みの分だけ。468 の順番の指定とも合わせる)
- **今の待ち**: 何を待っているか (PG の turn の途中 / テスト / 利用枠 / 順番 (468) / 人の番 (452))
- 🚨 読むだけ: `--view` でも出す。集めるのは画面ではなく dispatcher か読む口の側にし、画面が 3 秒ごとに git やファイルを重く読まない (441 の「人間の画面を遅くしない」)
- CLI の `pro-con card show` にも同じ進捗を出す (PM と外の Claude が読む)
