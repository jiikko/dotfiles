# 452 (ux): 人間の操作を待っているカードに目印を付けて、一目で分かるようにする

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-25): 「人間アクション待ちなレーンには何かマークとか、わかりやすいようにしてほしい」。
今のボードは、人間が何かしないと先へ進まないカードと、PG / PM / テストの係が動いているカードが同じ見た目で並ぶ。

## 詳細

- 人間の操作を待っているカード (列) に目印を付け、ボードを見て「自分がやること」がすぐ分かるようにする
- 今の待ちの種類 (`src/pro-con/card/card.go` の `WaitKind`): `NeedsAnswer` は質問 (`WaitQuestion`)・権限プロンプト (`WaitPermission`)・
  落ち続けて止めた (`WaitCrashed`) を「人間か PM の操作が要る」とまとめているが、**相手が人間か PM かは区別していない**。
  437 (PM を起こす) が入ると、PG の質問は先に PM が受け、人間に回すものだけが人間の番になる。目印は「人間の番」に付ける
- 人間の番の候補: 質問待ちのうち人間に回したもの / 権限プロンプト (PM には答えられない) / 落ち続けて止めた / PM が居ないときの依頼・レビュー。
  どれを人間の番とするかを決めて本文に書く
- 列の見出し (例: 人間の番の件数) と、カード 1 枚ごとの目印の両方を考える。ゲージや通知 (ベル) に出すかも決める

## 対応方針 (候補)

- 🚨 見た目 (記号・色・位置) は本体に入れる前にサンプルで候補を並べて、ユーザーに選んでもらう (`decide-layout-in-sample-renderer-first.md`)。
  端末で幅が揺れる記号 (⚠️ 等) は使わない (`no-mixed-width-columns-in-terminal-ui.md`)
- 「人間の番か」は card の側の 1 つの関数で決め、画面・`pro-con card list`・`pro-con screen` (443) がそれを使う (判定を画面ごとに作らない)

## 関連

- 437 (PM を起こす。誰の番かが変わる) / 440 (dogfooding で「テスト待ちなのに作業中と出る」も同じ「今誰の番か」の問題)

## 順番の見積もり (PM, 2026-09-26。C-032 を C-026 の後に積んだ)

- 触る場所: `src/pro-con/card/card.go` の `WaitKind` (質問 / 許可 / 落ちた) と、表示の `ui/view.go` の `badge` / `columnBlock`
- 変える判断: 「今は人間の番か」を card 側の 1 関数で新設し、質問の宛先 (PM / 人間) を分ける
- 順番の理由: 質問を PM が先に受け、人に回すかを決める形は C-026 (437 の続き) が入れる。その振り分けを前提に「人の番」を定義するので、437 の続きの後にする。469 (C-035) と 476 (C-038) はこの判定を読むので、この後に積んだ
