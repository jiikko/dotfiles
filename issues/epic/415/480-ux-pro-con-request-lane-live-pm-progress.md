# 480 (ux): 依頼の列で、PM が各カードをどう処理しているかを即時に見る

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-25): 「依頼レーンの中でリアルタイムで、どのカードがどう処理がなされているのかリアルタイムで見たいのだが、無理？できるなら issue にして」。
今の依頼の列は、カードが「依頼 / 担当: PM」と並ぶだけで、PM が知らされたか・読んでいるか・分けている最中か・積んだかが見えない。

## 2026-09-25 22:11 の実例 (出来事の記録から)

- 22:11:55 C-017〜C-020 を add → PM を再開して C-017 を知らせた
- 22:12:09 C-017 の plan を適用 (PG を起動)
- 22:12:16 PM を再開して C-018 / C-019 / C-020 を知らせた (C-017 の turn の後にまとめて)
- 22:12:30〜32 3 枚の plan を適用 (PG を起動)。知らされてから積むまで 1 枚 15 秒前後。4 枚とも正しい issue を付けていた
- この 40 秒のあいだ、画面の依頼の列は 4 枚とも同じ見た目のままだった

## 期待する動作 (候補。見た目は見本で決める)

- 依頼の列のカードごとに、PM の段階を出す: 知らせ待ち (PM がまだ知らない) / 知らせた (PM の turn 待ち) / PM が扱っている (今の turn で読んでいる・issue を書いている) /
  積んだ (分解済みへ) / その場で答えて閉じた。段階が変わったら即時に書き換える (socket の知らせ。444 の出来事で分かる)
- PM が今やっていること (読んでいる issue・書いている issue・打った `pro-con card` のコマンド) を、そのカードに 1 行で出す (PM の transcript の最後の道具の呼び出し。467 / 473 と同じ出どころ)
- 集めるのは dispatcher か読む口の側 (画面を遅くしない)。`--view` でも出す。読むだけ
- PM が 1 回の turn で複数のカードを扱うとき (22:12:16 は 3 枚まとめて知らせた)、今どのカードかが分かる

## 関連

- 476 (PM の数と様子をヘッダに・PM の仕事をレーンで) / 437 (PM を起こす) / 444 (出来事) / 467・473 (PG の活動の同じ出どころ) / 452 (人の番)

## 順番の見積もり (PM, 2026-09-26。C-041 を C-038 の後に積んだ)

- 触る場所: 依頼の列のカードの描画 (`ui/view.go`)、PM の段階と最後の道具の呼び出しを集める所 (dispatcher / 読む口)、出来事 (444)
- 変える判断: 依頼の列で「PM が今どのカードを扱っているか」をどう出すか
- 順番の理由: 476 (C-038) が「担当 = 今手を動かしている者」の表示規則と、PM の仕事をレーンで見せる形を作り直す。同じ列の同じ判断なので、476 の後にする (依頼の原文でも見積もりを求めている)。PM の最後の道具の呼び出しの出どころは 467 (C-034) / 473 (C-037) と同じだが、どちらも取り込み済み

## 進捗 (C-041, 2026-09-26)

- 決めたこと: 段階は `card.Progress` の 1 か所で決め、画面のバッジ・`card list` / `card show` (`--json` は `progress`) が同じものを出す。
  `PM 知らせ待ち` (知らせ済みの `role_states.cards` に無い) / `PM 知らせた` (知らせを渡している最中か、同じ turn でまだ扱っていない) /
  `PM 分解中 ▸ <最後の道具の呼び出し> <経過>` (水色。今の turn で扱っている 1 枚だけ。質問待ちは `PM 回答中`) / `PM 入力待ち` / `PM 知らせた (手を止めた)` (turn を終えたのに残っている)
- 🚨 476 の「PM が turn の途中なら知らせ済みを全部 分解中」を変えた: 22:12:16 のように 1 回の turn で 3 枚知らせると、3 枚とも分解中に見えて「今どのカードか」が分からない。
  分解中 (`card.Handling`・担当の `PM 分解中`) は `role_states.current` の 1 枚だけ。起動・再開の最中は「知らせた」(476 では分解中)
- 今扱っているカード: dispatcher が PM の turn の途中 (作業中・入力待ち) の Tick ごとに PM の transcript の末尾を読み (`live.Transcript.Uses` = 結果が返ったものも含む道具の呼び出し)、
  最後の起動・再開の後で、呼び出しの対象 (コマンド・ファイル・URL・パターン。説明と書く中身は見ない) に知らせ済みのカードの ID が出た最後のもの (`dispatcher/role.go` の `roleTurn`)。
  まだ出ていなければ、知らせ済みが 1 枚のときだけその 1 枚。PM の指示書は `pro-con card show <カード>` で読み `card plan <カード>` で積むので、ID は対象に出る
- 積んだ・その場で答えて閉じたカードは列を離れるので、列の移動と出来事 (444) で分かる (段階としては出さない)
- 即時性: socket の知らせは足していない。dispatcher の Tick (3 秒) で書き、画面は 1 秒ごとに読み直すので、段階の変化は数秒で出る
