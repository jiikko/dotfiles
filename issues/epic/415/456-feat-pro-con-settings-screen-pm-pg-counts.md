# 456 (feat): 設定画面 — PM の数と PG の枠を人間が画面から変える (スケーリングの判断は PM、上限は人間)

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-25): 「スケーリングの判断は pm に任せるはずだけど、人間から pm の数を変更できるような設定画面も作ってね」。
今は PM の数を持つ仕組みが無く (437 が 1 つで始める)、PG の枠は dispatcher の起動引数 `--limit` だけで、変えるには dispatcher を止めて
起こし直すしかない (止めると作業中の PG も止まる。440 の 3 回目で踏んだ)。

## 期待する動作

- 画面に設定画面を足し、人間が **PM の数** と **PG の枠 (同時に動かす PG の上限)** を変えられる。動いている dispatcher を止めずに、次の Tick から効く
- 役割の分け方: **どこまで使うか (スケーリング) は PM が決め、人間が決めるのは上限**。PM は上限の中で、キューの長さや利用枠を見て使う数を決める
  (今は dispatcher が `--limit` と利用枠の cap で決めている。PM に判断させる口は 437 の後で設計する)
- 利用枠による絞り (80% で 1 本 / 95% で 0 本。stage 5) は人間の上限より優先する (上限を上げても枠を超えて起動しない)
- 変えた値は状態の置き場に残し、dispatcher を起こし直しても続く。`--limit` を渡したときとの優先を決める

## 足す: 役ごとのプロセスの一覧 (2026-09-25 のユーザーの依頼)

「起動中の role ごとに claude-code や dispatcher などのプロセス一覧も欲しいね。設定画面にあるといいかな？」

- 設定画面の中を「見る所」と「変える所」に分ける。見る所 = **役ごとのプロセスの一覧**: dispatcher / PM / PG / テストの係 (実行中のコマンド) / 要約の係 (haiku) / 画面 (presence の印)。
  それぞれ pid・起動からの経過・状態 (busy / idle / 止まっている)・担当のカード・今のコマンドを出す
- 今あるのは `s` の PG の一覧だけ (担当カード・状態・実行中のコマンド・経過・pid)。それを役ごとに広げる形でもよい
- 🚨 出すのは pro-con が起動したものだけ (README の `s` の行の「pro-con の外の session は名前も本数も出さない」を守る。`no-unauthorized-branch-switch.md` の系)
- 見る所は読むだけ: `--view` でも出す。集めるのは dispatcher か読む口の側 (画面が数秒ごとに ps を重く回さない)。473 (今走っているコマンド) と同じ出どころを使う

## 対応方針 (候補)

- 書き手は dispatcher だけ (426 の決定 1): 画面は受付の箱に「設定を変える」依頼を置き、dispatcher が状態の置き場 (dispatcher-state.json の隣) に書いて使う
- 画面のキーと設定画面の形は glogx の UI の決まり (`docs/glogx-ui-guide.md`) に合わせ、見本で候補を並べてから本体へ
- CLI (`pro-con config …` など) でも同じことができると、PM と外の Claude からも使える
