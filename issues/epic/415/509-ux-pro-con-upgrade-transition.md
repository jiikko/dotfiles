# 509 (ux): ctrl+r の新版への切り替えにトランジションを入れる (今は一瞬ホワイトアウトして雑に見える)

起票日: 2026-09-26

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-26): 「ctrl+r をしたときにトランジションを入れられる？ 今のままだと一瞬ホワイトアウトしているので雑に感じる」→「お願いします」。

## 今の流れ (2026-09-26 に読んだ)

1. `ctrl+r` → `ui/upgrade.go` の `requestUpgrade` が `tea.Quit` を返す
2. bubbletea の終了で端末を戻し、pro-con の画面 (alt screen。`ui/view.go` の `v.AltScreen = true`) から元のシェルの画面へ出る
3. `main.go` が新しいバイナリへ `syscall.Exec` (`execFn`) で入れ替わる (PID と端末はそのまま。UI の状態は `upgrade` の Save / Load で引き継ぐ)
4. 新版が起動し、状態を読み、alt screen に入り直して最初の 1 枚を描く

→ 2〜4 の間、元のシェルの画面か空の画面が一瞬見える。これが「ホワイトアウト」に見えている (推測。端末の色の設定で白にも黒にも見える)

## 期待する動作 (案)

- **旧版 (消える)**: 終了の前に、今のボードを 300〜500ms かけて暗くし、中央に「新版へ切り替え中…」を出してから入れ替える
- **新版 (現れる)**: 起動したら、旧版が最後に描いた画面 (Save で引き継ぐ) を暗いまま即座に出し、本物のボードへ明るく戻していく
- **間を空けない**: 旧版が alt screen を抜けずに exec できるかを確かめる (抜けずに済めばシェルの画面は一度も見えない)。bubbletea v2 の終了処理 (端末の復元) と、
  新版が alt screen に入るときの画面の消去の両方を見る
- 長さ・暗くし方・文言は、見本を出して人に選んでもらってから本体に入れる (decide-layout-in-sample-renderer-first)。
  アニメは操作のメタファーにし、主役 (カードのボード) を高コントラストで残す
- 切り替えに失敗したとき (新版が起動しない) は、暗いままにせず、旧版に戻れないことを分かる形で出す (今の失敗の扱いと揃える)

## 実装 (C-065)

- 旧版: ctrl+r で暗転を始め (`ui/switchfade.go`)、暗くなりきったら終了する。暗転の間はキーを受けない
- **alt screen を抜けずに exec する**: bubbletea v2 は終了のとき `cursedRenderer.close` で `\e[?1049l` (alt screen を抜ける) と
  `\e[?25h` (カーソルを出す) を 1 度の Write で書く。画面の出力を `upgrade.Screen` で包み、切り替えのときだけこの 2 つを落とす。
  新版の `\e[?1049h` は、既に alt screen にいれば端末 (tmux・xterm) は何もしない
  - 🚨 包んだ出力は `*os.File` でないので、`tea.ExecProcess` に子の Stdout を任せると os/exec がパイプを挟む。子を起こす口
    (`m.execProcess`) の既定を `execOnTerminal` (Stdout を `os.Stdout` に固定) にした
- 新版: 旧版の最後の暗い 1 枚を引き継ぐ状態 (`uiState.Frame`) で受け取り、最初の読み込み (`changedMsg`) が届くまで (上限 1 秒。
  本物の backend の最初の読み直しは claude agents の一覧を待って最大 10 秒かかる) それをそのまま出し、届いたら明るく戻す。待つ間にキーを打てば待たずに戻す
- 既定の色は端末に問い合わせる (OSC 10 / 11。答えなければ暗い背景の前提)
- 失敗: exec に失敗したら明るい画面に戻して今どおり通知する。新版が画面を出す前に終わる (引数の誤り・panic) ときは、
  エラーを書く前に alt screen を抜ける (`main.go` の `altGuard`)
- 実機の確認 (隔離 tmux `-L`、`--mock`): ctrl+r から 3 秒間 `#{alternate_on}` を 130 回読んで全部 1 (シェルの画面は一度も出ない)。
  切り替えた新版の quit で alt screen を抜けてカーソルも戻る。新版に実行権が無いときは明るい画面に戻って失敗を通知する
  - この確認で見つけた不具合: exec の失敗から同じ Model で bubbletea を起こし直すと、演出のコマの印 (`framing`) が立ったまま残り、
    2 回目の ctrl+r の暗転が進まず暗いまま止まった。前の Program の tick は捨てられているので、`UpgradeFailed` で印を下ろす

### 敵対的レビュー (C-065、読むだけのサブエージェント)

- 直した: (1) Keep から exec までの間 (裏の処理を最大 5 秒待つ) と、新版が画面を出すまでの間は bubbletea の外で端末が cooked のまま。
  ctrl+c (SIGINT) の既定の動作だと alt screen に閉じ込めたまま終わるので、この間だけシグナルの見張り (`upgrade.GuardAltScreen`) を置く /
  (2) 新版の見張りを Run の前に外していた (Run が描く前に失敗すると抜けない)。最初の View で外す (`OnFirstView`) /
  (3) 暗転の途中に attach の照合が終わると端末を渡していた / (4) 引数の足りない色 (`38;5`) を残し、後ろに足す暗い色の引数と繋がって別の色に読まれた
- 残す (未対応): 切り替えの間に打ったキーは cooked のまま端末にエコーされ、新版にキーとして届く (最初の描き直しで消える) /
  「↻」「…」は East Asian Ambiguous で、ambiguous = wide の端末では枠が 1〜2 セルずれる (画面の他の「…」と同じ扱い) /
  exec の失敗から起こし直すと、前の Program が予約した toast の引っ込みの tick も消える (演出のコマと同じ種類。今回は framing と spinning だけ下ろした) /
  xterm 等で `\e[?1049h` を入り直したときにカーソルの保存を上書きするかは未確認 (tmux は何もしない)
