# 516 (feat): カードごとの所要時間などを測って 3 か月分溜め、あとで比べて振り返れるようにする

起票日: 2026-09-26

親: [415](../415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼: 「カードごとにどのくらい時間がかかったとか、比較しやすいように測定してログを貯めておいて。たまに振り返りたい。3 ヶ月分まで溜まればいいよ」。

## 今あるもの (2026-09-26 に確かめた)

- カードの記録は完了から 1 週間で消える (`store/purge.go` の `PurgeAfter`。497)。書庫 `cards-archive.jsonl` もその対象で、振り返りには使えない
- 出来事の記録 `events.jsonl` は消されずに伸び続けている (4040 行)。カードごとの時間の形にはなっていない
- 490 は最終的に見積もりのポイントだけを出す形になり、作業した時間はカードにも画面にも無い
- 枠の使用量をカードごとに数える方法は 449 にある (PG の transcript の usage を数え、$ と 5 時間枠の % に直す)

## 期待する動作

- カードを閉じたとき (完了・その場で回答・却下・削除)、そのカードの 1 行を**カードの記録とは別のファイル**に書く (例: 状態の置き場の `metrics.jsonl`)。
  1 週間の削除 (497) では消さない
- 1 行に載せるもの (比べられる数にする):
  - ID・題名・repo・issue・見積もりのポイント・終わり方
  - 時刻: 依頼を受けた・分けた・最初に PG が起きた・レビューに来た・閉じた
  - 列ごとに居た時間 (依頼 / 分解済み / 作業中 / 質問待ち / レビュー)、そのうち**人の番だった時間** (人が遅らせた分を分けて見るため)
  - 回数: PG の再開・差し戻し・質問 (PM が答えた / 人が答えた)・テストの係の実行
  - 枠: PG の token (入力・キャッシュの書き込み・読み・出力) と、449 の換算での $・5 時間枠の % (取れなければ空にして、取れなかったと分かる形)
- **3 か月 (90 日) より古い行は消す** (書くときか 1 時間ごとの片付けのついでに。消す前に消した件数を出来事の記録に残す)
- 振り返る口: `pro-con stats [--since 30d] [--by points|repo|week]` のような集計 (中央値・最大・件数)。見積もりのポイントごとに実際の時間を並べて比べられる

## 対応方針

- 書き手は dispatcher だけ (状態の置き場の他の記録と同じ)。閉じる処理 (`store` の close / delete / purge の手前) で 1 行書く
- 列ごとの時間はカードの履歴 (状態の移り変わりの時刻) から出す。新しく時計を足さない
- `events.jsonl` にも保持の期限が無いので、同じ変更で 90 日に揃えるかを決める (揃えるなら同じ片付けに載せる)
- 🚨 既に閉じた過去のカードは、1 週間の削除より前なら書庫から埋め戻せる (今残っている分だけ。無理に集めない)

## 受け入れ条件

- [x] カードを閉じると 1 行が書かれ、1 週間の削除の後も残る
- [x] 90 日より古い行が消え、消した件数が出来事の記録に残る (時計を注入したテストで確かめる。実時間を待たない)
- [x] 列ごとの時間・人の番の時間・回数が、カードの履歴と一致する
- [x] `pro-con stats` で期間・ポイントごとの中央値と件数が出る
- [x] 枠が取れないカードは、0 ではなく「取れなかった」と分かる形で出る

## 進捗

### 2026-09-26 C-074 (PG) で実装

- **足跡**: 列を移った時刻と人の番を `card.Trail` に残す (`card/trail.go`)。列を移す箇所 (store の遷移・入力待ちの出入り・dispatcher の起動/再開・落ち続けて止めた・分解済みへ戻す・テストの結果・模擬) を `Card.Enter` 1 つに寄せた。
  PM / 取り込みの係が人に回したときは `Mark` で人の番の足跡を足す。役を起こさない設定は閉じた時点のものを遡って当てる (設定の変更の時刻は持っていない)
- **1 行**: `metrics.Row` (`metrics/metrics.go`)。列ごとの秒数・人の番の秒数は足跡から、回数は履歴の文から (書く側と同じ定数)。
  足跡が依頼の列から始まっていないカード (入れた時点で動いていた・それより前に作った) は列ごとの時間を nil にする (途中からの時間を全部として出さない)
- **書く時 (dispatcher だけ。`dispatcher/metrics.go`)**: 完了は PG を止め終えてから・Apply の直後 (書庫へ移す前) / 依頼の列ですぐ消した削除は Apply の結果 (`store.Result.Dropped`) から / PG を止めてから消す削除は記録から外す前 (書けなければ外さない) /
  書庫のカードは 1 時間ごとの片付けで 1 週間の削除より前 (書けなければ消さない)。書庫に残っている過去のカードはここで埋め戻る。
  完了の行を書いた後の削除は完了の行を残す / 削除の行を書いたのに外せず残ったカードは、完了したら完了の行で書き直す (起動し直した後も)
- **90 日**: 1 時間ごとの片付けで、閉じてから 90 日たった行を消す。消す前に件数を出来事の記録 (kind `archive`) に書く
- **枠**: 起動の記録 (今の分と退いた分) の session の transcript とサブエージェントの transcript を、message.id ごとに後の行を正として足す。
  API 料金換算と 5 時間枠の % は 449 の単価と $3.5 / 1% (粗い値)。取れなければ `usage` を持たず `usageMissing` に理由 (PG を起こしていない / transcript が無い 等)。単価を知らない model が混じれば $ は無し (`unpriced`)
- **口**: `pro-con stats [--since 30d] [--by points|repo|week|all] [--json]` (`statscmd.go`。読むだけ)。`--since` の `30d` は `pro-con log` でも使える
- **`events.jsonl` の保持**: 揃えない。既に大きさで回している (1 MiB で `events.1.jsonl` へ。置き場は最大 2 MiB。`eventlog.MaxBytes`) ので伸び続けない。「4040 行」は上限の内
- 敵対的レビュー (read-only サブエージェント) の指摘のうち、途中からの足跡・起動し直した後の削除の行・記録を読めないときの削除の行・完了後の削除・同じ応答の複数行を直した (テストと変異で確認)

### 残した・未確認

- 子カードが 90 日より長く動き、親が記録か書庫に残り続けると、dispatcher を起動し直すたびに親の行を書いては 1 時間後に消す (出来事に「1 行を消す」が出る)。実害は小さいので直していない
- 入れた直後の最初の片付けで、書庫 1 週間分のカードの transcript をまとめて読む (Tick が一度長くなりうる)。**計測していない**
- 削除の行 (依頼の列で数秒で消したカードも) は stats の中央値に混ざる。除くかは使ってから決める
