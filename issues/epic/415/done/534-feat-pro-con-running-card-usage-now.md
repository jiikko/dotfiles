# 534 (feat): 作業中のカードが、今どれだけ枠を使っているかを見る

起票日: 2026-09-27

親: [415](../415-design-claude-pm-worker-orchestration.md)

## 概要

外から動かす Claude の確認 (カード C-083) に、ユーザーが issue にすると答えた。516 は閉じたカードの記録 (`metrics.jsonl`) で、
作業中のカードが今どれだけ枠を使っているかは見えない。

## 期待する動作

- 作業中のカードの詳細 (と `card show`) に、そのカードの PG が今までに使った token (入力・キャッシュの書き込み・読み・出力) と、449 の換算での $・5 時間枠の % を出す
- できれば、画面のどこかで作業中のカードの合計 (今の PG 全体でどれだけ使っているか) も見える
- 数え方は 449 / 516 と同じにする (PG の transcript の usage。再開で入れ替わった前の session も足す)。同じ数え方を 2 つ作らない
- 集めるのは dispatcher か読む口の側 (画面は読むだけ)。取れないときは 0 ではなく「取れなかった」と分かる形で出す
- 見た目は本体に入れる前に見本を出して人に選んでもらう

## 情報源と精度 (2026-09-27 に確かめた。ユーザーの問い「把握できるの? 情報源は?」)

| 値 | 情報源 | 精度 |
|---|---|---|
| token (入力・キャッシュの書き込み・読み・出力) | PG の transcript `~/.claude/projects/<worktree のパス>/<session>.jsonl` の応答ごとの `message.usage` | 正確 (記録そのもの) |
| $ | token × API の公開価格 (応答ごとの `model` で引く) | 計算は正確。ただしサブスクは token 課金ではないので「API で払ったら」の物差し |
| 5 時間枠の % | 449 の換算 (1% ≈ $3.5) | **粗い見積もり**。枠の数え方は公開されていない (449 でも書き込み・読み・出力の重みを分けられなかった)。画面でも見積もりと分かる形で出す |

- 🚨 **サブエージェントの分は別のファイル**: `<session>/subagents/agent-*.jsonl` (C-082 の PG にもある)。足さないと敵対レビューを回したカードほど少なく出る
- 1 枚のカードの session は再開のたびに変わる。カードの履歴 (「PG を起動した / 再開した (session …)」) から全部拾って足す
- `claude -p /usage` の差分ではカードごとに分けられない (アカウント全体の値で、PG・PM・外の session が同じ枠を同時に使う)

## 関連

- 449 (枠の数え方) / 516 (閉じたカードの記録) / 469 (進捗を裏で集める仕組み)

## 決着 (2026-09-27): 却下

- ユーザーの判断で却下 (「却下でいいかな」)。情報源と精度 (token は正確・5 時間枠の % は粗い見積もり) を確かめた後の判断
- C-087 は削除した (`card close` はレビューの列のカードしか受けないため。質問待ちだったので PG の質問ごと消えたが、却下なので答えは要らない)。PG が作った commit (集める処理 `23a6156d`・見本 `671cdd4c`・進捗 `4cc0c177`) は master に入れていない (worktree のブランチ `worktree-pc-c-087` に残る)
- 閉じたカードの記録は 516 (`pro-con stats`) で見られる。作業中に見たくなったら、上の「情報源と精度」から始め直す
