# 581 (perf): PM・取り込みの係が 1 時間以上空いた後の再開で、会話全体 (7〜70 万トークン) を書き直す

起票日: 2026-09-29

親: [415](../415-design-claude-pm-worker-orchestration.md) / 出典: [431](../pending/431-feat-pro-con-pg-session-settings.md) の「計測」(2026-09-29)

## 概要

PM と取り込みの係は 1 本の session を長く使い続けるので、会話が数十万トークンまで伸びる。前の応答から 60 分を超えて再開すると、
1 時間のキャッシュが切れていて会話全体を書き直す (transcript の `message.diagnostics.cache_miss_reason` が `previous_message_not_found`。
書き直した量は 7〜70 万、中央値は PM 約 18 万・取り込みの係 約 45 万)。60 分以内の再開は全部当たっている。

PG の再開の外れ (`tools_changed`。431 / 525 / 546) は、今の形で SendFeedback が入らなくなった (起動は直接、再開の側は間接に観測) ので起きにくくなった見込み。
こちらは今の形でも減らない。

## 実測 (2026-09-29、transcript の読み取りだけ。LLM を呼んでいない)

対象: 残っている PM・取り込みの係の transcript 全部 (PM 95 本・取り込みの係 61 本。2026-09-25 12:46Z〜09-27 02:30Z の約 1.5 日)。
claude 2.1.282 / 2.1.283、すべて claude-opus-5-5。数え方は 431 の「計測」と同じ (再開の時刻より後の最初の応答の `message.usage`)。

| 役 | 再開 | 当たり | 外れ (すべて TTL 切れ) | 外れの間隔 | 外れ 1 回の書き直し | 書き直しの計 |

  `tools_changed` の外れはこの 2 役では 0 回
- 書き込みはすべて 1 時間 TTL (5 分 TTL の書き込みは 0)
- 損の大きさ: 18 回で 5.26M トークン。1 時間の書き込み ($8 / MTok) で約 $42 (当たっていれば読み 0.05 倍で約 $1)。
  449 の 5 時間枠の換算 ($3.5 / 1%) で約 12%。PG の `tools_changed` の書き直しは transcript が残った分だけで 2.26M の下限 (消えた分があり、449 は C-002〜C-037 だけで 3.20M)
  なので、大小は比べられない
- PG も 60 分越えの再開は外れる (前の形で 4 回・0.54M) が、PG はカードごとに起動し直すので会話が短い (外れ 1 回 12〜15 万)

## なぜ起きるか

- Claude Code の session は 1 時間 TTL のキャッシュを使う。役が 60 分以上何も要求しないと切れる
- PM と取り込みの係はカードが無いと待つだけなので、人が dogfooding を中断すると 60 分を超えやすい (外れの間隔は 61〜346 分)
- 会話が長いので、1 回の外れが PG の起動の書き込み (約 2.2 万) の 3〜32 倍 (中央値で PM 約 8 倍・取り込みの係 約 21 倍) になる

## 考えられる手 (未決。決める前に、それぞれで何を失うかを確かめる)

1. 60 分以上空いた役は再開せず、新しい session で起動し直す (引き継ぎを prompt に渡す)。PM は最中のカードの文脈、
   取り込みの係は取り込み途中の状態を会話に持っているので、起動し直して何を失うかを先に確かめる
2. 役の会話を短く保つ (区切りで起動し直す / compaction)
3. 空いている間にキャッシュを温める (keep-alive)。Claude Code の session に外から安い要求を打つ手段があるかは未確認で、打つたびに会話全体を読む (0.05 倍)
4. 何もしない (dogfooding の中断が少なければ許容できる)
