# 531 (feat): 問いだけのカード (確認) を、作業のカードと見分けられるようにする

起票日: 2026-09-27

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

外から動かす Claude の確認 (カード C-083) に、ユーザーが issue にすると答えた。外から動かす Claude が人に確かめるだけのカード
(C-075「確認: 再開のキャッシュ外れを直す issue を起票するか」・C-076・C-080・C-083 など、題名の頭に「確認:」) が、作業のカードと同じ見た目・同じ列の流れで並ぶ。

- 題名の「確認:」だけが目印で、カードの記録には種類の欄が無い (`card.Card`)。🚨 別の目的の `Wait.Kind` (`WaitKind`。何を待っているか) が既にあるので、新しい欄を `Kind` と名付けると読み違えやすい
- 問いのカードは、答えが来たら PM が issue を書いて積むか閉じるだけで、PG は付かない。作業のカードと混ざると、何が作業待ちかが読みにくい

## 期待する動作

- 問いだけのカードを作る口 (例: `card add --kind question` か、`card ask` を最初から付けた add) と、カードの種類の欄を持つ
- 画面とカードの一覧で見分けられる (見た目は本体に入れる前に見本を出して人に選んでもらう)。`card list` で種類で絞れる
- 実装の選択 (欄の形・既存の「確認:」のカードの扱い) は PG が決めてよい

## 関連

- 498 (PM が人に確かめる依頼を人の番にする) / 510 (外から動かす Claude 向けの入口) / 532 (カードの検索・絞り込み)

## 進捗 (C-084 / 2026-09-27)

- 種類の欄は `card.Purpose` (作業 `work` / 確認 `question`)。`Wait.Kind` と読み違えないよう Kind にしない
- 口: `card add --purpose question` / `card list --purpose work|question` (`--json` に `purpose`) / `card show` と画面の詳細に「種類: 確認」
- 確認のカードへの `plan` は適用で断る (PG を付けない)。PM は `card ask` で聞いて、答えのとおり `close --ending answered [--issue]` で閉じる (pm-guide 役目 2)
- 見た目は見本 (`src/pro-con/samples/531-question-card/`) の案 A をユーザーが選んだ: カードの 1 行目の番号の後に桃色の太字で `?確認`。`card list` の題名の頭にも同じ印
- 既存の「確認:」の題名のカードは種類を付け直していない (題名からの推測で記録を書き換えない。どれも閉じる手前)
