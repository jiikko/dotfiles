# 556 (ux): カードの地の色が「色なし」(ほぼ黒) に見えないようにする

起票日: 2026-09-27

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの報告 (2026-09-27): 「カードの色だけど無色が選ばれることがあるよね？無色は選ばれないようにする」「色なしというか」。
カードの地の色はカード ID から決まる (`ui/style.go` の `cardColor`。README「カードは固有の地の色を持つ」)ので、
色味の無い色に当たったカードは、ずっとその色のまま (列を移っても・起動し直しても同じ)。

## 今の形 (2026-09-27 にコードで確かめた)

- `cardPalette = []int{52, 17, 22, 53, 58, 23, 54, 94, 24, 89}` (xterm の 256 色の番号) から、カード ID の FNV-32a の余りで 1 つ選ぶ
- 明るい地は文字が溶けるので暗い地だけにしてある (状態の色・現在地色 202 と紛れない暗さ)
- どれも灰色そのものではない。暗さのせいで無色に見えうる候補 (未確認):
  - 58 (#5f5f00。オリーブ。灰色がかった濁った色に見えやすい)
  - 17 (#00005f。濃紺。黒い背景に溶けて地が無いように見えやすい)
- 🚨 **有力な仮説: 待っているカードだけ色が消えて見える**。待っているカード (`waiting(c)`) は固有の色のまま明度を下げて塗る
  (`ui/view.go` の `cardCell` → `bgDim(cardColor(c.ID), waitDim)`、`waitDim = 0.55`)。パレットはもともと暗い地なので、0.55 倍すると
  17 は #00005f → #000034、52 は #5f0000 → #340000、22 は #005f00 → #003400 のようにほぼ黒になり、暗い背景の端末では「色なし」に見える
  (パレットの 10 色すべてで、いちばん明るい成分が 0x34〜0x4a 程度になる)
- 塗らない経路は無い (`cardColor` を使うのは `cardCell` の 2 か所だけで、どちらも背景を塗る)
- どれが「色なし」に見えているかは、見た目なので機械では判定できない

## 対応方針

1. 見本 (`src/pro-con/samples/`) で、パレットの 10 色を「普段」と「待っている (0.55 倍)」の 2 段でカードの形で並べて出し、
   ユーザーに「色なしに見えるもの」を指してもらう (`decide-layout-in-sample-renderer-first.md`。モデルが見て選ぶのは合意ではない)
2. 待っている側が原因なら、明度の下げ方を変える (下げ幅を小さくする・下限を置く・明度でなく別の印で待ちを示す) 案を見本で比べる。
   特定の色が原因なら、その色をパレットから外す (外した分を足すかどうかも見本で決める)
3. 🚨 パレットを変えると、既存のカードの色が変わる (ID の余りで選ぶため、数が変わると全部ずれる)。
   ずらさない形 (外した色に当たったときだけ次の色へ送る) にするかを決める

## 受け入れ条件

- [x] ユーザーが見本で「無色に見える」と指した色が、どのカードにも選ばれない
  - 特定の色は指せなかった (「わからん。ターミナルの設定次第かな」)。「普段も待ちも両方」色なしに見えるとの答えなので、
    色を外すのではなく **パレット全体を 1 段明るい段 (#5f → #87) へ上げ、待ちの暗さを ×0.55 → ×0.7 に緩めた**。
    旧パレットの色 (52 17 22 53 58 23 54 24 89) はどのカードにも選ばれなくなった (94 だけ据え置き。下記)
- [x] 残りのカードの色がどうなるか (ずれるか・そのままか) を決めて本文に書く
  - **全部ずれてよい** (2026-09-27 のユーザーの決定)。パレットの色が変わるので、既存のカードの色は全部変わる

## 進捗

2026-09-27 (pro-con C-002):

- 見本 `src/pro-con/samples/556-card-color/` で 2 回聞いた
  - `colors.ans`: 旧パレット 10 色 × 普段 / 待ち ×0.55 / ×0.7 / ×0.8 → 場面「両方」・色「わからん (端末の設定次第)」・待ち「×0.7」・既存の色「全部ずれてよい」
  - `palette.ans`: A 今 / B 1 段明るい (普段 + 待ち ×0.7) → 「B」。普段の地も RGB で塗るかに「RGB で塗る」
- 決まった形 (`ui/style.go`):
  - `cardPalette = {88, 18, 28, 90, 100, 30, 91, 94, 25, 125}`。茶の 94 は 1 段上げると (130 = #af5f00) 現在地 202 / 要対応 214 / 未 push 208 の橙に寄るので据え置いた
  - `waitDim = 0.7`
  - 普段の地も `bgDim(n, 1)` で RGB で塗る (256 色の番号だと端末のパレット設定で色が変わりうる。待ちの地はもともと RGB)
- テスト: `ui/waitdim_test.go` の「普段の地」の期待を RGB に、`ui/focus_test.go` の地の検出を `48;` (RGB / 256 色の両方) に直した
  (入力中にボードを灰にする処理は `ansi.Strip` で SGR を全部落とすので、RGB になっても地は消える)
- 実測: `cd src/pro-con && go test ./...` rc=0 (pro-con card run)。隔離 tmux (`-L`) の `--mock` で撮ったボードで、カードの地が
  `48;2;135;0;0` (88) 等の RGB で出ることを確かめた (C-002 に board-after.ans を添付)。mock に待ちのカードは無いので、×0.7 の地は画面では未確認 (`ui/waitdim_test.go` が値を見る)
- 🚨 注意: RGB で出すかは bubbletea (colorprofile) が端末を見て決める。tmux の中で RGB を名乗らない設定だと 256 色に落とされ、
  普段の地は旧来どおり 256 色の番号 (パレットの値そのもの) で出る。隔離 tmux (`-f /dev/null`) ではそうなった
  (`TMUX` を外し `COLORTERM=truecolor` を渡すと RGB になった)。明るい段への変更はどちらでも効く
