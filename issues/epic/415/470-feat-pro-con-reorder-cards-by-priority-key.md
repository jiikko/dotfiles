# 470 (feat): レーンの中の並び = 優先度。選択中のカードを 1 つ上 / 下と入れ替えるキー

起票日: 2026-09-25

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-25): 「レーンの中で、上が優先順位が高いとし、カード選択中に優先順位を下げるキーショートカットを作って。
優先度を下げるとしたのカードと入れ替えて、あげると上と入れ替える」。

## 期待する動作

- レーンの中の並びを優先度とする (上ほど高い)。選択中のカードを、キー 1 回で 1 つ上 (上のカードと入れ替え) / 1 つ下 (下のカードと入れ替え) へ動かす。
  選択はカードについて動く (入れ替えた後も同じカードを選んだまま)。端では止めて知らせる (巻かない)
- **並びを dispatcher も使う**: 分解済みの列は、上から順に PG を起動・再開する (今は `dispatcher.go` の `dispatch` が「回答を受けた再開が先、その中は古い順」で決めている)。
  依頼の列は PM が上から分ける順 (437)。質問待ち・レビューの列は人が上から見る順 (並べ替えの効き目は表示だけ)
- 書き手は dispatcher だけ (426 の決定 1): 画面は受付の箱に「並べ替え」の依頼を置き、dispatcher が記録の並び (または優先度の欄) を書く。
  キーを速く続けて押しても、押した回数だけ動く (箱の依頼を順に当てる)
- CLI にも同じ口 (`pro-con card move <カード> up|down` など)。PM と外の Claude も使える
- 並びは記録に残り、画面を開き直しても・dispatcher を起こし直しても続く

## 決めること

- **キー**: 候補は ①ボードでは `K` (上へ) / `J` (下へ) ②`[` / `]`。
  ①は glogx の UI の決まり (`docs/glogx-ui-guide.md` §2「大文字は小文字の強い版」: `j` / `k` が選択を動かし、`J` / `K` がカードそのものを動かす) に合うが、
  詳細を開いている間の `J` / `K` は「隣の項目へ送る」(§3 の後) に使っている。ボードと詳細で意味が割れる (glogx の issues の一覧と本文で既に同じ割れを承知で採っている)。
  ②は空いているがホームポジションから外れる。**推し: ①** (決めたら docs/glogx-ui-guide.md と README の表に足す)
- 再開を待つカード (途中まで進んだ作業) を、並びと関係なく先にするか。今の「再開が先」を残すなら、並べ替えは「新しく起動するカードどうし」の中だけに効くと画面に分かるようにする
- 468 (順番の指定 `--after`) と食い違ったとき (後にすべきカードを上へ上げた) は、`--after` を守って起動しない理由を出す
- 模擬のモード (`--mock`) でも同じに動く

## 決めたこと (2026-09-26、C-036 の PG)

- **キーは ① `K` (上へ) / `J` (下へ)** (推しのとおり)。詳細を開いている間の `J` / `K` は今までどおり隣のカードへ送る。割れは `docs/glogx-ui-guide.md` §8 に書いた
- **再開が先は残す**。並びが効くのは「再開どうし」「新しい起動どうし」の中。分解済みのレーンで再開を待つカードのバッジに `↻再開が先` を出し、`?` の表 (Planned の Meaning) にも書いた
- **`--after` と食い違ったら順番が勝つ**。前のカードが終わっていないカードを動かすと、履歴に「C-xxx の完了を待つので、それまでは起動しない」を書く (起動しない理由は dispatcher の既存の「順番待ち」の履歴にも出る)
- **repo のタブで押したら、その repo のカードの中の隣と入れ替える** (画面に見えている並びと同じ。global のタブなら全 repo の並び)
- 端を越えた依頼 (画面の古い並びで速く押した分) は dispatcher が「端」の理由で除ける (記録は変えない)

## 実装

- 並びの鍵はカードの `Rank{Key, For}` (`src/pro-con/card/rank.go`)。`For` が今の `Since` と同じ間だけ効くので、列を移ると外す処理なしで外れ、移った先では末尾に着く。入れ替えていなければ鍵は `Since` (今までの「入った順」と同じ)
- 同じ Tick で列に入ったカード (同じ `Since`) どうしでも入れ替わるよう、入れ替えの時にレーンの鍵を並びを保ったまま 1ns ずつばらす
- 比べ方は `card.LaneCompare` 1 つ: 画面のカンバン・dispatcher の起動の順・PM への知らせと `card list` の順・入れ替えの隣が同じものを使う
- 受付の箱の依頼 `move` (`Delta` = -1 / +1、`Repo` = タブ)。隣は適用の時点の並びで決める。CLI は `pro-con card move <カード> up|down [--repo <repo>]`、模擬 (`--mock`) も同じ `card.Move` を使う
- 画面は dispatcher の適用を待たずに、読んだ記録の並びへも同じ `card.Move` を先に当てる (`live.moveAhead`)。続けて押したキーが古い並びで端と断られない。正本は記録で、次の読み直しで置き換わる
- 依頼は画面が見ていたカードの `Since` (`Seen`) を持ち、適用までに列を移っていたら除ける (回答で分解済みへ移った後に、見ていない列で入れ替えない)
