# 485 (design): カードの依存関係を見るビュー (ボードとは別の見方)

起票日: 2026-09-26

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-26): 「カードのビューがあるけど、カードの依存関係を表したビューも欲しいね。アイディアを epic に書いといて」。
アイデアの置き場。要件は未合意で、着手前にユーザーと詰める。

今のボードは列 (状態) ごとに並べるだけで、依存は分解済みのカードのバッジに「…C-026 の後」と断片で出るだけ。
**どのカードが何枚を塞いでいるか**・**鎖の先頭がどこで止まっているか**が見えない。

## 2026-09-26 01:05 の実例 (cards.json から)

```
C-026 (レビュー) ──→ C-032 (分解済み) ─┬→ C-035 (分解済み)
                                        └→ C-038 (分解済み)
C-029 (作業中)   ──→ C-033 (分解済み) ───→ C-038
C-027 (レビュー) ──→ C-039 (分解済み)
```

レビュー列で止まっている C-026 / C-027 (取り込みの係が居ない) が、分解済みの 4 枚 (C-032・C-035・C-038・C-039) を塞いでいる
(C-033 は作業中の C-029 待ち)。ボードからはこれが読み取れなかった。

## 依存の出典 (今あるデータ。新しく記録を足さずに描ける)

- `Card.After` (`src/pro-con/card/card.go`。PM が `card plan --after` で付ける。dispatcher は完了するまで起動しない。468)。
  完了していない前のカードは `card.Blockers` が返す
- `Card.ParentID` (1 つの依頼を分けたとき / 別件の追加オーダーの元)。順番ではなく「どこから来たか」なので、`After` とは線の種類を分ける
- 記録に無い依存 (同じファイルを触るだけで `--after` を付けなかった組) は描けない。PM の見積もりは各 issue の本文にある (468)

## アイデア (候補。どれを採るかは未定)

1. **画面の中の別ビュー** (キーで切り替え。例: `g`): 左から右へ「先に終わるべきカード → 後のカード」の層で並べる。
   ノードはボードと同じカード固有の色 + 列の名前 (状態) で、ボードと行き来しても同じカードを目で追える
2. **選択中のカードの前後だけを強調**: ボードのまま、選んだカードを塞いでいるカード / そのカードが塞いでいるカードに印を付ける
   (別ビューより軽い。引き出し (enter) に「前: C-026 (レビュー) / 後: C-035, C-038」と出すだけでも一部は足りる)
3. **塞いでいる枚数をバッジに出す**: 「⛓ 3 枚を塞いでいる」。レビュー待ち・質問待ちのカードに付くと、どれから片付けるべきかが分かる
   (452 の「人間の操作待ちの目印」と組み合わせると効く)
4. **CLI**: `pro-con card graph [--dot|--mermaid]` — 読むだけ。外の Claude / PM が順番の見積もりを確かめるのにも使える (441 の読む口と同じ位置付け)
5. **鎖の先頭が止まっている理由**を出す: 先頭が レビュー待ち / 質問待ち / 停滞 / 枠待ち のどれかを、鎖ごとに 1 行で

## 決めること (着手前)

- 1〜5 のどれを最初にやるか (2 と 3 は小さく、1 は描画の設計が要る)
- 完了したカードを図に残すか (残すと鎖の由来が分かるが、24 時間で片付くので消える)
- 描画は見本 (`./tmp` のサンプルレンダラ) で候補を並べて見せてから本体に入れる (`~/.claude/rules/decide-layout-in-sample-renderer-first.md`)

## 順番の見積もり (PM, 2026-09-26。C-043 を C-032 の後に積んだ)

## 見本 (C-051 の PG。2026-09-26)

どのディレクトリからでも打てる (フルパス)。見本は PG の worktree の `tmp/` にあり、commit されていない。
C-043 の見本 (架空の 11 枚) は使わず、**本物の記録 (`~/.local/state/pro-con/live/cards.json`) の After と ParentID** を読んで描き直した
(2A / 2B / 2C・3A / 3B の形は C-043 の見本から引き継いだ)。
`--at HH:MM` を付けると、各カードの History の文から列を巻き戻して、その時刻のボードと依存を描く。

```sh
# 色つきで再生する (案 1A 1B 2 3 4 5 6 を全部。--at を省くと今)
python3 /Users/koji/dotfiles/.claude/worktrees/pc-c-051/tmp/pro-con-485-sample.py --at 01:05
python3 /Users/koji/dotfiles/.claude/worktrees/pc-c-051/tmp/pro-con-485-sample.py --at 07:50   # 鎖の先頭が 2 本とも人の番
python3 /Users/koji/dotfiles/.claude/worktrees/pc-c-051/tmp/pro-con-485-sample.py --at 10:05   # 完了を残すかで見え方が変わる

# 案を絞る / 選択中のカード / レーンの中の幅を変える
python3 /Users/koji/dotfiles/.claude/worktrees/pc-c-051/tmp/pro-con-485-sample.py --at 07:50 --sel C-032 --width 30 2 3

# 質問に添えた出力をそのまま見る (13:43 に書き出したもの)
less -R /Users/koji/dotfiles/.claude/worktrees/pc-c-051/tmp/pro-con-485-sample-0750.ans   # -0105 / -1005 / -now もある
```

見本が再現していないもの: 過去の時刻の列は History の文からの推定 (人の番は「PM が人に回した」の後だけ。レビュー列の人の番は出ない)。
選択の枠は上下の横線だけ・spinner / 待っている地の暗さ (455) / 右上の見積もり (490) は描かない・完了の列は最後の 3 枚だけ。

### 実物の分布 (13:43 の cards.json)

- カード 47 枚、**After の線 8 本、ParentID 0 本** (ParentID はまだ一度も使われていない。点線の見本は出せない)
- 鎖の形: 最長 4 段 (C-026 → C-032 → C-038 → C-041)、枝分かれ最大 2、合流 1 か所 (C-038 は C-032 と C-033 を待つ)
- 完了していないカードの間の線は、00:50〜13:00 を 20 時刻抜き取って最大 6 本 (01:05・01:30)、07:50 で 5 本、10:05 で 3 本、**今は 0 本**。
  依存はほとんどの時間「数本」で、**完了したカードを図から外すと、今のビューは空になる**
- 鎖の先頭の状態: 01:05 は レビュー 2 本 + 作業中 1 本、07:50 は 2 本とも **質問待ち (人の番)**、10:05 は レビュー 1 本

### 各案の長所 / 短所

| 案 | 見本の見出し | 長所 | 短所 |
|---|---|---|---|
| 1A 別ビュー (層を横に) | 案 1A / 1A' | 鎖の全体と合流 (C-038) が 1 画面で読める。ノードがカード固有の色なのでボードと行き来できる | 描画の設計が一番重い (合流は「↑」で 2 回目を省く形にした)。線が 0〜6 本の今の分布では、画面の大半が空く。深さ 4 段で幅 108 桁 |
| 1B 別ビュー (縦の木 + タイトル) | 案 1B | 狭い端末でも崩れない。タイトルが出るので何のカードかが分かる。4 の text とほぼ同じ描画を共有できる | 合流したカードは 2 回目を「↑ 上に出た」で済ませるので、合流の多い鎖は追いにくい |
| 2 ボードで前後を強調 | 案 2A / 2B / 2C | 別ビュー不要。選んだカードの前後だけなので軽い | 選んだカードからしか分からない (どれが一番塞いでいるかは探せない)。2C は前後の無いカードを選ぶと何も起きない |
| 3 塞いでいる枚数のバッジ | 案 3A / 3B | ボードを見るだけで「どれから片付けるか」が分かる。人の番の印 (452) の直後に並ぶ | バッジの行が混む。幅 22 では C-038 の「塞1 …C-032, C-033 の…」が切れる (3B の「1枚を塞ぐ」はさらに切れる)。鎖の形は分からない |
| 4 CLI `card graph` | 案 4 (text / --mermaid / --dot) | 画面に手を入れない。外の Claude / PM が順番の見積もりを確かめるのに使える。mermaid は GitHub や issue にそのまま貼れる | 人がボードを見ながら使うものではない |
| 5 鎖の先頭と理由 | 案 5A (ボードの上に鎖ごと 1 行) / 5B (ヘッダに詰める) | 「何が止めているか」が理由付きで 1 行。07:50 のように先頭が人の番なら、人がやることに直結する | 5A は鎖の数だけ行を取る (最大 3 行だった)。5B は理由が列の名前だけ |
| 6 (追加) 分解済みの列を前のカードごとに束ねる | 案 6 | 各カードのバッジから「…C-032 の後」が消えて見出し 1 行にまとまる。すぐ起動できるものが上に来る | 並べ替えのキー (470 の K / J) と衝突する (束ねると人が決めた並びが崩れる)。前のカードが 2 枚のときは見出しが長い |

- 1〜6 は排他ではない (例: 3 + 5B をボードに、4 を CLI に)
- 決めること 2 (完了したカードを図に残すか): 1A' が「残す」形。今の分布では、残さないと 1 のビューはほとんどの時間空で、残すと 24 時間分の鎖 (8 本) が暗く出る
