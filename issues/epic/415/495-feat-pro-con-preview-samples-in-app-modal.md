# 495 (feat): 見本の確認をアプリの中で — 選択肢から見本の出力をモーダルで開く (コマンドを貼り付けずに済む)

> 🚨 **担当中: dotfiles-0d**（2026-09-28〜）

起票日: 2026-09-26

親: [415](415-design-claude-pm-worker-orchestration.md)

## 概要

ユーザーの依頼 (2026-09-26): 「shell でコマンドを実行してデザインを確認する系のオペレーションだが、いちいちコマンドを貼り付けるのがめんどいので、
選択肢を実行したら、アプリ内モーダルで出力を確認できるようにして」。

## 今の形 (2026-09-26)

- PG は見た目を決める前に見本を作り (decide-layout-in-sample-renderer-first)、質問の文に確かめ方のコマンドを書く
  (例: C-033 の `python3 …/tmp/pro-con-455-spinner-sample.py --anim`・C-055 の `cat …/tmp/493/sample.ans`・C-047 の `python3 …/pro-con-490-effort-sample.py`)。
  人はそれを別の端末に貼り付けて実行し、見てから pro-con に戻って答えている。相対パスで書かれて動かないこともあった (490)
- 453 (C-030) で `pro-con card attach <カード> <ファイル> [--note]` が入り、文字の画面の添付は詳細 (enter) の中にそのまま出せる
- 493 (C-055) で、質問待ちのカードに選択肢の回答フォーム (中央の枠・問いを縦に並べる) が入る予定

## 期待する動作

- 回答フォームの選択肢 (と問い) に、その案の見本を結び付ける。フォームで選択肢を選んでいるときにキー 1 つで、その見本の出力を**アプリの中のモーダル**で開く
  (色つきのまま。閉じるとフォームの同じ位置に戻る)。貼り付けも端末の切り替えも要らない
- 見本の出し方は 2 通りを考える:
  1. **添付した出力を開く** (既定): PG が見本の出力 (`.ans` 等) を `card attach` で添付し、ask で選択肢と結び付ける。開くのはファイルを読むだけ
  2. **その場で実行する** (`--anim` のように動く見本・幅を変えて見たいとき): PG が登録したコマンドを、モーダルの中で実行して出力を映す
- 質問の文にコマンドが書かれているだけの今の形でも、コマンドを拾ってモーダルで実行できるか (互換) は決める

## 考えること

- 🚨 **PG が書いたコマンドを人の端末で実行する**のは、PG の permission の外で任意のコマンドを走らせる口になる (`card run` と同じ性質。README の注記)。
  実行は既定にせず、添付した出力を開く方を既定にする。実行するなら、実行する前にコマンドの全文を見せて確かめる・カードの PG の worktree の中で走らせる・
  時間の上限を置く・端末を奪う対話のコマンドは受けない、などを決める
- 見本の出力は PG が書くので untrusted: 端末を操作するエスケープ (OSC 52 等) を落とし、色 (SGR) だけ残す (termsafe の LineKeepTabs / DetailLine の線)
- モーダルの大きさ: 見本は幅 160 と 90 のように幅を変えて描かれることがある。端末より大きい出力のスクロールと、狭いときの見え方を決める
- 見た目 (モーダルの形・開くキー・フォームとの行き来) は本体に入れる前に見本で人に選んでもらう
