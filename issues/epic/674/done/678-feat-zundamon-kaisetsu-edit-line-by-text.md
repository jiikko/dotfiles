# 678 (feat): 台本の行を、行番号ではなく文で指して直す手段を用意する

起票日: 2026-10-08

## 概要

台本を直すとき、行番号 (lines の添字) で指すと、行の挿入・削除の後に番号がずれて別の行を書き換える。

## 根拠

2026-10-08 の Mac vs Windows で、60 字超の行を直したときに添字を取り違え、「ゲームが中心なら…」の行を別の文で上書きした
(同じ文が 2 行並んだ)。統合確認の校正で見つかって直したが、見つからなければそのまま合成されていた。

## 対応方針 (案)

- 行を文の先頭の一致で指して置き換える・分ける・前後に足す手段を用意する。一致が 0 件か 2 件以上なら止める
  (2026-10-08 は、その場の python でこの形 (`startswith` で 1 件を確かめる) にしてから取り違えが止まった)
- 道具にするか (`zundamon-kaisetsu edit`)、SKILL.md に手順として書くだけにするかは、作る前に決める
  (道具にすると、台本の他のキー (`show` の段・`chapter`) を保ったまま分ける規則まで持つことになる)

## 受け入れ条件

- [-] 一致が 0 件・2 件以上のときに止まる — 対象外 (道具を作らないと決めた。下の進捗)
- [-] 行を分けたとき、`show` / `chapter` / `pause_after` がどちらの行に残るかが決まっていて、テストで固定されている (道具にする場合) — 対象外 (道具を作らないと決めた。下の進捗)

## 進捗

- 2026-10-08: **道具 (`zundamon-kaisetsu edit`) は作らず、SKILL.md の手順 3-3 に手順として書いて閉じる**
  - 着手前の判断: 起きたのは 1 回で、その結果の「同じ字幕が 2 行並ぶ」形は issue 684 の lint の規則 (同じ字幕の行の重複) で機械的に拾える。
    道具にすると、行を分けるときに図解・チャプター・pause_after をどちらに残すかの規則まで持つことになり、価値に比べて重い
  - SKILL.md: 「台本の行は字幕の文の一致で指し、一致が 1 件であることを確かめてから書き換える」を足した
  - 受け入れ条件 (道具にした場合の 2 つ) は、道具を作らないので対象外。同じ取り違えが道具の側で防げないと分かったら再評価する
