## 概要

「理由が 4 つある」のような並びを出す図解が無い。2026-10-08 の Mac vs Windows では、コードの図解 (`code`) を流用して
4 項目を出したため、暗い背景・等幅の小さい文字になった (動画の 4 分 5 秒あたり。画面の幅に対して文字が小さい)。

## 対応方針 (案)

- `{"type": "list", "title": "見出し (省略可)", "items": ["項目", …], "steps": true}` のような形。項目は大きめの文字で、
  `"next"` で 1 項目ずつ強調を進める (コードの `steps` と同じ考え方)
- 上限 (項目の数・字数) は、720p で撮って収まる長さを実測して決める (`show.go` の上限の注記と同じやり方)
- Go (`showParsers`) と player.html (`drawShow` / `showAt`) の 2 か所に足す (src/zundamon-kaisetsu/CLAUDE.md の「Go と player.html の契約」)
- 見た目はサンプルを撮ってユーザーに見せてから決める

### 実装 (commit: zundamon-kaisetsu: 箇条書きの図解 list を足す (issue 680))

- 台本: `{"type": "list", "title": "見出し (省略可)", "items": [...], "build": true}`。段は比較と同じ `build` と `"next"` (コードの `steps` と違い、
  強調する項目は順番に 1 つずつなので番号を書かせない)
- 上限: 項目 2〜5 個・14 字、見出し 16 字 (折り返さない)。720p のまとめ撮り (`#sheet=`) で見出し 16 字と全角 14 字 × 5 個を撮り、
  カードの右端と字幕の上に余白を残して収まった (show.go の上限の注記)。超えると合成の前に止まる
- lint の show-sentence (`showTexts`) と `lint --source` (`showAllTexts`) が箇条書きの項目・見出しも見る。source-leak は図解の文字を全部辿るので変更不要
- SKILL.md の図解の節・台本 JSON の表、src の README
