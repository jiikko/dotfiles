# 679 (feat): 漢字の読み分けの候補の一覧をファイルにして、誤読を見つけたら育てる

起票日: 2026-10-08

## 概要

SKILL.md の手順 5 の 3 は、読み分けを誤りやすい漢字 (上・下・値・親・空・生・内製) を含む行を grep で挙げて main が見る。
この一覧は SKILL.md の中の grep に直書きされていて、新しい誤読を見つけても足す場所が決まっていない。

## 根拠

- 2026-10-08 の 2 本で、機械の検査 (issue 673) でも、確認を 1 体にまとめたサブエージェントでも拾えなかったのは、漢字の読み分け
  (「Boot Camp の上」を じょう) だけだった
- 今の一覧は 2 本分の経験 (内製・上) と、元からの例 (値・親・空) でしかない

## 対応方針 (案)

- 一覧を `_claude/skills/zundamon-kaisetsu/` のファイル (読み辞書・略語の一覧と並べる) にし、手順 5 の 3 の grep はそれを読む
- 手順 5 の 7 (辞書に足す手順) に、「文脈で読みが変わる語を誤読したら、この一覧に足す」を書く
- 余裕があれば `kana --script --check` の出力に、一覧の字を含む行を候補として足す。issue 673 は「grep と同じことしかしない」ので道具に
  しなかったが、一覧がファイルになると、grep の正規表現と Go の読み込みの 2 か所で同じ一覧を読むことになる。道具に寄せれば 1 か所で済む
  (673 の判断を覆す理由はこれだけで、覆すかは作るときに決める)
- ファイルの形式は、grep で読むなら 1 行 1 語のテキスト、Go で読むなら JSON (acronyms.json と同じ)。どちらで読むかで決まる

## 受け入れ条件

- [x] 一覧がファイルにあり、SKILL.md の grep がそれを読む
- [x] 足す手順が SKILL.md にある

  `grep -F -f` でそれを読む。手順 5 の 7 に「文脈で読みが変わる語を誤読していたら、この一覧に足す」を書いた
  - 着手前の判断: `kana --check` に組み込む案は見送った。grep と同じことしかせず (issue 673 の判断)、一覧がファイルになったので、正本は 1 つで済む
