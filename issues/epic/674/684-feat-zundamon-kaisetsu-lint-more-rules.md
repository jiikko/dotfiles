# 684 (feat): lint に、台本の書き方の決まりを機械で確定できる規則として足す

起票日: 2026-10-08

## 概要

issue 675 の `lint` (7 個の規則) の上に、SKILL.md の台本の書き方の決まりのうち、文字列と台本の構造だけで確定できるものを足す。
今は手順 3-3 の確認役 (サブエージェント) が目で見ている。675 とは別にして、規則ごとに入れる・外すを決めやすくする。

## 規則の候補

| 規則 | SKILL.md の決まり・根拠 |
|---|---|
| 同じ字幕の行が 2 回続く | 2026-10-08 の Mac vs Windows で、行番号を取り違えて別の行を上書きし、同じ文が 2 行並んだ (確認役が見つけた。issue 678) |
| 読み辞書 (`readings.json`) の語が台本の `readings` に無い | 手順 3-2 の合流を忘れると、確認済みの誤読が戻る。今は誰も見ていない |
| 1 セリフが 3 文以上 (「。」「？」「！」で数える) | 「1 セリフは 1〜2 文」 |
| めたんの行に「のだ」、ずんだもんの行に「〜わ」「〜のよ」 | 役割と口調 (675 の一人称の規則の続き) |
| 図解の中に文がある (重要語の補足・比較の項目が「。」で終わる) | 「図解に文を載せない。重要語の `sub` も文にしない」 |
| 1 チャプターの図解が 3 回以上 | 「種類を合わせて 1 チャプターに 1〜2 回まで」 |
| チャプターの数が 4〜6 個から外れる / チャプターの最初の行がずんだもんの質問でない | 流れの決まり (尺が 8 分を超える程度なら増やしてよい、を規則にどう入れるかは決める) |
| 声のスタイル (`style_id`) の行が全体の 5〜8% から外れる / 長い行に付いている | 「1 行の反応や一言にだけ使い、説明の行には使わない」 |
| めたんとずんだもんの行数の割合が 6〜7 割 : 3〜4 割から外れる | 役割の割合 |

## 対応方針 (案)

- 675 の `lint` に規則を足す形にする (675 の後に進める)
- 割合・数の規則 (チャプターの数・スタイルの割合・行数の割合) は目安なので、止めずに警告にするかを決める
- 規則ごとに、今日の 2 本の完成台本で誤検出の数を測ってから入れる。誤検出が多い規則は入れない

## 受け入れ条件

- [x] 入れる規則を決め、規則ごとに誤検出の数 (2 本の完成台本) を書く
- [x] 規則ごとに、規則を外す変異で red になる
- [x] SKILL.md の手順 3-3 の確認役の観点から、機械に移した分を外す

## 反証レビュー

起票時の反証レビューは行っていない (低優先度の feat。起票者の自己確認のみ)。着手時に規則の根拠を SKILL.md と照らし直す。
