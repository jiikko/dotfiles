# 676 (feat): 字幕の速さの警告に、mp4 の撮影の前に気づけるようにする

起票日: 2026-10-08

## 概要

字幕が速くて読み切れない行の警告 (`caption_speed.go` の `warnFastCaptions`。1 秒 7.5 字を超える行) は、今は build が出す。
mp4 の build の後に警告を見て `pause_after` を足すと、撮り直しになる。

## 根拠

2026-10-08 の Mac vs Windows で、字幕の速さの警告に気づいたのが mp4 を撮り終えた後で、`pause_after` を足して 2 回撮り直した。
ただし警告そのものは、build の中で撮影より前に出ている (`build.go` の `cmdBuild`: `warnFastCaptions` を呼んでから `writeMP4`)。
build を 1 つのコマンドとして最後まで流したので、撮影が済んでから警告を読んだ。**本当の原因は、警告が出ても撮影を止めないこと**。

## 対応方針 (案。どちらにするかは作る前に決める)

- **案 A: build が、警告があれば撮影の前に止まる** (`--allow-fast-captions` のような指定で続ける)。`pause_after` は合成の鍵に入らないので、
  直して build し直すだけで済む。撮り直しが無くなる。ただし今の「止めない (警告だけ)」の判断 (`caption_speed.go` の冒頭の注記) を変える
- **案 B: synth の時点でも警告を出す**。台本を書いた直後に気づける。ただし `pause_after` を直した後は synth を回さないので、
  synth の警告は古くなる (build の警告は残す)。開始時刻の計算は `assemble` (立ち絵・図解・mermaid の描画まで行う) から小さな関数に抜いて、
  synth と build で共有する (synth から `assemble` を呼ぶと重くなり、図解の検査も前倒しで走る)
- A のほうが撮り直しを直接止める。B は A と組み合わせてもよい

- [x] (B は採らなかったので不要) B を採るなら、開始時刻の計算を関数に抜き、synth と build の警告が同じ行・同じ値になることをテストで固定する
