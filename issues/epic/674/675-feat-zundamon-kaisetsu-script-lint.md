# 675 (feat): 機械で判定できる台本の校正を `zundamon-kaisetsu lint` にする

起票日: 2026-10-08

## 概要

手順 3-3 の統合確認 (サブエージェント 1 体) の指摘のうち、文字列の規則で決まるものを、合成の前に機械で出す。
確認役は意味の確認 (事実・図解と資料の整合・書き起こしの筋) に集中でき、指摘を受けて直して合成し直す往復が減る。

## 根拠

2026-10-08 の試験 (Mac vs Windows の台本に欠陥を 12 個仕込み、確認を 1 体にまとめた。issue 673 の進捗) で、仕込んだ欠陥のうち
次の 7 個は文字列の規則で判定できる: ずんだもんの「のだ」が 1 行に 2 回 / 60 字超 / 漢数字 / 「この図」で図解を指す /
チャプターが移っても図解が残る / めたんの連続発話 / ずんだもんの一人称が「わたくし」。

## 対応方針 (案)

- `zundamon-kaisetsu lint script.json` を足し、行番号つきで警告を出す (あれば rc=1)。候補の規則:
  - 字幕 (`text`) が 60 字を超える
  - ずんだもんの行に「のだ」が 2 回以上 / ずんだもんの行に「わたくし」、めたんの行に「ぼく」
  - 半角の算用数字にすべき漢数字 (「四つ」「三人」。「一番」「一緒」「統一」などの慣用語は除く)
  - 図解を指示語で指す (「この図」「左の」「上の」 等。「これ」「ここ」は誤検出が多いので外すかを試してから決める)
  - チャプター (`chapter`) が始まる行で、前の図解が `null` で消えていない
  - めたんが 3 行以上続く (`show: "next"` で段を進める連続は除く)
- 誤検出の候補 (受け入れ条件の誤検出の測定に入れる): 60 字の線 (SKILL.md は「60 字程度」) / 「なのだ」を 1 回と数えるか /
  めたんがずんだもんの言葉を引用して「ぼく」と言う行 / 「これ」「ここ」の指示語
- サブコマンドを足すときは `main.go` の `usageText` と引数の表 (`nPos`) にも足す
- SKILL.md の手順 3-2 の後 (合成の前) に `lint` を置き、手順 3-3 の確認役の観点から機械の分を外す
