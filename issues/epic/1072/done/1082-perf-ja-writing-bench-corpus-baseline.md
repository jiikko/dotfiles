読み取れること

- 中央値は C と D で 5% 以内に揃った。最大値には外れ (lint 1 MB で 7.8 秒) が出ていて、負荷の高いマシンでは最大値を比べる値に使えない。比べるときは中央値か最小値を使う
- lint の処理は、256 KB から 1 MB の間では 1 MB あたり約 0.50 秒で伸び、この 2 点の直線を 0 バイトに延ばすと約 0.04 秒になる。
  4 KB の処理は 0.019 秒で、この直線より下にある。--version を引いた処理には、入力に依らない準備 (語の一覧を読むなど。--version の判定より後で走る) も入るので、「入力の処理だけ」の時間ではない
- 4 KB の lint では、所要 0.098 秒のうち起動 (lint --version) が 0.078 秒で、8 割を占める
- 同じ 64 KB でも、出力の量でかかる時間が違う: 繰り返しの文書は出力が 180 B で処理 0.034 秒、長い 1 行は 32 KB で出力が 69 KB あり処理 0.051 秒。入力の形と出力の量のどちらが効いているかは分けていない
- diff は入力 4.0 倍 (64 KB → 256 KB) で処理が 3.0 倍。check は中で lint と diff を子プロセスで起こし、子は site を import するので、small でも処理が 0.33 秒ある
- 直す前の道具で測った 2 回 (21:44〜21:47 UTC) は、2 回目が全ケースで 10〜21% 遅く、中央値でもずれた。今回の 2 回は 5% 以内に揃ったが、どちらの時間帯が静かだったかは分からない。
  Go の側と比べるときは別の時間帯の run どうしで比べず、同じ run の中で交互に流す (1079 の後半で pybench.sh に Go のケースを足す形)

測っていないもの

- hook (`yomiyasu_hook.py`)・`--doc-type` / `--reader` / `--words` を付けた lint・diff の `--stance` / `--endings`。1079 で Go の側と並べるときに要るなら足す
- 測ったマシンは 1 台だけ。CI の runner と、負荷の低い状態では測っていない
