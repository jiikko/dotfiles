# 1077 (feat): yomiyasu の check (検査の記録と最終稿の照合) を Go で作り直す

起票日: 2026-11-12

## 概要

本家の `yomiyasu_check.py` (5,639 行) を `yomiyasu check` として作り直す。最終稿に lint を、原文と最終稿に diff をまとめて掛け、入力の写し・レポート・
記録を状態フォルダに書き、後で最終稿が記録と同じかを照らす道具。返すのは「検査を実行した」であって、意味の保持や読みやすさの合格ではない (本家の docstring)。

## 本家が持つもの (v3.1.0)

- subcommand: `run` (省くと run)・`verify`・`start`・`export`・`end`。`run` は lint と diff を時間の上限つきの子プロセスで動かし、資料があればプロセスの中で照らし、
  状態フォルダ (指定しないときは git の最上位の `.yomiyasu/`) に書く。`verify` は最終稿のハッシュを記録と照らす (読むだけ)
- 記録 (JSON。`ensure_ascii=True`・`indent=1`) には、道具のファイルと語の一覧 (`references/lists/<名前>.txt`) の SHA-256、
  動かした Python の情報 (`python.version`・`implementation`・`unicode_version`) が入る。`verify` は `unicode_version` が今と違えば似かた (NFKC と一般カテゴリ) を
  求め直さない
- 状態フォルダを `.gitignore` で扱う規則・書けないときの案内・書き込みを途中の状態で残さない (`_write_atomic`)

## 決めること (着手のときに、本家のコードを読んでから)

- **記録の互換**: Go の check が書く記録を、本家の check の `verify` が読める形にするか (逆向きも)。`tools` の SHA-256 は本家では Python のファイルの値で、
  Go のバイナリの値は意味が違う。`python` の欄に Go の情報を入れると事実と違う。互換を持たない場合は、記録の `format` かバージョンの欄で区別して、
  相手の記録を読んだときに「別の道具の記録」と知らせる
- **子プロセスか関数呼び出しか**: 本家は lint と diff を子プロセスで動かして時間の上限を掛ける。Go では同じバイナリの関数を呼べるが、
  上限を子プロセスで掛けている理由 (止まらない照合を止める) を、Go の取り消し (context) で同じ強さで守れるかを確かめてから選ぶ
- 揃える範囲: 記録の中の時刻・ホスト・パスは入力の集まりの記録と比べられないので、比べる前に置き換える表を決める
