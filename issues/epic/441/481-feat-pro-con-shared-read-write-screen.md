# 481 (feat): 共同で読み書きする画面 (--view は読むだけのまま、別に「加わる」画面を足す)

起票日: 2026-09-25

親: [441](441-design-pro-con-viewer.md)

## 概要

ユーザーの依頼 (2026-09-25): 「view モードっていうのはそれはそれでいいのだが、共同読み書きモードも欲しいね」。

## 今の形

- 画面は複数同時に開ける (package presence が画面の印を数える)。どの普通の画面からも依頼・回答・差し戻し・削除などを打てる (書き手は dispatcher だけで、画面は受付の箱に置く)
- ただし「共同」には足りない:
  - **閉じ方**: 後から開いた画面も普通の画面なので、最後に閉じた画面が dispatcher と PG を止める (quit の入力欄)。加わった人が閉じた拍子に全部止まりうる
  - **見分け**: 誰の画面がいくつ開いているか・ほかの人が何を選んでいるか・誰が何を打ったかが見えない (「画面 N」の数だけ)
  - **取り合い**: 2 人が同じカードへ同時に回答・差し戻し・削除したときの決まりが無い (箱の順に当たるだけで、後の方は「列が違う」で除けられ、打った人に分かりにくい)

## 期待する動作 (候補)

- `pro-con --join` (名前は決める): 読み書きできるが、**閉じても dispatcher と PG を止めない** (止めるのは持ち主の画面か、明示の `dispatcher --stop`)。dispatcher も起こさない (居なければそう出す)
- 開いている画面の一覧 (誰の・どのモード・いつから) をヘッダかパネルに出す。ほかの画面の選択を薄い印でボードに出す (任意)
- 打った依頼の履歴に「どの画面から」を残す (出来事にも)
- 同じカードへの操作が重なったら、後から来た方に理由つきで知らせる (除けた理由を打った画面へ返す)
- 外の Claude (441) は今も `pro-con card …` で読み書きできる。それと同じ権限の画面版という位置付け

## 関連

- 441 (viewer) / 445 (読むだけの担保) / 427 の複数の画面と presence / 459 (手の --stop と keeper)

## 順番の見積もり (PM, 2026-09-26。C-039 を C-027 の後に積んだ)

- 触る場所: 画面の quit の経路 (最後の画面が dispatcher と PG を止める所)、keeper の「dispatcher を起こす」条件、presence (画面の印)、ヘッダ
- 変える判断: 「どの画面が閉じたら止めるか」「どの画面が dispatcher を起こすか」
- 順番の理由: 459 (C-027) が同じ 2 つの判断 (手の --stop の印がある間は keeper が起こさない・最後の画面の quit では印を置かない) を変える。459 が入ってからその上に「加わる画面は止めない・起こさない」を足す (依頼の原文でも指定)。476 (C-038) もヘッダに PM のゲージを足すが、足す物が別なので順番は付けていない
- 期待する動作の「候補」で決まっていない点 (フラグ名など) は、PG が推測で決めずに質問する (依頼の原文)

## 決めた spec (2026-09-26。C-039 の PG の質問 6 点を、codex と相談して決めた)

ユーザーの依頼「いい感じに spec を codex と相談の上決めてください」。PG の推奨に codex が反論し、崩れる形を足した (codex-cli 0.157.0・読むだけ)。

1. **フラグ**: `pro-con --join` (`--e2e <dir>` と重ねてよい)。**`--view` と `--mock` とは併用させず、使い方の誤りにする** (読むだけのつもりが書ける形を作らない)
2. **持ち主**: `--join` でない普通の画面はすべて持ち主。止めるのは最後に閉じる持ち主の画面 (最初の 1 画面だけを持ち主にすると、それが落ちた後に残った普通の画面が
   dispatcher を起こせず、quit でも止められない)。最後の持ち主の quit の確認には「join の画面が N 残り、止めた後は表示が止まる」を出す
3. **数え方を 2 つに分ける**: `持ち主の数` と `持ち主 + join の数`。
   - 無画面で抜ける (`--exit-without-screens`) は **持ち主 + join** で数える (持ち主が kill -9 で消えても、join が開いている間は PG を止めない)
   - 持ち主の quit で止めるかは **持ち主の数** で決める。🚨 **明示の quit で始めた停止は join の画面では取り消さない** (今の `stopUntilDone` は止めている間に
     画面が開くと止めるのをやめる。数を 1 つのままにすると、join が残っているだけで持ち主の quit が取り消される)
   - 数え直しは今の quit の排他 (`quit.lock`) の中で行う。画面の印が古くても、生きているかの判定は flock を正本にする
4. **join は dispatcher を起こさない**: keeper を持たず、459 の `c` (人が止めた dispatcher を起こす) も受けない (緩めると、手の `--stop` や持ち主の quit の後に
   join が PG を再開して利用枠を使う)。dispatcher が居ない / 人が止めてあるときは理由を出し、打った依頼は「受付の箱で待っている」と分かるようにする
5. **画面の見分け**: presence の印に `モード (持ち主 / join)・開いた時刻・短い画面 ID・tty (取れなければ空)・pid` を書き、ヘッダに一覧 (多ければ省略してパネル)。
   任意で `--as <ラベル>` (例 `--as review`)。`--view` は今どおり presence に入れない (一覧に出すなら relay の情報から。持ち主の数・無画面の判定には入れない)
6. **このカードの範囲**: ① `--join` と閉じ方・起こし方 ② 画面の一覧 ③ 依頼の履歴と出来事に「どの画面から」 ④ **除けた理由を打った画面へ返す**
   (画面 ID と依頼 ID を結び、dispatcher が書いた除けた理由をその画面にだけ出す。カードの変化から理由を推測して出さない = 誤った知らせになる)。
   「ほかの画面の選択を薄い印で出す」は入れない (別の issue に残す)

### 不変条件 (追加)

- 起動したときから join しか無い: dispatcher を起こさず、「持ち主の画面か `pro-con dispatcher` が起こす」と出す。人が止めた印があれば、join からは外せないことも出す
- 持ち主が落ちて join だけが残った: dispatcher が動いていれば join から書ける。dispatcher も落ちたら join は起こさない。止まっていることと再開の方法を出す
