# 094 human: av1ify のクリップボード入力を実運用で確認する

起票日: 2026-08-22
期限: 2026-08-29
種別: human
関連: [089](089-bug-print-p-executes-command-substitution-from-filenames.md)（パス表示に `print -P` を使わない理由）

コミット 6973d99 で `av1ify` / `av1c` の引数なし呼び出しがクリップボードを入力に取るように
なった。自動テスト（`tests/zshrc/av1ify/test_av1ify_clipboard.sh`、変異 7 本で red 確認済み）と
実 pty での通し確認は済んでいるが、**この機能の目的そのもの（ターミナルへの貼り付けで文字が
落ちる事故が起きなくなること）は実運用でしか確認できない**ため、人の目での確認を残す。

## 確認してほしいこと

1. **件数の一致**: 今まで貼り付けで文字が落ちていたときと同じ規模のパス列（Finder で複数選択 →
   「パス名をコピー」等）をコピーし、`av1ify` を引数なしで実行する。表示される一覧の
   「対象 N件 / 除外 M件」の合計が、コピーした行数と一致すること（除外 = ✗ が出たら、
   それは貼り付け元のパスが実在しないのか、文字が落ちているのかを見分ける材料になる）
2. **y で変換が走る**: `y` を入れて実際に変換されること。`n` / Enter で何も起きないこと
3. **Finder 由来の形式が読めるか**: 「パス名をコピー」（プレーンな絶対パス）と、ターミナルへの
   ドラッグ由来の `\ ` エスケープ付きパスの両方
4. **av1c でも同じか**: `av1c` は成功時に元ファイルをゴミ箱へ移すので、一覧の内容が
   意図どおりか（消えてほしくないファイルが混ざっていないか）を確認してから `y` を入れる。
   確認プロンプトに「⚠️ 変換に成功したファイルは元ファイルをゴミ箱へ移します」が出ること。
   **2026-08-22 追記**: 当初は `av1c` がスクリプト (`bin/av1c`) だったため引数なしでは
   発火しなかった。ユーザーの明示要求で `_zshrc` に `av1c()` ラッパーを足し、対話シェルでは
   関数として動く（= 発火する）ようにした。ここは「発火すること」を確認する項目に変わった。
   **2026-08-23 追記**: そのスクリプトは `bin/binav1c` へ rename した（PATH 上の `av1c` が
   ラッパー未ロードのシェルで関数を隠し、この機能が黙ってヘルプに化けていたため）
5. **一覧が実際の処理範囲を表しているか**（敵対的レビュー 2026-08-22 の指摘への対応確認）:
   - フォルダのパスを貼ると `✓ [ディレクトリ] ...  (配下の動画 N 件)` と出て、集計が
     「対象 M行 → 処理するファイル K件」になること（1 行が N 件に展開されるため）
   - symlink を貼ると解決後の実体が `✓` に出て、貼った文字列が `(貼付: ...)` に出ること
   - 相対パスを貼ると絶対パスで表示されること
6. **対話シェル限定になっているか**: `zsh -c 'av1ify'` のようにスクリプト経由で引数なしで
   呼ぶとヘルプが出ること（クリップボードを読まないこと）。`bin/binav1c` の直叩き
   （`~/dotfiles/bin/binav1c`）も同様にヘルプで止まること
7. **glob が消えた `av1c` の見え方**（2026-08-22 に開けたリスクの実地確認）: 対話シェルで
   `av1c **/*.mkv(N)` をマッチ 0 件の場所で打つと、引数が消えてクリップボード確認に化ける。
   このとき **一覧・赤字の削除警告・既定 No** が揃って出ていて「うっかり y」で消える形に
   なっていないかを見る。危ないと感じたら報告してほしい（防波堤を増やすか、av1c だけ
   確認語を `y` より強くする等の対策を検討する）

8. **Finder のコンテキストメニューが生きているか**（2026-08-23 の rename で新たに生じた確認）:
   `bin/av1c` を `bin/binav1c` へ rename した。DotfilesSyncer はこの repo の外にあり、
   メニュー項目をスクリプト名で管理しているのか description で管理しているのか確認できない。
   動画ファイルを右クリックして **「av1c（720p+30fps）で変換」が今までどおり 1 項目だけ出る**
   こと（消えていないか / 旧名のゴースト項目が残って 2 個になっていないか）を見てほしい。
   崩れていたら DotfilesSyncer 側の再同期か、`@DotfilesSyncer:name` マーカーの追加で直す

9. **空白区切りで貼ったときの案内が実際に使えるか**（2026-08-23 追加）:
   シェルのコマンドラインからパス列をそのままコピーする（`av1c /path/a.mp4 '/path/b c.mp4'`
   の引数部分を選択してコピーする等）と、クリップボードは「1 行に全パスが空白区切り」に
   なる。この形は 1 行 1 パス契約から外れるため、行全体が 1 個のパス名として `✗` になる。
   - `✗` の下に `💡 空白区切りで複数のパスが並んだ行があります (N行 / 分割すると M件が実在)`
     と出て、`av1c ${(Q)${(z)"$(pbpaste)"}:#\;}` が案内されること
   - **その案内をそのままコピペして実行すると、実際に全ファイルが変換されること**
     （案内が動かなければヒントは害でしかない。自動テストでは通っているが、実クリップボードで
     一度確認したい）
   - `av1c` のときは案内の下に赤字で「引数で渡した場合はこの確認が出ず、そのまま
     ゴミ箱移動まで走ります」が出ること（位置引数の経路には一覧も `[y/N]` も無いため）
   - 逆に、**ただのタイプミス**（存在しないパスを 1 個貼っただけ、空白入りのファイル名）で
     この案内が出ないこと。判定は「分割した語のうちパス区切りを含み実在するものが 2 件以上」
     に絞ってあるが、実運用で誤って出るようなら報告してほしい

## 想定外だったときに見るもの

- 一覧に出ない / ヘルプが出る → 非対話判定に落ちている（`__av1ify_stdin_is_tty`）。
  リダイレクトやパイプ越しに呼んでいないか
- 文字化け・パスの途中で切れる → 貼り付けではなく **コピー元側** で落ちている疑い
  （この機能では救えない。コピー方法を変える必要がある）
