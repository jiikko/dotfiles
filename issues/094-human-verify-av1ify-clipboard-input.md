# 094 human: av1ify のクリップボード入力を実運用で確認する

起票日: 2026-08-22
期限: 2026-08-29
種別: human
関連: [089](089-bug-print-p-executes-command-substitution-from-filenames.md)（パス表示に `print -P` を使わない理由）

コミット 6973d99 で `av1ify` / `av1c` の引数なし呼び出しがクリップボードを入力に取るように
なった。自動テスト（`tests/zshrc/av1ify/test_av1ify_clipboard.sh`、変異 7 本で red 確認済み）と
実 pty での通し確認は済んでいるが、**この機能の目的そのもの（ターミナルへの貼り付けで文字が
落ちる事故が起きなくなること）は実運用でしか確認できない**ため、人の目での確認を残す。

## 確認してほしいこと

1. **件数の一致**: 今まで貼り付けで文字が落ちていたときと同じ規模のパス列（Finder で複数選択 →
   「パス名をコピー」等）をコピーし、`av1ify` を引数なしで実行する。表示される一覧の
   「対象 N件 / 除外 M件」の合計が、コピーした行数と一致すること（除外 = ✗ が出たら、
   それは貼り付け元のパスが実在しないのか、文字が落ちているのかを見分ける材料になる）
2. **y で変換が走る**: `y` を入れて実際に変換されること。`n` / Enter で何も起きないこと
3. **Finder 由来の形式が読めるか**: 「パス名をコピー」（プレーンな絶対パス）と、ターミナルへの
   ドラッグ由来の `\ ` エスケープ付きパスの両方
4. **av1c でも同じか**: `av1c` は成功時に元ファイルをゴミ箱へ移すので、一覧の内容が
   意図どおりか（消えてほしくないファイルが混ざっていないか）を確認してから `y` を入れる

## 想定外だったときに見るもの

- 一覧に出ない / ヘルプが出る → 非対話判定に落ちている（`__av1ify_stdin_is_tty`）。
  リダイレクトやパイプ越しに呼んでいないか
- 文字化け・パスの途中で切れる → 貼り付けではなく **コピー元側** で落ちている疑い
  （この機能では救えない。コピー方法を変える必要がある）
