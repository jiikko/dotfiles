# 727 (bug): treefiler の Model.recs と walker.results に消えたフォルダのキーが残り続ける

起票日: 2026-10-12

## 概要

裏の走査の結果 (`Model.recs` と `walker.results`、`walk.go`) は、フォルダが消えてもキーを持ち続ける。`walker.forget` は stale の印を付けるだけで消さない。
名前の違うフォルダを作って消すのを 60 回繰り返すと、`recs` と `results` がどちらも 61 件になる (監査の実験)。712 より前から。issue 697 の却下の一覧には無い。
発見はユーザー依頼「リソースリークの観点でコードスキャン」の監査 (dotfiles-4e。起票は 4e の依頼で dotfiles-5f)。

## 対応方針

- 消えたフォルダのキーを `recs` と walker の記録 (`results` / `delta` / `last` / `asked` / `deferred`) から落とす。
  🚨 「木から node が見つからないパス」で判定しない: 走査の結果は走査したフォルダの配下の全部のフォルダ (`walkDir` の `found`。node の無い未展開の子孫も) を持ち、
  `walker.request` はそれを見て数え直しを省く。node の有無で刈ると未展開の子孫の結果まで消え、開くたびに数え直す。
  判定は「読み込み済みのフォルダの子に名前が無い」(読み込んでいないフォルダに行き着いたら分からないので残す)
- 走査中の結果が刈った後に戻る競合がある。取り込むときにも同じ判定で捨てる。消えて縮んでいる項目 (ghost) には走査を頼まない (頼むと消えたフォルダを数え直し続ける)
- 1 件あたりは小さいので重さは低い (P3)。長く開いたままの glogx で、作っては消すフォルダ (ビルドの出力等) があると伸び続ける

## 受け入れ条件

- [x] 作って消すのを繰り返しても `recs` / `results` / `last` が木の中のフォルダの数を超えて伸びない。読み直し (force) とライブ更新 (force なし) の両方で (テスト + 変異)
- [x] 未展開の子孫の結果は読み直しでも残る (テスト + 変異)
