## 反省 1 (最重要): 「red が出た」を「自分の assert が守っている」と 4 回読み違えた

同じ誤りを **4 回**繰り返した。全部「変異で red → テストで守られている」と commit message に
書いた直後に、レビューが「そのテストは何も守っていない」を変異で示した形。

| # | 書いたこと | 実際 |
|---|---|---|
| 1 | 「M8 (`-r 10` 注入) を production の密度検査が捕まえた」 | 引数組み立て側への注入で、**実在する 4 バグはどれも決定点を壊す形**。退行の形を再現していなかった |
| 2 | 「Test 70i で nb_frames の採用を pin した」 | 見ていたのは**却下メッセージの不在**だけ。採用枝を「黙って常に尺ベース」に変える変異が全緑 |
| 3 | 「Test 70j で崖が無いことを固定した」 | その入力は trust ゲートが**却下する**側で、主張を一度も実行していなかった |
| 4 | 「Test 70k で env 検証の非対称を塞いだ」 | 撃っていたのは 2 変数のうち **1 つだけ**。もう片方を外す変異が全緑 |

共通の原因は **「その red を出したのはどの assert か」を確かめずに、スイートの結果を証拠に
数えたこと**。最終的に「**このテストだけが red になる変異を 1 本ずつ特定する**」形に切り替えて収束した。

さらに、判定する側の道具自体も 2 回壊れていた:

- 変異ハーネスの判定式を `grep -E '^\s+--- FAIL'` と書いたため、**サブテストでない
  `--- FAIL:` (インデントなし) を取りこぼし**、red の変異を「全緑」と誤読した (lockman 364)
- 「当たっていない変異の green」を検出力の欠如と読みかけたのが 4 回 (`if false` にしたら
  else 側が再代入して打ち消す / コマンド置換が壊れて判定不能に落ちる / 置換が別の呼び出しに当たる)

→ 切り出し提案: [`mutation-verify-new-tests.md`](../../_claude/rules/mutation-verify-new-tests.md) に
**「変異の red は、ケース名 × assert まで特定して初めて証拠になる」**を 1 項として足す。
既存の「テーブル駆動なら全ケースが red になるか」の隣。ハーネス側の判定式の罠
(`^ *--- FAIL` / go の出力形式) は実装側 (ハーネスのコメント) に置く。

## 反省 2: 自分の修正が P1 を持ち込み続けた (2〜5 周目は全部それ)

av1ify の 6 周のうち、**2〜5 周目の P1 はすべて私の修正が持ち込んだもの**だった。

| 周 | 持ち込んだ欠陥 | 種類 |
|---|---|---|
| 2 | 密度検査の期待値が**加害変数と同一** (自己言及) | 設計 |
| 2 | `format=duration` を映像の尺として使った | API の意味の誤解 |
| 3 | `nb_frames` を「デコードされるフレーム数」と誤解 (elst で乖離) | API の意味の誤解 |
| 4 | `__av1ify_get_stream_end` を「尺」と誤解 (実は終端時刻) | API の意味の誤解 |
| 4 | trust 窓と密度窓を同値にして崖を作った | 設計 |
| 5 | env 検証を片側だけにした | 実装 |

**3 件が「ffprobe / 自作ヘルパーが返す値の意味の思い込み」**で、どれも
「**その等式が破れる条件を確かめずに前提として書いた**」形だった
(`avg_frame_rate = nb_frames / duration` は elst があると成立しない、等)。

→ 切り出し提案: [`instrument-before-second-fix.md`](../../_claude/rules/instrument-before-second-fix.md) の
「前提の再検証」の行に、**「等式・定義を前提に書くときは、それが破れる入力を 1 つ挙げてから書く。
挙げられないなら『未確認の前提』と明示する」**を足す。新規ルールは立てない (発動点が同じ)。

## 反省 3: 「対照を置いた」と書いた対照が、対照になっていなかった (lockman 364)

issue 364 の本文に他セッションが書いた「対照も置いた (常に残すへ倒れていないこと)」が**偽**だった。
その対照は打刻の**後に自分で mtime を上書きする**ので、打刻値を一度も観測していない。
実測: 100 日先へ打つ変異で full suite が全緑。**片方向 (打刻しなさすぎ) しか検出していなかった。**

これは反省 1 と同じ構造 (「置いた」と書いたものが実際には効いていない) だが、
**他人が書いた記述を鵜呑みにしかけた**点が違う。issue 本文の主張も変異で確かめてから引き継ぐ。

→ 切り出し提案: 既存ルールで足りる
([`mutation-verify-new-tests.md`](../../_claude/rules/mutation-verify-new-tests.md) の「検査の不在を
主張するときの裏取り」が「対照の存在の主張」にもそのまま効く)。**追記も不要**と判断 —
反省 1 の追記が同じ発動点を覆う。
