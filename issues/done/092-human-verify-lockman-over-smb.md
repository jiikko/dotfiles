# 092 human: lockman を実機 SMB (macOS 2 台) で検証する

起票日: 2026-08-22
期限: 2026-09-05
種別: human (人間しかできない作業)
関連: [091](091-feat-lockman-directory-lease-lock.md) — 仕様と設計の正本

## なぜ人間が要るか

`src/lockman` の v1 は入っていて、**ローカル FS 上では**排他・引き継ぎ・掃除が
テストで固定されている (二重取得を作る変異で赤になることも確認済み)。しかし
**SMB 越しの前提は 1 つも検証されていない**。CI は ubuntu のローカル FS で回るだけで、
SMB 共有をマウントできない。実機 2 台を用意できるのは人間だけ。

**ここが未検証のまま「SMB でも安全」と書かないこと。**

## 用意するもの

- macOS のホスト A: ファイル共有 (SMB) で 1 つのディレクトリを公開する
- macOS のクライアント B: A の共有をマウントする
- 両方に dotfiles (`bin/lockman` が使えること)。初回起動時に自動ビルドが走る

以下、`$SHARE` は **A ではローカルパス**、**B ではマウント先のパス**を指す (別表記でよい。
lock の実体は対象ディレクトリの中にあるので、パスが違っても同じロックを見るはず)。

## 1. まず前提を測る (推論で決めない)

`091` の「実測が要る前提」の 4 つ。**B (SMB クライアント) 側で実行する**。

```sh
# (1) link(2) が smbfs 越しに使えるか
#     使えれば lock は最初から中身が入った状態で現れる。ENOTSUP なら O_EXCL 経路に
#     落ちる (実装は自動で追従するので、どちらでも動くこと自体は確認済み)
cd "$SHARE" && mkdir -p .probe && : > .probe/a && ln .probe/a .probe/b && echo "link OK" || echo "link 不可"
rm -rf "$SHARE/.probe"

# (2) 書き込み後の mtime を打刻するのはホストか、クライアントか
#     lockman renew が毎回検算しているので、ずれていれば renew がエラーで止まる。
#     B の時計を 30 秒ずらしてから renew して、止まるかどうかを見るのが確実
lockman acquire "$SHARE" --token-file ./tok && lockman renew "$SHARE" --token-file ./tok; echo "renew exit=$?"

# (3) fcntl byte-range lock がサーバへ届くか (v1 は使っていない。将来の二重の壁の材料)
# (4) 属性・ディレクトリキャッシュの遅れ: A で作った lock が B から何秒後に見えるか
```

測った結果を **091 の「実測が要る前提」の表に追記**する (次にこれを触る人が測り直さずに済む)。

## 2. 本命: 同時取得で片方だけが勝つこと

**(a) SMB クライアント 2 台から同時**

```sh
# B と C で同時に (時計を合わせて秒単位で叩く / あるいは両方で while ループを回す)
lockman acquire "$SHARE" --token-file ./tok; echo "$(hostname) exit=$?"
```

期待: **片方が 0、もう片方が 3**。両方 0 なら排他が壊れている (最重要の失敗)。

**(b) ★ 混在経路: ホスト A のローカルパス と クライアント B から同時**

これが今回の本命。キャッシュの非対称が最も出る組み合わせ。

```sh
# A (ローカルパス) と B (マウント) で同時に叩く
lockman acquire "$SHARE" --token-file ./tok; echo "$(hostname) exit=$?"
```

期待: 片方が 0、もう片方が 3。

**(c) キャッシュ遅延下でも負けること**

```sh
# A で取得した直後 (1 秒以内) に B から取りにいく
# B の一覧キャッシュが古くても、判定はサーバが下すので B は負けるはず
```

期待: B が exit 3。**B が 0 を返したら、事前チェックがどこかに紛れ込んでいる証拠**。

## 3. 引き継ぎと掃除

```sh
# TTL を短くして (下限 30s)、holder を kill -9 してから他マシンが取れること
lockman with "$SHARE" --ttl 30s -- sleep 300 &   # 別マシンから kill -9
# 30 秒経過後: 他マシンの acquire が成功する / 経過前は exit 3

# 走行中に奪われた側が気づけること: release が exit 4 を返す
```

## 4. 報告してほしいこと

- 上の各項目の **実際の exit code**
- (1)〜(4) の実測値 (link の可否 / mtime の打刻元 / キャッシュの遅れ秒数)
- **両方が 0 を返した組み合わせがあれば、そのときの `$SHARE/.lockman/` の中身**
  (`lock` の JSON と `graveyard/` の一覧)。これが二重取得の唯一の物証になる

## 完了条件

2 と 3 が期待どおりで、1 の実測値が 091 に追記されたら done。
**両方が 0 になるケースが 1 つでも出たら、done にせず 091 を再設計に戻す。**
