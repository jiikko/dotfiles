# 182 ux: 狭い幅で意味が消える表示が 4 系統ある (blocked 理由 / 長いラベル / バイト幅 pad / 再利用注記)

起票日: 2026-09-02
重要度: **P3**
関連: [issues/163](163-audit-doctor-implementation-red-team.md) (体 6) / [`_claude/rules/no-mixed-width-columns-in-terminal-ui.md`](../../_claude/rules/no-mixed-width-columns-in-terminal-ui.md) / [issues/148](148-feat-glogx-doctor-disk-diagnosis.md) (「レイアウトの決定」)

## 対象

`src/glogx/doctor_view.go` の `diskSection` (マーク列 / 助言行 / Enter の詳細順)、`src/doctor/disk/report.go` の `Format` (`%-48s`)、
`src/doctor/disk/catalog.go` の長いラベル

## 何が起きるか

いずれも実証済み (体 6 が幅 60 / 80 / 120 でサンプル出力を目視)。

### (a) blocked の理由をマーク列に置くので、狭い幅で理由が消える

- 幅 80: `🚨 Google Chrome Canary …` (「起動中のため対象外」が落ちる)
- 幅 60: 全マークが `✅ 安…` `🚨 注…` になる
- `NO_COLOR` では caution も blocked も同じ 🚨 なので、記号だけでは区別できない

対応: マーク列は固定語彙にする (例 `🚫 対象外`)、理由は下の dim 行へ移す。CLI の `Format` も同型。

### (b) ラベルが 40 桁を超えるエントリが 1 件ある

「アンインストール済み formula の状態 (/opt/homebrew/var)」= 55 桁 → UI で `(/o…` になる (実機サンプルでも同じ)。

対応: 括弧内の path を Enter の詳細へ移す。

### (c) `disk.Format` の `%-48s` はバイト幅で詰めるので、日本語ラベルで列が揃わない

CLI 出力のマーク列が行ごとにずれる。対応: 表示幅で pad するか、揃えを諦めて改行する。

### (d) 「N 分前の計測を再利用」が助言行の末尾なので幅 80 で切れる

値が stale であることが分からなくなる (issue 172 の「注記で分かる形にしてある」という前提が幅で崩れる)。

対応: 再利用の注記は行頭側 (または専用の記号) に置く。

### (e) Enter の詳細の挿入位置

詳細 (削除経路 / 補足 / 内訳) が親行の直下に入るので、助言行「再取得されます。最終更新…」と Failures 行が
その**後ろ**に来る。failed の行にも「削除経路 / 補足」が出る (CLI は理由だけ)。

対応: 詳細は助言行の後に置くか、failed の行では削除経路を出さない。

## 受け入れ条件

- [x] 幅 60 / 80 / 120 のサンプル出力を端末に出して目で確認する (幅計算のテストだけでは判定しない)
- [x] `NO_COLOR` で blocked と caution が区別できる

## 対応 (2026-09-03)

5 件すべて対応した。方針は **「幅で最初に切れるのは行末なので、そこに置いてよいのは
失っても困らない情報だけ」**。切れて困る順は 状態 > 扱い方 > ラベルの詳細。

| # | 内容 | 直し方 |
|---|---|---|
| (a) | blocked の理由がマーク列で切れる | マーク列を**固定語彙** `🚫 対象外` にし、理由は 1 行下の dim 行へ (failed と同じ形)。記号を caution の 🚨 と分けたので `NO_COLOR` でも区別できる |
| (b) | 55 桁のラベルが切れる | カタログの Label を「アンインストール済み formula の状態」(34 桁) に縮め、場所は `Detail` へ移した。**Label は表示幅 40 桁に収める**とコメントで明示 |
| (c) | CLI の `%-48s` がバイト幅で pad する | doctor module は幅計算の依存を持たないので、**揃えるのを諦めて**マークを先に出す形にした (`%9s  %s  %s`)。size は ASCII なので `%9s` が効く |
| (d) | 再利用の注記が末尾で切れる | 注記を**行頭**へ移した (「20 分前の計測を再利用 (r で再計測)。<助言>」) |
| (e) | failed の行にも削除経路が出る | `diskDetail` で failed のとき削除経路を出さない (CLI の `Format` に揃えた) |

### 追加で見つかった問題

**(a) を直しただけでは幅 60 でマークごと切れていた** (`⛔ 要…`)。ラベル列が 40 桁固定で、
`size(9) + ラベル(40) + マーク` が幅 60 に収まらないため。ラベル列を**幅に応じて縮める**形にした
(下限 8 桁)。マークより先にラベルを削るのは、切れて困る順がそうだから。

### 目視で確認した出力 (幅 60)

```
▶     3.0GB  アンインストール済み formula の状態 ⛔ 要確認
             DB データ等の本体
      2.0GB  npm キャッシュ                      ✅ 安全
             20 分前の計測を再利用 (r で再計測)。再取得され…
         0B  Chrome 一時ファイル                 🚫 対象外
             Google Chrome Canary 起動中のため対象外
```

CLI (色なし) も同様に、マークが先でラベルが行末:

```
    3.0GB  ⛔ 要確認  アンインストール済み formula の状態
           DB データ等の本体
       0B  🚫 対象外  Chrome 一時ファイル
           Google Chrome Canary 起動中のため対象外
```

### 変異検証 (使い捨て worktree、4 本とも red)

| 変異 | 最初に落ちた assert |
|---|---|
| blocked の理由をマーク列に戻す | 幅 60 でリスク記号が切れた |
| ラベル列を縮めない (40 固定) | 幅 60 でリスク記号が切れた |
| 再利用の注記を末尾に戻す | 幅 60 で再利用の注記が切れた |
| failed でも削除経路を出す | 走査できなかった行に削除経路が出た |

🚨 注記の変異は最初 green だった。fixture の `Recover` が「再取得されます」と短く、
**末尾に置いても行が幅に収まってしまった**ため。実物に近い長さ (最終更新の注記つき) に
直して red になった。
