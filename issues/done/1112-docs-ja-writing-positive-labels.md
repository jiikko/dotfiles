# 1112 (docs): ja-writing に「状態・区分は、その状態を名指す 1 語で書く」を足す

起票日: 2026-11-26

## 概要

状態・区分・表の見出しの語の選び方の規範を足す。起点のユーザーの指摘は「否定形じゃなくて、基本的に肯定系で単語を書く」(2026-11-26)。
規範の形は、その指摘を Claude が解釈したもので、「状態・区分は、その状態を名指す 1 語 (「有効」「使用中」「不使用」) で書く。
別の属性を否定する句 (「論理削除されていない」) や、決まったラベルの外の語 (「対象外」) で書かない」とする (解釈の理由は下の「起票時の案の見直し」)。

## 詳細

起点は、別の業務の repo で画像を物理削除にする作業をしたときの説明。

- 画像の仕分けを説明するときに、行の状態を「論理削除されていない / 論理削除済み」と否定形の語で並べた。ユーザーから「否定形じゃなくて、基本的に肯定系で単語を書く」と指摘された
- 同じ説明で、仕分けのラベルが 3 つ (使用中・不使用・新規) と決まっているのに、ラベルに無い「対象外」を持ち込んで説明した。ユーザーに「対象外って何。3 つのラベルで語ってくれ」と聞き直された
- その前にも、仕分けのラベルを「残す・消す・足す」と動作の語で書いていて、「残すっていう名称がわかりにくい」と言われ、状態の語 (使用中・不使用・新規) に直した。
  このラベルは Claude が付け、ユーザーはその後「3 つのラベルで語ってくれ」と、これを使うよう求めた

## なぜ分かりにくいか (認知的な負荷)

- **否定は、読む処理を重くすることがある**。否定を含む文では、肯定の文より真偽の判定に時間がかかり、誤りも増える (Clark & Chase 1972 の、文と絵を照らし合わせる実験。扱ったのは文の否定)。
  ただし、否定が自然に出る文脈 (2 値の対の片方を言うときなど) では差が小さくなることも知られている。この項だけでは決め手にならない
- **別の属性を否定する句は、状態を補集合で定義する**。「論理削除されていない」は何であるかを言わず、全体から 1 つを除いた残りを指す。
  読み手は全体に何があるかを自分で組み立てる
- **決まったラベルの外の語は、区分を増やす**。「対象外」は 3 つのラベルのどれにも当たらないので、4 つ目の区分に見える。読み手は、既にあるどのラベルに当たるかを考えることになる。今回の 3 つの中で負荷が最も大きかった
- **動作の語のラベル (残す・消す) は、状態と、これから行う処理を混ぜる**。行が今どうであるかを読み手が知りたい場面で、処理の予定を答えている

## 起票時の案の見直し

起票時に Claude が書き下した案 (「肯定形の単語で書く」を語の形で判定する、規範 8 の近くに足す) を、次のように見直した。ユーザーの指摘は「基本的に」と例外を認めており、見直しはその範囲の中での解釈。

- **語の形 (否定の接頭辞の有無) で一律に判定すると、良いラベルまで弾く**。「不使用」は否定の接頭辞の付いた語で、今回の 3 つのラベルの 1 つとして使われた。「未読」「無効」も同じ。
  分かりにくさの元は、状態を 1 語で名指していないこと (別の属性の否定の句で言い表す・決まった語の外の語を持ち込む) と読む
- **ja-writing に置くだけでは、今回の場面に届かないおそれがある**。今回つまずいたのは、作業中のチャットでの説明だった。
  ja-writing は、文言の手直しを頼まれたときとキーワードで起動する skill。`_claude/CLAUDE.md` のスキル表の ja-writing の行に、説明や報告を書く場面の語は無い
- **規範 8 (否定対比) とは対象が違う**。規範 8 は文の中の「A ではなく B」の構文で、今回は状態・区分を名指す語の選び方。規範 8 の下に足すと、構文の規範と語の規範が混ざる

## 対応方針

1. `_claude/skills/ja-writing/SKILL.md` の規範 5「同じものは同じ語で呼ぶ」に項として足す (正本)。「決まったラベルの外の語を足さない」は規範 5 の既存の項 (同じものを別の語で呼ばない・画面に出ている語と一致させる) の延長なので、新しい規範は立てない。足す項:
   - 状態・区分・ラベル・表の見出しは、その状態を名指す 1 語で書く。別の属性を否定する句 (`論理削除されていない`) で言い表さない (✓ `有効`・`使用中`)
   - 否定の接頭辞の付いた語 (`不使用`・`未読`・`無効`) は、状態を 1 語で名指しているので使ってよい
   - 区分のラベルが決まっていれば、説明でもそのラベルだけを使い、外の語 (`対象外`) を足さない。足すなら、どのラベルに当たるかを先に書く
   - 状態のラベルに動作の語 (`残す`・`消す`) を使わない。行が今どうであるかを状態の語で書く
2. 作業中の説明に届かせる。`_claude/CLAUDE.md` の「応答・成果物の長さとスコープ」に 1 行を足す (ユーザー決定 2026-11-26。下の別案ではなくこちら)。そこは毎セッション読まれる。
   - 1 行は ja-writing の項と内容が重なる。同じ節の、使わない語の 2 行 (ユーザー指示 2026-11-10・11-11) も ja-writing の規範 7 と二重に置かれている。この前例に倣い、ja-writing の項を変えるときは 1 行も一緒に直す
   - 別案は、スキル表の ja-writing の行に発動点 (状態・区分の語を選ぶとき) を足す形。重ならないが、表はキーワードで skill を読みに行く入口で、チャットで説明を書く場面では引かれにくい
3. 機械で拾えるかを試す。対象は textlint の自作の規則 (`_claude/skills/ja-writing/textlint/rules/`) だけ。`ja-writing lint` は本家 yomiyasu と同じ出力であることを記録との比べで守っているので、dotfiles だけの規則は足さない。
   表の見出しと箇条書きのラベルの位置にある「〜されていない」「〜していない」を候補に出せるかを見る。否定の接頭辞の付いた 1 語は候補に出さない。誤検知が多ければ足さず、試した結果をこの issue に書く。
   この検査が掛かるのはファイル (issue・文書・Claude Code が書いた Markdown) だけで、チャットの説明には掛からない。今回の場面を防ぐのは 1 と 2
4. skill を直したら、規定どおり整合のチェックを観点を変えて 3 周回す。`bin/skill-eval ja-writing` も回す (`.claude/rules/skill-eval-after-edit.md`)
