# 122 bug: issues viewer に「押しても何も起きず理由も出ない」キーが 2 つある

起票日: 2026-08-27 / 出典: ux 監査 / priority: low〜medium

## この repo は既に「理由を返す」規律を持っている

`tui.go:handleKey` の status viewer 分岐には、pull を `u` で押した人へ
「pull は p です (status viewer では u を使いません)」とトーストを出す実装があり、
**「黙って無視すると『押したのに何も起きない』になるので理由を返す」**という
コメントが添えられている。以下の 2 箇所はその規律から外れている。

## (1) 本文モードで `i` が無反応 — `--help` / README は「`i` 閉じる」と案内している

- **再現**: `glogx` → `i` → `Enter` (本文の引き出しが開く) → `i`
- **見えるもの**: 何も起きない (本文も viewer も閉じない、トーストも出ない)。一覧モードでは
  `i` が toggle で閉じるので「本文を開いている間だけキーが死んでいる」形になる
- **該当**: `issues_view.go:handleBodyKey` に `"i"` の case が無い
  (`q/esc/h/left/enter` / `s` / `u` はある)。default の `pagerScrollKey` へ落ちて offset 不変で返る
- **ここが効く**: 同じ `handleBodyKey` の `case "s"` には**この件そのものの論理**が書かれている —
  「status viewer への横断は本文からも効く (一覧の s と同じ。**`--help` が「viewer 内のキー」として
  案内しており、本文だけ沈黙すると案内が嘘になる**)」。`i` も `--help` の同じ列挙と README に
  載っているので、同じ論理の適用対象
- **反証の試み**: `docs/issues-viewer-spec.md` で「一覧モードだけで受ける」と明記されているのは
  `n` (実ファイル移動) だけ。`i` についての記述は無く、本文モードの `i` を固定するテストも無い
- **対応**: `handleBodyKey` に `case "i": v.close()` を足す (README の「閉じて一覧へ戻る」と一致)。
  本文を先に畳む 1 段戻り案は `Enter`/`q`/`h` と重複するので、toggle 語彙の方が README と揃う

## (2) 一覧モードで `u` が無音

- **再現**: `glogx` → `i` (一覧モード) → `u`
- **見えるもの**: 何も起きない。同じキーが 4 通りに分かれ、**無音なのはここだけ**:

  | 場所 | `u` の動作 |
  |---|---|
  | git log 一覧 | `pull --rebase` 確認 |
  | issues 本文 | URL ピッカー |
  | status viewer | 「pull は p です」トースト |
  | **issues 一覧** | **無音** |

- **該当**: `issues_view.go:handleKey` の一覧 switch に `"u"` が無い
- **反証の試み**: `openURLPicker` の doc に**効かせない理由**は書かれている
  (「一覧で押せるようにするとキー 1 打ごとにファイルを読むことになり、しかも『その issue に
  URL があるか』は一覧に出ていない」)。ただし「**無音にする**」という判断の記述は無く、
  spec にも該当なし。理由があるのに画面に出していない状態
- **対応**: `setNotice("URL 一覧は本文を開いてから u で出します", false)` 相当を足す。
  優先度は (1) より低い (hint に `u` を出していないので誤解の入口が狭い)

---

## 対応 (2026-08-28)

### (1) 本文モードの `i`

`handleBodyKey` に `case "i": v.close()` を足した。**同じ関数の `case "s"` と同じ理由**
(「--help が『viewer 内のキー』として案内しており、本文だけ沈黙すると案内が嘘になる」) が
そのまま当てはまる。

⚠️ **本文だけ畳む 1 段戻りにはしなかった**: それは `Enter` / `q` / `h` が既に持っている語彙で、
README の「`i` で閉じて一覧へ戻る」とも食い違う。変異検証でもこの形 (`closeBody()` に変える) を
当てて red を確認した。

### (2) 一覧モードの `u`

`setNotice("URL 一覧は本文を開いてから u で出します", false)` を返すようにした。
効かせない理由自体は `openURLPicker` の doc にあったが、**画面に出ていなかった**。

これで `u` の 4 通りが全部「何かを返す」になった:

| 場所 | `u` |
|---|---|
| git log 一覧 | `pull --rebase` 確認 |
| issues 本文 | URL ピッカー |
| status viewer | 「pull は p です」トースト |
| **issues 一覧** | **「本文を開いてから」の通知** (旧: 無音) |

### 変異検証 4/4 red

本文モードの `i` を消す / 一覧の `u` を無音に戻す / 理由を空文字にする /
`i` を本文だけ畳む形に変える。
