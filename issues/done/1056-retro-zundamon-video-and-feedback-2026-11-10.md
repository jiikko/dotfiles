# 1056 (retro): zundamon-kaisetsu の動画づくりと、その振り返りの反映で踏んだこと

起票日: 2026-11-10

## 概要

社内の記事 (esa) から zundamon-kaisetsu で mp4 を作り (ubiregi-server のセッション)、その制作の記録から skill の改善点を挙げて直した
(issue 1055)。どこで踏んだかと、次に効きそうな改善を書く。

## 踏んだこと

1. **compaction の要約から書いた事実が、一次の記録と食い違っていた**。制作の後に文脈が要約され、要約から書いた
   「main が覚えている一覧」7 件のうち 2 件が制作の記録 (transcript) と合わなかった: 誤読を見つけた道具 (kana --check でなく読み分け候補の grep。
   その行だけの合成し直しも無かった)・資料が更新されたか (記録で確かめられない)。ほかに 2 件は原因の書き方が記録より粗かった
   (尺の超過の主因は台本が自分で決めた行数を超えたこと・目安の残り 9 件は書式の違いでなく導出)。漏れを探す係に「記録で裏を取る」を頼んでいたので、
   issue に写す前に訂正できた。頼んでいなければ、誤った事実が issue と improving.md に載っていた
2. **Edit ツールが、Go の文字列の `\u3000` を全角空白の字そのものに変えて保存した**。保存の直後には気づかず、変異の置換が
   「当たっていない」(rc=4) で止まって初めて分かった。この形は rule (`verify-execution-not-just-exit-code.md`) に既にあり、
   「書いた直後に表記を grep する」を守れなかった。この retro の下書きを Write ツールで書いたときにも、本文の `\u3000` が同じく字に変わった
   (読み直して気づいた。2 回とも、知っている rule を守るだけでは止まらなかった)
3. **skill の手順を省いた判断が、ユーザーの決定と食い違っていた**。書く前の裏取り (手順 3-1) を main の判断で省いたが、
   「省かない」という決定は improving.md (振り返りのときに読む文書) にだけあり、手順書 (SKILL.md) には無かった。
   作る最中に読む文書に決定が無かったので、省く判断を止めるものが無かった (SKILL.md の 3-1 に書いて直した)

## 次に効きそうな改善 (提案。採否はユーザー)

1. compaction の要約から事実 (回数・件数・どの道具が何を見つけたか) を issue や文書に写すときは、写す前に一次の記録 (transcript・ログ) で
   裏を取る。要約は主張であって証拠ではない
   - 既存の規範: `~/.claude/CLAUDE.md` の「時間を置いて質問を出し直すとき」の項 (要約は出した時点の状態しか持たない) と、
     `decide-layout-in-sample-renderer-first.md` の「要約にある『見せた / 合意した』は transcript で確かめる」。どちらも範囲が狭く、
     事実を issue・文書へ写す場面を含まない
   - 切り出し先: 既存の rule への追記 (`~/.claude/CLAUDE.md` の「レビュー方針」の「主張は証拠ではない」の項に、要約も主張に含めると 1 文)
   - **決着: 採用** (2026-11-10 にユーザーが採ると決めた)。`_claude/CLAUDE.md` の「主張は証拠ではない」の下に 1 項足した
     (commit: CLAUDE.md: compaction の要約にある事実も主張として扱う)
2. Edit / Write の入力に `\uXXXX` の表記があるとき、保存したファイルに同じ表記が残っているかを PostToolUse の hook で確かめ、
   字そのものに変わっていたら知らせる。rule を読んで守るのに頼ると、2 の形で守れない
   - 切り出し先: 新規 issue (hook)
   - **決着: 採用** (同日にユーザーが採ると決めた)。issue 1058 に起こした。測ると Bash の入力でも同じ形が起き、rule の範囲 (ファイルを書くツール) より広かった
3. ユーザーの決定は、それを破りうる手順の側 (作る最中に読む文書) に書く。振り返り用の文書にだけ置くと、作る最中には読まれない
   - 局所: zundamon-kaisetsu では SKILL.md の 3-1 に書いて直した。他の skill でも「決めたこと」を手順と別の文書に置く形があれば同じ形になるが、
     今は見つけていないので、一般化はしない
   - **決着: 却下** (局所の対処で閉じる)。他の skill で同じ形を見つけたら、そのときに一般化を考える
