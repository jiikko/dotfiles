# 1100 (retro): epic 1072 を 40 分で並列に進めたセッションの振り返り

起票日: 2026-11-20

## 概要

ユーザー指示「40 分で並列数を最大にして epic 1072 を進める。weekly の枠を使い切りたい」で、opus の係を同時に 4 体
(1077 の 2 本目・3 本目、1078 の `bin/ja-textlint`、1077 の 1 本目の敵対的レビュー) と、後から 1078 のレビューを 1 体起こした。
master に入ったのは main agent が直した 2 件 (float の長い仮数・`--fail-on` の小文字化) と issue の更新だけ。
係 3 体の成果はレビューか検査が済まず、worktree に残った。同じ日の続きの作業で、1 体ずつ直列に敵対的レビューと修正を回し、3 つとも master に入れた (1077・1078)。

## どこで踏んだか

- A. **係の締め切りの後に検査が走った**。重い検査 (`make -C src/ja-writing lint test` など) は serial-run の列で 1 本ずつになる。
  係 3 体と main agent が同じ列に並び、3 体とも、係への指示に書いた締め切り (07:22 に起こし、40 分の区切りの手前として 07:52 とした) を過ぎてから最後の検査の結果を得た (2 本目 08:00・3 本目 08:04・1078 の係 08:06。各係の rc のファイルの時刻)。
  並列にしたのは編集までで、検査は直列のままだった
- B. **変異を当てている最中に、係が同じ木の README を編集して run が止まった** (2 本目と 3 本目の係の両方。その変異 1 本が rc 9 で止まり、一覧の残りは走らなかった)。
  「検証が走っている間は同じ対象を編集しない」は `verify-execution-not-just-exit-code.md` にあるが、係への指示に書かなかった
- C. **本家の記録が 4,000 件あっても、`strconv.ParseFloat` の誤り (仮数の 0 が 800 個を超えて並ぶ入力) を素通りした**。記録の乱数の入力は数字の並びが最長 4 字で、
  長さの極端が無かった。見つけたのは敵対的レビュー
- D. **(続きの作業) 抜き出した記録で守るテストに、敵対的レビューが周ごとに別の穴を出した**。1077 の 2 本目の `report-shape.json` は、例外にならない書き換えを鍵ごとに 1 つだけ残していた。
  鍵に欄を足すたびに、足していない欄で分かれる退行が通った (path の最後の 2 段 → kind・subkind → hunk の tag など。周ごとに変異 1 本が緑)。4 周目の後に抜き出しをやめ、全部の書き換えを digest で持つ形にして閉じた (11.6MB を 1.07MB に)

## 次に役立ちそうな改善 (提案。実行はユーザーの判断を待つ)

1. **締め切りのある並列の作業では、共有の直列化 (serial-run の列・CI の concurrency) の待ちを見積もり、係の作業の締め切りをその分だけ前に置く**
   (待ち ≒ 1 本の所要 × 同じ列に並ぶ数)。A の一般形。切り出し先: `_claude/rules/subagent-model-tiering.md` の「指示を書くとき」に 1 項追記
2. **係に変異・長い検証を頼むときは、走っている間に同じ木を編集しないことを指示に書く**。B の一般形 (規範はあるが、係は読まない)。
   切り出し先: 同じく「指示を書くとき」に追記 (1 と同じ項にまとめてよい)
3. **標準ライブラリや外部の実装の上に写した関数を、本物を oracle にした差分で守るときは、乱数の入力とは別に長さ・桁数・入れ子の極端を明示して足す**。
   乱数の生成器の分布は自分が想定した範囲しか出さない。C の一般形。切り出し先: その項が指す `_claude/rules-checklists/mutation-verify-new-tests.md` の
   「差分テストの oracle」の節に追記 (`measure-external-cli-streams-separately.md` の「外部の道具の意味論を自分で書き直すなら」の項はそこを指しているので、本文は変えない)

4. **記録 (正解の出力) を抜き出して持つテストで、レビューが抜き出しの穴を見つけたら、鍵を細かくする前に「抜き出しをやめて全部を小さく持てないか」(digest・圧縮) を先に問う**。
   鍵を細かくする直しは、まだ鍵に入れていない次の分け方で同じ形に破れる。D の一般形。切り出し先: `_claude/rules-checklists/mutation-verify-new-tests.md` の「差分テストの oracle」の節に追記 (3 と同じ節)

局所的なこと (提案にしない): 変異が構文エラー (第 3 の結果) になった 3 本 (lint 側 2・3 本目 1) は、1077 の残りに当て直しとして書いた。
