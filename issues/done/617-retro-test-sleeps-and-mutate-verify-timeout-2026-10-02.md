## どこで踏んだか / 何が回りくどかったか

1. **棚卸しの数え方が書き方の変種を落とした。** `sleep +[0-9.$]` で数えて、`sleep "$x"` の 5 行を落とした。
   反証レビューに指摘されるまで、107 行を全数だと書いていた。
2. **待ちを外したことで、その待ちが担保していた検出が消えた** (2 回)。
   - 並列ランナーのテスト: `sleep 1` が「失敗の後にまだ走っている target」を作っており、それが fail-fast の退行を見る唯一の手段だった。
   - go_autobuild のテスト: 同期の合図 (`GO_AUTOBUILD_PENDING`) だけで判定する形にしたら、合図なしに裏で起こす退行が見えなくなった。
   - どちらも敵対レビューで再現された。`avoid-wall-clock-assertions.md` は「窓以外に何を担保していたかを列挙する」と書いているが、
     列挙したのは窓の側だけで、**その sleep が作っていた「退行が見える状態」**を列挙していなかった。
3. **タイムアウトでバックグラウンドへ回ったコマンドが走り続け、後の計測と作業ツリーを汚した。**
   - 3 回ループの検証が Bash の上限で背景へ移った。その後、ファイルを直して別の計測を始めたが、背景の 2 周目・3 周目が
     古い版の印のファイルを worktree の直下に作り続けた。
   - 「残骸が新しい版から出ている」と読んで調べ直す往復が 2 回あった。
4. **字句の検査 (615) の敵対レビューが 3 周かかった。**
   - 1・2 周目は heredoc の判定を正規表現で継ぎ足し、周ごとに別の書き方で素通りされた。
   - 3 周目に「引用符の外の `<<` を探し、タグは bash の規則で読む」へ軸を変えた。
   - 脅威モデルに「意図的な迂回は含めない」を最初から書いていれば、3 周目の形 (組み立てないと起きない組み合わせ) は対象外にできた。
5. **子を背景・別グループで起こす変更が、端末の job control を壊した。**
   - mutate-verify の最初の版は run を別のプロセスグループにした。その結果、`stty tostop` の端末で出力が SIGTTOU で止まり、Ctrl-Z も run に届かなくなった。
   - 同じグループに戻すと、今度は非対話の bash の `( … ) &` が INT / QUIT を無視した状態で子を起こすことが出た。
   - どれも敵対レビューが pty で実測して見つけた。自分の確認は非対話の経路だけだった。
6. **完了をポーリングで待つ形に変えたら、全体が遅くなった。** 固定 0.1 秒の刻みで 1 run あたり平均 0.05 秒遅れ、
   42 ケースのテストが 34 s → 58 s になった。呼ばれる回数 × 刻みの見積りをせずに書いていた。
7. **「プロセスが残っていない」を見る検査が、何も検査していなかった。** `bash -c 'sleep 60' <印>` はコマンドが 1 つなので、
   bash が exec に置き換え、印が引数から消える。`pgrep -f <印>` は実装が正しくても誤っていても当たらなかった (敵対レビューの実測)。
8. **自分の新しい関数の中で `$5` を使った。** 位置引数は関数自身の引数で、空になる。ゲートのファイルが worktree の直下にでき、待ちが毎回上限まで伸びた。
9. **直列の指示に反して、サブエージェントを 2 体同時に起こした。** 敵対レビューを背景で走らせたまま、書き換えのエージェントを起こした。気づいてすぐ止めた (書き込みは無し)。

## 次に効きそうな改善 (切り出し先の提案。実行はユーザーの判断)

| # | 一般形 | 切り出し先 |
|---|---|---|
| A | **待ち (sleep・固定の上限) を外す / 置き換えるときは、その待ちが作っていた「退行が見える状態」を列挙する**。順序 (失敗の後にまだ走っている) や時間差 (合図なしの副作用が起きるだけの時間) が、別の退行を見る唯一の手段になっていることがある。置き換えたら、その退行を当てる変異を 1 本ずつ当てる (2) | 既存への追記: `_claude/rules/avoid-wall-clock-assertions.md` の「担保していたものを列挙する」の項 |
| B | **コマンドが Bash の上限で背景へ回ったら、それを止めるか終わるのを見届けるまで、同じ対象を編集・計測しない**。背景の続きが古い版で走り続け、成果物や残骸が新しい版のものに見える (3) | 既存への追記: `_claude/rules/verify-execution-not-just-exit-code.md` の「非同期・background の完了」節 |
| C | **字句の検査の脅威モデルに「意図的な迂回を含めるか」を、書く前に決めて書く**。決めていないと、組み立てないと起きない形まで周を重ねて潰しにいく (4) | 既存への追記: `_claude/rules/adversarial-review-own-safeguards.md` §8 の ①脅威モデル |
| D | **子を背景で起こす / プロセスグループを分ける変更は、端末で使われる経路 (前景のグループ・SIGTTOU / SIGTTIN・Ctrl-C / Ctrl-Z) と、非対話の bash が背景の子に INT / QUIT を無視させることを、pty で確かめる**。非対話の経路だけの確認では出ない (5) | 既存への追記: `_claude/rules/adversarial-review-own-safeguards.md` §1 の表に 1 行 (「端末から使われる」条件) |
| E | **待ちをポーリングに変えるときは、呼ばれる回数 × 刻みの平均遅延を先に見積もる**。刻みは短く始めて伸ばすか、完了を `wait` で受ける形を先に検討する (6) | 既存への追記: `_claude/rules/avoid-wall-clock-assertions.md` の「待つために sleep を書かない」節 |
| F | **プロセスの引数の印で生死を見る検査は、印がシェルの exec 最適化で消えないかを確かめる** (`bash -c '<1 コマンド>' 印` は exec され、印が消える)。印を付けた形で 1 回 `pgrep` が当たることを先に見る (7) | 既存への追記: `_claude/rules/mutation-verify-new-tests.md` の「観測の設計」 (生死・存在の判定の項の隣) |
