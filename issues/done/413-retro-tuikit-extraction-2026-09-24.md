`fix(tuikit,glogx): 敵対レビュー 3 周目 (9c176cf0 / b7a095c9) の指摘に対応する` までの 6 commit
(anim / layout / listnav / sgr / termwidth / widthenv と、glogx 7 画面の移動キーの語彙の統一)

## どこで踏んだか

1. **コードを別 module へ移すと、元の場所に「パスで」掛かっていた検査が黙って外れた**。
   敵対レビュー 3 周ぶんで、移設が外した守りを 4 つ見つけた (自分では 1 つも先に気づけなかった):
   - VS16 リテラル / 2 本目の幅エンジンの走査 (`WalkDir(".")` なので tuikit が対象外になった)
   - ruleguard の `padViaPadSpaces` (glogx の lint 設定にしか無い)
   - depguard の `render-pure` (`**/render.go` にしか掛からない)
   - 走査の根を一覧にしたあと、一覧から外す退行を止める検査が無かった
   どれも移設直後は全テストが緑で、「挙動を変えない移設」の自己申告を裏付けているように見えた。

2. **確保の退行を止めるテストが、今の toolchain では名指しした退行を観測できなかった**。
   埋め草を `strings.Repeat` へ戻す変異が、確保回数の上限テストを緑のまま通った。原因は Go 1.26 の
   `strings.Repeat(" ", n)` が n <= 128 なら確保しないこと (実測)。幅 80 の fixture では埋め草が
   境界より短く、退行が等価変異になっていた。境界を実測して幅 250 のケースを足し、red を確認した。

3. **録画ツールの描画崩れを、あやうく部品のバグとして直しにいくところだった**。vhs の gif では詳細を
   開ききるとカーソル行の反転が消えたが、隔離した tmux の `capture-pane -e` では正しく出ていた。
   原因は xterm.js が East Asian Ambiguous の `○` を 2 桁と数えること。

## 残課題 (切り出し先)

- [x] **提案 1** (→ `list-masked-failure-modes-before-removing-guard.md` の発動点に追記済み): 発動点に
      **「コードを別の module / ディレクトリへ移すとき」**を足す。移設は、元の場所に掛かっていた
      検査 (lint 設定の path / exclusions、`WalkDir` で走る走査テストの根、CI の paths filter、
      depguard の files) を**何も言わずに外す**。移す前に「元の場所に掛かっていた検査」を列挙し、
      移し先に張り直すか、外す理由を書く。
      → 既存ルールへの追記。「冗長だから外す」と同じく**守りが減る変更**だが、外す意図が無いまま
      外れるので、既存の発動点 (「冗長だと判断した瞬間」) では発動しない

- [x] **提案 2** (→ `mutation-verify-new-tests.md` の fixture の項に追記済み):
      **性能・確保のガードの変異が緑なら、その退行が今の toolchain で測定値を変える入力域を実測してから
      判定する**。標準ライブラリの最適化 (短い繰り返しを定数から返す等) で、ある入力域では退行が
      等価変異になる。fixture をその域の外 (境界より大きい入力) にも置く。
      → 既存ルールへの追記 (fixture の選び方の項の具体例として)
