# 849 (bug): lan-manager の初期設定で固定し直すと、前と違う IP になる (アダプタの差し替えで冪等でない)

起票日: 2026-10-20

## 概要

LAN アダプタを差し替えて固定 IP が外れた Mac を初期設定で固定し直すと、前の IP ではなく空いている最小の IP を振っていた
(m2macmini が 192.168.100.12 → .15)。差し替えても冪等なセットアップにしたい (ユーザー要望 2026-10-20)。

## 原因

- 固定 IP はネットワークサービスごとの設定で、差し替えた先のアダプタのサービスは DHCP (169.254) から始まる。Plan はそれを
  「相手の固定が未完了」と正しく読み、手順を出し直す (手順の組み立て自体は冪等)
- 番号は `usedIPs` に無い最小の番号から選んでいた。`usedIPs` は台帳の全員の内部 IP を数えるので、固定し直す Mac 自身の前の IP も
  使用中になり、毎回新しい番号になった (台帳も新しい番号へ書き換わる。繋ぐ先は有線の名前なので動くが、IP を直に書いた接続先は古い IP を指す)

## 対応 (「初期設定で固定し直すと前と同じ IP を振る」)

- 前の IP の候補を順に試し、帯の中で使われていなければ振る (`setup.PickIP`): 相手は台帳の内部 IP → 有線の名前の広告の IP → この起動で振った IP、
  この Mac は自分の有線の名前の広告の IP。使えなければ従来どおり空いている最小の番号
- 使用中 (`usedIPsExcept`) から固定し直す Mac の前の IP を除く。その Mac が今 Bonjour で見せている IP は数える
- 1 台の中の 2 つの I/F に同じ IP が乗るのを防ぐ: 相手の観測に全部のサービスを残し、同じ Mac の別のサービスが繋がったまま・繋がっているか
  読めないまま前の IP を持つなら振らない (理由を板に出す)。抜いたアダプタのサービスが持っているだけなら振り、両方を同時に繋がないよう板で知らせる
- `netinfo.Service` に `IfRead` / `IfGone` を足した (ifconfig の失敗を黙って「繋がっていない」に倒していた。I/F が無いときは rc=1・
  stderr に `interface en99 does not exist`。2026-10-20 macOS 26.7 で実測、LANG=ja_JP でも英語)

## 検証

- mac-lan-manager の test / lint、make test-lint、go_packages_index、glogx の lanview・app の test が緑
- 変異 21 本がすべて red (内訳は commit message)
- 実機の固定し直しは未確認 (相手の IP を本当に変える操作で、デッドマンスイッチの窓もある。次にアダプタを差し替えたときに板に
  「(前と同じ IP)」が出るかで確かめる)

## レビューの決着

opus の敵対的レビュー 3 周 (codex は週の枠が 100% で使えなかった。issue 本文は実装のレビューの後に書いた記録で、本文だけの反証レビューは通していない)。

- 1 周目 (反映): 前のアダプタが繋がったままでも Bonjour は I/F ごとに相手の IP を 1 つしか持たず、前の IP を新しい I/F にも振る (P1) /
  この Mac の固定で開いている相手の試した IP を数えない / 台帳の内部 IP が帯の外だと広告の IP を試さない / 台帳のこの Mac の行で自分の前の IP を塞ぐ /
  PickIP と SuggestIP で使用中の判定が 2 つ
- 2 周目 (反映): ifconfig を読めない (ssh が途中で落ちた) と抜いたと読む / 前の IP を振らなかった理由が板に出ない / サービス名の無害化 /
  呼び出し元が 0 になった SuggestIP
- 3 周目 (反映): Device の無いサービス (VPN) も "does not exist" で落ちる / 終了コードを見ない / 案内の文言
- 記録だけ (直していない。再提起には実測を添える):
  - Active は link が上がっているかで、I/F に IP が乗っているかとは別の軸。macOS は link が落ちると手動の IPv4 も外すと理解しているが実測していない
  - `m.self.Services` は読んだ時点の値: 読んだ後に前のアダプタを差し直すと古い Active のまま前の IP を振りうる (前からある古さ。r で読み直せば消える)
  - glogx の板と単体の 2 プロセスは振った番号 (claimed) を共有しない (前から受容済み)
