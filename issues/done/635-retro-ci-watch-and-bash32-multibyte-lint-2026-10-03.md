## 踏んだ所 / 回りくどかった所

### 1. 置換の失敗で後段を止めず、未反映の下書きを「反映済み」と書いて push した (634)

- 1 本の Bash に「python で issue を置換 → `git add` → `git commit` → `git push` → worktree の削除」を改行でつないだ。
  1 か所目の置換が assert で落ちたのに、後段が全部走った
- commit message には「反証レビューの指摘を反映済み」と書いた。実際の中身は下書きのままだった。
  push の後、worktree まで消えてから気づいた。反映は別の commit で入れ、message でも訂正した
  (commit「issues: 634 に反証レビューの指摘を反映する (起票の commit では反映できていなかった)」)
- 既存の rule で覆われている。`verify-execution-not-just-exit-code.md` の「検証の手順は `&&` で繋ぎ、`;` で繋がない」と、
  `.claude/rules/worktree-per-session.md` の「push が成功したことを確認するまで worktree を消さない (`&&` で繋ぐ)」が当たる。
  改行で繋いだので、どちらも踏み損ねた。630 の push の手では、テストの rc で後段を止めていたのに、この手では止めていなかった

### 2. 字句の近似の検査を 1 つずつ直す周回が収束せず、本物を正解役にして閉じた (633)

- 検査は、bash 3.2 が `"$rc。"` を読み違える形を字句で落とすもの。敵対的レビュー (opus) を 3 周回し、3 周とも壊された
- 1 周目と 2 周目は、どちらも「状態を見失って、後ろの行が引用の中に見えて素通りする」形だった。
  2 周目の指摘では、実ファイル 4 本の末尾 200 行あまりが実は無検査だった
- 2 周続いたところで、rule (`adversarial-review-own-safeguards.md` §7 → 0-B) どおり近似の直しをやめた。次の 2 つで閉じた
  - **正解役**: この不具合は UTF-8 のロケールでだけ起きる。同じ fixture を `/bin/bash` 3.2 で `LC_ALL=C` と UTF-8 の 2 回走らせ、
    食い違えば本物の違反とした。検査の判定とこの答えを全 fixture で突き合わせる形にした。
    入れた直後に、fixture の側の空振りが 4 件見つかった: 何も出力せず 2 つのロケールで差が出ない 2 件と、
    前置きで変数を定義したため既定値 (`${x:-…}` の後ろ) が評価されていなかった 2 件。
    手で決めた期待値の誤り (二重引用符の中の `${x:-$'…'}` を通すと書いていた) は、その前に bash 3.2 で直接確かめて見つけた
  - **見失いの可視化**: ファイルの末尾で字句の状態が初期に戻っていなければ失敗にした (fail-closed)。
    近似が状態を見失うと黙って素通りする形を、見える失敗に変えた
- 回りくどかった所: 1 周目の後、正解役を持ち込む前に近似を 1 周ぶん直した。「環境差で起きる不具合なら、起きない環境が対照になる」と
  最初に気づいていれば、正解役は 1 周目から作れた

### 3. CI の結果を「最新の run」で待ち、関係の無い run の緑を拾いかけた (634 で道具化)

- `gh run list --workflow tests.yml --limit 1` が 2026-09-04 の run を返した。その success を待ち終わりとして読みかけた。原因は未確認
- 後続の push が前の run を cancel するので、その run を追う待ちのループを 3 回手で書いた。1 回は判定式の誤りで、完了の前に抜けた
- run の ID を名指しして待ち直して気づいた。「この commit の run を名指しする」口が ci-log に無いことは 634 に起こした

### 4. 報告の中で、原因を確かめずに断定した

- 3 の古い run について、完了報告で「名前が同じ古い workflow が混ざった」と書いた。調べ直すと同じ `tests.yml` の run だった
- CLAUDE.md「レビュー方針」の「主張は証拠ではない」で覆われている。次の報告で訂正した
