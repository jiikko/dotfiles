# 871 (test): treefiler の仮想化の等価性のテストが負荷の下で揺れる

起票日: 2026-10-22

## 概要

`src/treefiler/filer/virt_test.go` の `TestVirtualizedRandomOpsMatchFull` (仮想化した Model と全部を動かす Model の毎フレームの画面を比べる)
が、線の 1 セルの**色だけ**違って落ちることがある。issue 870 の作業中に `TREEFILER_VIRT_SEEDS=300` で回して見つけた。

## 詳細

観測 (2026-10-22。どれも同じマシン・go1.26.0。load average は 20〜90 の間で揺れていた):

- 870 の変更 (線の格子のセルを値で持つ) を入れた木で、300 本の 1 回目に seed=23 が赤:
  `[キー . → キー 0 → 速さ slow → キー j] キー j の遅いフレーム 1: (23,7) が違う`。文字は同じ `╚` で、fg だけ
  仮想化 `[163.75 186.5 255]` / 全部 `[146.54 99.44 117.6]`
- 同じ木で seed=23 を単独で回すと緑。300 本の 2 回目は全部緑。origin/master (870 の変更の前) でも単独・300 本とも緑
- **波紋の肘の切り詰め (870 の 1) より前の commit (`e9506403^`) では、seed=23 は単独で毎回赤** (色の向きは上と逆)

見立て (起票時。**半分外れ**。下の「結果」): 線の色は持ち主のフォルダの「配下の新しさ」の熱の色で、それを数える裏の走査 (`filer/walk.go` の walker) は時計を
`time.Now` で持ち、Model に注入した時計 (`Options.Now`) を使わない。2 つの Model で走査の結果が届くフレームが実時間の速さ次第でずれ、
片方だけ熱の色が変わる。1 フレームが重かった旧版 (切り詰めの前) では、ずれが毎回起きる時間になっていた、という読み。

## 対応方針

1. 見立ての確認: seed=23 の失敗のフレームで、2 つの Model の walker の結果 (`recs`) と熱の年齢 (`heatAge`) を出して比べる
2. 確かなら、比べる前に 2 つの Model の走査の結果が全部届くまで待つ (色を決めるのは結果の到着の順なので、walker の時計を `Options.Now`
   にそろえるだけでは直らない見込み。熱の年齢 `heatAge` は結果 (`recs`) の有無と `m.now` で決まる)

再開の条件: 次にこのテストが CI か手元で落ちたとき、または treefiler の walker / 熱の色を触るとき。

## 結果 (2026-10-23)

`GOMAXPROCS=1` で再現した (負荷の下で裏の goroutine が後回しになる形を作る)。失敗の瞬間に 2 つの Model の状態 (走査の結果・
セルの線の部品と持ち主・熱の年齢・波紋・光の粒) を出して比べ、揺れは **2 種類**あった:

1. **光の粒 (ビーズ) の尾の長さ** (seed=23 のセル (23,7)。起票時の観測はこれ)。走査の結果も線の部品も同じで、違ったのは粒の速さ
   (`beadVel`) だけ (47.78 / 63.77)。尾の長さは速さで決まる。速さは経過時間が 0 のフレーム (同じ時刻の Advance・描くだけ) では更新されず、
   カーソルが変わって粒が走り直した最初のフレームでも**前の走りの速さ**が残っていた。前の走りは経緯で違いうるので、同じ画面で尾が 1 セル
   ずれる。製品側の小さな不具合 → `filer/model.go` の `stepBead` で、走り直すときに速さも 0 に戻す
2. **走査の結果が届くフレーム** (seed=49 などのステータスバーの数字。`r` やライブ更新の後)。片方の Model だけ走査が終わっていた
   (busy=true / false)。起票時の見立てはこちらに当たる。仮想化と関係のないテストの組み立ての問題 → `virt_test.go` の `quiet`: フレームを
   進める前に、両方の Model の裏の計算 (走査・`e` の展開) が終わるまで待つ (結果は次の Advance で両方とも同じフレームに取り込まれる)

実測 (`GOMAXPROCS=1 TREEFILER_VIRT_SEEDS=60 go test -v -count=2` を 8 セット。種ごとの実行の数を `-v` の行で数えた):
直す前 (origin/master) 960 回中 **10 回赤** (seed 23・41・49) → 直した版 960 回中 **0 回**。片方ずつ外すと (各 4 セット): 待ちだけ = 480 回中 1 回
(seed 23、粒の尾) / 粒の速さだけ = 480 回中 2 回 (seed 49、ステータスバー)。どちらの直しも要る。
起票時に書いた「origin/master では単独でも 300 本でも緑」は、負荷の軽いときの観測で、`GOMAXPROCS=1` では約 1% で落ちていた。
