# av1ify: 開始シフト + 音声を長めに残す形が、avsync 初回ゲートを潜って検知されない

起票日: 2026-08-15
種別: bug
優先度: **P2** (実害級 (〜4s) の音ズレを ✅ 完了で通しうる。ただし av1ify 自身の encode が
この形を作る実証は無く、postcheck という網の識別能力の話。058 の敵対的レビューで発見)

## 何が起きるか

`__av1ify_postcheck` の avsync 判定は 2 段構え:

1. **初回**: 宣言 duration ベースの A/V drift が閾値 (既定 2.0s) を超えたときだけ FLAG
2. **再判定**: FLAG が立ったときだけ packet 実測 + 開始オフセットで降格を判断 (issue 058 で修正)

問題は **1 の初回ゲートを潜る形**。音声を後ろへ N 秒シフトし、音声の**長さ**を映像に近づける
(宣言 duration drift < 2.0 に収める) と、初回判定が FLAG せず、058 で足した開始シフト
チェック (`__av1ify_start_time`) に**構造的に到達しない**。開始オフセット N は最大 ~2×閾値
(≈4s) まで取れる。

## 再現 (実 ffmpeg 8.0.1 / ffprobe で実測)

```sh
# src: 30s testsrc + sine (h264/aac)
ffmpeg -y -f lavfi -i "testsrc=size=320x240:rate=30:duration=30" \
       -f lavfi -i "sine=frequency=440:duration=30" \
       -c:v libx264 -preset ultrafast -c:a aac -shortest src.mp4
# 音声を 3.8s 後ろへ + 28.1s ぶん残す (-t で切らない = 音声終端は映像より長い)
ffmpeg -y -i src.mp4 -itsoffset 3.8 -i src.mp4 -map 0:v -map 1:a \
       -af "atrim=duration=28.1" -c:v libx264 -preset ultrafast -c:a aac outG-enc.mp4
```

ffprobe 実測:

```
outG  0,video,0.000000,30.000000
      1,audio,3.776009,28.123220   ← 開始 3.78s シフト
format=duration 31.899229
```

`__av1ify_postcheck outG-enc.mp4 src.mp4` の出力に **avsync サフィックスが付かない**
(実測は h264 ハーネスのため「映像コーデック不一致」だけで rc=1 だが、本物の AV1 出力なら
avsync でもコーデックでも拾えず **rc=0 = ✅ 完了**)。

理由:
- 宣言 drift = |28.12 − 30| = **1.88 < 2.0** → 初回 FLAG せず、開始シフトチェックに未到達
- format duration の再生時間比較も Δ=1.9s で閾値内

3.78s の全編音ズレはリップシンク体感として明確に実害級 (2s 閾値の設計意図を大きく超える)。

## 058 との関係 (これはデグレではない)

058 の修正が守るのは「FLAG が立った後の降格の正しさ」だけで、そこは 058 の敵対的レビュー
(観点 B/C) が「壊せなかった」と実測確認済み。本件は初回ゲートを潜る**別の穴**で、058 の
修正コメントも「宣言ベースの初回判定を素通りするズレは変更前 (997d078) も検知しておらず、
ここで守るのは降格の正しさだけ」と明示的にスコープ外と宣言している。997d078 でも同じく
素通りする (初回 FLAG しないため再判定に入らない)。

## 対応方針 (案)

058 の敵対的レビュー (観点 A) の提案:

- **開始オフセット (start_time) の関係差チェックを、初回ゲートの内側でなく常時 (宣言 drift の
  大小に依らず) 走らせる**。`__av1ify_start_time` は ffprobe 1 フィールド × 4 の安価な検査で、
  058 が「双方向化 (ok→FLAG) を避けた」理由 (packet 走査 4 本の常時コスト) には該当しない。
  start_time だけなら常時化してもコスト増はほぼ無い
- ⚠️ 常時化すると誤検知 (false positive) の回帰リスクが戻るので、058 の観点 C レビュー
  (AAC priming は実測 20〜50ms で閾値 2.0s の 2 桁下 / TS 等の全体ベースシフトは関係差で相殺)
  の結果を踏まえ、**関係差 (a_start − v_start の src/out 差分) で見る**こと。絶対 start では
  正常な TS 抜き素材で誤検知する

## 未確認

- **av1ify 自身の encode がこの形 (開始シフト + 音声を映像より長く残す) を作るか**は未実証。
  再現は `-itsoffset` の人工合成。postcheck は想定外の ffmpeg 挙動を拾う網なので、網の穴
  としては成立する (058 と同じスタンス)
- 常時 start チェックを入れたときの、壊れた宣言 duration ソース (058 の Test 14 が守る誤検知
  是正ケース) との相互作用 — start が揃っていれば降格されるはずだが要実測

## 対応記録 (2026-08-15)

対応方針の案どおり、**開始オフセットの関係差チェックを常時化**して解決した。

- 開始シフト判定 (`__av1ify_start_time` × 4 + `__av1ify_calc_drift`) を 058 の降格ブロック内から
  外へ出し、宣言/終端の drift とは独立した**第 2 の avsync 信号**にした。最終判定は
  `drift_bad == 1 || s_bad == 1`。duration が測れなかったケース (Test 7 の全パス N/A) でも
  開始シフトだけは判定できるので、duration 取得の成否にも従属させていない
- 計算失敗時の既定を反転: 降格ブロック内では `s_bad=1` (検査不能なら降格しない) が正しかったが、
  常時チェックでは同じ既定が全ファイル誤検知になるため `s_bad=0` (宣言/終端に委ねる) にした
- **「測れなかった」と「測って閾値内だった」を別変数に分けた** (`s_measured` / `s_bad`)。
  降格ゲートは `s_measured == 1 && s_bad != 1` でしか降格しない。1 変数で兼ねると、常時判定側の
  fail-open (`s_bad=0`) が降格ゲートの fail-closed を黙って壊す (下記レビュー参照)
- 降格ブロック側で開始を見る条件自体も残した。最終判定は s_bad が拾うので verdict には影響しないが、
  外すと「正常と判定」と報告した直後に avsync で NG にする矛盾した出力になる
- 理由を stdout の print から NG 理由の文字列へ移した (`音ズレ疑い (開始シフト Δ=3.776009s ...)`)。
  `__AV1IFY_LAST_NG_REASON` にも載るので ng_list から追える

検証:

- **実ファイル A/B**: issue の再現手順 (`-itsoffset 3.8` + `atrim=duration=28.1`) で作った
  `outG-enc.mp4` を実 ffprobe 経由の `__av1ify_postcheck` に通し、HEAD (997d078 系) では
  `映像コーデック不一致` のみ = avsync 素通り、本修正後は `音ズレ疑い (開始シフト Δ=3.776009s)`
  + codec の 2 件で NG になることを実測
- **誤検知の実測確認**: 常時化で新たに危ないのは「絶対 start を持つ素材」。実 ffmpeg で
  TS (`video 1.423 / audio 1.400` → mp4 出力で `0.033 / 0.000`) を実測し、関係差は 0.0098s で
  閾値 2.0s の 2 桁下に収まることを確認。mkv/flv は start_time を N/A にせず実値を返し、
  avi はシフトを表現できず duration 側に出るため、start_time 欠落起因の誤検知経路は見つからなかった
- **変異検証**: Test 19 は最終判定から `|| s_bad == 1` を落とすと red、Test 20 は開始判定を
  絶対 start (映像のベースラインを引かない形) にすると red になることを確認。どちらも他テストは
  green のままで、検知側と誤検知側の不変条件が分離して守られている
- avsync テスト 20 本 (assert 30 本) green / `make test` green

## 敵対的レビュー (観点を 2 つに分けて実施)

「自分で作った検査・ゲートは自己レビューで閉じない」(`_claude/rules/adversarial-review-own-safeguards.md`)
に従い、①検知漏れ ②誤検知・正常系の破壊 の 2 観点で red team を回した。両者とも実 ffmpeg で
ファイルを作って `__av1ify_postcheck` を実行している。

採用した指摘:

- **降格ゲートの fail-safe 方向が逆転していた** (②の P2)。常時判定に合わせて `s_bad=0` を既定に
  したことで、開始判定の計算が失敗した場合に「本物の時間シフトが黙って正常へ降格される」経路が
  できていた。`s_measured` を分離して修正し、**偽 ffprobe + 開始判定だけ失敗させるハーネスで実測**:
  ガード無しでは `rc=0` (「正常と判定」を出して ✅ 完了)、ガード有りでは avsync で NG になることを確認
- **Test 18 が降格ゲートの条件を独立に検証できていなかった** (②の P3)。最終判定の OR に吸収され、
  ゲートから開始判定を外しても green のままだった。降格時にだけ出る「正常と判定」の不在を
  assert に追加し、同じ変異で red になることを確認

採用しなかったもの (記録):

- **コンテンツレベルのシフトは素通りする** (①の P1。`adelay=5000` + `atrim` で音声内容だけ後ろへ
  ずらし総尺を揃えた出力は、宣言 duration・packet 実測の終端・start_time のどれにも痕跡が残らず
  実測で素通り)。これは本変更のデグレではなく、**メタデータだけを見る網の設計上の射程外**
  (検出には音声内容の相関解析が要る)。av1ify の現行 encode 経路は音声フィルタを通さないため
  この形を作らない。将来 audio filter (loudnorm/afade 等) を入れるなら再評価する
- **開始オフセットには packet 実測のフォールバックが無い** (①の P2)。終端は「宣言 → packet 実測」の
  2 段だが開始は宣言値のみ。宣言 start_time が嘘をつく実例は観測されていないため、推測で防御コードは
  足さず未確認リスクとして記録する

誤検知側は mkv/webm/ts/flv/mpg/avi、AAC/Opus の priming、TS の PCR ベースオフセットで 10 本以上
試して**再現せず** (ノイズは実測 0.007〜0.033s オーダー)。追加した ffprobe 4 回のコストは実測 ~90ms。

未確認のまま残るもの:

- av1ify 自身の encode がこの形を作る実証は依然として無い (網の穴を塞いだだけ、というスタンスは 058 と同じ)
- 60s 超のシフト・負方向シフトは 058 の未確認事項をそのまま引き継ぐ (start_time は宣言値なので
  走査区間には依らない / calc_drift は絶対値比較なので方向に依らない、という式上の確認のみ)
- 上記「採用しなかったもの」2 件 (コンテンツレベルのシフト / 宣言 start_time の信頼性)
