# 1032 (retro): treefiler の New のカーソルの持ち越し (1020) の振り返り

起票日: 2026-11-05

## 概要

treefiler の仮想化の等価性のテストが全体 run の seed 269 だけで落ちる flake (1020) を、観測で本体の不具合 (`New` が設定を読む前の package の並び `order` でカーソルを決めていた) と突き止めて直したセッションの振り返り。
観測から原因の確定までは対応方針どおりに進んだ (状態の比較 → 出発点の項目の違い → `root.last` → `New`) ので、ここには書かない。

## どこで踏んだか

1. **呼び出し元の挙動を記憶で書き、ユーザーが頼んだセルフレビューまで残った**
   - 修正のコメント (`filer/model.go` の `New`)・回帰テストのコメント・1020 の本文・commit の本文に「glogx は F を開くたびに New する」と書いた。
     実際に glogx が `filer.New` を呼ぶのは、初めて F を開くときと、前と違うフォルダで開くときだけ (同じフォルダなら Model を使い回す)
   - 修正が要ることは変わらない (違うフォルダで開けば前の Model の並びが残る) が、影響の範囲 (誰が・いつ踏むか) を言い過ぎていた
   - 最終ゲートの敵対的レビュー (opus、読み取りのみ) は、コードの不変条件を攻めて P1・P2 なしで、この文は見なかった。セルフレビューで glogx の呼び出し元を読んで気づき、push の前に 4 か所を直した
   - 規約には「レビュー・調査の出力にある数値・入口・経路を issue や文書へ写すときも、写す前にコードの定義を 1 回引く」(`claude-md-maintenance.md`) があるが、
     対象が「レビュー・調査の出力」で、自分の記憶から書く呼び出し元の挙動は名指ししていない

2. 起票時の種別 `test` が、原因を見ると本体の不具合 (`bug`) だった。ファイル名は規約どおり変えず、本文に書いた (局所。規範は要らない)

## 提案

- **A. 不具合の影響 (どの呼び出し元が・いつ踏むか) をコメント・issue・commit に書くときも、書く前にその呼び出し元のコードを読む。記憶の頻度の語 (「毎回」「開くたびに」) はそのまま書かない**
  - 切り出し先: `_claude/rules/claude-md-maintenance.md` の「書き方」の、引く行をその場で読む項への追記 (既存への追記)
- 却下: 敵対的レビューの依頼に「diff の中の文 (コメント・commit の本文) の事実の主張も反証の対象にする」と足す案。書く時点で読めば A で止まり、レビューの観点を増やすとそのぶん本題 (不変条件) が薄くなる。A の後にも同じ形が出たら再評価する

## 局所 (直さないもの)

- `order` が package に 1 つなので、設定の違う Model が 2 つ同時に生きると食い違う形は残る。glogx の F は Model を 1 つしか持たないので今は起きない (1020 の「残る形」に記録済み)。
  Model を 2 つ同時に持つ呼び出し元を足すときが、`order` を Model ごとに持たせる trigger
