# 813 (retro): ずんだもん解説の動画 2 本と、ラベルの改行の検査 (810〜812)

起票日: 2026-10-17

## 概要

シャボン玉 (PDF の調査レポート) とクリーンアーキテクチャ (ChatGPT の調査レポート) の動画を作り、その振り返りから skill の改善 (810・811)
と、ラベルの意図しない改行を描画で測る検査 (812) を足したセッションの振り返り。

## どこで踏んだか / 回りくどかったこと

1. **字数の上限で守っていた見た目が、描画では崩れていた**。重要語は「16 字まで」、タイトルは上限なしで、どちらも検査は通るのに、
   mp4 ではタイトルが 2 行・重要語が「図は / フォルダ構成ではな / い」になった。SKILL.md に「文節は 9 字以内に」と書いてあったが、
   台本を書いた本人 (私) が破り、確認役のサブエージェントも拾わなかった。ユーザーが mp4 を見て指摘するまで誰も気づかなかった
2. **計測の API が「測れない」を 0 の座標で返し、それを値として読んだ**。空白だけのラベルの Range は外接矩形が (0,0,0,0) になり、
   はみ出しの量として要素の座標そのものを返した (2 周目の敵対的レビューが本物の Chrome で再現)。直した「矩形が無ければ測らない」は、
   今度は display: none のラベルを黙って通した (3 周目が再現)。「無い」と「0」を同じ値で扱う形を 2 回続けて作った
3. **テストの偽物を、本番の期待の集合 (ExpectedLabels) から作った**。偽物は常に期待と一致するので、本物の計測 (player.html の JS) が
   壊れても、項目を返さなくなっても、テストは緑のままだった (1 周目の敵対的レビューの P2)
4. 局所: テストの `return a, b.String(), dispatch(...)` で、stderr を読む式が dispatch より先に評価されて空を読んだ (その場で直した)

## 次に効きそうな改善 (提案)

- [x] 1 → **見た目の制約を数値の上限 (字数・幅) で守っているなら、その上限の根拠になった描画を検査として残し、本物の描画で守る**。
  上限は「収まる長さ」の目安で、どこで折り返すか・どの環境で崩れるかを表さない。手順書の「〜を選ぶ」という規範は、機械で確かめない限り
  書いた本人も破る。切り出し先: `_claude/rules/decide-layout-in-sample-renderer-first.md` に追記 (見た目の意思決定の後、その見た目を守る側の規範)
- [x] 2 → **測る API が値を返さない・0 を返すとき、「測れない」と「0」を別の値で持つ**。空・描かれない・取得できないを 0 に畳むと、
  検査はそれを「問題なし」か「最大の問題」のどちらかに誤読する。切り出し先: `_claude/rules/verify-execution-not-just-exit-code.md` の
  「収集 0 件 / 対象 0 件は失敗扱い」に追記 (同じ形の観測版)
- [x] 3 → **テストの偽物を、検査が照合する期待 (production の期待の集合) から作らない**。作ると、偽物は検査対象と必ず一致し、
  本物の経路の退行を構造的に見えなくする。偽物は独立した入力 (固定の fixture) から作るか、本物の経路に届かないことを明記する。
  切り出し先: `_claude/rules-checklists/mutation-verify-new-tests.md` の「fake / stub」に追記
- 却下: 4 (Go の評価順の局所的な罠。その場で直し、汎用の規範にはならない)
