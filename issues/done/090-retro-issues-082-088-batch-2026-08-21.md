# 090 retro: issues 082-088 の一括対応で踏んだこと (2026-08-21)

起票日: 2026-08-21

対象セッション: issues 082〜088 の 7 件を順番に対応 (088 → 087 → 086 → 084 → 085 → 083 → 082)。
コミット 8 本 + 新規 issue 1 本 (089)。

## 1. PATH 先頭に置く shim が自分自身へ再帰して CPU を焼いた

bench に「hook が起動する tmux クライアント数」を数える shim を書いたとき、shim の中で
`exec "$TMUX_BIN_PATH" ...` と**相対名 (既定値 "tmux")** で呼んだ。PATH 先頭に置いた shim 自身へ
解決し直して無限再帰し、`-L <socket>` が延々と積み重なった `/bin/sh` が CPU を焼き続けた
(2 分以上気づかなかった。bench の出力はファイルへブロックバッファされていて見えなかった)。

同じセッション内の `tests/tmux/test_mark_seen.sh` では `command -v` で絶対パス化していたのに、
bench 側で同じ規律を落とした = **1 つの変更の中で同型の間違いを片方だけ直した**形。

- 切り出し先の提案: **`_claude/rules/` に新規** (例 `path-shim-must-resolve-real-binary.md`)。
  「計測・テスト用の shim / wrapper を PATH 先頭に置くときは実体を絶対パスで解決し、
  解決結果が shim 自身の下でないことを assert する」。既存の
  `tmux-probe-requires-socket-isolation.md` と同族 (自作の計測装置が本番を壊す形) だが、
  トリガが違う (socket 隔離ではなく PATH 解決)
- 補助的な気づき: **長時間走るバックグラウンド計測はブロックバッファで無音になる**。
  暴走に気づくのが遅れたのはこれが効いている (`stdbuf -oL` / 進捗を stderr へ etc.)

## 2. 関数の返し方を変えたら呼び残しが 1 件出た (既存テストが捕まえた)

`now_epoch` を「echo で返す」から「REPLY へ入れる」へ変えたとき、`$(now_epoch)` の呼び出しが
1 箇所残り、`@agent_panel_saving` に空文字が書かれる状態になった。既存の
`tests/tmux/test_agent_panel.sh` が即座に検出した (テストが無ければ「保存中の follow 抑止が
効かない」形で静かに壊れていた)。

CLAUDE.md「不具合対応の原則」の「同じ間違いが別の場所にもある前提で grep する」は**バグ修正**に
ついて書かれているが、実際に効いたのは**関数の契約変更**だった。

- 切り出し先の提案: **却下 (既存ルールの範囲)**。CLAUDE.md の当該項に「契約変更 (返し方・
  シグネチャ) も同様に全 callsite を grep する」を足すだけで足り、新規ルールにするほどではない。
  ただし「テストが無ければ静かに壊れていた」ことは 1 行の実例として価値があるので、
  上記 1 行の追記だけ提案する

## 3. 変異検証と並行レビューを同じ working tree で同時に走らせた

083/087 の red team を走らせている最中に、私が同じファイルで変異検証 (壊す変更を当てて red を
見る) を回していた。レビュワーは「外部プロセスに書き換えられ旧バグが再導入された状態」を
**P1 として報告**してきた (実際は私の変異検証中のスナップショット)。裏取りに時間を使わせた。

- 切り出し先の提案: **`_claude/rules/parallel-write-agents-need-worktree-isolation.md` に 1 項追加**。
  「レビュー/検証エージェントを走らせている間は、同じファイルで変異検証をしない (どちらかを
  worktree へ分ける)」。既存ルールは「書き込み権限のエージェント 2 体以上」を対象にしているが、
  今回は**読み取り専用レビュー + 自分の変異**でも同じ混乱が起きた
- 併せて: red team のエージェントが検証用の `*_test.go` を working tree に 3 本残した
  (`repro_race_test.go` 等)。ビルドを壊す状態だった。**エージェントに一時ファイルの置き場と
  後始末を明示する**指示は毎回入れているが、それでも残った

## 4. 無音 skip は「テスト自身の出力」に出さないと存在しないのと同じ

nvim の `]]` 実挙動 assert は parser 不在で skip していたが、その `print` は headless nvim の
ログファイルへ行き、**失敗時しか表示されない**。つまり skip の事実がどこにも出ておらず、
手元でも CI でも一度も走っていないことに気づけない状態だった (今回可視化した)。

- 切り出し先の提案: **`_claude/rules/adversarial-review-own-safeguards.md` の「沈黙 = 成功に
  なっていないか」節に 1 行追加**。「skip したことは*テスト自身の出力*に出す。子プロセスの
  ログへ書くだけでは、そのログが失敗時のみ表示される設計だと沈黙と区別できない」

## 5. hermetic なはずのテストが非同期の外部書き込みで壊れた

遅延ロードの本体を実行する assert を足した途端、隔離 HOME の後始末が毎回
`rm: Directory not empty` で失敗するようになった。原因は goenv の遅延ロードが `GOROOT` を
取るために呼ぶ実 `go` が、telemetry のカウンタを `$HOME/Library/Application Support/go/telemetry`
へ**遅れて**書くこと (`GOTELEMETRY=off` でも止まらないことを実測)。リトライで回避した。

- 切り出し先の提案: **却下 (単発の環境知識)**。テスト側のコメントに実測を残したので足りる。
  ルール化すると「非同期に書く外部コマンドを列挙する」形になり保守できない

## 6. 同型バグの横展開が P1 を掘り当てた (効いた実例)

086 (prompt へブランチ名を埋める `%` 注入) を直した後、CLAUDE.md の規律どおり同じイディオムを
grep したら、`zshlib` の `print -P` 37 箇所が**ファイル名を prompt 展開に通していて、
ファイル名内の `$(...)` が実行される**ことが分かった (実経路で再現)。086 は「表示の破壊のみ・
コマンド実行は反証済み」だったのに、その反証で使った「危険な形」が別ファイルに 37 個あった。

- 切り出し先の提案: **issue 089 として起票済み** (P1)。この retro 側には残さない

## 7. 自作の計測装置は「測れないもの」を書き、形に依存しない裏付けを併置する

083 で「1 tick の fork 数」を予算化したが、SIGCHLD は**直接の子しか数えない**。red team が
「行ループをパイプへ移し、その中で行ごとに外部コマンドを呼ぶ」変異を当てると、実際には
100 行で 30+ の exec が走っているのに metric は 4 のままで素通りした (= 予算ゲートの意味が
消える)。しかもこの変異の形は、まさに同じコミットで取り除いた `printf | while read` の形。

対処は「比を測る」だった: 行数 10 倍で 1 tick の時間が何倍になるかを併置すると、fork が
どんな形で隠れていても伸び率に出る (かつ比なので runner の速度差が打ち消える)。

- 切り出し先の提案: **`_claude/rules/adversarial-review-own-safeguards.md` に 1 項追加**。
  「自作の計測に予算を付けるときは『この計測が構造的に見落とすもの』を先に書き、見落としが
  致命的なら形に依存しない指標 (比・伸び率) を併置する」。既存の「沈黙 = 成功にしない」節と
  同じ思想だが、対象が「検査が動かない」ではなく「検査が構造的に見えない」

## 8. 敵対レビューの出力も、再現条件が具体的でも鵜呑みにはできない (2 実例)

- 083 の red team が出した **P1「bench が本番 tmux サーバへ書き込む」は反証で崩れた**
  (PATH shim が -L を強制するため。レビュワー自身が偽の本番サーバを用意して bench を完走させ、
  無変化を実測して REFUTED を出した)。事実の前提 (「$TMUX を消していない」) は正しいのに
  帰結が間違っている形
- 089 の反証で「ファイル名の `$(touch pwned.txt)` が実行される」と報告されたが、こちらで
  壊れたダミーファイルで試すと**再現しなかった** (rc=2 の skip 経路で何も print されない)。
  実 mp4 で再試して初めて再現した。再現条件の記述が不足していると「false positive」と
  誤って棄却しうる

いずれも CLAUDE.md「レビュー方針」の「主張は証拠ではない」「敵対レビューの出力こそ無検閲で
採用しない」の実例。ルールは既にあるので**却下 (新規ルール不要)**。ただし retro に実例として
残す価値はある。
