pro-con (epic 415) の演出・操作の作り込み、issue 421〜423 の修正、425 の実測、426 の聞き取り、424 の本物の backend を 1 セッションで進めた。
踏んだところと、次に効きそうな改善だけを書く。

## 踏んだところ / 提案

1. **同期の呼び出しを非同期 (裏の処理) に変えたら、「呼ばれていない」を見る否定のテストが空振りになりかけた**。
   attach を裏に回したとき、「attach していない」を spy の記録が空かで見ていたテスト 3 本は、返ったコマンドを実行しないと
   依頼そのものが起きないので、実装を壊しても緑のままになる形だった (気づいて、返ったコマンドを走らせる形に直した)。
   - 一般形: **処理を遅延・非同期に変えたら、その処理が「起きないこと」を見ている assert を全部洗い、遅延した先まで走らせてから確かめる**
   - 切り出し先: `_claude/rules/mutation-verify-new-tests.md` の「到達しているか」節へ 1 項目追記 (新規ルールにしない。発動点は既存の「守っていないテストの形」と同じ)
2. **共有の外部資源 (他の session・プロセス・サーバ) を見せる機能を、所有の範囲を決めずに「全部見せる」で作った**。
   「今の Claude Code の session を全部カードにする」を実装してから、「pro-con が起動したものだけ。外の session に触れる経路を作らない」と方針が返り、作り直した。
   - 一般形: **自分が作っていない共有資源を読む・操作する道具は、書く前に所有の範囲 (自分が起こしたものだけか、全部か) を決める。既定は自分が起こしたものだけ**
   - 切り出し先: `_claude/rules/no-unauthorized-branch-switch.md` の「共有資源はユーザーの領分」の系として追記する案 (ユーザー判断)
3. **同じ外部の情報を 2 つの経路で読んでいたので、片方に入れた絞り込みをもう片方が素通りした**。
   backend に「pro-con が起動した session だけ」の絞り込みを入れても、画面が自分で `claude agents` を読む経路が残っていて、外の session の本数が出続けた。
   - 一般形: **不変条件 (見せない・触らない) を 1 か所に入れたら、同じ情報源を読む別の経路を grep で全部挙げ、1 本に寄せる**
   - 切り出し先: `_claude/rules/survey-receiver-guards-before-passing-new-values.md` の「自分が宣言した不変条件」節へ追記
     (「崩せる経路を grep で全部挙げる」の具体例として、読み取りの経路も数えることを足す)
4. **週の利用枠を見ずに、計測・レビューのサブエージェントを重ねて 96% まで使った**。431 の計測 (1 回 約 13 万 token) を始める直前に気づいて止めた。
   - 一般形: **本物の session を起こす計測や、上位モデルのレビューを重ねる前に、`claude -p "/usage"` で残量を機械で読む** (モデルを呼ばずに返る)
   - 切り出し先: `_claude/rules/subagent-model-tiering.md` の「枠 (5h / weekly) の残量が少ないときは並列数を絞る」へ、読み方 (`/usage`) を 1 行追記

却下:
- サブエージェントのレビューが、実在しないテスト名を根拠に挙げた → 既存の「主張は証拠ではない」(CLAUDE.md レビュー方針) で足りる
- 敵対的レビューが 4 周回った (直すたびに照合の規則に新しい穴) → 同一性は安定キーで持つ、は既存の「不具合対応の原則」にある。局所の設計の詰めの問題
