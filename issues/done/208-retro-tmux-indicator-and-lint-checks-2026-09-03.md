## 反省・気づき

### 1. 直したのと同じ穴を、直後に新しい関数で作り直した

`refresh_pane_indicator` に socket + サーバ pid の照合を入れた (敵対的レビューの P1) その
**同じセッションで**、新設した `refresh_session_status` に照合を入れ忘れ、sonnet の
セルフレビューが同じ P1 を再検出した。

既存ルール「直したバグは別の場所にもある前提で grep する」の**適用漏れ**。新しい関数を
足すときに「今日直した不変条件を、この関数も守るか」を見ていなかった。

→ 切り出し先: **既存ルール (`~/.claude/CLAUDE.md`「不具合対応の原則」) の適用漏れなので新規ルールは不要**。
ただし「同じセッションで新設した関数」は grep の対象として意識から外れやすいので、
retro としてここに記録するに留める (却下)。

### 2. false green を 4 回作った (このセッション最大の反省)

いずれも「抽出・判定が空になった結果を『違反 0 件』として緑にする」形:

| # | 形 | 気づいた経路 |
|---|---|---|
| a | `set -euo pipefail` 下で grep の無マッチが代入ごとスクリプトを殺し、1 本目で静かに終了 | 変異が素通り (3 回踏んだ) |
| b | 関数列挙のフィルタがパス名に `/dotfiles/` を期待し、**worktree では 1 件も一致せず何も走査しない** | 変異 9 本が全部素通り |
| c | sed の式を壊して refs が空になり「違反 0 件」 | canary を足して初めて見えた |
| d | `comm` を locale のままにして引き算が黙って崩れた | canary が捕まえた |

→ 切り出し先: **新規ルールの候補**。「検査・抽出を書いたら、**同じ経路を通る canary** を
置く (既知の入力で既知の答えが出ることを先に固定する)」。既存の
`verify-execution-not-just-exit-code.md` は「走ったか」、`mutation-verify-new-tests.md` は
「テストが効くか」を見るが、**抽出そのものが空を返す形**はどちらの発動点でもない。
⚠️ ルールを足す前に、既存 2 本への追記で足りないかを判断すること。

### 3. 変異検証が素通りした 5 本 — fixture が退行を観測できない場所にあった

- 別サーバの job を「退行しても見えない場所」に置いていた (opus が実験で証明)
- 前任サーバの job に偽 pid を使い、通常の stale 掃除が先に消していた
- glob 順で「最後が最早」になる fixture を作り、最早選択の変異を素通しした

→ 切り出し先: **`mutation-verify-new-tests.md` への追記候補**。既存の「よくある守っていない
テストの形」に「**fixture が退行を観測できる場所にあるか**」を 1 項足す。

### 4. 性能の主張を足し算で書いた

tests/CLAUDE.md に「`make test` は 414 秒」と書いたが、それは個別 target の**合計**で、
通しは測っていなかった (opus が指摘)。測り直して 433 秒。

→ 切り出し先: **`perf-claims-need-measurement.md` の適用漏れ**。あちらは「数字なしで書かない」
までしか言っていないので、「**合計で代用したら『合計』と明記する**」の 1 行追記は価値がある (候補)。

### 5. sonnet のレビューでは出ず、opus で出た指摘が実害級だった

同じ変更に対して sonnet 2 本 → 指摘 2 件 (どちらも実害) / opus 2 本 → 指摘 13 + 8 件で、
**「検査が何も見ていない」形の指摘は opus 側にしか出なかった**。sonnet は「コードが何をするか」
は読めるが「この検査は退行を観測できるか」の反実仮想が弱い。

→ 切り出し先: **`subagent-model-tiering.md` への追記候補**。「**自作の検査・ゲートの敵対的
レビューは opus に投げる**」(定型レビューは sonnet で足りる、の例外)。

### 6. 計測のために zsh テストを bash で直接実行し、repo root を汚した

`bash tests/zshrc/**/test_*.sh` を直接回して、`cd` の失敗を見ていない経路が repo root に
fixture を 3 件書いた。数字も無効 (rc=127/2 で即落ち) で、測り直しが必要になった。

→ 切り出し先: **issue 204** (別セッションが実装中) + **ルール候補**: 「テストの単体実行は
ランナー経由 (`make test-dir DIR=...`) を使う。直接実行は shebang の方言と helper の前提を
壊す」。⚠️ tests/CLAUDE.md に既に `make test-dir` の案内があるので、**追記の価値は薄いかもしれない** (判断待ち)。
