# 712 (perf): treefiler の配置・描画・アニメが全ノードに比例する (画面の近くだけを扱う)

起票日: 2026-10-11

## 概要

issue 711 で、巨大なフォルダ (5 万件) の 1 フレームの確保を 18 MB → 2 MB に減らした後も、時間はノードの数に比例して残る:
View 約 7.6 ms、`j` 1 回 (動きが止まるまで 40 フレーム) 約 580 ms (1 フレーム約 14.5 ms。60fps の予算 16 ms ぎりぎり)。
残りの CPU は、毎フレーム・毎 tick に全ノードを舐める処理の map の読み書き:

- `layout()` (`filer/layout.go`): 全ノードの目標位置を `pos` の map に入れる (動きの最中は `Advance` の `step` が毎 tick、`draw` も毎フレーム呼ぶ)
- `draw()` (`filer/model.go`): 全アニメの「今の位置」を `now` の map に入れる
- `sync()` / `step()` (`filer/model.go`): 全アニメの tween を毎 tick 進める・幅を付け直す
- `lines()` (`filer/layout.go`): 全アニメ (`m.order`) を舐め、開いたフォルダごとに子の座標を集める (縦棒の端を決めるため、画面の外の子も見る)
- `step()` の後半: 全アニメを舐めてフォルダの走査を頼む (`m.walker.request`)
- `drawNames()` (`filer/model.go`): 全アニメを 2 周舐める (画面の縦範囲の外は飛ばすが、舐めること自体が全ノードぶん)
- `sync()`: 生まれたノードを深さとパスで並べる (`sortByDepth`)。`snapAll()`: キー入力のたびに全アニメを舐める
- 動きの最中は 1 フレームで `layout()` が 2 回走る (`step` と `draw`)。配置をキャッシュする案はこの 2 回目も消せる

画面に出るのは高々数十行なので、画面 (カメラ) の近くのノードだけを扱えれば、時間はノードの数に依らなくなる。

## 対応方針 (案。未設計)

- 配置の結果をキャッシュし、変わったとき (カーソル・開閉・設定・木の読み直し) だけ作り直す。または、巨大なブロック (1 つの親の子が
  画面の行数を大きく超えるもの) は、画面の縦範囲 ± 余白の子だけに位置とアニメを持たせる
- 🚨 仮想化は意味に触れる: 画面の外から入ってくる項目の湧き方 (spec §4.2 の「いちばん近いアニメ中の祖先の右端から湧く」)・
  消える項目の縮み方・縦棒の端 (画面の外の子まで伸びる)・検索の `column` (画面の外の項目も対象) が、全ノードの位置を前提にしている。
  設計の前に、これらがどの範囲のノードを読むかを列挙する
- 計測はベンチ `filer/perf_bench_test.go` (`BenchmarkViewHugeFolder` / `BenchmarkLayoutHugeFolder` / `BenchmarkMoveHugeFolder`) で
  前後を比べる

## 受け入れ条件 (案)

- [x] 5 万件のフォルダで、`BenchmarkMoveHugeFolder` の 1 フレームあたりの時間がノードの数に比例しない (5 千件と 5 万件で比べる)
- [x] 小さなフォルダの見た目・動き (湧き方・消え方・縦棒) が変わらない (子が 1024 件以下は仮想化しない。巨大なフォルダも、仮想化しない Model と
  毎フレームの画面を比べるテストで同じを固定した)

## 実装 (2026-10-12)

- `filer/virt.go` (新設): 巨大なブロック (子が `virtMinDefault` = 1024 を超える。一度仮想化したら半分を下回るまで続ける) は、画面 + 上下の余白
  (画面の高さの 4 倍) の子だけを配置しアニメを持たせる。捨てた子が要るとき (画面の近くへ入ってきた・ブロックが消えて縮む・読み直しで外れた) は、
  アニメを持つ兄弟の状態を前の順位の差だけずらして作り直す (`reviveAnim` / `ghostCulled`)。仮想化のまま扱うのは「子が全員同じだけずれる変化」
  (カーソル・ブロックの寄せ直し・カメラ) だけで、見せる子の覚えの作り直し (読み直し・隠しファイル・並び替え・ライブ更新で一覧が変わる)・
  行の間隔の変更・ブロックが現れた直後は、`spawnHold` (0.6 秒。動きの時計 = Advance の dt の和で測る) の間は全部を動かす (`noteGeo`)。
  縮んで消える子の親は遠くても捨てない (`cullFar`)
- `filer/kids.go` (新設): 見せる子の覚え (`visKids`)。並びと見せ方が変わったときだけ作り直し、各子に順位 (`vidx`) と世代を振る。
  並びが同じ作り直し (中身だけのライブ更新・labelMax) は世代を変えない (`sameKids`)。`kids()` / `moveSibling` / `spine` / `descend` が使う
- `layout.go`: 列の幅を覚えの最長の名前から取り、巨大なブロックは `placeVirtual` へ。検索の列は `layoutAll` (仮想化しない)。`reusedMap.fit`
- `model.go`: `compactAnims` (anims が最近の最多の 1/4 を切ったら map を作り直す)・描く順を「生まれた回 → 深さ → パス」に保つ (`sortOrder`)・
  線はアニメを持つ今の子から引く (`collectDrawn`)・祖先へ辿るループを `liveAncestor` に寄せた (issue 717 の `restoreOrigin` と合わせて 3 か所)
- docs: `docs/treefiler-spec.md` §0.4 に巨大なフォルダの項、`src/treefiler/CLAUDE.md` の地図と乱数のテストの回し方

## 実測 (`filer/perf_bench_test.go`。件数別の sub-benchmark。`-benchtime 3x`、M3 Max、2026-10-12)

| ベンチ | 前 (5 千件 / 5 万件) | 後 (5 千件 / 5 万件) |
|---|---|---|
| View (止まった画面 1 フレーム) | 0.69 ms / 9.5 ms | 0.20 ms / 0.20 ms |
| layout | 0.11 ms / 1.54 ms | 0.02 ms / 0.02 ms |
| `j` 1 回 (止まるまで 40 フレーム) | 51 ms / 641 ms | 9.4 ms / 9.5 ms |
| `j` 1 回の確保 | 13 MB / 109 MB | 1.6 MB / 1.6 MB |

- 🚨 全部を動かす期間 (0.6 秒) の間は全件に比例する (712 より前は常にそう)。書き込みの続くファイルが 1 つある巨大なフォルダの毎秒のライブ更新は、
  一覧が変わらないので期間に入らない (`TestVirtualizedContentOnlyLiveUpdateStaysVirtual`)
- ベンチの準備は 60fps で 1 秒進めて期間を抜ける (期間は動きの時計で測るので、1 秒先へ 1 回進めても抜けない)

## 正しさの確認

- 等価性のテスト (`filer/virt_test.go`、29 本): 同じ木・同じ時計で仮想化しない Model を正解役にし、毎フレームの View を 1 文字残らず比べる。
  乱数の操作列 (`TestVirtualizedRandomOpsMatchFull`。キー・ライブ更新の増減・行の間隔・並び替え・画面の高さ・速さ・遅いフレーム・16ms より短い間隔・
  Advance を挟まない View) は CI で 12 本、手元で `TREEFILER_VIRT_SEEDS=300` の 300 本が全部一致 (乱数の操作列だけ、縮んで消える子の消えかけ
  (透明度 1 割未満) の名前の重なりの差を許す。許さずに比べると 300 本中 3 本)。`-race` では 7 倍遅いので飛ばし、Makefile の `-race` なしの run で回す
- 変異 (`bin/mutate-verify`): 最終の仕組みのそれぞれを外して red を確認 — 捨てた子の作り直し (`reviveAnim`)・作り直しの置き方を step のものにする・
  描く直前の作り直し (全部を動かす期間も含む)・作り直しの覚えの世代で期間に入る・期間を動きの時計で測る・期間の起点を最初の Advance にする・
  並びが同じなら世代を変えない・ブロックが消えたときの縮む子・外れた子の縮む子・縮む子の親を捨てない・外れた子を描く直前に作り直す・
  外れた子の記録を捨てる・新しく現れた子の判定・今の見せる子だけ置く・捨てる・画面に入る範囲を今のずれで広げる・遠くの開いたフォルダを置く・
  先頭と末尾を置く・描く順・`reusedMap.fit`・閾値の履歴・余白の幅。緑のまま通った変異は、テストを足して red にするか、仕組みが不要と分かって外した
  (湧いている子を写し元から外す・線を引く子から消えた子を外す・いちばん近い兄弟を探す・縮む子の親を配置の段階でも置く・外れた子の持ち越し)
- 敵対レビュー 5 周 (opus)。1 周目 4 件 + 性能 1、2 周目 4 件 + 窓 1、3 周目 性能 1 + 等価 1、4 周目 2 件、5 周目 性能 1 (画面の食い違いは作れず)。
  全部直した。2 周続けて「捨てた子の作り直し」が別の入力で破られたので、細かい条件で写せるかを見分ける形をやめて規則を 1 つにし
  (`~/.claude/rules/adversarial-review-own-safeguards.md` §7 → 0-B)、本物 (仮想化しない Model) を正解役にした乱数の網羅の検査を置いた。
  5 周目の直し (外れた子の記録を捨てる) は判定を足さず、直接のテストで確かめたので、周回はそこで打ち切った
