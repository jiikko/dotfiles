## 気づき

### 1. **fixture が 11 回嘘をついた** 🔴

全部「有無で結果が変わらない観測」。列挙する (同じ罠を繰り返し踏んだので、形の一覧に意味がある):

| # | 嘘 | 気づいた手段 |
|---|---|---|
| 1 | `kill(pid,0)` はゾンビにも成功する (生死に使えない) | 対照テストが赤 |
| 2 | `trap "" TERM` でグループごと死ぬ、と誤記録 (実は SIG_IGN は exec を跨いで継承される) | 再実測 |
| 3 | `kill(pid,0)` は trap 設置前でも成功する (「起動した」に使えない) | SIGKILL 側に一度も到達していなかった |
| 4 | torn read のテストが静止状態しか見ていない | 変異が全緑 |
| 5 | production に出ない文字列で red を出していた | レビュー |

🚨 **11 のうち 4 つは「変異が全緑」で気づき、5 つはレビューでしか気づけなかった。**
変異検証とレビューは**代替にならない**ことの実測 (`adversarial-review-own-safeguards.md` の
「変異は自分が想定した不変条件しか試さない」がそのまま出た)。

→ 切り出し先: [`mutation-verify-new-tests.md`](../../_claude/rules/mutation-verify-new-tests.md) の
「よくある『守っていないテスト』の形」へ**追記 2 行**:
**「①生死・存在を `kill(pid,0)` やプロセスの有無で見ない (ゾンビ・exec 前が同じ顔で出る)。
`Wait` の完了・成果物で見る ②『案内した先』を検査する — 文字列が出ているかではなく、
名指ししたコマンドを**実際に走らせて**何を返すか」**。既存の項が多いので**節を増やさず**該当項へ足す。

### 2. **修正が新しい機構を足すと、§7 が次の周を要求して自己増殖する** 🔴

383 は核 (fail-closed = 実質 2 行) が 1 周目で閉じており、**2〜4 周目は全部「私が足した案内文と
後始末」由来**だった。足した機構がそれぞれ固有の failure mode を持ち、その修正がまた新しい判定を
足す、の連鎖。4 周のうち 3 周は自分で作った複雑さへの対応。

→ 切り出し先: [`adversarial-review-own-safeguards.md`](../../_claude/rules/adversarial-review-own-safeguards.md)
§0-A への**追記 1 行**: **「機構を足すたびに §7 の周回が 1 つ増えると見積もる。『あると親切』な
案内・後始末は、それ自体が新しい安全機構で、周回のコストを持つ」**。

### 3. 助言が**危険な行動**になっていた 🔴

fail-closed の代償として「`lockman break` で剥がす」と案内したが、同じ観測が**健全な保持者の
`Renew` が truncate している一瞬**からも出る。助言に従うと**生きた保持者を剥がして二重実行**。
区別しようとするのではなく、**破壊的操作を促すのをやめて**読み取り専用の `status` へ誘導した。
(そして 4 周目で「その `status` が空振り」と言われた。)

→ 切り出し先: 新規ルールは立てない。
[`adversarial-review-own-safeguards.md`](../../_claude/rules/adversarial-review-own-safeguards.md)
§2 (沈黙 = 成功にしない) の隣へ**追記 1 行**: **「人へ出す案内に破壊的操作を書くときは、
その案内が出る状態を全部列挙する。1 つでも『やってはいけない状態』が混ざるなら、
読み取り専用の確認へ誘導する」**。

### 4. 記録の誤りが 2 回 (どちらも issue と commit に残っていた) 🔴

- 「`readLock` を 1 つの open にすれば torn read が消える」→ **truncate には効かない** (実測)
- 「zero-mtime busy 全部に効く discriminator」→ **2 箇所中 1 箇所しか直していなかった**

どちらも**その場で実測すれば分かった**もので、issue は done 後も残るので次の監査を誤らせる。

→ 切り出し先: **却下 (既存で足りる)**。`perf-claims-need-measurement.md` の
「主張するなら実測値か『未実測 + trigger』」と同じ構造 (こちらは正しさの主張)。実例として rationale へ。

### 5. 良かったこと 🟢

- **ユーザーへの 1 問で設計が決まった** (fail-closed か fail-open か)。トレードオフ
  (永久 wedge vs 二重実行) と復旧路 (`break` が壊れた lock にも効くことの実測) を添えたのが効いた
- **380 の「fd スコープ化」は窓を縮めるのではなく消した**。名前に対する操作を実体に対する操作へ
  変えるのは、この領域で唯一「構造的に閉じる」手だった
- **verbatim 書き戻し**が 3 つの問題を同時に消した (未知フィールドの喪失・混ざった JSON の窓・
  `Truncate` 枝)。レビュワーの「1 行の提案」で、私の修正より単純かつ強かった
