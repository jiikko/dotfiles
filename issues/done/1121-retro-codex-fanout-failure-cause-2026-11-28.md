## どこで踏んだか

1. **判定の述語を狭めたのに、旧い述語で真だった入力の形を着手前に挙げなかった**。上限の判定の events 側を
   「events のどこかの error / turn.failed の行に上限の語」から「最後の文に上限の語」へ変えた (1110 のテスト③の要件)。
   旧い述語では上限になり新しい述語ではならない形 (具体的な error の後に、汎用の文だけの turn.failed) は、敵対的レビューの 1 周目で P2 として出た。
   候補の側だけを直したところ、2 周目に「判定の回帰が残り、テストで固定された」と再び出た。最後は未実測の仮説 (codex は最後の error の文を
   turn.failed に写す) に立つと決めて、再提起の条件を残した。着手前に旧新の差を表にしていれば、仮説に立つかどうかの判断を 1 周目の前にできた
2. **完了報告・途中経過が英語に崩れ、「日本語にして」と言われた**。サブエージェントの報告を受けた後の数通が英語だった。
   retro 1031 で auto memory (`reports-in-japanese`) を置いた後の再発
3. Bash (python) で書いたテストのコメントに `(issue 1110)` を入れ、`make test` の `test_check_comment_provenance` で初めて落ちた (検査は書いた時点では走らない)

5. `mutate-verify` で Go のファイルをわざと壊して試すと、`--syntax` を推定できず rc=2 で止まった (bash のファイルは同じ書き方で通る)
