# 1024 (retro): mac-lan-manager の有線の名前で SMB も広告する (1011) の振り返り

起票日: 2026-11-04

反証レビューは省略した (セッションの観察記録。事実の主張は各項の出典で確かめた範囲)。

## どこで踏んだか

1. **操作に新しい副作用を足したのに、その操作の承認を求める文を直さなかった**。広告のループに `_smb._tcp` の登録を足したが、
   初期設定の確認の板 (`lanmgr/setup.go` の名前の手順) は目印の `dns-sd -P` しか説明していなかった。ユーザーは Wi-Fi 側にも SMB の行が
   出ることを知らずに `y` を押す。テストもレビューも板の文を見ておらず、ユーザーに頼まれたセルフレビューで初めて気づいた
2. **他の機械での作業が要る変更 (形の目印を v4 に上げた) を、issue の本文の「残り」とチャットにだけ書き、human issue を起こさなかった**。
   規約 (`_claude/issue-rules.md`「人にやってほしいことは chat に流さず issue に起こす」) はあったが、完了報告を書く時点で「人の作業」と
   意識していなかった。前回同じ形 (964 → 967) では起こしていた。セルフレビューで 1023 を起こした
3. **変異を当てる前にチェックリストを読まなかった**。`rules-checklists/mutation-verify-new-tests.md` の fake・stub の節に
   「外部コマンドを模す stub は `"$*"` で照合しない」が既にあり、敵対的レビューが同じ穴 (表示名が空白で割れても緑) を指摘した。
   rule (`mutation-verify-new-tests.md`) は「変異を当てる前に Read する」と書いている
4. (局所) ループの引数を末尾に足したとき、ProgramArguments の 0 始まりと sh の `$N` を取り違え `$9` / `${10}` と書いた。テストが捕まえた
5. (局所) 実験のコマンドで zsh の `echo == before` が `=` 展開で落ちた

## 提案

- 1 → `_claude/rules/verify-execution-not-just-exit-code.md` の「利用者に約束する出力文」の項に追記: 操作が新しい副作用 (登録・公開・送信) を
  持つようになったら、その操作の確認・承認を求める文 (確認の板・プロンプト・usage) を同じ変更で書き足す。発動点は既存の項と同じ
  (利用者に向けた文と実際の効果の対応) なので追記にする
- 2 → `_claude/issue-rules.md` の `human` 節に追記: 自分の変更が他の機械・アカウントでの操作 (入れ直し・移行・再起動・目視) を要するなら、
  その変更を push する前に human issue を起こす。完了報告やほかの issue の本文の「残り」に書くだけにしない
- 3 → 却下: 規範はチェックリストに既にあり、rule も読む時点を書いている。読み飛ばしを防ぐ仕組み (道具が起動時に案内する等) は、
  案内の行が増えて読まれなくなる見込みのほうが大きい
- 4・5 → 却下 (局所): 4 はテストが捕まえた。5 は zsh の既知の挙動
