# 1108 (feat): issue-progress-check が、commit が名指した issue の本文に骨組みの印が残っていたら差し戻す

起票日: 2026-11-26

- 由来: obaket retro 1555 の 2 (2026-11-26 にユーザーが「片付けて」と指示し、retro の提案どおり起票)

## 概要

骨組みで起票した issue (本文が「本文は追って書く」だけ) を名指しする実装の commit が入っても、本文が骨組みのまま残ることがある。
Stop hook `_claude/hooks/issue-progress-check.sh` は「変更の有無」と「構造 (`[x]` の数・進捗 / 結果 / 残タスク / 対応 の見出し) が増えたか」の 2 段で判定し、
骨組みの文言が残っているかは見ない。

## 起きたこと (obaket retro 1555 の記録)

- obaket の 1546・1547・1549 は骨組みで起票した。実装の commit の subject は `(1542 / 1546 / 1547)`・`(1549)` と番号を名指したが、この 3 本の issue を触らず、
  本文は人が `/issue-writeback` を呼ぶまで骨組みのままだった
- hook の抽出式はこの subject の番号に当たる。当時 hook が差し戻したか、差し戻しをどう閉じたかは記録に無い (retro の反証レビューでも確かめられなかった)

## 対応方針

- 判定に 3 段目を足す: 関わった issue の本文に骨組みの印 (「本文は追って書く」など。印の語の一覧は 1 か所に持つ) が残っていたら差し戻す。
  構造が増えたか (2 段目) とは別に見る (骨組みの下に進捗の見出しだけ足しても、本文が無いことは変わらない)
- 印の語は issue 規約 (`_claude/issue-rules.md` の「ファイル名」で、骨組みを先に push する手順) が使う言い回しと揃える。規約に骨組みの書き方の例が無いなら、同じ変更で足す
- 骨組みのまま番号だけを取る commit (起票の commit) は差し戻さない (番号を取った直後は本文が無いのが正しい)。見分け方は、その commit が issue ファイルを足した commit か、issue の外を変えた commit か
- テスト: 骨組みの issue + 名指す実装の commit で block / 起票だけの commit では block しない / 本文を書いた後は block しない、の 3 本。変異で 3 段目を外して red を見る

## 進捗

- [ ] 印の語の一覧と判定
- [ ] テストと変異
