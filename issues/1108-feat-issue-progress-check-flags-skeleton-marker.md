# 1108 (feat): issue-progress-check が、commit が名指した issue の本文に骨組みの印が残っていたら差し戻す

起票日: 2026-11-26

- 由来: obaket retro 1555 の 2 (2026-11-26 にユーザーが「片付けて」と指示し、retro の提案どおり起票)

## 概要

骨組みで起票した issue (本文が「本文は追って書く」だけ) を名指しする実装の commit が入っても、本文が骨組みのまま残ることがある。
Stop hook `_claude/hooks/issue-progress-check.sh` は「変更の有無」と「構造 (`[x]` の数・進捗 / 結果 / 残タスク / 対応 の見出し・番号の近くの「解消」「継続」の行) が増えたか」の 2 段で判定し、
骨組みの文言が残っているかは見ない。本文の中身を点検する入口は、今は手で呼ぶ `/issue-writeback` だけ。

## 起きたこと (obaket retro 1555 の記録)

- obaket の 1546・1547・1549 は骨組みで起票した。実装の commit の subject は `(1542 / 1546 / 1547)`・`(1549)` と番号を名指したが、この 3 本の issue を触らず、
  本文は人が `/issue-writeback` を呼ぶまで骨組みのままだった
- hook の抽出式はこの subject の番号に当たる。当時 hook が差し戻したか、差し戻しをどう閉じたかは記録に無い (retro の反証レビューでも確かめられなかった)

## 対応方針

- 判定に 3 段目を足す: 関わった issue の本文に骨組みの印 (「本文は追って書く」など。印の語の一覧は 1 か所に持つ) が残っていたら差し戻す。
  構造が増えたか (2 段目) とは別に見る (骨組みの下に進捗の見出しだけ足しても、本文が無いことは変わらない)
- 対象は「commit が番号を名指しし、その commit が issue ファイルの外を変えた」issue に限る。今の hook は全 worktree の commit の件名と `next/` の claim を
  1 つの番号の集合にまとめる (`issue-progress-check.sh` の件名の抽出)。この集合に文言の検査を足すと、着手の claim だけでも骨組みを差し戻す。
  commit ごとに名指した番号とその commit の変更を対応づける (起票と実装が同じ commit に入る・別 issue の実装と一緒に起票する、の形も区別できるように)
- 印の位置: obaket の 1546・1547・1549 では、印は概要を説明する行の末尾にあった (obaket の `579130eea` 時点の 1546・1547 と `9eed1b828` 時点の 1549 の 11 行目)。
  印だけの行を探すとこの 3 件を漏らし、本文全体の部分一致にすると、印の語を説明のために引用した issue (この 1108 や obaket retro 1555) を誤検出する。
  どちらを採るか (印を規約で 1 つの形に固定する・引用の形を除く) を実装の前に決める
- 本文は、構造の判定と同じく作業した worktree のものを読む。起動元の checkout の本文だけを読むと、作業先で消した印を指摘し直し、作業先にしかない issue を見落とす
- 印の語は issue 規約 (`_claude/issue-rules.md` の「ファイル名」で、骨組みを先に push する手順) が使う言い回しと揃える。規約に骨組みの書き方の例が無いなら、同じ変更で足す
- テスト: ①骨組みの issue に `## 進捗` だけを足し (2 段目は通る)、名指す実装の commit を置いて、**印を理由に** block すること ②起票・claim だけの commit では block しない
  ③本文を書いた後は block しない。今の hook は、基準点にある issue を名指して issue ファイルを変えない commit を既に差し戻すので、①で 2 段目を通さないと新しい判定を試せない。
  変異で 3 段目を外して①が red になるのを見る
