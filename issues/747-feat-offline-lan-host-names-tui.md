# 747 (feat): インターネットに繋がっていない有線 LAN のホストへ、名前で簡単に繋ぐ (TUI)

起票日: 2026-10-13

## 概要

ユーザー依頼 (2026-10-13)「インターネットに繋がっていない方のネットワーク内のホストへの接続を簡単にしたい。host に名前をつけたい」。
ネットワークの IP と hosts をまとめて扱う TUI を作る案を、作る前に要件として残す。

## 前提 (2026-10-13 時点の構成)

- Mac には 2 つのネットワークがある:
  - **Wi-Fi**: インターネットに繋がる (ルーターあり・DHCP)
  - **有線**: Mac mini と周辺の Mac をハブで繋いだ閉じた LAN。**ハブの先にルーターは無い**。2026-10-13 にこの Mac で IP が付いていたのは
    `Thunderbolt Ethernet` (en13)。有線になりうるサービスは他にも `USB 10/100/1G/2.5G LAN` (en10)・`Thunderbolt Bridge`・`iPhone USB` があり、
    **どれが有線 LAN かは決め打ちできない** (`networksetup -listnetworkserviceorder` でサービス名とデバイス名を対応させる)
- 有線の IP は DHCP が無いので macOS が自分で付けた `169.254.13.42` (リンクローカル)。**起動のたびに変わりうる**
- 🚨 **`169.254` 宛ては、そのままでは有線を通らない** (2026-10-13 実測): `netstat -rn` に `169.254` の経路が 2 本あり、スコープ無しは
  Wi-Fi (`169.254 link#14 UCS en0`)、有線は ifscope 付き (`169.254 link#27 UCSI en13`)。`route -n get 169.254.13.99` は `interface: en0` を返す。
  つまり 169.254 の IP へ名前を付けても、普通の接続は Wi-Fi 側へ出る (相手機器が無いので、実際に繋がらないところまでは未確認)
- 有線側にルーター欄を入れると、インターネット宛ての経路が有線へ流れて切れる。**有線のルーター欄は空のまま**が前提 (`route -n get default` が Wi-Fi を指すこと)

## やりたいこと (ユースケース)

- 有線 LAN の相手へ **自分で付けた名前** で繋ぐ (`ssh mini` / 画面共有 / ファイル共有)
- 相手の IP を覚えたり、毎回調べ直したりしない
- **有線を通ること** (同じ Mac が Wi-Fi 側にも見えていても、Wi-Fi を経由しない)

## 名前を付ける手段の比較 (どれを使うかは未決)

名前の手段と経路の手段は別の問題で、**名前だけ決めても上の経路の問題 (169.254 が Wi-Fi へ出る) は解けない**。

名前の手段 (sudo の要否・効く範囲は未実測。設計の前に確かめる):

| 手段 | sudo | 効く範囲 | 欠点 |
|---|---|---|---|
| `/etc/hosts` に専用ブロック (`# BEGIN …` 〜 `# END`) を持つ | 要る | getaddrinfo を使うもの (ssh・ブラウザ・Finder の `smb://` のはず。未実測) | IP が変わると古くなる。書くたびに sudo |
| `~/.ssh/config` の `Host <名前>` + `HostName <IP>` | 要らない | ssh / scp / rsync だけ | ssh 以外には効かない。`BindInterface en13` で有線に縛れる (未実測) |
| mDNS の `.local` 名 (相手の `LocalHostName`。`scutil --get LocalHostName`) をそのまま使う | 名前を変えるなら相手側で要る | getaddrinfo を使うもの | 自分で付けた別名にはならない。`.local` は mDNS で特定のインターフェースに縛られず (`scutil --dns` の `domain: local`)、解決した 169.254 の IP は上の経路の問題を抱える |

経路の手段 (有線を通すため。どれか 1 つは要る):

| 手段 | sudo | 欠点 |
|---|---|---|
| **全台の有線を Wi-Fi と被らない固定 IP にする** (`192.168.100.0/24` 等・ルーター欄は空) | 各 Mac で 1 回 | 全台で設定が要る。名前の対応表も変わらなくなる |
| 169.254 のままスコープ付きの経路を足す (`route add -net 169.254.0.0/16 -interface en13`) | 要る | 再起動・ケーブルの抜き差しで消える。Wi-Fi 側のリンクローカル (AirDrop 等) に影響しうる (未確認) |
| ssh だけ有線に縛る (`ssh -b <有線の IP>` / ssh config の `BindInterface`) | 要らない | ssh だけ |

## 要件

1. **自分のネットワークの状態を見せる**: サービスごとに (デバイス名との対応つき) IP・サブネット・ルーターの有無・自動 (`169.254`) か手入力か。
   インターネット宛ての経路が Wi-Fi を向いているか。**相手の IP 宛ての経路が有線を向いているか** (`route -n get <IP>` の interface)
2. **有線 LAN の相手を見つける**: `dns-sd` (Bonjour) で有線のインターフェースにいる Mac を一覧にし、ping で生きているかを出す。Wi-Fi 側でだけ見えている相手と区別する
3. **相手に名前を付ける**: 一覧から選んで別名を付け、その名前で有線の IP へ届くようにする (上の比較のどれで実現するかは未決)
4. **名前の対応表を最新に保つ**: 169.254 のまま運用するなら、相手の IP が変わったら書き直す (起動時の更新・手動の再読込)
5. **自分の有線 IP を固定する** (上の経路の問題を解く最も素直な手段なので、任意ではなく第一候補): 手入力にし (ルーターは空)、`-setdhcp` で戻す。
   固定にすると相手の IP が変わらないので 4 も要らなくなる。ただし**全台**で同じ帯に揃える必要がある。
   🚨 `networksetup -setmanual networkservice ip subnet router` は man の上で router が必須の位置引数で、**ルーターを空にする書き方は未確認**
   (空文字を渡せるか・システム設定の GUI でしか空にできないか)。`-setmanualwithdhcprouter` は別物

## 制約・注意

- **書き込みには管理者権限が要る** (`/etc/hosts`・`networksetup` の変更)。TUI 全体を sudo で動かさず、書く瞬間だけ sudo を呼ぶ
- `/etc/hosts` は**自分のブロックの外を触らない** (他の行・コメントは残す)。書くときは atomic に置き換える (`src/atomicfile`)
- `169.254.0.0/16` を手入力で固定するのは避ける (自動で付ける側との衝突確認が効かない。複数のインターフェースに付くと経路があいまいになる)。固定するなら `192.168.100.0/24` のような、Wi-Fi と被らないプライベートの帯
- 1 台で完結しない: 固定 IP・`LocalHostName` の変更は各 Mac で行う。名前の対応表 (hosts / ssh config) は使う側の Mac だけでよい
- 台数が少ない (2〜3 台) なら、TUI を作らず `networksetup` を 1 回と hosts / ssh config に数行で済む。作る価値は台数が増える・頻繁に変わるとき

## 対応方針 (案)

- 置き場所は `src/<名前>/` の新しい Go のパッケージ。画面は `tuikit` + bubbletea v2 (glogx・treefiler と同じ)
- 見た目は本体に入れる前にサンプルレンダラで決める (`_claude/rules/decide-layout-in-sample-renderer-first.md`)
- 書き込み (hosts・networksetup) のテストは本物のファイルを書くので、一時ディレクトリの外を実行前に拒否する仕掛けを同じ commit で入れる (`_claude/rules/sandbox-real-destructive-test-apis.md`)
