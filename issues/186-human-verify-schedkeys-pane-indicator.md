## 前提

conf を reload する (`prefix+R` → 確認 → 実行)。reload しないと稼働中サーバには乗らない。

## 追記 (2026-09-03): 本文を status の 2 行目に出すようにした

ユーザー要望「2 行目に予約内容の先頭 100 文字」。**tmux は pane の枠を 1 行しか描けない**
(枠の format に改行を入れても 2 行にならず、`pane-border-status` に `both` は無い。3.7b で実測)
ため、2 行目は **status 行の 2 行目**にした。

- 枠 (pane-border-format) = 時刻の島。**どの pane に仕掛かっているか**を示す
- status の 2 行目 = 本文の先頭 100 文字。**今いる pane の予約だけ**が出る (status は
  クライアント単位)。予約があるセッションだけ `status 2` にし、無くなったら 1 へ戻す
- scratch セッションの 2 行目は従来の演出のまま (あちらは常時 2 行)

下の確認項目に加えて、**2 行目の出入りで画面が 1 行ずれること**が許容できるかを見てほしい
(予約を作った瞬間に 2 行になり、発火・取消で 1 行に戻る)。うるさければ「常時 2 行」か
「枠の島だけ」に倒せる。

予約の無い pane を見ているときは、2 行目に「このセッションに N 件の入力予約」が出る
(セッション単位の控え)。空行にしないための措置だが、**文言がこれで良いか**も見てほしい。

## 確認してほしいこと

1. **予約すると出るか**: `prefix+m` で 1 分後の予約を作り、その pane の**上端の枠バー左端**に
   ` 入力予約 HH:MM ` が黄背景・黒文字で出ること。発火したら消えること。
2. **位置**: 要望は「pane の左下」だったが、この repo の `pane-border-status` は既に `top`
   (`_tmux.conf` の意図的な設計: 現在地を上端 ACTIVE 帯で示す) なので**上端の左**に出している。
   下端が良ければ `pane-border-status bottom` へ変えられるが、ACTIVE 帯の位置も一緒に動く。
   どちらが良いか判断してほしい。
3. **邪魔でないか**: 黄帯が ACTIVE 帯 (明緑) や claude 状態表示と並んだときにうるさくないか。
   うるさければ色を落とす (`colour226` → `colour178` 等) か、文言を詰める (「入力予約」→「予約」)。
4. **複数予約**: 同じ pane に 2 件仕掛けると ` 入力予約 HH:MM ほか1件 ` になる。
   最早の時刻が出ていること。件数の表記がこれで読めるか。
5. **取消で消えるか**: `prefix+m` → 一覧 → 取消 で表示が消えること (残りがあれば次の時刻へ
   繰り上がること)。
6. **他 pane を汚さないか**: 予約していない隣の pane・別 window の枠に出ていないこと。
6b. **scratch popup (prefix+t) の中でも出るか**: scratch は別サーバではなく同じサーバの別
   セッションなので、その pane の枠にも出るはず。**ヘッドレスでは確認できていない**
   (popup を開くには attach 済みのクライアントが要る)。実測したのは「scratch セッションの
   pane も `pane_top=1` = 枠の行を持つ」ことと「その pane にオプションを立てると format が
   展開される」ことまで。popup の枠が狭くて文字が切れる・枠自体が描かれない、なら
   status-right へ出す案 (issue 166 の案 B) を併用する判断が要る。
   なお予約の置き場は scratch と通常セッションで共通 (同じサーバなので分かれない)。
7. **サーバ再起動後**: 予約を仕掛けて `kill-server` → 立ち上げ直し → `prefix+m` を開くと
   失効の通知が出て、表示も消えていること (prune 経路)。

## 確認できたら

`issues/done/` へ移動する (既読はファイルの位置で表す)。表示の調整が必要なら
その内容を新規 issue に起こしてから移動する。
