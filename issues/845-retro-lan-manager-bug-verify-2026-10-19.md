# 845 (retro): lan-manager のバグ探しと残りの検証の振り返り

起票日: 2026-10-19

## 概要

lan-manager のバグ探しで 824〜826 (17 件) を起票した。別のセッションが 10/18 に 16 件を直して done へ送り、
残りの 1 件は 830 (risk) に切り出された。このセッションは、done の本文で「未実測」「未解明」と残っていた項目のうち、
測れるものを測った。

- 825 の 4: ssh-copy-id は .pub が無いと rc=1、空だと rc=1 で失敗した (直しは必要だった)
- 825 の「setup のテストが 1 回だけ赤」: setup を 10 回、全 package を並行で 3 回回して全部緑。ここで打ち切り、本文の trigger を待つ
- 826 の 4: 使っていない Thunderbolt Bridge を切り替えて `-getinfo` の実出力を採り、戻した (ユーザーに確認を取ってから)。作った値は
  `Subnet mask:` / `Router:` の行を持っていたが、実出力には無かった (Router の行が未接続で出ないことは netinfo.go の reRouter の注記に 2026-10-15 の実測として既にあった。
  新しく分かったのは Subnet mask の行も無いことと、2 つの方式の 1 行目の実出力)。実装はその行に頼っていなかったので、テストの入力を実出力に置き換えただけで済んだ
- 途中で、別のセッションの commit (0f2ca38f) が残した `src/mac-lan-manager` の lint の赤 (intrange) を直した

## どこで踏んだか / 何が回りくどかったか

1. **「本物の設定を変えるので打っていない」で未実測のまま閉じられていた項目が、使っていない同種の資源で安全に測れた**。
   826 の 4 は、done の本文で「該当するサービスが無く、`-setmanualwithdhcprouter` を打つと本物の設定を変える」として
   未実測のまま閉じられていた。実際には、使っていない Thunderbolt Bridge (DHCP・IP 無し) で切り替え → 読む → 戻す →
   前後の一致を確かめる、が数十秒で済み、sudo も要らなかった。測ってみると作った値が実出力と違っていた (作った値にある Subnet mask / Router の行が実出力には無い。Router の欠落は別の方式で既知だった)。
   直していた側は、測る経路を「使っている資源を変える」か「測らない」かの 2 択で考えていた
2. **mutate-verify を 2 回、使い方の誤り (rc=2) で空振りした**。`--expect` が必須なこと、`--file` を repo root からの
   相対パスで渡すことを知らなかった。どちらの回も出力を grep で絞って読んだので、1 行で出ていた理由が見えなかった。
   rc=2 を見てから全文を cat し、やっと理由が分かった
3. **作った値の fixture が、実出力にある/無い行の違いを隠していた**。c37214ae より前のテストの入力は `...\nSubnet mask: 255.255.255.0\nRouter: (null)\n` で、
   未接続のサービスが Router の行を出さないことは同じファイルの注記で既に分かっていたのに、作った値はそれを反映していなかった。
   1 に書いたように測れる経路はあったので、作った値で済ませる理由は無かった

## 次に効きそうな改善

- **提案 A (1)**: 「測ると本物の状態を変えてしまう」から未実測で残す前に、**使っていない同種の資源 (使っていない network service・
  予備の I/F・テスト用のアカウントやボリューム) で切り替えて、元に戻して、前後の一致まで確かめる案**を探す。見つかったら、
  変える対象と戻し方を示して確認を取る (今回は AskUserQuestion で、変える service・切り替えの順・DHCP へ戻すこと・測る間は DHCP でなくなることを示して了解を得た)。
  「隔離できる」と言ってよい条件も文面に入れる: その資源を今使っているものが無い (IP 無し・経路に載っていない) / 戻す手順が 1 コマンドで、前後の読み出しを
  diff して一致を確かめられる / 他の資源 (使っている service・経路の順) に触れない。条件を満たさないなら、今の項のとおり強行せず未確認の範囲を書くtmux の隔離サーバで「human に回す前に測れないか」を問うのと同じで、
  外の CLI の設定の読み書きにも広がる話
  - 切り出し先: 既存の `_claude/rules/measure-external-cli-streams-separately.md` の「実 CLI を足すのは副作用を隔離できる場合に限る」の項に 1 行足す
    (新しい rule は立てない。発動点は同じ「副作用を隔離できるか」の判断)
- 却下 (2): 「検証コマンドの出力を grep で削って読まない」は `verify-execution-not-just-exit-code.md` に既にある。守らなかっただけで、足す規範は無い
  (道具の側では、mutate-verify は rc=2 の理由を `mutate-verify: --expect は必須 (red の帰属を…)` / `--file が repo 内に無い: …` の 1 行で出していた (このセッションのログで確認)。直すところは無い)
- 却下 (3): 「fixture に本物と書くなら本物を貼る・作った値は照合の規則の誤りを隠す」は `measure-external-cli-streams-separately.md` に既にある。
  今回はその実例が 1 つ増えただけ (提案 A が入れば、作った値で済ませる理由そのものが減る)
- 局所 (直した): lint の intrange を range にすると、今度は prealloc が出た。その場で両方直した (`6dd4ef07`)。他に効く形ではないので提案しない
