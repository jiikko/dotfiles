## どこで踏んだか / 何が回りくどかったか

1. **zsh の関数で `local path` と書き、PATH が空になった** (670 の `bin/lib/go_tool.sh`)。zsh の `path` は PATH と結び付いた配列で、
   bash では同じコードが動く。bash から source した確認だけでは見えず、zsh から呼んだときだけ「ビルドできない」で落ちた
2. **字句で判定する lint を、まず rc=1 で止める警告として書いた** (686)。正当な使い方 (公開文献を名前で引く「DX レポート」) を含む実際の台本で
   流すまで、警告と目安の振り分けが逆になっていることに気づかなかった。敵対レビューの 2 周目で、手元の別の台本を流して初めて分かった
3. **新しいテストが必要とする道具を、そのテストが走る CI のジョブが持っていなかった** (670 の 2 本目。concat のテストは heavy のジョブで、
   Go を入れていなかった)。レビュワーが「未確認」と書いた点を確かめて見つけた
4. **変異検証の red の数え方を誤った** (670)。`"\n--- FAIL"` で数えて、出力の 1 行目に出た FAIL を落とし、12 本中 10 本を green と読みかけた。
   red=0 が多すぎることに違和感を持って数え方を疑った
5. **pathspec を付けずに `git commit` し、変更済みのファイルが WIP に入らなかった** (670。自分の worktree の中なので混入は無かった)

## 次に効きそうな改善 (提案)

- **1 → `.claude/rules/` の zsh の規則へ追記** (dotfiles の zsh 固有の規範の置き場): 「zsh の関数の中で、特別な名前 (`path` `fpath` `cdpath`
  `manpath` `status` `pipestatus` 等) を local の変数名に使わない。bash と zsh の両方から source される lib は、両方から呼ぶテストで固定する」。
  新規の規則にはしない (発動点が zsh の lib を書くときで、既存の zsh の規則と同じ)
- **2 → `_claude/rules/adversarial-review-own-safeguards.md` §8 へ追記**: 「字句の gate を rc=1 にする前に、正当な使い方を含む実際の入力 (別の書き手の
  文書を最低 2 つ) で流し、偽陽性と見逃しの両方向を数えてから強さを決める」。§8 は検出しない形を先に書く節で、強さの決め方が無い
- **3 → `_claude/rules/verify-execution-not-just-exit-code.md` の「CI のジョブに足す依存」の行へ追記**: 今は「依存を足すとき」だけ。
  「**依存を要するテストを足すとき**も、そのテストが走るジョブ (グループ) を Makefile / workflow で辿り、依存があることを確かめる」を足す
- 4 → 却下: 既存の `verify-execution-not-just-exit-code.md` の「抽出・判定を書いたら、同じ経路を通る canary を先に置く」で足りる (今回は守らずに踏んだ)
