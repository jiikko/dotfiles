# 765 (retro): 利用上限の表示・バナーの除去・claim の道具を作ったセッションの振り返り

起票日: 2026-10-15

対象: 762 (codex-fanout の利用上限の表示) / 705 (viewer の `o` のテスト) / 763 (issue_done.sh のバナー) / 764 (issue_claim.sh)。

## 踏んだところ

1. **出力の中から「原因の行」を字面で探す判定が、敵対的レビューのたびに 1 段ずつ崩れた (762、5 周)**。
   log 全体の grep → 末尾 40 行 + プロンプトの除外 → 末尾の塊 → 区切り行で切る → 自分で控えた長さで切る、と直すたびに、
   プロンプトの echo・コマンドの出力・本文の追記が同じ文言を引用する別の形で崩れた。収束したのは「どこに在るか」を、
   出力を書いた側 (driver 自身) が境界を控えて決めたとき
2. **`&&` で繋いだ手作業の複数段の git 操作が、先頭の失敗で後段を飛ばし、半端な commit を作った** (763 の採番: pull の失敗で本文が書かれず symlink だけの commit)。
   pre-push が止めたので外へは出なかった。764 の道具化の起点
3. **ロケールに依存する道具 (awk) を、正しさを判定する側で素のまま呼んでいた** (763)。不正なバイトで UTF-8 の awk が止まり、xargs の残りを読まないまま緑、
   別の awk では `|| true` で握り潰されて別の理由で落ちた。最初の修正は呼び出しごとの `LC_ALL=C` で、同じ仕組みの別の呼び出しが残った (レビューが字面でなく仕組みで grep して見つけた)

## 次に効きそうな改善 (提案。切り出し先はユーザーの判断を待つ)

- A. **外部の道具の出力から原因を読み取る判定は、出力の中の位置を、出力を書いた側が控えた境界で決める。引用されうる文言を字面で探さない**
  (別の道具・別の repo でも同じ形: ログの分類・CI の失敗の分類・レビューの集約)。切り出し先: 既存の `_claude/rules/measure-external-cli-streams-separately.md` への追記
- B. **複数段の状態変更 (採番 → 書く → commit → push) を手で `&&` に繋ぎかけたら、1 本ずつ結果を見るか、まとめて道具にする**。
  切り出し先: 却下候補 (764 で道具にしたので、この repo の claim については解消。一般形は既存の `verify-execution-not-just-exit-code.md` の「`&&` のつなぎ」の項で足りている)
- C. 局所: 763 の LC_ALL の件はその場で直した (issue_done.sh の先頭で export)。提案にしない
