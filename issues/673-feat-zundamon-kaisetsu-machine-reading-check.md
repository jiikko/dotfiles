# 673 (feat): zundamon-kaisetsu の読みの見直しを、機械の検査と短い一覧に置き換える

起票日: 2026-10-08

## 概要

skill の手順 5 (読みの見直し) は、`kana --script` で全行の読みを書き出し、sonnet のサブエージェント 1 体に全行を読ませて
誤読を探させている。1 本の動画で 1 体あたり約 15 万トークン使うが、見つけた誤読はどれも、ツールの出力から機械で
見つけるか、候補を数十語の一覧に絞れる種類だった。誤読の種類ごとに、機械で確定できるものは検査に、
確定できないものは「語ごとの短い一覧」にして main agent が見る形に置き換え、サブエージェントを要らなくする。

## 実測 (2026-10-08、同じセッションで作った 2 本)

|---|---|---|---|

  誤読は今回 0 件で、この issue の対象から漏れているかは分からない (手順 5 の観点には入っている)

## 対応方針 (案)

1. **`kana --script` に、英字の語を 1 文字ずつ読んだ行の検査を足す** (例: `--check`)。字幕の英字の語 (読みの置き換え表 `readings` で
   置き換えた後の文に残った語) ごとに、読みの中にその綴りの文字名の連結が現れたら警告する
   - 文字名の表は**実際のエンジンの出力から作る** (VOICEVOX 0.25.2 では A=`エエ`、D=`ディイ`、R=`アアル`、W=`ダブリュウ`、K=`ケエ`。
     「エー」のような普通の書き方では一致しない)。照合の前に読みから `'` `/` `_` `、` を取り除く
   - kana は文単位で語との対応が無いので、文全体の読みへの部分文字列検索になる。短い語の文字名の連結は、別の語の読みに偶然現れて
     誤検出しうる (今回のデータでは未確認。実測する)
   - 文字名が 2 通りある文字 (Z = ゼット / ズィー 等) は、表に両方を持つ
   - **1 文字ずつ読むのが正しい略語 (CPU・GPU・OS・IT・AI・VPN・SSH・SNS・ID・IPA・DX・SI) は、許可リストに並べて通す**。
     「大文字 4 文字以下は略語として通す」案は採らない (IDOR は大文字 4 文字なので、それでは検出できない)。許可リストは辞書
     `readings.json` の隣に置く
2. **英字の語ごとの一覧を出す** (例: `kana --words`)。台本に出る英字の語 (重複を除く) を、語だけをエンジンに読ませた読みと並べて出す。
   main agent はこの数十行を自分で見る (サブエージェントを起こさない)。辞書 `readings.json` に載っている語は除く
3. **漢字の読み分け**は、読み分けを誤りやすい字の一覧 (上・下・値・親・空・内製・生 等) を持ち、それを含む行を読みと並べて
   2 と同じ一覧に足す案がある。正しく読めている行も混ざる (「上」を含む行は全部挙がる) ので、確定ではなく候補の一覧として扱う。
   一覧に無い字の誤読は見つからないので、この種類は「機械では一部しか拾えない」と SKILL.md に書く
4. SKILL.md の手順 5 を、1 → 2 → 3 の順に置き換え、サブエージェントの起動を外す
