# 411 (retro): Terminal プロファイルへフォントを足したセッションの振り返り

起票日: 2026-09-23

対象: commit `feat(terminal): プロファイルにフォント (HackNFP-Regular 13) も含めて復元する`

## どこで踏んだか

1. **「既に動いている値を repo に固定するだけ」に見えた作業が、無音で壊れる罠を 2 つ持っていた**。
   どちらも実機では正常に見え、フォント未導入のマシンでだけ壊れる形だった
   (Terminal が代替フォントへ黙って差し替える / NSFont の decode が未導入フォントを代替名に化けさせる)。
   気づけたのは「設定した後に読み戻す」「在庫の無い名前で実験する」を先にやったからで、
   正常系の確認だけなら 3 回やっても出なかった。

2. **同型バグの横展開を自分では grep しなかった**。フォントのサイズに `isFinite` 検査を入れた
   直後に、**同じファイルの 10 行上にある色成分の `Int()` 変換**が無検査のまま残っていた
   (NaN で SIGTRAP)。敵対レビュー 2 周目が指摘するまで気づかず、しかもその失敗モードは
   issue 084 が潰したものの再来だった。

3. **新設したシェル側の 2 段 (在庫ゲート / 読み戻し比較) を grep の pin だけで「守った」と扱った**。
   レビューが変異を当てると**どちらを外しても全緑**で、commit message に「2 段で守っている」と
   書く直前だった。fake `osascript` / `pgrep` を PATH 先頭に置く挙動テストへ置き換えて解決した。

## 残課題 (切り出し先)

      までで、**「今まさに新設したガードの射程外に、同じ変換が残っていないか」**という向きが無い。
      → 既存ルールへの追記。発動点は「ガードを 1 箇所に入れた瞬間」

- [ ] **提案 2**: 「外部コマンド / GUI アプリへ設定を書いたら、**同じ呼び出しの中で読み戻して
