# 660 (bug): zundamon-kaisetsu の mp4 で、字幕と口の切り替わりが音声と 1 フレーム前後し、終わりの映像が欠ける

> 🚨 **担当中: dotfiles-4d**（2026-10-07〜）

起票日: 2026-10-07

## 概要

audit の「仕様から独立に計算した値で実出力を測る」実験 (issue 656 の続き) で見つけた。`mp4.go:writeMP4` は状態ごとの絵を
ffconcat の一覧 (各絵の表示秒数を `duration`) で並べ、`-r 30 -fps_mode cfr -shortest` で 30fps にしている。この変換で、
プレイヤーのデータの規則 (フレーム k は時刻 (k+0.5)/30 の状態。`build.go:frameRuns`) どおりのフレームにならない。

## 実測 (2026-10-07、ffmpeg 9.0.2 / libx264、testdata/build の台本 5 行・3.5835 秒)

- 実物の mp4: 映像 105 フレーム (3.500 秒) / 音声 3.5835 秒。仕様の総フレーム数は `ceil(尺 × 30)` = 108
- 行の字幕が変わるフレーム: 行 0〜2 が 1 フレーム早い (期待 12 / 28 / 60 → 実際 11 / 27 / 59)、行 3・4 は一致
- 状態ごとに一意の灰色の単色 PNG で同じ一覧と同じオプションを再現: 108 フレーム中 17 フレームが期待と違う状態
  (`-shortest` を外しても同じフレームでずれる。ずれの原因は concat の duration を 30fps に変換するところ)
- 20 分ぶん (36,000 フレーム・6,399 回の切り替わり) の合成の並び: ずれは累積せず、各切り替わりが ±1 フレーム
- concat のまま直す変種 (duration を 9 桁 / fps フィルタの round=near・down・up / settb + setpts で丸め) は、どれもずれが残った (4〜17 フレーム)
- **フレームごとに状態の絵への symlink を連番で並べ、`-framerate 30` の連番として読む形は 108 フレームすべて期待どおり**
  (`-shortest` を付けると音声の終わりの手前のフレームの境で切られて 107 になるので付けない)
- 速度: 1280x720 の絵 40 種類・2 分 (3,600 フレーム) で concat 3.6 秒 → 連番 4.4 秒 (testsrc2 の絵での実測。本番の絵の重さは未実測)

## 影響

- 字幕と口の切り替わりが音声と最大 1 フレーム (33ms) 前後する (口の動きのずれが気づかれる閾値 約 45ms の内側)
- 短い台本では最後の約 0.1 秒の映像が欠ける (-shortest と変換の取りこぼし)

## 対応方針

- writeMP4 を「総フレーム数ぶんの symlink を連番で並べ、`-framerate 30` で読む」形にする。`-r` / `-fps_mode cfr` / `-shortest` は外す
- 状態の並び (フレームごと) を作る純粋な関数を置き、`frameRuns` の規則と 1 対 1 で一致することをテストで固定する
- 実物で同じ実験 (framemd5 ではなくフレームの平均の灰色で状態を読む) を回して、ずれが 0 になることを確かめる
