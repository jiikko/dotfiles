# retro: statusline に weekly 消化ペース行を足したセッション (2026-08-22)

対象コミット: `37b3432` (`_claude/statusline-command.sh` / `tests/claude/test_statusline.sh`)

## やったこと

7 日窓の「今どこまで来ているか」を出す 3 行目を追加した。UI は 3 パターン出して
ユーザーがパターン A (バー→数値→助言) を選び、想定通りの帯は ±10pt に広げた。
残り時間表記は最初「残2.5日」だったが、ユーザー指摘で既存 `fmt_remaining` を再利用した
「残2日13時間」に変えた。

## 敵対的レビュー 3 観点の全数勘定

観点を分けた red team 3 本 (誤表示・境界 / テストの false green / 環境・性能)。

### 採用 (このコミットで修正)

| 指摘 | 対応 |
|---|---|
| リセット済み (`resets_at <= now`) で「-38pt 余らせ過ぎ・もっと使える」と逆向きの助言 (2 観点が独立に指摘) | ガードを `-gt "$now"` に。1 日予算の 0 除算も同時に封じ、境界の両側をテストで固定 |
| 非整数の `used_percentage` (`"08.5"` / `5e1` / 全角) で `$(( ))` が fatal になり **3 行目が無言で消える** | `to_int` で整数へ正規化。数字判定に範囲 `[!0-9]` を使うと locale の照合順で全角が素通りする (実測) ので列挙にした |
| テストの素通り変異 10 件 (小数部の `.0` 固定 / 切り捨て↔四捨五入 / バー塗りの丸め / 末尾 `\|` / グレー / 行末 reset / クランプ) | 端数を持つ fixture (222912 秒 / 45% / 3600 秒 / 120%) を足して全部 red 化 |
| 追加分で fork +2・+1〜2.5ms/描画 | `printf -v` と `fmt_remaining` の REPLY 返しで解消 (実測 29ms/描画で変更前と同値) |

### 却下 (理由つき。次の audit が同じ指摘を再生成しないため残す)

- **クランプの `-gt 9999` → `-ge 9999`**: どちらも 9999 を代入する**等価変異**。テストが
  検出しないのは正しい (false positive)
- **実績 100% 超 × 窓終盤でバーが飽和し先行が見えない**: バーは概観、符号は数値ラベル
  (`+12pt 先行`) が持つ。バーを歪めてまで表現しない。理由はコード直近のコメントに残した
- **負の `used_percentage`**: 正規化で「その段を出さない」に落ちるため個別対応なし
- **20 桁の `resets_at`**: 既存ガードが黙って弾き、誤った数字は出ない (機能が消えるだけ)
- **format string injection**: レビュアーが再現できず。外部値は `%d`/`%s` にしか届かない

### 未確認リスク

- **TZ / clock skew / うるう秒**: レビュアーがシステム時刻を触らず未検証。`date +%s` は
  UTC epoch で算術も TZ 非依存なので理屈上は影響しないが、実測はしていない

## 残課題

  短縮形 (`7d [bar] 62%/想定71% (-9pt 想定通り)`) に切り替える判断が要る
  → 切り出し先: 実害が出てから新規 issue。今は却下 (speculative)
