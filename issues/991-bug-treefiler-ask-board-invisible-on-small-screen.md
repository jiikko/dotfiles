# 991 (bug): treefiler の確認の板と設定の板が小さい画面で描かれないのにキーを取り、見えないまま実行・変更する

起票日: 2026-10-30
優先度: 中 (発火は小さい画面に限るが、`d` のゴミ箱へ移す操作が見えない確認で実行される)

## 概要

`d` (ゴミ箱へ移す) と `>` (100 件以上を開く) が出す中央の確認の板 (`filer/ask.go` の `askBoard`) は、`Model.drawAsk` が
幅 `min(confirm.MaxWidth+8, m.w-2) < 20` か `m.h < 7` のとき**何も描かずに戻る**。一方で `m.ask` は立ったままなので、`HandleInput` は
次のキーを全部この板へ渡す (`askKey`)。`d` の板は `yOnly` でないので **y と Enter が「実行」**、それ以外が取り消しになる。

単体の `bin/treefiler` の最下行 (`Model.statusBar`) は層によらず固定の案内 (`!` cmd・`s` shell …) を出すので、板が開いていることは
画面のどこにも出ない。glogx の F は層の間、glogx の最下行を `LayerHints` (「y/enter ゴミ箱へ移す」) にするので、見える手掛かりが 1 行残る。

## 発火条件

- 単体の treefiler (tmux の `prefix f` の popup は端末の 90%×85%、またはペインで直接起動) で、端末が幅 22 列未満か高さ 7 行未満
- `d` を押す → 板は見えない → 木の操作のつもりで Enter (`l` の別名。フォルダを開く) を押すと、カーソルの項目がゴミ箱へ移る
- `>` の板は `yOnly` なので Enter では実行しない (取り消しになる)。y だけが危ない
- tmux の popup は枠を持つ (`-B` を付けていない) ので、しきい値は枠の内側に掛かる。端末に直すと、およそ幅 26 以下・高さ 10 以下
- **同じ形が設定の板 (`,`) にもある** (反証レビューで見つかった): `settings.go` の `drawPanel` は `min(52, m.w) < 24` か `m.h-1 < 6` で描かずに戻るが、
  `HandleInput` は `panelKey` へ渡す。見えないまま `l` / Enter / `h` で値が変わり (`adjust` → `applySettings`)、`r` で既定へ戻る。`q` は板を閉じるだけで終了しない
- キー一覧 (`?`。`drawHelp` は `w<20 || h<4`) も描かれないが、どのキーでも閉じるだけで害は無い (1 打鍵を食う)

ゴミ箱へ移すだけなので戻せるが、確認の板が「唯一の確認」になっている操作で、確認が見えないまま実行される。

## 対応方針

- 板を描けない大きさのときも、確認していることと答え方を最下行に出す (例: `ゴミ箱へ移す? y/enter: 実行 その他: キャンセル`)。
  最下行は高さ 1 から在るので、どの大きさでも見える。幅が足りないときは**答えのキーを先に残す** (切れて `y/enter` が見えないのでは意味が無い)。
  設定の板も同じく、描けないときは最下行に「設定 (画面が小さい)」と閉じるキーを出す。最下行を使う検索欄・入力欄は確認の板・設定の板と同時には開かない
  (`takeExplode` は `OwnsKeys` の間は板を重ねず、`d` は検索中は検索欄へ行く)
- 描けないときに板そのものを開かない (操作を断る) 形も考えられるが、`>` の板は裏の走査の終わりで出るので、断ると何が起きたか分からない。案内を出す方を採る

- [ ] 同じ大きさで `,` を押したとき、最下行に設定の板が開いていることと閉じるキーが出る
