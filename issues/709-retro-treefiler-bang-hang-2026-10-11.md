# 709 (retro): treefiler の `!` が固まる不具合の調査と修正 (2026-10-11)

起票日: 2026-10-11

対象の作業: treefiler / glogx の `!` で `ls` を走らせると「[done] 何かキーを押すと…」のまま固まる不具合。
commit「fix(treefiler): ! の後に端末の前面が戻らず treefiler / glogx の F が固まるのを直す」で直した。残りは 707・708。

## どこで踏んだか / 何が回りくどかったか

1. **修正の効果を、修正前とは別の入力で測った**。修正前の固まりは外部コマンド (`ls`) で再現し、修正後 (`zsh +m -ic`・`sh +m -ic`) は
   ビルトインの `echo` で測った。ビルトインは前面を動かさないので、修正の有無に関係なく「戻る」が出る。これを根拠に
   「`+m` で zsh・bash の両方が直る」とユーザーへ報告し、後で bash 3.2 に効かないことが分かって訂正した。
   後の perl 案の slow ケース (`a; b` の形) でも、同じく機構を通らない入力で緑が出ていた (変異で見つけた)
2. **cwd の外の repo を、その repo のルールを読む前に編集した**。セッションは `~` で始まり、dotfiles の `.claude/rules/`
   (worktree-per-session) は cwd が dotfiles に入ってから注入された。共有ツリーに 2 ファイル書いた後で気づき、worktree へ移した
3. **解法が `+m` → perl で前面を取り返す → `trap 'exit $?' EXIT` と 3 回変わった**。最初に「前面を戻すのは誰で、なぜ戻らないのか」
   (シェルが最後のコマンドを exec する) を観測せず、症状を抑える案から測った。perl 案は後片付けの機構で、作らずに済む構造
   (exec させない) が後から見つかった

## 次に効きそうな改善 (提案。切り出し先はユーザーの判断を待つ)

- **1 → 既存ルールへ追記**: `_claude/rules/verify-execution-not-just-exit-code.md` の「有無で結果が変わらない観測」節に、
  「修正の前後を比べるときは、修正前で赤を見たのと同じ入力で修正後を測る。入力を変えるなら、変えた入力で修正前も赤になることを先に見る」を足す。
  一般形: 対照実験の両腕で入力を揃える (別の repo・別の不具合でも同じ形で起きる)
- **2 → 既存の `~/.claude/CLAUDE.md`「作業開始前の準備」へ追記**: 「依頼が cwd の外の repo を触るなら、編集の前にその repo の
  CLAUDE.md と `.claude/rules/` を読む (repo のルールは cwd がその repo に入るまで注入されない)」。一般形: 起動した場所の外の
  repo には、その repo の規約が自動では届かない
- **3 → 却下**: `adversarial-review-own-safeguards.md` §0-A (掃除機構を作る前に、発生させない構造を問う) が既に同じことを言っている。
  ルールの不足ではなく適用漏れ
