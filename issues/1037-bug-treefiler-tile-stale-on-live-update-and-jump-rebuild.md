# 1037 (bug): treefiler のタイルが、ライブ更新での書き換えと表示の作り直しに追いつかない

## 概要

[1035](1035-research-treefiler-audit-2026-11-05.md) の監査の 4 周目の敵対的レビューが見つけた 2 件。どちらも 1035 の修正の前からある形で、
1035 では直していない (直し方に、読んでいる最中に本文や選択を差し替えてよいかの判断が要るため)。

## 詳細

### 1. ライブ更新でタイルのファイル自体が書き換わっても、本文を読み直さない

- 発火条件: タイルでファイルを開く → 別のペインでそのファイルを書き換える (ライブ更新が拾う) → `!` / `s` / `e` を挟まずに `G` や `j` で先へ送る
- 実際: `filer/model.go` の `applyChange` → `filer/fileops.go` の `reloadDir` はフォルダの子とリンクの解決 (`forgetLinks`) しか扱わず、
  タイルの `textSource` は差し替えない。`textSource.ensure` は読んだ所 (`off`) から先を読み足すだけなので、新しいファイルを古い読み位置から読み、
  行の重複・欠け・行の途中からの表示が混ざる。`e` / `s` / `!` から戻ったときは 1035 の `rereadTiles` が開き直す (`ExecDone`)
- 未確認: 書き込みの続くログ (`tail -f` で見るようなもの) を開いたときの見え方は実機で見ていない

### 2. ジャンプ中に表示の行を作り直すと、選んでいるリンクが知らせなしに別のパスへ移る

- 発火条件: タイルで `Tab` でリンクを選ぶ → 端末の大きさを変える (幅が変わり、折り返しで行の切れ目が変わる)。または差分の取得中にジャンプしていて行が届く
- 実際: `filer/tileview.go` の `view` は作り直すときに `t.links` を捨てる。`t.sel` (添字) は残るので、作り直した並びで別のリンクを指す。
  1035 は `forgetLinks` (フォルダの読み直し) の経路だけを `stale` の印で据え置く形にした (同じ理由)。この経路は防いでいない

## 対応方針 (案。判断が要る)

- 1: `applyChange` の `changed` にタイルのファイルの名前があれば、そのタイルに `rereadTiles` と同じ開き直しを掛ける。
  書き込みの続くログでは毎回開き直すことになるので、読んだ所までを読み直す量 (G で深く送ったタイル) の扱いを決める
  (末尾に足されただけなら読み足しで済む: 大きさが増え、読んだ所までの中身が同じ)
- 2: 作り直しの前に選んでいるリンク (行・桁・パス) を控え、作り直した並びで同じものに `sel` を合わせ直す。見つからないときだけ先頭へ寄せて知らせる
