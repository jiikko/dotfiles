## どこで踏んだか

### 1. 終了とシグナルの扱いを、敵対的レビューの指摘ごとに直して 5 周回った (862 の 7)

- 「閉じた後に裏の ssh の結果を待つ」を足し、待つのをやめる合図 (INT / TERM / HUP) を周ごとに直した。
  周ごとに別のセルが壊れた: Run の後に聞くと最初の合図を見落とす → ssh に端末を渡している間の Ctrl-C で「止める」が残る →
  聞いていない区間の INT で死ぬ → 印と bubbletea の区間のずれ → HUP を Close の後に聞く
- 4 周目の前に「合図 × 時点」の期待の表を作って組み直してから収束した。`survey-receiver-guards-before-passing-new-values.md` には
  一般形の「状態 × 読み手の表を先に作る」(状態に取り消し、読み手に外部からの完了通知を含む) と、UI の状態機械に裏の動作を足すときの
  「共有の状態 × 他の書き手」の表があるが、発動点が「どちらが正かの規則を決める・例外の状態を足す」「UI の状態機械に裏の動作を足す」で、
  シグナルと終了の扱いを足す場面に当てはめなかった

## 次に効きそうな改善

1. **シグナル・終了・取り消しの扱いを足すときも、先に「合図 × 時点」の表を作る**
   - 表の中身 (状態に取り消し・読み手に外部からの完了通知) は一般形の項に既にある。足りないのは発動点に「プロセスの終了の扱い
     (シグナル・取り消し・後片付けの待ち) を足すとき」が無いことだけ
   - 切り出し先: `_claude/rules/survey-receiver-guards-before-passing-new-values.md` の「状態 × 読み手」の表の項の発動点に追記
     (例として軸: 合図 (INT / TERM / HUP / Ctrl-C) × 時点 (画面の中・子に端末を渡している間・閉じてから・待っている間))
2. **画面・出力の全体に語が含まれるかを見る assert は、同じ語が別の場所にも出ないかを確かめる。出るなら該当の行・領域に絞る**
   - 「その assert が見ている量は、壊れたときに動くのか」は rule 本体 (`_claude/rules/mutation-verify-new-tests.md`) にあり、checklist の
     「文字列を部分一致で pin していないか」は全体が契約の場合 (完全一致で固定する) を言う。全体の Contains が別の出所の同じ語で満たされる形は名指しされていない
   - 切り出し先: `_claude/rules-checklists/mutation-verify-new-tests.md` の「文字列を部分一致で pin していないか」の項を広げる (新しい行は足さない)
3. **done の決着節は、確かめた範囲と相手の言葉どおりに書く。「両方」「全部」「〜とも」と書く前に、その全部を確かめたかを数える**
   - 「done へ送る前に本文の現状を実測し直す」は他人の書いた本文が対象の書き方で、自分がその場で書き足す決着節に当たらなかった
   - 切り出し先: `_claude/issue-rules.d/move-report-conclusions-to-issues.md` の「issue を done/ へ送るときは…実測する」節に 1 行追記
4. **待ちの間 (レビュー・CI) に残す作業は、worktree の中でも未コミットのまま置かない。WIP でよいので commit する**
   - commit 済みなら hash から戻せることは `.claude/rules/worktree-per-session.md` (push の前に worktree を消した実例 266) に既にある。
     新しいのは「未コミットの変更は object にも残らず戻せない」の点だけ
   - 切り出し先: `.claude/rules/worktree-per-session.md` (dotfiles) に 1 項追記。あわせて、他人の worktree を消す前に持ち主を確かめる形が
     既存の rule (`parallel-write-agents-need-worktree-isolation.md` の「他人の worktree / 未コミット差分を『放置された残骸』と判断する前に」) で
     足りているかを、消した側が分かったときに見直す
