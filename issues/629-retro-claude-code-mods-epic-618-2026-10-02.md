# 629 (retro): Claude Code の mods (epic 618) を 619〜625 まで進めたセッション (2026-10-02)

起票日: 2026-10-02

## 概要

epic 618 の子を順に進めたセッションの振り返り。619 (土台) / 620 (移さない) / 621 (帯) / 622 (sh に分けた) / 623 (ask) を done、625 は 628 (human) の確認待ち。
うまくいった話は書かない。

## どこで踏んだか / 何が回りくどかったか

1. **設計の前提にした拡張点が、この環境では届かなかった。** epic は `prompt.compose` (システムプロンプトへの節) と `classic.*` (settings の hook のイベント) を
   使う前提で組まれていた。619 で probe を書いて初めて、managed settings のあるマシンでは組み込みの `cc-plugin-sec-default` がそれらを
   user の mod に届かせないと分かり、620 は計測の腕すら作れずに閉じた。型定義とドキュメントは「使える」と書いていた
2. **Claude の中から claude を起こして測ると、親の環境が子に混ざる。** desktop のセッションの `CLAUDE_CODE_*` と、619 の後は settings の env の
   `CLAUDE_CODE_PLUGIN_DIRS` が子に継承される。`env -i` の最小環境から起こすまで、どの経路で読まれたかを区別できなかった
3. **「新しい仕組みに移す」前に「今の仕組みのまま軽くする」を測らなかった。** 622 は mod の試作 (12ms) まで作ってから、敵対レビューの
   P2 (失敗・拒否でも発火 / 読まれないとベルが鳴らない) を受けて、初めて「bash を起こさない sh に分ける」(15.7ms) を測った。
   後者は新しい失敗モードを持たず、最初から並べて測っていれば試作と 1 周分のレビューは要らなかった
4. **人やコマンドを止める gate を、広い範囲から始めて削っていった。** 623 は「確実に捨てる形は ask」を字句の判定で広く取り、
   敵対レビュー 5 周で「引用符の中」「コメント」「cd の追跡」「複数の segment」「対象の repo の取り違え」を 1 つずつ削った。
   最終形は「1 つの単純な git コマンドで、対象の repo に自信があるときだけ ask、それ以外は今までどおり注意」で、最初からこの形で始められた。
   同じ日の 617 の retro (項目 4) も、字句の検査で同じ形を踏んでいる
5. **テストの道具の制約を、確かめずに文書とコメントに書いた。** `claude plugin test` で `$.session.id` を答えられない、と 619 で書いたが、
   op のイベントは `{ value }` で包んで答える決まりだっただけだった (エラーの「result object ではない」が言っていた)。622 の試作で気づいて訂正した
6. **背景のサブエージェントと自分の計測を重ねていた。** 5h 枠を気にしたユーザーに「直列で、ゆっくり」と止められた (記憶 serial-agents-only に追記済み)
