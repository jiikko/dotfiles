# 828 (feat): lan-manager の IP の後ろに (有線) / (無線) を出す

起票日: 2026-10-18

## 概要

一覧と詳細カードの IP の後ろに、その IP へ繋がる線が有線か無線かを括弧で出す (例: `192.168.1.23 (無線)` / `10.0.0.5 (有線)`)。

## 要望と目的 (ユーザー、2026-10-18)

- 接続している IP の後ろに、有線か無線かを括弧で出したい
- 目的は issue 827 (通信速度) と同じ: 基本は有線で繋ぐが、無線で繋がっていると遅くなるので、どの線で繋がっているかを一目で知りたい。
  827 とは別の issue にする (表示だけで帯域を食わない。ユーザーの指示)
- 背景: issue 747 の決定 (2026-10-13) に「既定は両方を出し、有線 / 無線の列を付ける」があり、未実装のまま残っている。この issue がそれを引き継ぐ

## 詳細

### 分かること・分からないこと (2026-10-18 時点のコードで確かめた)

- **この Mac 側の線は分かる**: 相手の IP は、この Mac のどの I/F で見えたか (`dev`) を一覧を組むときに持っている
  (`lanmgr/model.go` の `rows()` → `ifKind(dev, ip)`)。その I/F のサービスの Hardware Port (`netinfo.Service.Port`。"Wi-Fi" /
  "Thunderbolt Ethernet" / "Thunderbolt Bridge" など) で無線か有線かが決まる
  - 🚨 `netinfo.Service.NotWiredLAN` は**無線の判定ではない** (「Mac 同士の有線の網に使わない I/F」の判定)。"iPhone USB" (USB ケーブル = 有線) も
    真になるので、流用すると iPhone USB が (無線) と出る。無線の判定は Port が "Wi-Fi" / "AirPort" / "Bluetooth PAN" のときとして別に持つ
- 🚨 **今の「メイン」「内部」の分類は無線・有線の分類ではない**: `netinfo.Kind` はルーターの有無で分ける (`KindInternet` = ルーターのあるサービス、
  `KindWired` = ルーターの無いサービス)。ルーターに有線の Ethernet で繋いだ Mac のメイン IP も `KindInternet` になる。
  括弧は `Kind` から作らず、Port から作る
- 🚨 **`row` はメイン IP と内部 IP がどの I/F で見えたかを捨てている**: `row.mainIP` / `row.lanIP` は文字列だけで、`dev` を持つのは
  `row.others` (`netinfo.IP.Device`) だけ。括弧を出すには、メイン・内部の IP にも見えた I/F (か、その Port から決めた有線 / 無線) を持たせる
- 🚨 **管理対象の内部 IP は Bonjour で見えた IP ではなく台帳の値**: `rows()` は台帳の行を `lanIP: clean(h.LAN)` で作り、`lanPicked := r.ledgerLAN != ""` の
  ときは Bonjour の有線の IP を `others` へ回す。内部 IP に括弧を出すには、台帳の IP を Bonjour の `Addrs` と照合し、見えた I/F が分かったときだけ出す
- 🚨 **複数の I/F で見えた相手のメイン IP は I/F 番号の小さい方**: `rows()` は `slices.Sorted(maps.Keys(p.Addrs))` の順に回し、最初の `KindInternet` を
  メイン IP にして、2 つ目以降の `KindInternet` は `others` にも入れず捨てる (`discover.Peer.Addrs` は I/F ごとに IPv4 が 1 つ)。Wi-Fi (en0) と
  ルーター向けの有線 (en7 など) の両方で見えた相手は、メイン IP が (無線) と出て有線の経路が見えなくなる。目的 (無線で繋がっていないか知りたい) と逆の表示になるので、
  有線と無線の両方で見えたときにどちらをメインにするか・捨てている方をどう出すかもこの issue で決める
- **ルーターの無い Wi-Fi で見えた IP は内部 IP の列に入る**: `Snapshot.class` は無線を除かないので `KindWired` になる (747 の残りの項に既知として記録)。
  Port で作れば (無線) と出るので、「内部 IP なのに (無線)」という表示になる (嘘ではないが、内部の網の判定側の穴が見える形)
- **相手側の線は Bonjour からは分からない**: 「この Mac は有線 → ルーター → 相手は Wi-Fi」の経路では、この Mac 側から見ると (有線) だが途中に無線がある
- **相手側は、鍵で入れる相手なら ssh で読める**: `setup.ObservePeer` (`setup/remote.go`) は鍵で入れた相手の `netinfo.Read` を ssh 越しに
  走らせて相手のサービスを全部読んでいる (今は `Offline()` の先頭だけを `PeerNet` に残す)。相手の IP が載る I/F の Port を残せば相手側も出せる。
  ただし今 `Observe` を起こすのは初期設定の画面 (`lanmgr/setup.go`) だけで、一覧では走らない (一覧で走らせると相手ごとに ssh が要る)

### 表示の候補

- (a) この Mac 側だけ: `192.168.1.23 (無線)`。全部の相手に出せる。相手側の無線は見えない
- (b) (a) + 相手側を読めた相手は両側: `192.168.1.23 (有線 → 無線)`。相手側を読むのは鍵で入れる相手だけ (管理対象のうち初期設定を済ませた相手が主)
- 推奨は (a) を先に入れ、(b) は相手側を読む契機 (初期設定の画面を開いたとき / 827 の測定のとき / 一覧で定期的に) を決めてから

## 決めること (着手前にユーザーへ確認する)

1. (a) だけか、(b) まで入れるか。(b) なら相手側をいつ読むか (一覧で全相手に ssh するのは重いので、初期設定の画面か 827 の測定のついでを推奨)
2. 括弧を出す場所 (宛先の行は `Model.target` が有線の名前を返すことがあり、IP とは限らない。名前のときも括弧を出すか): 一覧の「メイン IP」「内部 IP」の列 (今の幅は 17 / 18 桁。括弧の分だけ広げるか、列見出しの側に出すか)・詳細カードの
   「メイン」「内部」の行・ssh / smb / 画面共有の宛先の行。推奨は詳細カードの全部と一覧の 2 列
3. 判定できないとき (I/F がサービスに登録されていない・`-getinfo` を読めない) の出し方: `(?)` か括弧なしか。推奨は括弧なし (嘘を出さない)
4. **有線と無線の両方で見えた相手のメイン IP**: 有線を優先してメインにし、無線の IP を「その他」に残す形を推奨 (今は I/F 番号順で、無線の側が捨てられることも有線の側が捨てられることもある)
5. 見た目 (語・色)。本体へ入れる前に見本で決める (全角の括弧と半角の IP を同じ列に縦に並べると揃って見えないので、括弧は半角か列を分ける)

## 対応方針 (決めることが決まった後)

- 有線 / 無線の判定は `netinfo` に 1 つ置く (Port から決める関数。`NotWiredLAN` とは意味が違うので別の関数にする)。issue 827 の結果の行の「経路 (有線 / 無線)」もこの関数を使う (2 つ作らない)
- `rows()` でメイン・内部の IP に見えた I/F の判定を持たせる (表示の側で I/F を引き直さない)
- 判定のテストは `netinfo/testdata` の本物の出力を使う。Hardware Port が入っているのは `serviceorder.txt` / `serviceorder_renamed.txt`
  (`-listnetworkserviceorder` の出力。`getinfo_*.txt` は `-getinfo` の出力で Port を含まない)
