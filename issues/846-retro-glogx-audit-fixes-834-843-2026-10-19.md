# 846 (retro): glogx の監査 (844) の issue 834〜843 を直したセッションの振り返り

起票日: 2026-10-19

## 概要

glogx の全体監査 (844) で起票した 834〜843 を、1 つの worktree で直した (codex の実装レビュー 4 周 + opus の敵対的レビュー 2 本・変異は計 150 本超)。
途中で Claude と codex の 5h 枠の切れ目を 1 回挟み、最後に codex の週の枠が切れて、最後の 1 周は Claude のサブエージェントで代えた。

## どこで踏んだか / 何が回りくどかったか

1. **読み取りのみのレビューの最中に、同じ worktree を書き換えた** (規約違反)。opus と sonnet のレビューが worktree を読んでいる間に R1〜R4 の直しを入れた。
   指摘はレビュー開始時点の commit に対するものなので内容は有効だったが、どの版を読んだかが曖昧になった。
   後半は「レビュー用の detached worktree を HEAD に切り、レビューにはそちらを読ませる」に変え、レビュー中も本体で次の作業を進められた
2. **置換のスクリプトが当たらないまま黙って進んだ (2 回)**。python の `s.replace(a, b)` を件数を確かめずに書き、テストの入力を「300 件 → 1 件」に変える置換が当たっていなかった。
   変異 (256 件ごとの判定に戻す) が緑のまま通って初めて気づいた。もう 1 回は、python が失敗した後の行の `git rm` が走ってファイルを消した (別の行に書いて `&&` で繋いでいなかった)
3. **再開メモの「済」を確かめずに書いていた**。resume.md に「842 の A1〜A5 の一部は 840 で済」と書いたが、今の木で確かめると済んでいたのは A5 と B2 だけだった (A1〜A4 は未着手)
4. **敵対的レビューの指摘を 1 つずつ直すと、直し方が次の周の指摘を生んだ** (status viewer の X の指紋)。「受け取った diff」→「描いた diff」→ キーに XY を含めた → 世代を持たない取得中の札、と 4 周続いた。
   基準 (最後に見せた diff の指紋) を読む経路 (描画・取得・閉じる・r・XY の変化・evict) と、書く側の状態 (取得中・世代) の表を先に作っていれば、3・4 周目の指摘は最初に潰せた
5. **変異の run で、テストが返した tea.Cmd を実行して止まった** (tick を含む Cmd を実行すると 1.5 秒ずつ待ち、600 秒の時間切れまで判定が出なかった)。testenv.TakeMsg の doc に「tick を含む Cmd を渡さない」と書いた (局所)

## 次に効きそうな改善 (提案)

- A (1): **読み取りのみのレビューを起こすときは、レビュー用の detached worktree を HEAD に切ってそちらを読ませ、本体では作業を続ける**。「レビュー中は書き換えない」「どちらかを worktree へ分ける」は既に規則にあるが、分ける側を決めていないと、待ちの時間に手が動いて本体を書き換える。
  レビュー側を分ければ待ちが作業の止まりにならないので、守る動機が「我慢」から「得」に変わる。repo・道具を問わず、長いレビュー (codex・サブエージェント) を待つ作業全般で効く。
  切り出し先: `_claude/rules/parallel-write-agents-need-worktree-isolation.md` の「read-only のレビュー / 検証エージェントを走らせている間は、そのファイルを書き換えない」の項へ、やり方として 1 行追記 (新しい規範ではなく既存の項の具体化)
- B (2): **ファイルを書き換えるスクリプト (python の replace・sed・perl) は、置換の件数を確かめて、0 件なら落とす**。0 件の置換は何も言わずに成功し、後の検査が緑のまま「直したつもり」の状態を検査する。
  言語・道具を問わず、手で書いた置換で一括編集する作業 (リファクタ・テストの書き換え・設定の移行) すべてで起きる。今の項は崩し・変異体に限っているので、射程を広げる。
  切り出し先: `_claude/rules/verify-execution-not-just-exit-code.md` の「崩し・fixture・変異体を作ったら、走らせる前に作る前と違う状態になったことを機械で確認する」の項を、編集のスクリプト全般へ広げる追記
- 却下 (2 の後半): 依存する手順を `&&` で繋ぐのは既存の規律 (verify-execution の「検証の手順は `&&` で繋ぎ、`;` で繋がない」) で足りる。守らなかっただけ
- 却下 (3): 「記録した対策も前提に数えず、頼る場面で読む」は instrument-before-second-fix の前提の再検証の表に既にある (環境の対策の記録の話だが、再開メモの「済」も同じ扱いで読める)。新しい規範は要らない
- 却下 (4): 「状態 × 読み手の表を先に作る」は survey-receiver-guards の「自分が宣言した不変条件」節に既にある。表を作らずに直し始めたのが原因で、規範の不足ではない
- 局所 (5): testenv.TakeMsg の doc に書いた。ほかへ広げない
