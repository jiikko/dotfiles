# 127 human: width-probe を実端末で走らせて「揃える先」を決める

起票日: 2026-08-28
期限: 2026-09-04

## お願いしたいこと

**tmux の中と外の両方**で、実端末から次を実行して出力を控えてください。

```
cd ~/dotfiles/src/glogx && go run ./tools/width-probe
```

⚠️ **stdout をリダイレクトしないこと** (CPR の問い合わせが端末に届かなくなる。ツールが検出して
止まります)。結果を残すときは画面をコピーするか `script(1)` を使ってください。

⚠️ 実行中は**何もキーを押さないこと**。キー入力が CPR の応答に紛れると測定がずれます
(基準文字 `ASCII x` が 1 にならなければツールが「この run は無効」と言って止まります)。

## 何が知りたいか (issue 124)

「診断用」と付いた行の **`got` がどの列と一致するか**です。

| 一致した列 | 意味 |
|---|---|
| `grapheme` | 今の `dispWidth` のままでよい |
| `wc` | 描画エンジン (bubbletea v2) の既定側へ揃える議論になる |
| どれとも不一致 | 端末が独自。別の対策が要る |

特に見てほしい行: `カンナダ ಕಾ` / `タミル கா` / `Arabic sign U+0600` / `RI 単独 🇦` / `keycap 1️⃣` /
`⚠+VS16`。**tmux の内と外で `got` が違うなら、tmux が幅を書き換えています**。

## 出力と一緒に控えてほしいもの

ヘッダ行に出ます (ツールが出力します)。**`go-runewidth` の版は必須** — `wc` 列はその版に依存し、
版が変われば判定が反転しうるので、後から結果を再現できなくなります。

```
width-probe  TERM=…  TERM_PROGRAM=…  TMUX=…  SSH=…
  deps: x/ansi=…  uniseg=…  go-runewidth=… (wc 列はこの版に依存する)
```

## ⚠️ この測定だけでは決まらないこと (既知の限界)

bubbletea v2 は起動時に **mode 2027 (Unicode Core) を交渉し、対応端末では端末側の幅解釈も
切り替える**。width-probe は 2027 を要求も設定もしないので、**glogx が実際に描画する構成とは
別の構成の端末を測っています**。2027 対応端末では `got` が glogx 実行時と変わりえます。

したがってこの測定は「2027 OFF 側の答え」です。ここで `wc` と一致するなら揃える先の議論に進み、
そのとき初めて 2027 の交渉結果 (DECRQM `CSI ? 2027 $p`) を測る価値が出ます。
