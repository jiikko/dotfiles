## 概要

issue 742 で glogx (package main、約 6 万行) から描画の土台 (internal/term)・共有の状態 (internal/app)・doctor 画面
(internal/doctorview) を出した。改名と修飾は go/types で機械的に当て、等価は 3 つ (テスト緑・テスト名の一致・トークン列の比較) で確かめた。
段 3 の後の実測で効き目が小さく (ソースの先頭に 1 行足して `go test -race -count=1 -run '^$' ./...` を回したときの GOCACHE の増分が、tui.go で −10%・doctor_view.go で +10%。issue 742 の実測の表)、ユーザー判断で止めた。

## どこで踏んだか

移設のたびに「元の場所・元の名前・同じパッケージ」に暗黙に掛かっていた検査が外れかけた。テストは緑のままなので、
赤になって気づいたもの・レビューで見つかったものを並べる:

1. **パッケージ単位の前処理が付いてこない**: main の TestMain (幅 env のガード・キャッシュ置き場の隔離) は、移したテストには掛からない。
   `RUNEWIDTH_EASTASIAN=1` で移したテストだけが緑のまま通った (codex の敵対的レビューで発覚。自分では見ていなかった)
2. **非公開の名前で照合する検査**: reflect で非公開メソッドの interface (`ownsKeys()`) を満たす型を数える検査は、別パッケージの
   公開名 (`OwnsKeys()`) を黙って外す (canary が赤になって見えた)。AST の呼び出し名 (`fitHintItems` / `cacheBaseDir`)・
   別 module のテストが覚えているフィールド名 (`diskRep` / `r`) も同じ形
3. **lint の既定が公開名を飛ばす**: unparam は package main 以外の公開関数を既定で見ない (`check-exported`)、定数引数の検査は
   公開名を常に飛ばす、golangci の unused は公開名を使用済みとみなす。internal へ出すために公開名にしただけで検査から外れる
4. **cwd 相対で読むテストは Skip で緑になる**: theme/colors.yml を `../../` で読むテストは、移すと読めずに Skip
5. **参照の解析で仕分けると、ファイルを名前で読む検査を取り違える**: main.go を固定名で読むテストは、宣言の参照では doctor の
   ものしか使わないので doctor 側へ仕分けられた

回りくどかったこと: 移設の道具 (rename / move / テストの宣言単位の仕分け) を段ごとに直した (ジェネリック型のメンバが
インスタンスの別オブジェクトになる・未追跡ファイルの移動)。どれも使い捨ての局所的な話なので提案にしない。
