# runtimeout

コマンドを時間の上限付きで実行し、時間が来たら**子孫ごと**止める CLI (coreutils の `timeout` 相当。macOS には無い)。
シェルからは `bin/runtimeout`、スクリプトとテストからは `bin/lib/runtimeout.sh` の `runtimeout_resolve` で解決した
`$RUNTIMEOUT` (バイナリの絶対パス) で呼ぶ。

```sh
runtimeout [-f] [-k <猶予秒>] <秒> <コマンド> [引数…]
```

- `<秒>` は小数可。`0` は上限なし
- rc: 子の rc (シグナルで死んだら 128+n) / `124` 時間切れ / `125` 誤用 / `126` 起動できない / `127` 見つからない
- stdin / stdout / stderr は fd をそのまま子へ渡す
- `-f`: 子を呼び出し元のプロセスグループのまま起こす (下の「止め方」)
- 🚨 子が自分で 124 を返すこともある。時間切れと区別したい呼び出し側は、経過時間が上限以上かも併せて見る (`bin/mutate-verify`)

## 止め方

実装は共有 module の `src/proctree` (zundamon-kaisetsu の mermaid の描画も同じものを使う)。

子は専用のプロセスグループで起動する (道具自身は呼び出し元のグループに残る)。時間切れでは、グループの全員と
子から ppid でたどれる子孫 (`setsid` でグループを抜けた子も含む) を SIGSTOP で凍らせて集め、TERM → 猶予 (`-k`、既定 5 秒) → KILL。
TERM / HUP を受けたら同じ止め方で止め (凍らせてから集める)、止め終わってから道具も同じシグナルで死に直す。
INT / QUIT は子へそのまま伝え (`-f` では端末から子にも直接届くので伝え直さない)、猶予の間に子が終わらなければ同じ止め方で止める。
道具がシグナルを受けて子もシグナルで死んだら、道具も同じシグナルで死に直す (呼び出し元の bash に「中断された」を伝える。rc=128+n で返すと、
bash は子が INT を処理したと読んで次へ進む)。

- 呼び出し元から止めるときは、道具の pid へ TERM を送り、`wait` で止め終わるのを待つ (`kill -- -<pid>` は道具がグループ leader ではないので届かない)
- 止められないもの: 時間切れより前に親を離れて init の子になり、かつグループも抜けたもの (daemon 化した子・`tmux -L` のサーバ等)
- 子が自分で終わった直後に時間切れ・TERM が重なると、刈り取り済みの子の pid へ撃ちうる (数 ms の窓。pid が再利用されて
  いれば別のプロセスに当たる。macOS の pid は概ね連番なので実害の見込みは低い。根治は刈り取りを止め終えるまで遅らせる形)
- 止める途中 (凍らせてから TERM / CONT を撃つまで) に道具自身が KILL されると、木が停止 (T) のまま残る。止めるときは道具へ TERM を送る
- 起動時に無視されていた HUP は無視のまま子へ渡す (`nohup` が効く)。TERM は常に捕まえる。INT / QUIT は無視されていても既定に戻して子へ渡す
- 既定では子のグループは端末の前景ではないので、子が端末から読むと SIGTTIN、`stty tostop` の端末へ書くと SIGTTOU で止まり、
  Ctrl-Z でも子は止まらない (coreutils の `timeout` と同じ)。端末に出力しうる子を対話で走らせるなら `-f` を使う。
  `-f` ではグループ宛てに撃てないので、止めるのは ps でたどった木だけになる (グループを抜けて親を離れた子は取りこぼす)

設計の経緯と、置き換えた手組みの一覧は issue 640。
