# mac-lan-manager

手元の Mac 同士を、ネットに繋がっていない有線の LAN (内部の網) で繋いで管理する道具。Bonjour で見えている Mac を一覧にし、
初期設定 (鍵を置く・この Mac と相手の内部の I/F を固定 IP にする・台帳に登録する・有線の名前 `<ホスト名>.wired.local` を広告する) を
済ませた Mac を「管理対象」として ssh / 画面共有 / smb で繋ぐ。有線の名前が引ければ、繋ぐ・コピー・画面共有の宛先は IP でなくその名前。
glogx の `L` の板からも開く (要件・決定・設計の正本は issue 747)。

**今の状態**: 段 3〜5 (一覧 (タブは管理対象 / 未管理 / この Mac。管理対象で初期設定が途中の行は先頭の `!` と黄の地。判定は台帳の内部 IP と有線の名前で、公開鍵は見ない)・詳細カード・台帳への登録と削除・別名とユーザー名 (`m` / `u`)・
ssh / 画面共有 / コピー (`O` は Finder で smb に繋ぐ `open smb://…`)・この Mac の IP と有線の名前のコピー (`c`)・設定 (有線で見えた相手だけに絞る項目を含む)・glogx の `L`・初期設定)。一覧の行で `Enter` を押すと詳細のパネルを一覧に重ねる (端末が低くて一覧の下の詳細が 1 行に畳まれていても見られる。入らなければ `j`/`k` で送り、`q`/`Esc` で戻る)。初期設定はそのパネルでもう一度 `Enter` を押して開き (パネルを下に残して少しずらして重ねる。`q`/`Esc` で 1 枚ずつ戻る)、`x` で次の手順を確認の板に出して `y` で実行する (`r` で相手を読み直す)。
管理対象の相手は詳細カードで `t` → 板で経路 (内部 IP / メイン IP / その他の IP。既定は有線。`j`/`k` で選ぶ) を選んで `y` (Enter・Y では流さない) を押すと、ssh 越しに上り・下りを 5 秒ずつ流して通信速度を測る (帯域を使い切る。値は ssh の暗号化を通した速さで、1 Gbps を超える回線は頭打ちになりうる。issue 827)。IP の後ろの `(有線)` / `(無線)` は、相手の IP が見えた**この Mac の** I/F の Hardware Port で決める (相手側の線と、同じサブネットに Wi-Fi と有線の両方で居るときに実際に送る I/F は分からない。issue 828)。本物の相手での最初の確認は issue 789。起動は `bin/mac-lan-manager`。キーの一覧は中で `?`。

**デバッグ (画面を出さない)**: `GO_AUTOBUILD_SYNC=1 bin/mac-lan-manager dump` (`--json` で JSON、`--wait 8s` で Bonjour を待つ上限)。
この Mac のサービス・一覧 (画面と同じ判定。各行の内部 IP・メイン IP・その他の IP・固定か・繋ぐ IP と実際の宛先 (target)・有線の名前と
引けるか・有線だけの表示で隠れるか)・Bonjour の生の結果・知らせを出す。台帳・設定・操作のログには書かない (初めて動かしたときだけ、旧い置き場の台帳と設定を新しい置き場へ移す)。「見つからない」「違う IP に繋ぐ」を調べるときはまずこれを見る (LLM に渡すのも安い)。
相手の Mac は `dump --peer <IP> [--user <name>] [--host <Bonjour のホスト名>]` で、鍵で入れるか (ok / denied / unknown) と相手のルーターの無い有線のサービスを読む (段 4 の初期設定が見るのと同じ。読むだけ)。
**通信速度のヘルスチェック (画面を出さない)**: `GO_AUTOBUILD_SYNC=1 bin/mac-lan-manager speedtest [--json] [<ホスト名か別名>...]` で、管理対象の相手との通信速度を
ssh 越しに 1 台ずつ測る (画面の `t` と同じ宛先 = 内部 IP を優先・同じ測り方。上り・下り各 5 秒、その間は回線をほぼ使い切る。確認の板は出さない)。
有線で 100 Mbps 付近なら頭打ちの疑い (`capped_100m`) を出す。終了コードは 0 = 全部測れた / 1 = 測れない相手がいた / 2 = 引数の誤り・管理対象に無い相手。
Claude から定期の確認に使うときは `--json` を読む (帯域を使うので、頻繁には回さない)。`scan_settled: false` は裏の読み込み (Bonjour の走査・有線の名前など) が
`--wait` までに終わらず途中の一覧で宛先を決めた回 (`link` が無線・空なら有線をまだ測れていない)。`scan_error` は Bonjour の走査そのものの失敗 (rc=1)。名前はホスト名にちょうど一致すればそれ、別名・`.local` を落とした名前が 2 台に当たれば rc=2 で断る。
**操作のログ**: `~/Library/Logs/mac-lan-manager.log` に、押したキーとそのときの画面・知らせ・相手を読んだ結果 (鍵で入れたか・理由・有線の設定・
かかった秒数)・起こしたコマンドとその戻りを 1 行ずつ残す (単体と glogx の `L` の両方。1 MiB を超えたら新しい方の半分を残す。入力欄に打っている途中の文字と
パスワードは残らない。確定した別名・ユーザー名は知らせとして残る)。詰まったときはこれを LLM に渡す。初期設定の確認の板では `c` で実行するコマンドの全文をコピーできる (板には要約)。
`GO_AUTOBUILD_SYNC=1` を付けないと、bin は古いバイナリで起動して裏で作り直す (直した直後は古い版の結果になる)。

## package

| package | 何か |
|---|---|
| `netinfo` | この Mac のネットワークのサービスと I/F の IP を `networksetup` / `ifconfig` の出力から読む (読むだけ) |
| `discover` | `dns-sd` の `-B` / `-L` / `-G` の出力を 1 行ずつ読む |
| `ledger` | 管理対象の台帳 (`~/.config/mac-lan-manager/hosts.toml`。`$XDG_CONFIG_HOME` があればその下。前の置き場 `~/.config/glogx/mac-lan-manager` のファイルは初回に移す)。この Mac の中だけに持つ。読み書きは `Store` の口だけを通す (共有を後から足す余地) |
| `prefs` | 設定 (一覧に出す IP・内部 IP の決め方・その他の IP の種類。`settings.toml`) |
| `lanmgr` | 画面 (一覧・詳細カード・設定・確認の板・初期設定・メッセージ一覧)。有線の名前を引いて宛先に使う (`wiredname.go`)。lipgloss v2.0.5 + tuikit。単体の `main.go` と glogx の板の両方から使う口 (`New` / `HandleKey` / `HandleInput` / `Advance` / `View` / `Busy` / `Changed` / `Reload` / `OwnsKeys` / `Binds` / `TakeExec` / `TakeNotices` / `Close` …) |
| `setup` | 初期設定 (段 4) の手順を組む: 観測から残りの手順を組み直す `Plan` (鍵 → この Mac の固定 → 相手の固定 → 台帳 → この Mac / 相手の有線の名前。相手の固定は確認まで含む) / 相手の有線を固定 IP にする命令列 `StaticIP` (確認の印が来なければ元へ戻すデッドマンスイッチ) / 有線の名前を広告する LaunchAgent の命令列 (`wiredname.go`) / 空き番号の提案 `SuggestIP`。命令を組むだけで起こさない (起こすのは `lanmgr` の初期設定の画面で、確認の板の `y` の後だけ)。テストは偽物だけが見える PATH (`<sandbox>:/bin`) で走らせ、外へ解決したら走らせる前に落とす |
| `speedtest` | 通信速度の測定 (鍵の確認 → 上り = 相手の `wc -c` が数えた量 → 下り = 相手の `head -c` を最初の 1 回から数える)。プロセスを起こす口と時計は呼び出し側が渡す (本物は `live/speed.go`) |
| `live` | `lanmgr` を本物 (ネットワーク・Bonjour・台帳・設定・クリップボード・相手への ssh の `SSHRun` / `Observe`) につなぐ `Options()`。単体の `main.go` と glogx の板が共有する (glogx はクリップボードと時計だけ自分の口に替える) |

## 触る前に読むもの

- 出力を読む処理の正本は各 package の `testdata/` (2026-10-15 にこの Mac で本物のコマンドを起こして取った出力。MAC アドレスなどは伏せた)。
  形を推測で書き換えない。`networksetup -getinfo` の `IPv6 Router:` の行や、`dns-sd -L` の `\032` (空白) のような罠はテストが押さえている
- 🚨 台帳のテストは本物のファイルを書く。`ledger/main_test.go` が置き場所 (`MAC_LAN_MANAGER_CONFIG_DIR`) を一時ディレクトリへ向け、その外への
  書き込みを書く前に拒否する (`writeGuard`)。テストを足すときは `sandbox` の中に書く (`t.TempDir()` は関門の外に作られる)
- 台帳は版 (`version`) を持ち、この版より新しい形式の台帳には書き込まない (古い版で上書きして中身を失わないため)。壊れた台帳も空として上書きしない
- 台帳の書き換えは隣の `hosts.toml.lock` に flock を取ってから読み直して書く (単体のコマンドと glogx の板が同時に書いても登録を消さない)

- 🚨 lipgloss は **v2.0.5 に固定**する。v2.0.6 は x/ansi v0.11.8 と ultraviolet の新しい版を要求し、tuikit を使う全 module の版上げと描画のエンジンの変更を連れてくる (issue 747 の段取りの 2)
- 🚨 色は 24bit で書く。tmux の中では bubbletea の判定が tmux の端末の定義 (RGB が missing) しか見ずに 256 色へ落とし、面の色が紺になる。
  `main.go` (と glogx の `RunBrowse`) が `tuikit/termcolor` でクライアントの機能 (`#{client_termfeatures}` の RGB) を聞いて 24bit にする
- 外から来た名前 (Bonjour のインスタンス名・ホスト名・台帳の別名・ユーザー名) は `lanmgr` の `rows()` の入口で 1 回だけ termsafe を通す (描画の側では無害化しない)
- `dns-sd` は終わらない。`discover.Scanner` が起こしたプロセスだけを `Close` で止める (名前で探して止めない)
