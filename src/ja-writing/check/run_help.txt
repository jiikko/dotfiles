使い方: yomiyasu_check.py run --final 最終稿 (--source 原文 | --material 資料) [--material 資料 …]
           [--stance 立場] [--doc-type 種類] [--reader 読者] [--fail-on meaning-risk|warn|error …] [--timeout 秒]
           [--run-id ID | --new-run] [--session ID] [--state-dir DIR] [--no-record] [--fact-gaps] [--json]
           [--words フォルダ | --no-words]
       yomiyasu_check.py run --stdin [上と同じオプション]

最終稿に lint、原文と最終稿に diff（新規作成では資料との照合）をまとめて実行し、記録を残します。結果は『検査を実行した』で、意味の保持や読みやすさの合格ではありません。
--source があれば推敲（lint と diff。資料があれば資料との照合も）、なくて --material があれば新規作成（lint と資料との照合）です。新規作成で資料の1つが最終稿とよく似ていれば、その資料を原文とみなして diff も実行します（同じ実行のあとの回も、その資料を原文とみなします）。
記録はこのコマンドだけが作ります。同じ権限で原稿と記録の両方を書き換えられる環境では、記録は実行漏れを見つけるためのもので、改ざんの防止や人の承認の証明にはなりません。

入力:
  --final 最終稿           検査する最終稿のファイル（UTF-8）。- を渡すと標準入力を読みます。
  --source, --original 原文
                        推敲で、書き直す前の原文のファイル。最終稿と別のファイルにしてください。
  --material, --materials 資料
                        提供された資料のファイル。何度でも指定できます。最終稿の数値、名前、語、確度の語を資料と照らします。
  --stdin               ファイルを作らない対話のため、原文（か資料）と最終稿を標準入力から読みます。行全体が
                        <<<yomiyasu:original>>>、<<<yomiyasu:material
                        出典>>>、<<<yomiyasu:final>>> の行で区切ります。出典は省略可、200字まで（>>>
                        を含めない）。--material のファイルと -
                        の中身も同じ資料の区切りを使えます。区切りの行は一字一句このとおりに書きます（<<<yomiyasu:
                        で始まるほかの行があれば、終了コード2で止めます）。

オプション:
  --fact-gaps           事実の穴の候補の一部を表示します（失敗条件には含めません。essay・promo では出しません）
  -h, --help            このヘルプを表示して終わります。
  --stance 立場           文書の立場（diff と同じ）。勧め（読み手に勧める）、決まり（手順）、説明（報告、体験）のどれか。
  --doc-type 種類         文書の種類。lint と diff に渡し、記録と状態の行に残します。lint
                        は、その種類で普通な書き方を候補にする規則を外します（yomiyasu_lint.py -h の一覧）。差分
                        （意味が変わる恐れと規則の見直し候補）の見つけ方と、資料との照合の判定は変わりません。pr、article、
                        incident、proposal、manual、formal、paper（事実や仕様を述べる種類）では、「
                        場合がある」「ことがある」を消した言い切りと、断定に「必ず」などを足した書き換えを --fail-on
                        に数えます（意味の検査で種類によって変わるのはこの2つだけです）。文体の硬化の検査は
                        incident、formal、paper のとき、勢いの検査は
                        pr、article、incident、manual、formal、paper
                        のとき、候補を参考として出します。promo と mail
                        以外の種類を指定すると、勢いの検査の絵文字の候補も参考として出し、promo、minutes、mail
                        以外では見出しの候補も参考として出します。promo
                        では、番号つき項目の行と太字だけの行も勢いの検査の見出しに数えます。mail
                        だけ敬語の度合いを検査します。値: pr（PR説明）、article（技術記事）、incident（障害報告
                        ）、proposal（提案書）、minutes（議事録）、manual（マニュアル）、slides（スライド
                        ）、essay（エッセイ・小説）、formal（公用文、規程、契約書、仕様書）、promo（紹介記事・宣伝文
                        ）、mail（メール・チャット）、paper（論文・研究レポート）、script（台詞・脚本）。
  --reader 読者           想定する読者の知識。lint と diff に渡し、記録と状態の行に残します。判定は変わりません。
  --fail-on meaning-risk|warn|error
                        指定した条件に当たれば、記録を残したうえで終了コード1で終わります。何度でも、カンマ区切りでも指定できます。
                        meaning-risk: 意味が変わる恐れのうち、数値、否定、主語と目的語の入れ替え、文の種類（問いと平叙
                        、文の種類を表す語）の変化、引用の書き方の変化、確度を強めた書き換え（見込み → 予定、と思われる → 断定
                        など）、原文の状態の語（未定、未確認、調査中など）が消えた書き換え、原文にない書き手の約束・保証・再発防止の
                        誓いを足した書き換え、許可の言い方（してよい、してもよい、構わない）が消えたか増えた書き換え、関連・相関を述
                        べた原文の文に因果の言い方（因果、原因、引き起こす
                        など）を足した書き換え、選ぶ範囲が入れ替わった書き換え（または・どちらか →
                        両方・すべて、またはその逆）、同じ数に付いた概数や範囲を表す語（約、ほど、以上、未満
                        など）が消えたか増えた書き換え、--doc-type が
                        pr、article、incident、proposal、manual、formal、paper
                        のときは「場合がある」の言い切りと「必ず」などを足した書き換え（ここまでは diff の --fail-
                        on=meaning-risk と同じ）と、新規作成で資料にない数値。コード・URL・引用ブロックなど変えな
                        い箇所の変化と、資料にない名前は数えません。否定対比の主張の逆転と、元にない気持ちの語も数えません。確度を弱
                        めた書き換え、数えない語だけの確度の変化、予定の言い切り（する予定です → します）、かぎかっこの中の言葉の
                        変化も数えません。原文にない因果のつながりを足した書き換えと、書き手の行為と読む言い方（いたします、今後・改
                        めて、弊社などの主語）のない「〜します」を足した書き換えと、事実の穴の候補（--fact-
                        gaps）も数えません。warn: lint の warn か error の候補。error: lint
                        の error の候補。条件に当たらなくても、意味が同じだという証明にはなりません。
  --timeout 秒           子プロセスの検査（lint と diff）に使える秒数の合計。既定は90。超えたら止めて、状態を
                        partial にします。
  --run-id ID           記録をつなぐ実行ID（英数字で始まり、英数字と「.」「_」「-
                        」だけの64字まで。末尾の「.」と、Windows で使えない名前（CON、NUL、COM1
                        など）は使えません）。フックや CI が自分で決めるときに使います。
  --new-run             前の実行につながず、新しい実行IDで記録します。
  --session ID          記録に入れるセッションの識別子（入れるだけ）。省くと環境変数 YOMIYASU_SESSION。
  --state-dir DIR       記録を書く状態フォルダ。省くと環境変数 YOMIYASU_STATE_DIR、なければ git
                        の最上位（なければ作業ディレクトリ）の .yomiyasu/。書けないときもほかへ逃がしません。
  --no-record           記録を書きません（状態 unrecorded）。利用者が記録も作らないよう頼んだときだけ使います。
  --words フォルダ          語の一覧（allow.txt と flag.txt。名前と正規表現を書く flag-patterns.txt
                        も置けます）のフォルダ。省くと、作業ディレクトリから上へたどった git の最上位（.git
                        のあるフォルダ。git の外では作業ディレクトリ）の .yomiyasu-words/
                        を探します（lint、diff と同じ）。linked worktree にこのフォルダがなければ、元の
                        checkout の一覧を探します。check が探して読み、lint と diff
                        にこの場所を渡して、記録に場所と語の数と SHA-256
                        を残します。読めない一覧は終了コード2で、何も書きません。
  --no-words            語の一覧を探さず、読みません（--words と一緒には使えません）。
  --json                結果をJSON（結果の形式1）で出します。日本語は \uXXXX の形で出します。

終了コード:
  0  run: 検査を最後まで実行し、--fail-on の条件に当たらなかった（状態 executed か unrecorded。候補の有無によらない）。verify: 記録と照合が合った（executed）。-h と --version も0。start: 登録した（started）。export: 写しを書いた（exported）。end: 登録を終えた（ended）
  1  run: --fail-on の条件に当たった（記録は残す）。verify: 記録がない、または記録と合わない（理由は2行目の状態の行と --json の problems）。run: 登録の上限で実行しなかった（unverified）。export: 照合が合わない。end: 登録がない
  2  使い方か入力の誤り（ファイルを開けない、読まないファイル（作業フォルダの外、名前が点で始まる部分を含むパス）を渡した、UTF-8 として読めない、区切りの誤り、使えない値、原文と最終稿が同じファイル、資料と最終稿が同じ中身、空の最終稿、別の原文の実行ID、語の一覧を読めない（--words のフォルダがない、UTF-8 でない、1万行を超える、flag.txt か flag-patterns.txt に使えない行がある。ファイルの中身の誤りは、ファイルの名前と行番号を出す）、--words と --no-words を一緒に指定した）。何も書かない（状態 not_run）
  3  検査の一部を実行できなかった（lint か diff が内部の誤りか時間切れで終わらなかった、途中で最終稿が変わった。状態 partial）か、check の予期しない内部の誤り、出力先が閉じられて結果を最後まで書けなかった
