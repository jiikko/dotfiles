使い方: yomiyasu_check.py run --final 最終稿 (--source 原文 | --material 資料) [オプション]
       yomiyasu_check.py run --stdin [オプション]
       yomiyasu_check.py verify --final 最終稿|- [オプション]
       yomiyasu_check.py start --source 原文 [オプション]
       yomiyasu_check.py export --final 最終稿 [オプション]
       yomiyasu_check.py end (--run-id ID | --source 原文) [オプション]
       yomiyasu_check.py --version

最終稿に lint、原文と最終稿に diff（新規作成では資料との照合）をまとめて実行し、記録を残します。結果は『検査を実行した』で、意味の保持や読みやすさの合格ではありません。
記録はこのコマンドだけが作ります。同じ権限で原稿と記録の両方を書き換えられる環境では、記録は実行漏れを見つけるためのもので、改ざんの防止や人の承認の証明にはなりません。

オプション:
  -h, --help            このヘルプを表示して終わります。
  --version             バージョンを表示して終わります。

サブコマンド（省くと run）:
  {run,verify,start,export,end}
    run                 検査を実行して記録を残します。最終稿ができたら1回、直したらもう一度実行します。
    verify              提出の直前に、最終稿のハッシュを記録と照らします（読むだけで、何も書きません）。
    start               原文の写しを取り、原稿を登録します。
    export              照合の合う最終稿の写しを書き出します。
    end                 原稿の登録を終えます。

終了コード:
  0  run: 検査を最後まで実行し、--fail-on の条件に当たらなかった（状態 executed か unrecorded。候補の有無によらない）。verify: 記録と照合が合った（executed）。-h と --version も0。start: 登録した（started）。export: 写しを書いた（exported）。end: 登録を終えた（ended）
  1  run: --fail-on の条件に当たった（記録は残す）。verify: 記録がない、または記録と合わない（理由は2行目の状態の行と --json の problems）。run: 登録の上限で実行しなかった（unverified）。export: 照合が合わない。end: 登録がない
  2  使い方か入力の誤り（ファイルを開けない、読まないファイル（作業フォルダの外、名前が点で始まる部分を含むパス）を渡した、UTF-8 として読めない、区切りの誤り、使えない値、原文と最終稿が同じファイル、資料と最終稿が同じ中身、空の最終稿、別の原文の実行ID、語の一覧を読めない（--words のフォルダがない、UTF-8 でない、1万行を超える、flag.txt か flag-patterns.txt に使えない行がある。ファイルの中身の誤りは、ファイルの名前と行番号を出す）、--words と --no-words を一緒に指定した）。何も書かない（状態 not_run）
  3  検査の一部を実行できなかった（lint か diff が内部の誤りか時間切れで終わらなかった、途中で最終稿が変わった。状態 partial）か、check の予期しない内部の誤り、出力先が閉じられて結果を最後まで書けなかった
