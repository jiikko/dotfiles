使い方: yomiyasu_lint.py [-h] [--json] [--strict] [--fail-on {warn,error}]
                      [--doc-type 種類] [--reader 読者] [--words フォルダ]
                      [--no-words] [--version]
                      [file]

日本語の表現とMarkdownの書式を、決まった規則で点検します。結果は見直し候補です。候補の数や点数は、文章の品質、意味の保持、読者にとっての分かりやすさの合否ではありません。

引数:
  file                  検査するファイル（UTF-8）。省略するか - を渡すと標準入力を読みます。

オプション:
  -h, --help            このヘルプを表示して終わります。
  --json                結果をJSON（形式2）で出します。日本語は \uXXXX
                        の形で出します。rule_penalty_score
                        は、候補の多さを地の文の長さで割った目安です（下の式）。合否には使わないでください。
  --strict              warn か error の候補が1件でもあれば、終了コード1で終わります。info
                        の候補と点数は使いません（--fail-on=warn と同じです）。
  --fail-on {warn,error}
                        指定した中身の候補があれば、終了コード1で終わります。warn: warn か error
                        の候補。error: error の候補（太字が表示されない書き方）。何度でも、カンマ区切りでも指定できます
                        。点数は条件に使えません。meaning-risk
                        は2つの文章を比べないと判定できないので、yomiyasu_diff.py か
                        yomiyasu_check.py に付けてください。
  --doc-type 種類         文書の種類。指定すると、その種類で普通な書き方を候補にする規則（下の一覧）の候補を外し、外した件数を出します
                        。外した候補の中身は、指定せずに実行すると見られます。省くと、すべての規則を当てます（今までどおり）。値:
                        pr（PR説明）、article（技術記事）、incident（障害報告）、proposal（提案書）、mi
                        nutes（議事録）、manual（マニュアル）、slides（スライド）、essay（エッセイ・小説）、f
                        ormal（公用文、規程、契約書、仕様書）、promo（紹介記事・宣伝文）、mail（メール・チャット）、p
                        aper（論文・研究レポート）、script（台詞・脚本）。
  --reader 読者           想定する読者の知識。表示と JSON に残すだけで、候補は変えません。値: expert（同じ分野の専門家）
                        、informed（分野は違うが技術に詳しい人）、general（専門知識のない人）。
  --words フォルダ          語の一覧（allow.txt と flag.txt。名前と正規表現を書く flag-patterns.txt
                        も置けます）のフォルダ。省くと、作業ディレクトリから上へたどった git の最上位（.git
                        のあるフォルダ。git の外では作業ディレクトリ）の .yomiyasu-words/
                        を探します（下の「語の一覧」）。linked worktree にこのフォルダがなければ、元の
                        checkout の一覧を探します。
  --no-words            語の一覧を探さず、読みません（--words と一緒には使えません）。
  --version             バージョンを表示して終わります。

文書の種類ごとに外す規則（--doc-type）:
  pr        excess_list
  article   なし
  incident  excess_list
  proposal  なし
  minutes   bold_label_list、excess_list、sentence_end_repetition
  manual    excess_list
  slides    bare_verb_chain、bold_label_list、cleft_list_ending、count_declaration、excess_list、short_summary_heading
  essay     bare_verb_chain、metaphor_label
  formal    なし
  promo     bare_verb_chain、emoji_prohibited、fragment_run、metaphor_label
  mail      emoji_prohibited
  paper     なし
  script    bare_verb_chain、fragment_run、metaphor_label、sentence_end_repetition
mail は meta_filler の返信・結びの5型だけも外します（ご質問ありがとうございます、必要なら次に〜します、いかがでしたでしょうか、ぜひ〜してみてください、参考になれば幸いです等）。宛名・挨拶・署名を削る専用規則はありません。paper は慎重表現を削る規則がないため除外なし。
種類を指定したときだけ当てる規則: pause_comma（promo、script を除く11種類。種類を指定しないときは出しません）
種類を指定したときだけ当てる規則: dialogue_period（script だけ。種類を指定しないときは出しません）
種類を指定したときだけ当てる規則: narrative_density（essay だけ。種類を指定しないときは出しません）
種類を指定したときだけ当てる規則: slide_comma（slides だけ。種類を指定しないときは出しません）
外した候補は、見直し候補の件数と --strict、--fail-on の判定に入れません。

rule_penalty_score（--json の目安）:
  候補が0件なら100。候補があれば 100 × 40 ÷ (40 + x) を四捨五入し、1〜99に収めます。
  x は、行ごとの候補の重み（error 3、warn 2、info 1）を地の文1,000字あたりに直した数です。
  地の文はコード、表、引用、見出し、前置きの設定（frontmatter）、HTML、URL と空白を除いた字数で、
  1,000字に満たなければ1,000字として割ります。
  excess_bold と excess_list は1件で2、bold_label_list は1を x に足し、
  negative_parallelism_density は数えません。ダッシュの規則に当たった行は、候補に出さない4行目からも数えます。
  2.2.0 から 2.5.0 で足した次の規則の候補も数えず、その候補だけのときは100です: calque、metaphor_label、
  say_hedge、thin_evaluation、katakana_term、dialogue_period、narrative_density、copy_comma_noun、
  bare_verb_chain、project_term、renyo_noun、slide_comma、ai_phrase。
  --doc-type で候補が変わると、点数も変わります。CI では --fail-on か counts を使ってください。

語の一覧（--words、--no-words）:
  allow.txt の語は、次の規則の候補から外し、外した件数を出します: ai_phrase、calque、katakana_term、metaphor_label、
  metaphor_verb、project_term、renyo_noun、slop_vocabulary、translated_term。flag.txt の語には project_term（info）の
  指摘を出します。どちらも1行に1語（UTF-8。# で始まる行と空の行は読み飛ばします）。
  flag.txt は「使わない語<TAB>使う語」とも書けます（<TAB> は実際のタブ文字）。TAB の左だけを探し、使う語も指摘に出します。
  使う語は80字までで、使う語の中に TAB がある行（3列の行）は使えません。
  flag-patterns.txt（なくてもよい）には1行に「名前<TAB>正規表現」を書き、当たった行に、パターンの名前を入れた
  project_term（info）の指摘を出します。

終了コード:
  0  検査を最後まで実行し、--strict と --fail-on の条件に当たらなかった（候補の有無によらない）。-h と --version も0
  1  --strict か --fail-on の条件に当たった
  2  使い方か入力の誤り（ファイルを開けない、読まないファイル（作業フォルダの外、名前が点で始まる部分を含むパス）を渡した、UTF-8 として読めない、標準入力を読めない、使えない --fail-on、--doc-type、--reader の値、語の一覧を読めない（--words のフォルダがない、UTF-8 でない、1万行を超える、flag.txt か flag-patterns.txt に使えない行がある。ファイルの中身の誤りは、ファイルの名前と行番号を出す）、--words と --no-words を一緒に指定した）
  3  予期しない内部の誤り（標準エラーにトレースバックを出す）か、出力先が閉じられて結果を最後まで書けなかった
