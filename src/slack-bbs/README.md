# slack-bbs

購読した Slack のチャンネルの会話を、**話題ごとに組み直して掲示板風に読む** CLI。時系列に混ざった発言をほどいて、
「何が決まり、何が自分待ちか」から読めるようにする。設計と経緯は dotfiles の issue 706。

```sh
slack-bbs sub                 # 購読するチャンネルを一覧から選ぶ (Space / x で切り替え、/ で名前の検索。打つたびに絞り込み、打ったまま ↑↓ で移動して Tab で切り替えられる。n / p でページ送り、Enter で保存)。読む画面の中でも s で開ける
slack-bbs -dry-run            # LLM を呼ばず、送る件数と文字数だけを見る
slack-bbs                     # 読む画面 (TUI) を開く。購読しているチャンネルの直近 2 日分。前回の板 (キャッシュ) をすぐ出して裏で読み直す。r で今のチャンネル、R で全部を読み直す (読み込み中のチャンネルは読み直さず、右下の知らせで伝える)。u で既読と未読を入れ替える
slack-bbs -md -since 12h C0123456789 | less -R   # 画面を開かず Markdown で出す (パイプの先では既定で Markdown)
slack-bbs -json > board.json  # 話題に組んだ結果 (中間表現)
```

## 何をするか

1. **取得** — [slack-cli](https://github.com/jiikko/slack-cli) (読み取り専用) で history・thread・users・whoami を読む。
   slack-cli の呼び出しは 1 列に並べ、Slack のレート制限の段に合わせて間を空ける (`source/throttle.go`)。列は
   `~/.cache/slack-bbs/slack-cli.lock` で共有するので、読む画面と 2 段の実行を同時に走らせても合計で数える。429 で止められたら列ごと待つ
2. **まとめ直し** — スレッド 1 本、またはスレッド外の発言 1 件を「単位」にする (スレッドは既に 1 つの話題なので割らない)。
   **親が期間より前でも、期間内に返信が付いたスレッドは「続いている」単位として拾う** (チャンネルの流れに出ない返信を見逃さない)。
   history の親の `latest_reply` で見つけるので、`-lookback` (既定 30 日) より前に始まったスレッドは見ない (画面にそう書く)
3. **分類** — `claude -p` に単位を渡し、話題への分け方・見出し・要約 (結論・経緯・次の動きの 3 つの欄)・ラベル (要対応 / 必読) を返させる
4. **検査** — LLM の出力は信じない。全部の単位がちょうど 1 つの話題に入る (落ちた単位は「未分類」、無い ID は捨てる)。
   要約の項目・ラベルの根拠はその話題の中の発言に限る。捨てたものは stderr に出す
5. **表示** — 端末なら読む画面 (左に話題の一覧、右に中身)、そうでなければ Markdown。話題ごとに、印 (🔴 要対応 / 📌 必読 / 🟢 決定 / 🟡 議論中 / ⚪ 共有)・要約の欄 (▍結論 / ▍経緯 / ▍次の動き)・原文 (時系列) を出す。
   読む画面は人の名前 (太字。自分は紫の太字)・「」の中・PR などの番号・原文の時刻に色を付ける。青と水色の文字色と背景色は使わない (背景が青い端末で沈む・端末の配色を上書きする)。
   左の一覧は話題を最後の発言の日ごとに見出し (「11/10 (火) 今日」) の下へ組み、新しい日を上に出す (未分類は最後)。
   キーは TUI ガイド (`docs/glogx-ui-guide.md`) の語彙に揃える: `l` / `Enter` で本文の欄へ入り、`h` / `q` / `Esc` / `Enter` で一覧へ戻る (`q` は 1 段戻る。一覧の `q` で終わり、`Ctrl-C` はすぐ終わる)。
   本文の欄では `J` / `K` で開いたまま隣の話題へ送る。本文が欄に収まらないときは右端にスクロールバーを出す。読み直している間は状態の欄と他のチャンネルのタブに回る印 (と経過秒) を出す。
   未読の話題は ● と太字で出し、タブにチャンネルの未読の数を添える。j / k で選んだ話題・l で開いた話題・o で Slack で開いた話題を既読にする
   (起動・読み直しで先頭に乗っただけでは既読にしない。読み直しは本文を開いたままでも既読にしないので、読んでいる最中に付いた返信は ● で出る。
   u で未読に戻した話題も、次に選ぶと既読になる)。既読の後に他の人の発言が付いたら、また未読になる (自分の発言だけなら未読にしない)。
   要対応のうち、自分への名指しと自分が書いたスレッドへの返信は機械で確かめたもの、それ以外は LLM の推定として分けて出す。
   「自分が書いたスレッド」は 1 度でも書き込んだスレッドで、同じスレッドで自分がその後に書いていれば済んだものとして外す (名指しも同じ)
6. **言及** — 板の発言へのリンクを貼った発言 (別のチャンネルでの引用・感想) を、slack-cli の search で「`archives/<チャンネル ID>`」を引いて探し、
   リンクが指す発言の話題に「▍この話題への言及」として出す (自分の発言へのものは「あなたの発言」と書く)。既読にした話題でも、その後に他の人の言及が
   付けば未読に戻る。言及は分類 (claude) には送らない。同じスレッドの中で上の発言を貼っただけのものは数えない。
   🚨 **見えるのは自分のアカウントで検索できる発言だけ** (公開チャンネルと、自分が入っている非公開チャンネル・DM)。自分の入っていない
   非公開チャンネル・他の人どうしの DM での言及は見えない。「転送」で共有された発言も見えない (本文に元の URL が無い。slack-cli の search が添付を出さない)。search は 1 チャンネルにつき期間の始まりまで新しい順に読み、10 ページ (1000 件) で打ち切る
   (打ち切った・検索に失敗したことは板の注記に出す)

## 2 段の実行 (分類を別のアカウントのセッションで行う)

端末の `claude` が使いたいアカウントと違うときは、分類を外 (GUI の Claude のセッション) に任せる。手順は skill `slack-bbs` (`_claude/skills/slack-bbs/SKILL.md`)。

```sh
slack-bbs prepare [-since 2d] [-out <dir>] [<チャンネルID>...]   # 依頼を書き、{"dir", "key", "channels": [{"prompt","response",…}]} を出す
# 分類する側が各 prompt を読み、response に board.Response の形の JSON を書く (key は分類する側に渡さない)
slack-bbs show -key <key> <dir>                               # 検査して板を出し、依頼と応答を消す
```

- show は、依頼のファイルが prepare の書いたままか (一覧のハッシュと、一覧全体の HMAC の署名) と単位の形を確かめてから組む。
  分類する側はファイルを書けるので、本文の中の指示に従って依頼と一覧を書き換えうる。署名の鍵はディレクトリに置かず prepare の出力にだけ出す。
  守る範囲: ディレクトリの中のファイルの書き換え。鍵は prepare を打った親のセッションの記録には残るので、分類役が親の記録まで探しに行く形は守らない
- 前の依頼が残ったディレクトリへの prepare は断る (古い応答が新しい単位に当たらないように)

## 送るもの・残すもの

- 🚨 **期間内の発言と、その文脈の発言の本文が `claude -p` (Anthropic) へ送られる**。プライベートチャンネルを購読すれば、その本文も送られる。
  送る前に `-dry-run` で量を見られる。1 チャンネルで送る発言が `-max` (既定 500) を超えたら送らずに止める
- 🚨 1 段の実行 (`slack-bbs`) は、**取得した発言の本文と分類をチャンネルごとに `~/.cache/slack-bbs/` (`$XDG_CACHE_HOME` があればその下) に残す**
  (`<チャンネル ID>.raw.json` と `.summary.json`、既読の印は `.read.json`。ディレクトリ 0700・ファイル 0600)。読む画面は起動したらこれで前回の板をすぐ出し、裏で取り直す。
  取り直した発言がすべて前回に分類済み (新しい発言・編集された発言が無い。期間から外れただけは含む) なら、claude を呼ばずに前回の分類を使う。
  `-no-cache` で読まずに分類し直す (書くのは続ける)。消すならそのディレクトリを消す。
  読む起動のたびに、14 日書き換わっていない発言と分類のファイル (購読をやめたチャンネルのものなど) と、60 日書き換わっていない既読の印のファイルを消す
- `~/.config/slack-bbs/subscriptions.json` に残すのは購読するチャンネルの ID と名前だけ
- 2 段の実行 (`prepare` → 分類 → `show`) は、本文を prepare のディレクトリ (既定は一時ディレクトリ) に書く。show は全チャンネルを出せたら
  prepare と分類する側が書いたファイルだけを消し、ディレクトリは prepare が作ったときだけ消す。出せなかったときは残す (残った場所を出す)
- `claude -p` は `--no-session-persistence` (セッションを残さない)・`--setting-sources ""` (hooks と CLAUDE.md を読まない)・
  `--tools ""` で起動する (理由は `llm/llm.go` の `Args`)

## 前提

- slack-cli が、スレッドの親の `reply_count` / `latest_reply` を出すバージョン (slack-cli の commit 3cf3c5e 以降) であること。
  古いバージョンでは「続いている」スレッドが見えなくなるので、疑わしいとき (どの親も返信の数を持たない) は板に 🚨 の注記を出す。
  止めはしない (返信が全部消された親しか無いチャンネルは、新しいバージョンでも同じ形になる)
- `claude` に、分類に使うアカウントでログインしていること (`SLACK_BBS_CLAUDE` で別の claude を指せる)

## 構成

| package | 役目 |
|---|---|
| `source` | slack-cli を起動して JSON を読む |
| `board` | 単位へのまとめ直し (`Build`)・LLM の応答の検査と並べ替え (`Assemble`)・機械で確かめるラベル |
| `llm` | `claude -p` の引数・入力 (指示と単位の JSON)・応答の読み取り |
| `render` | 掲示板風の Markdown |
| `subs` | 購読するチャンネルの一覧の保存と、それを選ぶ画面 |
| `view` | 読む画面 (TUI)。読み直しは別の goroutine で走らせ、結果を世代で照合して古い結果を捨てる |
| `job` | 2 段の実行のファイル (依頼・応答・一覧) の読み書きと後始末 |
| `cache` | チャンネルごとの取得の結果 (Raw) と分類 (Summary) のキャッシュ、既読の印 (Read)。分類を使い回せるかの判定 (`Summary.Covers`) |
