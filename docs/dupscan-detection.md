# dupscan が類似メソッドを検出する方法

**状態: 未実装 (計画。epic 890)**。要件の正本は issue 891 で、この文書と食い違ったら 891 が正しい。全体の構成は [`dupscan-overview.md`](dupscan-overview.md)。

## 流れ

1. **走査**: 対象の repo のファイルを `git ls-files` で列挙する (`gate` は ignore されていない untracked も含める)
2. **parse**: tree-sitter で構文木にする。読めない構文 (ERROR / MISSING) を含む単位は比べる対象から外し、件数と場所を報告に出す
3. **単位の抽出**: 比べる単位 = 関数・初期化子・クロージャの本体。関数名と引数ラベルは比べない (名前が違う写しを拾うため)
4. **正規化**: 本体の構文木を段 (L1 / L2 / L3) ごとに潰す
5. **ハッシュ**: 潰した木のハッシュを段ごとに取る
6. **組分け**: 同じ段でハッシュが同じ単位を 1 組にする (Type-2)。少し違う写し (Type-3) は後回し (下)

## 段ごとの正規化

| 段 | 何を潰すか | 拾える写し |
|---|---|---|
| L1 | 局所の名前 (単位の引数・`let` / `var` などで束縛した名前・クロージャの引数) を番号にする。引数は宣言の順に先に振り、残りは初めて出た順。型名・呼び出す関数の名前・メンバー名・enum の case 名・リテラル・`$0` (位置に意味がある)・`$isOn` (projected value) は残す。戻り値の型もハッシュに入れる | 引数やローカル変数の名前だけが違う写し (関数名はもともと比べない) |
| L2 | L1 に加えて、リテラルを種類ごとの記号にする (文字列の中の式の埋め込みは式として残す) | 直書きの値だけが違う写し (`"conn"` と `"c"`) |
| L3 | L2 に加えて、**局所の名前 (と `$0`) を参照しない最大の式**を 1 つの記号に畳む。呼び出しの callee (`JSONEncoder().encode` の受け手を含む) と代入の左辺の下は畳まない。処理の呼び出し (小文字で始まる関数・メソッドの呼び出し。`try`・`await`・`return`・代入の右辺の中でも) を含む式も畳まない。畳むのは値を作る式 (型の初期化 `ConnectionID(…)`・暗黙のメンバー `.bucket(…)`・プロパティ・リテラル) | 同じ値を別の書き方で作る写し (直書きとプロパティ経由) |

ハッシュに入れるもの: ノードの役割 (呼び出し・メンバー参照・文など)・木の形・匿名トークン (`+` / `-`、`==` / `!=`、`try` / `try?`、暗黙のメンバーの `.`)・
呼び出しの引数ラベル (`rawValue:` など。ラベルまで潰すと、ラベルの違う呼び出しがどれも同じになる)。

- 名前を一律の 1 記号にしないのは、`a == a` と `a == b` を区別するため。引数を宣言の順に振るのは、`a - b` と `b - a` を区別するため。代わりに、引数の並びが違う・前に引数が 1 つ多い写しは、本体が同じでも割れる (見逃しの向き)
- 型名や呼び出す関数の名前を番号にしないのは、別の型を組む薄い wrapper がどれも一致するのを避けるため (全部を番号にする案と比べるのは issue 898)
- L3 で「最大の部分式」に限るのは、値を作る式を全部畳むと、本体が 1 つの呼び出しである関数がどれも同じになるため

## 例

```swift
// A: 直書きで組む
func location(path: String) -> StorageLocation {
    StorageLocation(connectionID: ConnectionID(rawValue: "conn"), path: ObjectPath(rawValue: path))
}

// B: 名前が違い、接続の ID をプロパティから読む
func bucketLocation(_ p: String) -> StorageLocation {
    StorageLocation(connectionID: connectionID, path: ObjectPath(rawValue: p))
}
```

| 段 | A と B | 理由 |
|---|---|---|
| L1 | 違う | A は `ConnectionID(rawValue: "conn")` の呼び出し、B はプロパティ `connectionID` の参照で、木の形が違う (関数名は比べず、引数の名前 `path` / `p` は同じ番号になる) |
| L2 | 違う | リテラルを潰しても、呼び出しとプロパティの参照の違いは残る |
| L3 | **同じ** | `ConnectionID(rawValue: "conn")` も `connectionID` も引数を参照しないので、同じ記号に畳まれる。残るのは `StorageLocation(connectionID: ■, path: ObjectPath(rawValue: 引数1))` で、両方で同じ。引数を使う `ObjectPath(rawValue: path)` は残るので、本体全体は潰れない |

報告では、一致した段と、メンバー間のリテラルの違いの表 (B のプロパティは初期値を 1 段だけ解決して並べる) を出す。
`connectionID` の初期値が `"conn"` なら寄せてよい写し、違えば意図した違いかもしれない。最後の判断は人か Claude がする。

## 検出しないもの

- **書き方が違って振る舞いが同じもの (Type-4)**: 構文木では原理的に取れない
- **少し違う写し (Type-3)**: 文が 1 つ多いなど。部分木のハッシュの重なりで類似度を測る案はあるが後回し (issue 895)
- **小さすぎる単位**: ノード数・文の数の下限より小さいもの (下限は obaket と DualNoteApp での実測で決める。issue 898)
- **読めない構文を含む単位**: 外したことは報告に出る
- **局所の名前の有効範囲**: 名前がどこかで局所に宣言されていれば、単位の中の同じ名前を全部局所として扱う (`items.map { name in … }; print(name)` の後ろの `name` が `self.name` でも番号になる)。誤検知の向きに働く
- **`gate` の入れ替え**: 同じ組の古い写しを 1 つ消して新しい写しを 1 つ足しても、写しの数が増えないので落ちない (issue 905)

## 誤検知 (false positive) と除外

出やすい誤検知:

- 🚨 **本体で引数を使わない単位は、L3 で本体全体が 1 記号に畳まれる**。同じ型を返す単位が、中身に関係なくどれも一致する (自明な一致)。この扱い (除くか別に数えるか) は issue 898 で決め、決まるまで L3 は報告だけにする
- テストの表の形が似ているだけの関数、生成コード、意図して分けている写し
- 同じファイルの別の型に同じ名前の関数がある・クロージャ: 鍵に囲む型とクロージャの順番を入れて名指しする (issue 905)

除外の設定 (issue 906):

- 組の除外 (誤検知と判断した組を、メンバーの鍵の集合で指す。行がずれても効く)
- 単位の除外 (単位の直前の `dupscan:allow <理由>`)
- パス・段の除外、下限・閾値の変更
- どの除外にも理由と種別 (誤検知 / 意図した写し) が要る。単位の除外 (`dupscan:allow`) は寄せる側の違反から外すだけで、数には入れたまま。組の除外は書いたメンバーの間にだけ効き、新しく増えたメンバーは出る。効いていない (指す先が無くなった) 除外は毎回出し、`gate` は新しく足された除外を別の一覧に出す (寄せる代わりに除外を書く抜け道を、人が見て止められるように)

## いつ使うか

| 時点 | 使い方 | issue |
|---|---|---|
| メソッドを書く前 | 索引で名前・署名の型・doc 文を引き、似たものが既に無いかを見る (気軽に引く。結果は短い) | 903・897 |
| 実装が終わったセルフレビュー | `dupscan gate` を回し、今の変更で増えた写しが無いかを見る。違反があれば既存のメソッドへ寄せるか、誤検知なら除外を書く | 903・905 |
| `make test` と CI | 同じ `gate` を網として回す (止めるかは実行コスト次第) | 905 |
| 判定を確かめたいとき | `dupscan near` で 1 つの関数に近いものを見る。`dupscan explain` で段ごとに潰した形とハッシュを見る | 904 |
