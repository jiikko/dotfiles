# 動画のシェル関数 (repair / av1ify / concat)

`zshlib/` に定義している動画処理のシェル関数。

## repair

問題のある動画ファイルを修復します。

```bash
repair movie.mp4           # 単一ファイル
repair *.mp4 *.ts          # 複数ファイル
repair -h                  # ヘルプ
```

- mpegtsなど問題のあるコンテナをMP4に変換
- 異常なフレームレート（240fps超）を自動で30fpsに正規化
- 可能な限りストリームコピー（無劣化）
- 対応形式: `.mp4`, `.m4v`, `.mov`, `.ts`, `.mts`, `.m2ts`
- 出力: `*-repaired.mp4`
- 依存: `ffmpeg`, `ffprobe`

## av1ify

動画ファイルをAV1形式のMP4に変換します。

```bash
av1ify movie.avi           # 単一ファイル
av1ify /path/to/dir        # ディレクトリ内を再帰処理
av1ify -f list.txt         # ファイルリストから処理
av1ify                     # 引数なし: クリップボードのパス（1行1パス）を確認して処理
av1c                       # 720p+30fps プリセット + 成功時に元ファイルをゴミ箱へ（引数なしはクリップボード）
av1ify /path/to/dir --dry-run  # 変更せず実行内容だけ確認
AV1_CRF=35 av1ify movie.mp4  # CRF指定
```

- SVT-AV1エンコーダを使用（なければAOM-AV1にフォールバック）
- 引数なしで呼ぶとクリップボードを1行1パスとして読み、一覧表示して `[y/N]` 確認後に処理（大量のパスをターミナルへ貼ると文字が落ちる事故を避けるため）。見つからないパスは除外して続行。表示は絶対パス化 + symlink 解決済みで、ディレクトリ行は配下の件数を出す（一覧が実際の処理範囲を表すようにするため）
- 発火するのは**対話シェルで打ったときだけ**。Finder アクション・CI・`bin/av1ify` や `bin/binav1c` の直叩き（= 非対話）では発火せずヘルプを表示する
- `av1c`（`--compact` + 成功時に元ファイルをゴミ箱へ）も対話シェルでは関数なので引数なしでクリップボードを読む。確認プロンプトは赤字の削除警告つき。**マッチ0件の glob で引数が消えた `av1c **/*.mkv(N)` もこの確認に化ける**ので、一覧を読んでから答えること（既定は No）
- 解像度に応じてCRFを自動調整
- 音声は可能な限りコピー、非対応形式はAACに再エンコード
- `--dry-run` で実行内容のみ表示（ファイルを変更しない）
- 対応形式: `.avi`, `.mkv`, `.rm`, `.wmv`, `.mpg`, `.mpeg`, `.mov`, `.mp4`, `.flv`, `.webm`, `.3gp`, `.ts`
- 出力: `*-enc.mp4`
- **同じファイルへの二重実行は `lockman` で防ぐ**。1 ファイル 1 ロックで、他プロセスが
  処理中なら SKIP して次へ進む。ロックが無いと、一時出力 `*-enc.mp4.in_progress` が
  入力パスから決まる決定論的な名前なので、片方がもう片方の作業中ファイルを消したうえで
  「検証 OK」と判定して元ファイルをゴミ箱へ送る (2026-09-08 に再現確認)
  - ロックの置き場は `~/.lockman/av1c/<パスのハッシュ>/`。`AV1IFY_LOCK_ROOT` で変更できる
  - **同一マシン内の排他**。複数マシンから同じ共有を触るなら `AV1IFY_LOCK_ROOT` を
    共有上のパスへ向ける (lockman 自体は SMB 越しを想定して作られている)
  - 処理した本数ぶんの空ディレクトリ (1 本 4KB) が溜まる。**アイドル時に
    `rm -rf ~/.lockman/av1c` で片付く**。実行中に消すと、走っているプロセスの
    lease が飛ぶので消さないこと
  - `lockman` が PATH に無いときは警告を出して排他なしで続行する (黙って進めない)
- 依存: `ffmpeg`, `ffprobe` (SVT-AV1サポート付き)

## concat

複数の動画ファイルを無劣化で結合します。

```bash
concat video_001.mp4 video_002.mp4 video_003.mp4  # 連番ファイルを結合
concat --force video1.mp4 video2.mp4               # コーデック不一致でも強制実行
concat -h                                          # ヘルプ
```

- FFmpegのconcat demuxerを使用して無劣化結合
- 同一コーデック・フォーマットの動画を高速に連結
- ファイル名の連続性（連番パターン）を自動チェック
- コーデック・解像度の不一致を検出
- クラウドストレージ（Dropbox等）の自動プリフェッチに対応
- 対応形式: `.mp4`, `.avi`, `.mov`, `.mkv`, `.webm`, `.flv`, `.wmv`, `.m4v`, `.mpg`, `.mpeg`, `.3gp`, `.ts`, `.m2ts`
- 出力: 共通プレフィックス + `.mp4` (例: `video_001.mp4, video_002.mp4` → `video.mp4`)
- 依存: `ffmpeg`, `ffprobe`
