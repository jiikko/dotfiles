# pro-con 経由で作業させるか、Claude を何本も立ち上げてチャットで指示するか (2026-09-26)

2026-09-25〜26 の dogfooding (pro-con で pro-con 自身を開発した 2 日。カード C-001〜C-073) を材料にした比較。
数字のうち**実測**は出典を添え、それ以外は**見立て**と書く。pro-con 自体が作りかけなので、下の「pro-con の弱み」の一部は直せる類。

## 比べるもの

- **並べたチャット**: 人が Claude Code の session を何本か開き、それぞれに直接書き込んで作業させる。取りまとめは人
- **pro-con**: 依頼をカードにし、PM (分ける・PG の質問に答える)・PG (1 カード 1 session・1 worktree)・取り込みの係 (レビューして master へ)・
  dispatcher (割り振り・枠・順番) に回す。人は画面か `pro-con card` で依頼し、人の番のカードにだけ答える

## 並べたチャットが勝つところ

- **会話の往復が要る作業**: 設計の相談・見た目の見本を見ながら決める・調べながら方針を変える。pro-con では PG と人の間に PM とカードが挟まり、
  問いは `card ask`、方針変更は追加オーダーで届く。1 往復が turn の区切り待ちになる
- **小さい作業**: 数分で終わる修正は、カードを作る・PM が分ける・PG を起こす・取り込みの係がレビューする分だけ遅く重い。
  PG の起動そのものは安い (1 回 ≈ 5 時間枠の 0.05%。issue 449) が、PM と取り込みの係の session の分が上に乗る (見立て。役ごとの枠の使用量は分けて測っていない)
- **道具が素直に使える**: AskUserQuestion・plan モード・画面の確認などを、その session でそのまま使う。pro-con の PG は AskUserQuestion の代わりに `card ask` を使う (493 で選択肢のフォームは入った)
- **壊れる所が少ない**: 仕組みが Claude Code だけ。pro-con は dispatcher・supervisor・見張り・画面・状態の置き場を持ち、それ自体が不具合を出す
  (この 2 日で見つけたもの: 質問待ちのカードを消すと質問が消える / issue から足したカードの原文が空で PM が聞き返す (511) /
  `--join` の画面だけだと dispatcher を誰も起こし直さない (506 の確認で判明。481 の決定どおり))
- **調べやすい**: 1 つの会話を読めば何が起きたか分かる。pro-con では transcript・`cards.json`・`events.jsonl`・`pro-con ps` を突き合わせる

## pro-con が勝つところ

- **並べる本数が増えたとき、人が振り分け係にならない**: どの session に何を頼んだか・どれが止まっているかを人が覚えなくてよい。
  カードの列と「人の番」の印が、人が今答えるべきものだけを出す (452)
- **依頼が消えない**: 依頼 1 件 = カード 1 枚で、閉じるまで列に残る。session を閉じても端末が落ちても残る (カーネルパニックの後、
  `cards.json` と session の記録から復旧できた。483)。並べたチャットでは、閉じた session に頼んだことは人の記憶にしか残らない
- **worktree と取り込みが自動**: PG ごとに worktree を切り、取り込みの係が diff を読んでテストを回し、master へ push する。
  並べたチャットで書き込み係を 2 本以上走らせると、worktree の分離と統合を人が組む (`parallel-write-agents-need-worktree-isolation.md`)
- **実装の細かい判断で人が止まらない**: PG の質問はまず PM が受け、実装の選択は PM が答える。人に来るのは目的・見た目・方針だけ
- **枠と順番を機械が守る**: 利用枠が近いと起動を待たせる・同じファイルを触るカードに順番を付ける (468)・重いコマンドを直列にする (471)
- **記録が後から読める**: カードの履歴・出来事の記録 (`pro-con log`) が残るので、何が起きたかを後から追える (512 でこれを画面でも見る)

## 実測で分かったコスト (issue 449)

- カード 1 枚 (中央値) ≈ 5 時間枠の 2.2% ($7.9)。2026-09-25 の PG 42 枚の計 ≈ $369
- PG の書き込みの約 36% は、再開のたびにキャッシュに当たらず会話を書き直した分 (tools の並びが揺れる。直し方は未起票)。
  これは pro-con の作り方から来る無駄で、並べたチャットでは起きにくい (session を起こし直さないため)
- PG を使い回す (プール) のは採らない (449。カードの文脈が混ざり、会話が伸びて毎回の読み直しが増える)

## どちらを使うか

| 作業の形 | 向く方 |
|---|---|
| 仕様が issue に書き切れていて、互いに独立した作業が何本もある | pro-con |
| 数分で終わる修正・1 本だけの作業 | 並べたチャット (か、今の session で直接) |
| 相談しながら決める・見本を見て選ぶ・調べながら方針が変わる | 並べたチャット |
| 夜間や席を外す間に進めたい、依頼を溜めておきたい | pro-con |
| pro-con 自体が壊れていそう・何が起きたか追いたい | 並べたチャットで直す |

実際の運用 (この 2 日) は**混ぜた形**がいちばん回った: 人と話す Claude の session を 1 本持ち、その Claude が pro-con の外から
依頼を issue にしてカードに積み、PM の質問を代わりに答え、止まったものを調べる。会話の良さ (往復が速い) と pro-con の良さ
(並べる・残る・取り込む) を両方取れる。その役の Claude のための入口が 510 (`pro-con help` と skill)。

## 見立てのまま残っていること (測っていない)

- PM と取り込みの係の枠の使用量 (役ごとに分けて測っていない)
- 同じ作業を並べたチャットでやった場合の枠と時間 (対照を取っていない)
- 取り込みの係のレビューが、人が読む場合と比べてどれだけ漏らすか
