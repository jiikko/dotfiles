# glogx UI ガイド — 操作感の世界観とキー語彙

glogx の画面 (git log 一覧 / job パネル / diff / issues viewer / status viewer / doctor /
ratelimit) に共通する**操作の考え方**を 1 箇所に置く。個々のキーの一覧は
[`src/glogx/README.md`](../src/glogx/README.md) と `glogx --help` が正本で、ここには
「なぜそのキーか」「新しい操作を足すときに何に揃えるか」を書く。

各画面の契約 (何をしてはいけないか) は [`issues-viewer-spec.md`](issues-viewer-spec.md) /
[`status-viewer-spec.md`](status-viewer-spec.md) にある。本書はその上に乗る語彙の層。

## 1. 世界観: 「pager の中に居る」

glogx は `git log` の pager を置き換えるものとして始まった。だから体感の基準は **less / tig**
であり、GUI のウィンドウでもエディタでもない。ここから 3 つの原則が出る。

- **手はホームポジションから動かさない**。移動・開閉・コピー・実行のすべてを英字と Enter で
  済ませる。矢印や PgUp/PgDn は別名として受けるが、案内 (hint 行) が出すのは英字
- **画面は「板」の重なりで、板は奥から手前へ飛び出してくる**。issues viewer は右から、
  status viewer は左から、引き出し (本文) は右から。方向で「どの板か」を見分ける。
  板の出入りは演出つきだが、**演出中のキーは即着地させ、かつ飲み込まない** (押した瞬間に
  意図した操作が始まる。待たせない)
- **1 段戻る操作と、全部終える操作を分ける**。`q` は tig 流に「今の板を 1 段戻る」で、
  即終了は `Ctrl-C`。ただし issues / status viewer は例外で `q`/`Esc` が glogx ごと終了する
  (ユーザー選定 2026-08-06。`i` / `s` が「閉じて一覧へ戻る」を担うため)

## 2. キーの 3 層構造

キーは 3 つの層に分かれ、**新しい操作は必ずどの層かを決めてから割り当てる**。

| 層 | 由来 | キー | 意味 |
|---|---|---|---|
| **移動** | vim | `j` `k` `g` `G` `h` `l` `Ctrl-D` `Ctrl-U` `Space` `f` `b` | カーソルとスクロール。全画面で同じ |
| **移動の別名** | emacs / 矢印 | `Ctrl-N` `Ctrl-P` `Ctrl-F` `↑` `↓` `←` `→` `PgUp` `PgDn` `Home` `End` | 移動層の同義語。**新しい意味を与えない** |
| **動作** | 画面固有 | 英字 1 文字 (`d` `e` `y` `p` `n` `a` `r` …) と `Enter` | その画面の対象に対する操作 |

### vim 層 (一次語彙)

- `j`/`k` は常に「1 行」。一覧ではカーソル、pager (diff / 本文) では行送り
- `h`/`l` は「左右」だが、glogx で左右に並ぶものは**タブ・セクション・開閉**なので、
  一覧では `l` = 開く / `h` = 閉じる、タブのある画面では `h`/`l` = タブ移動になる。
  「戻る = 左」「進む = 右」の向きは全画面で守る
- `g`/`G` は端ジャンプ。`Ctrl-D`/`Ctrl-U` と `Space`/`f`/`b` は半ページ (less の語彙)
- スクロールは全 pager で `pagerScrollKey` (`scroll_glide.go`) を共有し、**手触り (glide の
  フレーム数・末尾で止まる挙動) を 1 箇所で決める**。画面ごとに別実装しない

### emacs 層 (別名だけ)

- `Ctrl-N`/`Ctrl-P` = ↓/↑、`Ctrl-F` = → は**全ビューで同じ**。`Ctrl-F` は `tui.go` の入口で
  `right` に正規化しているので、各画面は `right` だけ見ればよい
- 🚨 **`Ctrl-B` は ← の別名ではない**。本家 glog で push だった名残で未割当のまま。
  issues viewer だけタブ移動の左として受けている (ユーザー要望 2026-07-31) が、全画面へは
  広げない (一覧・パネル側の `left` に別の意味を与えないため)
- emacs 層のキーに**新しい意味を足さない**。これは「矢印の代わり」であって動作層ではない。
  `Ctrl-N` を「次の項目」のような別の意味にすると、pager で行送りのつもりが項目が飛ぶ

### 動作層 (画面固有だが、語は横断で揃える)

同じ字は全画面で同じ動詞にする。画面が違っても意味が変わらないことが、案内を読まずに
押せる条件になる。

| 字 | 動詞 | 例 |
|---|---|---|
| `Enter` | **TUI 内の開閉 toggle** | job パネル / 本文の引き出し / doctor の内訳。開くのも閉じるのも Enter |
| `o` | ブラウザで開く | コミット / job / PR |
| `e` (`v`) | エディタで開く | repo root / issue 本文 / job ログ |
| `y` | コピー (素の値: URL / パス) | |
| `Y` | コピー (整形した参照: Markdown / 番号+タイトル+パス) | |
| `p` | PR または番号 | 一覧では PR を開く、issues では番号コピー (「PR / number」の頭文字) |
| `d` | diff | コミット / status のファイル |
| `r` | 再読込 / 再実行 | issues の再読込、job の rerun |
| `a` | all / 巡回 | status で全部 stage、issues で状態フィルタ巡回 |
| `n` | next (次にやる目印) | issues の claim |
| `N` | 次の番号 | issues の採番コピー |
| `i` `s` `R` `D` `U` | 板の toggle (横断キー) | どの画面からも同じ板へ飛べる |
| `C` `X` | update (claude / codex) | どの画面からも。**status では `X` = 変更を捨てる**なので例外 |
| `Space` | 選択 / stage | 「対象に印を付ける」。一覧では半ページ (less) |

🚨 **大文字は小文字の「強い版」または「まとめ版」**にする (`y` → `Y`、`n` → `N`、
`j` → `J`)。無関係な意味を大文字に与えると、shift の押し間違いが別の操作になる。

## 3. 開閉の語彙

- **Enter は開閉 toggle**。行送りには使わない (ユーザー要望 2026-08-01。job パネルと issues
  本文で同じ)。pager の共有ロジックは `enter` を 1 行送りに写すので、**画面側で先に捌く**
- **閉じるキーは `q` `Esc` `h` `←` + 開いたキー自身** (`d` で開いた diff は `d` でも閉じる。
  `i` で開いた viewer は `i` で閉じる)。開いたキーで閉じられると「押し直せば戻る」が成り立つ
- 演出は「飛び出す / 抜ける」であって「幅が伸びる」ではない。板は最終幅のまま位置だけ動く
  (詳細は issues-viewer-spec の引き出し節)

## 4. 破壊的操作の語彙

- 実行系 (`b` push / `u` pull / `X` 捨てる / `x` 実行 / `d` 削除 / `r` rerun) は**必ず y/N 確認**。
  `y` と `Enter` だけが実行で、**知らないキーはすべて取り消し**に倒す
- 確認モーダルの `Enter` は「飲む」場合がある (doctor の削除確認は Enter で実行もキャンセルも
  しない。issue 243)。Enter が開閉 toggle として全画面に効くため、連打の勢いで削除が
  走らないようにしている
- 破壊的操作のキーは**画面ごとに衝突を明記する** (`X` は codex update と「変更を捨てる」で
  割れている。README がその旨を書く)

## 5. 案内 (hint 行) の規律

- 最下行の案内は端末幅で落とすが、**抜ける手段 (`q` / 閉じるキー) は必ず残す**
- 案内に載せたキーは**その画面のあらゆる状態で案内どおりに動く**こと。ピッカーや絞り込みの
  入力中に案内が残っていると、載せたキーが全部検索語に化ける (issues viewer の URL ピッカーで
  実測)。入力中は案内を差し替える
- 幅の都合で案内から落としたキー (`R` 等) も**動く**。案内は「全部」ではなく「よく使う」

## 6. 「詳細を開いたまま隣へ」= `J` / `K`

2026-09-05 まで、glogx には**詳細を開いたまま次の項目へ送る操作がどの画面にも無かった**
(commit diff / status の全画面 diff / job 詳細 / issues 本文の 4 つとも、閉じる → `j`/`k` → 開く
の 3 打)。issues viewer で「本文を読みながら次の issue へ」が欲しいという要望から、
次の語彙を決め、同日に 4 画面すべてへ入れた。

- **`J` / `K` (shift+j / shift+k) = 詳細を開いたまま次 / 前の項目へ**
- 小文字 `j`/`k` が「行」なら大文字は「項目」。層の対応 (§2 の「大文字は小文字の強い版」) に沿う
- 引き出しの左に一覧の先頭が残る設計なので、左のカーソルが一緒に動けば位置が見える。
  開閉の演出は挟まず本文だけ差し替える。スクロール位置は先頭へ戻す
- Epic の親行 (本文が無い) は飛ばす。端では止めて notice を出す (巻かない)
- 空いていることは確認済み: `Ctrl-N`/`Ctrl-P` は emacs 層でスクロール済み、`Tab`/`h`/`l`
  はタブ移動、`n` は claim、`]`/`[` は未使用だがホームポジションから外れる
- 🚨 issues の**一覧**では `J`/`K` が範囲選択の伸張 (shift+矢印は tmux 越しで届かないことがある
  ので、確実に届く大文字を残している)。一覧では「選択を伸ばす」、本文では「隣へ送る」と
  同じ画面内で意味が割れる。範囲選択は本文に無いので衝突はしないが、この割れは承知の上で採る

**4 画面での形は同じ**: 「隣へ移す → 既存の open 関数で開き直す → スクロールは先頭 (job 詳細は
末尾) へ」。新しい状態は増やさず、各画面に既にある移動と開く関数を繋いでいる。起点だけ画面で
違う: commit diff は**表示中の SHA** (job パネルから開いた diff はカーソルと食い違うため)、
他はカーソル。端の案内は全画面「これが最後 / 最初の〜です」で揃えている。
新しい詳細画面を足すときも同じ形で `J`/`K` を持たせること (持たない画面が 1 つあると
「その画面だけ効かない」になる)。

## 7. 新しいキーを足すときのチェック

1. どの層か (移動 / 別名 / 動作)。別名層には新しい意味を与えない
2. その字は他の画面で何の動詞か。**同じ字は同じ動詞** (§2 の表に足す)
3. 大文字なら小文字の「強い版 / まとめ版」になっているか
4. 破壊的なら y/N 確認と「知らないキーは取り消し」を守っているか
5. 案内に載せるなら、その画面の全状態 (入力中・演出中・モーダル中) で案内どおりに動くか
6. README のキー表と `--help` を同じ変更で直す (案内・README・help の 3 つが正本の分担で、
   コードのコメントは入口に数えない)
